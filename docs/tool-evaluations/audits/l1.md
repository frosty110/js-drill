## Strengths
- **Misses feed three independent signal lanes** (`12a-l1.js:257, 293, 379-380`): `state.weakness` (lesson-grain), `state.misses` (concept-grain via tag chips), and `state.history` (event log for hint trends, Pace-Bar, Streak Map).
- **Per-session shuffle resists pattern memorization** (`12a-l1.js:208-216`) — question order AND option positions both reshuffle on retry; cached for tab-switch survival.
- **Letter-labeled options** (`12a-l1.js:242`) keep the AI-export prompt's "I picked B" intelligible (`12a-l1.js:32-34`), which closes the loop with external LLM tutoring.

## Weaknesses
- **Recognition ceiling on Encoding (1/3)** — by construction L1 can never produce free recall. This is the design intent (PROFILE.md:30 → "L1 (multiple choice) is the smoothest interaction on mobile"), but it means L1 alone can't move Encoding past 1/3. The salvage is layering production-direction recall on top, not replacing the MC core.
- **Feedback rarely explains the user's specific wrong pick** (`12a-l1.js:267`) — `q.explain` is authored *for the question* (why the correct answer is correct), not per-option. The "Ask AI to teach me" export (`12a-l1.js:319`) does diagnose specific wrong picks but requires manual action.
- **No cross-lesson interleave from inside the L1 tab itself** (`12a-l1.js:223` — all cards belong to one lesson). Rapid-Fire L1 (separate tool) covers this, but the per-lesson L1 view is fully blocked. A user drilling 5 lessons in a row on one section is effectively block-practicing concepts that should be interleaved.

## Salvage path (if IMPROVE)
Ordered by leverage. Each edit names file:line + the dim it lifts.

1. **Auto-mix one weak-spot question into every L1 session** — `12a-l1.js:208-217` — when rendering L1 for lesson X, prepend ONE random unanswered question from `state.weakness` (other lessons), tagged as "Carry-over weak spot." Lifts **Interleaving** by +1 (1→2: per-session mixes another lesson's concept) without changing the lesson-level pass criterion (`maybePassL1` could exclude carry-over from the all-correct check via a `carryover: true` flag).
2. **Per-option authored `whyWrong` field, validator-soft** — `12a-l1.js:267` — extend the L1 question schema to `options: [{text, whyWrong?}]` (back-compat with bare strings). When user picks wrong, feedback shows `q.options[picked].whyWrong` instead of (or after) the generic `q.explain`. Lifts **Feedback quality** by +1 (2→3: per-pick diagnostic). Authoring cost is real — backfill is a future iter; the engine ships first.
3. **Add one "blank editor token" L1 variant per Patterns lesson** — author MC where the question shape is "Pick the missing token in this line of the canonical: `for (let i = ___; i < n; i++)`" with 4 token options. Lifts **Transfer-context match** by +1 (1→2: scaffolded code context) AND nudges **Encoding** toward 2/3 (token-grain cued recall vs prose concept). This is content-authoring, not engine work.
