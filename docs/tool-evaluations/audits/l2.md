## Strengths
- **Mobile-first variant ships its own UX** (`12b-l2.js:211-488`) — tap-chip + shared bottom sheet honors PROFILE.md:31-33 ("L2 is feasible on mobile — short token typing"). Cache shape mirrors desktop so viewport-switching mid-attempt is symmetric (`12b-l2.js:215-225`).
- **96px uniform input width prevents length-leak** (`12b-l2.js:91`) — a real production-direction discipline; longer/shorter slots would telegraph answer length.
- **Smart-scroll on pass** (`12b-l2.js:11-22, 137`) — after `✓ Pass`, auto-scrolls next unpassed exercise into view; honors PROFILE.md:50-54 ADHD single-focus + tap-tap-tap mobile loop.

## Weaknesses
- **Reveal answers is one-click flat** (`12b-l2.js:152-162`) — even per-card. A "show me ONLY blank 2's answer" tier would preserve the production attempt on blanks 1, 3, 4. Current UX makes giving up easy.
- **Misses don't write to `state.weakness`** (`12b-l2.js:144-149`) — runtime errors and output mismatches are surfaced in feedback but never persisted. The SR loop only knows about reveals + passes, not the "struggled but eventually passed" middle case which is exactly the signal a memory tool wants.
- **Block-practiced at lesson grain** (`12b-l2.js:49`) — same as L1, no cross-lesson card mixing inside the L2 tab.

## Salvage path (if IMPROVE)
Ordered by leverage.

1. **Record attempt count as a weakness signal** — `12b-l2.js:108-150` — track `exerciseState[exi].attempts++` per Check click; if `attempts >= 3` AND pass eventually fires, call `state.weakness[lesson.id] = (...||0)+1` once. Lifts **Closed-loop signal use** by +1 (2→3: misses feed weakness, not just reveals). Three sloppy passes shouldn't be invisible.
2. **Per-blank reveal (tier the reveal)** — `12b-l2.js:152-162` — replace the flat "Reveal answers" button with a per-blank "?" affordance on each `.blank-input`. Tapping the ? reveals ONLY that blank and writes a per-blank-revealed flag to `state.revealed`. Lifts **Active recall** by +1 (2→3: full per-card reveal stops being one tap; user must intentionally surrender each blank).
3. **Authored per-blank `whyAnswer` (validator-soft)** — `12b-l2.js:104, 138-142` — extend schema `blanks: [{answer, hint?, whyAnswer?}]`; on a wrong-blank check, surface `whyAnswer` next to the red outline. Lifts **Feedback quality** by +1 (2→3: per-blank conceptual diagnostic). Authoring cost is real; engine ships first.
