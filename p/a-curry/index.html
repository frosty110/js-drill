Curry

Turn `fn(a, b, c)` into a function you can call as `f(a)(b)(c)`, `f(a, b)(c)`, or `f(a, b, c)` — the recursive-args-accumulator pattern.

Problem

Implement curry(fn). Demonstrate all three call shapes on add(a,b,c) — f(1)(2)(3), f(1,2)(3), and f(1,2,3) — log each result.

Expected output: 6 6 6 6

Canonical solution

Recursive arity check (args accumulator) · O(n) / O(n), n = arity (time / space)

function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {           // enough args — fire it
      return fn.apply(this, args);
    }
    return function (...more) {                // not enough — collect more
      return curried.apply(this, args.concat(more));
    };
  };
}
const add = (a, b, c) => a + b + c;
const c = curry(add);
c(1)(2)(3);        // 6
c(1, 2)(3);        // 6
c(1)(2, 3);        // 6
c(1, 2, 3);        // 6
  • fn.length is the count of declared parameters (before any default value) — the arity the curry compares against.
  • Recursion via the named curried callee lets each partial call append args and re-check arity.
  • Default params and rest params change fn.length semantics; rest params count as 0. For variadic functions, curry doesn't apply.
  • Time O(n²) worst-case (n one-arg calls each copy growing array via concat). Space O(n) for closure chain. n = arity, typically ≤ 5 in practice.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What does fn.length measure?

  1. A Number of times fn has been called
  2. B Number of declared parameters before the first default value or rest param correct
  3. C Length of fn.toString()
  4. D Number of arguments most recently passed

Why: fn.length is a static property of the declaration, which is why args.length >= fn.length can decide when to fire. It also means curry silently breaks on (a, b = 1, c) => … (length 1, stops at the first default) and (...args) => … (length 0) — both fire fn far too early.

Q2 Why does the inner function call curried(...) instead of fn(...) directly?

  1. A It memoizes intermediate calls so repeated partials share results
  2. B So the new args list can re-check arity and chain further partials correct
  3. C Calling fn directly would bypass the closure that holds the accumulated args
  4. D fn(...args) only accepts spreads in non-strict mode

Why: Recursing into curried re-runs the args.length >= fn.length test on the grown list, which is what lets c(1)(2)(3) and c(1)(2, 3) both work. Calling fn there would invoke it after two args with c left undefined.

Q3 What does curry(add)(1, 2)(3) return for const add = (a, b, c) => a + b + c?

  1. A 1
  2. B 3
  3. C 6 correct
  4. D a function

Why: The first call collects [1, 2] — 2 is short of add.length of 3, so it hands back a collector, not a result. The second call concats to [1, 2, 3], the arity test passes, and add fires.

Q4 Why use args.concat(more) instead of args.push(...more)?

  1. A push would reject the spread when more has more than 65536 items
  2. B concat returns a new array — push mutates, leaking state across sibling partial calls correct
  3. C concat preserves argument order; push reverses the appended items
  4. D push returns the new length, so the recursive call would receive a number instead of an array

Why: args is captured by the closure and shared by every partial branched off it, so push would make c(1)(2) permanently corrupt the c(1) collector for the next reuse. concat hands each branch its own array.

L3 — Write it from memory

One position, the code's third segment.

Implement curry(fn). Demonstrate all three call shapes on add(a,b,c) — f(1)(2)(3), f(1,2)(3), and f(1,2,3) — log each result.

Hints
  • Compare collected args.length against fn.length to decide fire-or-defer.
  • Use a named inner function so the next partial can recurse on it.
  • Concat the new args onto the closure's args — never mutate the closed-over array.
function curry(fn) {
  // Named inner fn so each partial call can recurse on itself to re-check arity.
  return function curried(...args) {
    // fn.length is declared param count — enough args means fire.
    if (args.length >= fn.length) return fn.apply(this, args);
    // concat (not push) — never mutate the captured args across sibling partials.
    return function (...more) { return curried.apply(this, args.concat(more)); };
  };
}
const add = (a, b, c) => a + b + c;
const c = curry(add);
console.log(c(1)(2)(3));
console.log(c(1, 2)(3));
console.log(c(1)(2, 3));
console.log(c(1, 2, 3));
