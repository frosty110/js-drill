Deep Clone

Recursively clone plain objects and arrays so mutating the clone never touches the original — the canonical recursion + WeakMap-for-cycles pattern.

applied Applied Problems 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Implement deepClone(value) with cycle detection. Clone a nested object, mutate the clone, log original.nested.x and clone.nested.x to prove independence, then clone a cyclic object and confirm cycle.self === cycle.

Expected output: 1 99 true true

Canonical solution

Recursive copy + WeakMap cycle guard · O(n) / O(n), n = nodes (time / space)

function deepClone(value, seen = new WeakMap()) {
  // Primitives (incl. null which is typeof 'object') are immutable — return as-is.
  if (value === null || typeof value !== 'object') return value;
  // Cycle guard: a child pointing back to value finds the in-progress clone.
  if (seen.has(value)) return seen.get(value);
  const out = Array.isArray(value) ? [] : {};
  // Register BEFORE recursing so cyclic graphs don't recurse forever.
  seen.set(value, out);
  for (const k of Object.keys(value)) out[k] = deepClone(value[k], seen);
  return out;
}
  • Primitives (number, string, boolean, null, undefined) are immutable — return as-is, no copy needed.
  • Register the new object in the WeakMap before recursing into children, or cyclic graphs recurse forever.
  • This minimal version skips Date, Map, Set, RegExp, and class prototypes. Real structuredClone handles those; interviews usually only ask for the recursive core.
  • Time O(n) where n = total nodes. Space O(n) for the clone + WeakMap + recursion stack.

Alternate approaches

structuredClone (built-in, production answer) O(n) / O(n)

Use in production code when you're targeting Node 17+ or modern browsers — it handles Date, Map, Set, ArrayBuffer, typed arrays, and cyclic references natively and is faster than a JS implementation. The recursive version in the primary is what an interviewer wants (shows you understand the algorithm); structuredClone is what you'd ship in real code.

function deepClone(value) {
  return structuredClone(value);
}
const a = { nested: { x: 1 }, list: [1, 2, 3] };
const b = deepClone(a);
b.nested.x = 99;
console.log(a.nested.x);
console.log(b.nested.x);
console.log(a.list !== b.list);
const cyc = { name: 'root' };
cyc.self = cyc;
const cycClone = deepClone(cyc);
console.log(cycClone.self === cycClone);
  • structuredClone is a W3C standard built into browsers (Chrome 98+, Node 17+) — no library needed.
  • Handles cycles, Date, Map, Set, ArrayBuffer; throws on functions, DOM nodes, and class instances that aren't serializable.
  • Prefer this in production; use the recursive version in interviews to demonstrate you understand the algorithm.

JSON round-trip (JSON.parse + JSON.stringify) O(n) / O(n)

Acceptable for plain JSON-shaped data where you know there are no functions, undefined values, Date objects, cycles, or class instances. It is the one-liner answer — name it first to show you know it, then explain why the recursive version is correct for the general case.

function deepClone(value) {
  return JSON.parse(JSON.stringify(value));
}
const a = { nested: { x: 1 }, list: [1, 2, 3] };
const b = deepClone(a);
b.nested.x = 99;
console.log(a.nested.x);
console.log(b.nested.x);
console.log(a.list !== b.list);
// Note: cyclic inputs throw "Converting circular structure to JSON".
// The line below demonstrates independence without cycles:
console.log(b.nested.x === 99);
  • Silently drops functions, undefined, and Symbol keys — the clone will be missing those properties entirely.
  • Converts Date to ISO string, Map/Set/RegExp to {} — prototypes are lost.
  • Throws on cyclic references (circular structure); use the recursive+WeakMap version or structuredClone for those.

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why must you set seen.set(value, out) before iterating the object's keys?

  1. A Reads in WeakMap return stale values until a write commits, so it primes the cache
  2. B To handle cycles: a child that references back to value must find the in-progress clone correct
  3. C Setting after the loop overwrites the populated children with the empty out
  4. D Otherwise seen.has(value) short-circuits the recursion before children are copied

Why: For cyc.self = cyc, the recursion into self re-enters with the same object; registering out first means that call hits seen.has and returns the half-built clone instead of recursing forever. Registering after the key loop would blow the stack on any cycle — the loop never gets to finish.

Q2 What does deepClone(42) return?

  1. A An object wrapping 42
  2. B 42 — primitives are returned as-is correct
  3. C undefined
  4. D Throws because 42 is not cloneable

Why: typeof 42 !== 'object' so the first guard returns it untouched — primitives are immutable, so sharing one is indistinguishable from copying it. That guard also carries null, which has to be tested explicitly because typeof null === 'object'.

Q3 After const b = deepClone(a); b.nested.x = 99;, why is a.nested.x unchanged?

  1. A Spread {...a} would copy nested by reference, but deepClone returns a structuredClone-backed proxy
  2. B Because b.nested is a new object, distinct from a.nested correct
  3. C Because the WeakMap pins the original so writes to b are rerouted to a new sub-object
  4. D Because Object.assign copies values, and deepClone is built on top of it

Why: The recursion hit a.nested, took the Array.isArray ? [] : {} branch and rebuilt it, so b.nested is a fresh object and the write lands only there. {...a} or Object.assign would have copied the nested POINTER, and this exact mutation would show up on the original.

Q4 Why WeakMap instead of Map for the seen cache?

  1. A Map keys are compared by ==, so two equal objects would collide; WeakMap uses identity
  2. B WeakMap holds keys weakly, so the cache doesn't block GC of cloned graphs correct
  3. C WeakMap's .has() is O(1); Map's .has() is O(log n)
  4. D Map throws if a key is reassigned, which would fire when registering the clone

Why: seen keys every source object it visits, and a plain Map would keep all of them alive for as long as the map lives — the standard leak when a cache is hoisted out of the call. Both keep keys by identity, so identity lookup is NOT the difference between them.
