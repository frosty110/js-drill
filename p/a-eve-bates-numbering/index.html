Bates Numbering

Assign each produced document a Bates range with a `for...of` carrying a running counter — algorithm shape, because each doc's range depends on the cumulative page count of everything before it.

Problem

Assign each produced document a Bates range: prefix EVE, 6-digit zero-padded, starting at 1. A 1-page doc gets a single label; multi-page gets start-end.

Expected output: Intake: EVE000001-EVE000002 X-Ray: EVE000003 ER Report: EVE000004-EVE000008

Canonical solution

Single pass carrying a running counter · O(n) / O(n) (time / space)

function bates(docs, prefix = 'EVE', width = 6) {
  // Fixed-width zero-padded labels sort and collate correctly in a legal production.
  const label = n => prefix + String(n).padStart(width, '0');
  const out = [];
  let next = 1;
  // The counter is stateful across docs — can't be a pure .map.
  for (const d of docs) {
    const start = next;
    const end = next + d.pages - 1; // off-by-one: a 1-page doc spans start..start, not start..start+1
    out.push(`${d.name}: ${d.pages === 1 ? label(start) : label(start) + '-' + label(end)}`);
    next = end + 1;
  }
  return out;
}
const docs = [{ name: 'Intake', pages: 2 }, { name: 'X-Ray', pages: 1 }, { name: 'ER Report', pages: 5 }];
bates(docs).forEach(l => console.log(l));
  • padStart(width, '0') produces fixed-width labels (EVE000001) so the strings sort and collate in numeric order — essential when documents are produced and referenced by Bates number.
  • The next counter carries state across iterations, so this is a for...of, not a pure .map: each doc's range depends on the cumulative page count of all prior docs.
  • Off-by-one: end = next + pages - 1. A 2-page doc starting at 1 spans 1..2 (not 1..3), and the next doc starts at end + 1.
  • Time O(n), Space O(n) — one pass over n docs; O(1) per doc (padStart is O(width), a constant).

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why use String(n).padStart(6, '0') instead of just String(n)?

  1. A Unpadded numbers can collide when prefixes share a substring (e.g., EVE10 and EVE100)
  2. B Fixed-width zero-padded labels sort and collate in numeric order as strings — EVE000002 < EVE000010, which 'EVE2' vs 'EVE10' would get wrong correct
  3. C padStart coerces the input to BigInt so the counter doesn't overflow past 2^53
  4. D Without padding, String(n) would render large integers in exponential notation

Why: String sort is lexicographic: 'EVE10' sorts before 'EVE2'. Zero-padding to a fixed width makes lexicographic order match numeric order, which is what document-production tooling relies on.

Q2 Why is this a for...of with a next variable rather than docs.map(d => ...)?

  1. A .map ignores break, so we couldn't bail out early on a malformed doc
  2. B Each doc's Bates range depends on the running page count of all prior docs — the iteration carries state that isn't a clean per-element transform correct
  3. C .map callbacks run in undefined order, which would scramble the Bates sequence
  4. D for...of is the only loop form that can read the previous element via arr[i-1]

Why: The start number for doc N is determined by how many pages docs 0..N-1 consumed. That cross-element accumulation is algorithm-shape; a .map would need to mutate an external counter, which is the anti-pattern.

Q3 A document starts at Bates 4 and has 5 pages. What is its end, computed as next + pages - 1?

  1. A 9
  2. B 8 correct
  3. C 10
  4. D 5

Why: Pages 4, 5, 6, 7, 8 — that's 5 pages ending at 8. 4 + 5 - 1 = 8. Forgetting the - 1 would claim the doc occupies page 9 too and shift every subsequent doc.

Q4 Why does the code special-case d.pages === 1 to emit a single label instead of a range?

  1. A A range with equal start and end (EVE000003-EVE000003) is redundant and not how single-page docs are cited correct
  2. B Without the guard, end would be start - 1 and the range would render backwards
  3. C Computing label(end) for a 1-page doc would re-trigger padStart and emit EVE000003-EVE000004
  4. D Single-page docs are cited with their filename, not a Bates number

Why: A one-page document is cited by a single Bates number, not a degenerate range like EVE000003-EVE000003. The conditional keeps the output matching real legal-production convention.
