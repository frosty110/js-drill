Damages Roll-up

Hash-fold then sort — total medical bills by category into a Map, sort the category entries by total descending, then append a grand total computed by folding the category totals.

Problem

Aggregate medical bills by category, then output each category total (highest first) and a final TOTAL line. Each bill is {category, amount}; amounts are integers.

Expected output: Hospital: $20000 Physical Therapy: $4500 Medication: $500 TOTAL: $25000

Canonical solution

Map-keyed fold by category, then sort entries descending · O(n + k log k) / O(k) (time / space)

function rollup(bills) {
  // Fold each bill into a running per-category total.
  const totals = new Map();
  for (const b of bills) {
    // (totals.get(cat) || 0) seeds 0 the first time a category is seen.
    totals.set(b.category, (totals.get(b.category) || 0) + b.amount);
  }
  // Sort entries by total descending: b[1] - a[1] compares the amounts (index 1 of each entry).
  const sorted = [...totals.entries()].sort((a, b) => b[1] - a[1]);
  const lines = sorted.map(([cat, amt]) => `${cat}: $${amt}`);
  // Grand total = sum of the already-aggregated category totals.
  const grand = sorted.reduce((s, [, amt]) => s + amt, 0);
  lines.push(`TOTAL: $${grand}`);
  return lines;
}
  • (totals.get(cat) || 0) handles the first-seen category: Map.get returns undefined for a missing key, and undefined + amount is NaN, so the || 0 fallback is load-bearing.
  • Sorting entries() by b[1] - a[1] (not a[1] - b[1]) gives DESCENDING order — entries are [category, total] pairs, so index 1 is the amount.
  • Aggregate first, THEN total: the grand total folds the category totals (4 numbers), not the original bills — same result here, but it keeps the total consistent with the displayed category lines.
  • Time O(n + k log k), Space O(k) — n bills folded in one pass; k distinct categories sorted (k ≤ n, typically k << n for billing data).

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why is the accumulator written as (totals.get(b.category) || 0) + b.amount?

  1. A Map.get throws on a missing key unless wrapped in a truthy-check fallback
  2. B Map.get returns undefined for a never-seen category, and undefined + amount is NaN; the || 0 seeds the first total correct
  3. C Without || 0, the running total would be coerced to a string via concatenation
  4. D Map.set rejects values that aren't pre-initialized via a get-first pattern

Why: On the first bill of a category there is no existing total, so the || 0 fallback provides the starting value instead of producing NaN.

Q2 The entries are sorted with (a, b) => b[1] - a[1]. What ordering does that produce and why index 1?

  1. A Ascending by category name; entries from Map.entries() are [index, [key, value]], so index 1 is the value-pair
  2. B Descending by total; entries are [category, total] pairs so index 1 is the amount correct
  3. C Ascending by total; subtracting a from b reverses the conventional descending sense
  4. D Stable insertion order; b[1] - a[1] always returns 0 because both equal the position in the Map

Why: Map entries are [key, value]. Index 1 is the total; b[1] - a[1] is the descending comparator.

Q3 The grand total is computed by folding the sorted category totals, not the raw bills. Why does that matter?

  1. A The raw bills array has already been consumed by the for-loop and would re-iterate empty
  2. B It keeps the TOTAL consistent with the category lines being displayed — they sum the same aggregated numbers correct
  3. C Folding aggregated values avoids floating-point accumulation error that would compound over n raw bills
  4. D Raw bills include refunds that have already been netted out of the category totals

Why: Summing the same aggregated category totals that are shown guarantees the displayed lines and the TOTAL always reconcile.

Q4 In sorted.reduce((s, [, amt]) => s + amt, 0), what is the empty slot in [, amt]?

  1. A A rest position — it captures everything before amt into an unnamed array
  2. B A skipped destructuring position for the category key, which the sum doesn't need correct
  3. C A default-value marker — amt falls back to whatever the first element holds
  4. D An array hole, which makes the destructure throw on undefined entries

Why: Each entry is [category, total]; the hole skips the category and binds only amt, since the grand total only needs the amounts.

Hints

function rollup(bills) {
  const totals = new Map();
  for (const b of bills) {
    totals.set(b.category, (totals.get(b.category) || 0) + b.amount);
  }
  const sorted = [...totals.entries()].sort((a, b) => b[1] - a[1]);
  const lines = sorted.map(([cat, amt]) => `${cat}: $${amt}`);
  const grand = sorted.reduce((s, [, amt]) => s + amt, 0);
  lines.push(`TOTAL: $${grand}`);
  return lines;
}

  { category: 'Physical Therapy', amount: 3000 },
  { category: 'Hospital', amount: 8000 },
  { category: 'Medication', amount: 500 },
