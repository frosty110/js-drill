Demand Letter Template Engine

Render a demand-letter template in a single left-to-right `while` scan — string state-machine shape, because we handle `{{...}}` tokens, dotted keys, and missing keys without a naive global replace.

Problem

Render a demand-letter template: replace each {{key}} with its value from a data object (support dotted keys like client.name). A missing key becomes [MISSING:key], never a crash.

Expected output: Dear Jane Doe, We demand $50,000 for injuries on 2024-03-01. Ref: [MISSING:caseId].

Canonical solution

Single left-to-right cursor scan · O(n + k·d) / O(n + m) (time / space)

function renderTemplate(template, data) {
  let out = '';
  let i = 0;
  while (i < template.length) {
    const open = template.indexOf('{{', i);
    if (open === -1) { out += template.slice(i); break; }
    out += template.slice(i, open);
    const close = template.indexOf('}}', open + 2);
    if (close === -1) { out += template.slice(open); break; }
    const key = template.slice(open + 2, close).trim();
    // Dotted keys (client.name) resolve via reduce; null-guard each hop.
    const val = key.split('.').reduce((o, k) => (o == null ? undefined : o[k]), data);
    // Missing key → placeholder, never a crash. A half-built letter beats an exception.
    out += val === undefined ? `[MISSING:${key}]` : String(val);
    i = close + 2;
  }
  return out;
}
const tpl = 'Dear {{client.name}},\nWe demand {{amount}} for injuries on {{date}}. Ref: {{caseId}}.';
const data = { client: { name: 'Jane Doe' }, amount: '$50,000', date: '2024-03-01' };
console.log(renderTemplate(tpl, data));
  • A left-to-right scan beats chained .replace calls: it handles repeated/overlapping tokens correctly in one pass and won't re-substitute text a previous replace just inserted (template injection).
  • Dotted keys like client.name resolve by key.split('.').reduce(...), null-guarding each hop so a missing intermediate object yields undefined instead of a 'cannot read property of undefined' throw.
  • A missing key becomes [MISSING:key], not a crash — a paralegal can eyeball a half-rendered letter and fix the gap; an exception just loses the whole document.
  • Time O(n + k·d), Space O(n + m) — n = template length; k = token count; d = max dotted-path depth (≤3 in practice, so effectively O(n + k)); m = output length.

Q1 Why scan the template left-to-right instead of chaining template.replace('{{amount}}', ...).replace('{{date}}', ...)?

  1. A String.replace without /g only swaps the first occurrence, so repeated {{key}} tokens would be silently skipped
  2. B A single scan handles repeated/overlapping tokens in one pass and won't re-substitute text an earlier replace already inserted correct
  3. C Chained replace mutates the original template parameter, which would corrupt subsequent renders
  4. D replace would coerce the data values to RegExp objects, breaking on values containing ( or ?

Why: Each {{key}} is found and resolved exactly once as the cursor moves forward. Chained replaces re-scan the whole string per key and can accidentally substitute into text a prior replace produced — a template-injection footgun if a value itself contains {{...}}.

Q2 How does key.split('.').reduce((o, k) => (o == null ? undefined : o[k]), data) resolve client.name?

  1. A It joins the parts back with a dot and reads data['client.name']
  2. B It walks the path one key at a time — data → data.client → data.client.name — short-circuiting to undefined if any hop is null/undefined correct
  3. C It throws if client is missing
  4. D It only works for two-level keys

Why: reduce threads the object through each path segment. The o == null ? undefined guard means a missing intermediate (no client) produces undefined cleanly instead of throwing on undefined.name.

Q3 Why does a missing key render as [MISSING:caseId] instead of throwing?

  1. A String(undefined) returns 'undefined', and rendering that into a demand letter is worse than the sentinel
  2. B A partially-rendered letter is more useful to a paralegal than a crash that loses the whole document correct
  3. C Throwing would leave the cursor mid-token, so the next call would resume in the wrong state
  4. D Legal-doc templates contractually disallow exceptions in render — a sentinel is the audit-trail-friendly alternative

Why: Graceful degradation: the operator sees exactly which field is unpopulated and can fill it, rather than getting an unhandled exception that discards everything rendered so far.

Q4 What does template.slice(open + 2, close).trim() extract for the token {{ client.name }}?

  1. A {{ client.name }}
  2. B client.name
  3. C client.name correct
  4. D client

Why: open + 2 skips past {{ and close stops before }}, giving client.name ; .trim() removes the surrounding whitespace so the key lookup tolerates {{ key }} spacing.
