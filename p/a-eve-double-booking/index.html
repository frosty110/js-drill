Double-Booking Detector

Interval shape on object input — sort depositions by start time, then a single scan comparing each event's start against the furthest end seen so far to surface scheduling conflicts.

Problem

Given an array of {caseId, start, end} depositions for one attorney, return an array of [caseId, caseId] pairs that overlap in time (the attorney can't be in two places at once).

Expected output: [["A-101","B-205"],["C-309","D-412"]]

Canonical solution

Sort by start, scan against furthest end · O(n log n) / O(n) (time / space)

const depositions = [
  { caseId: 'A-101', start: '09:00', end: '10:30' },
  { caseId: 'B-205', start: '10:00', end: '11:00' },
  { caseId: 'C-309', start: '11:00', end: '12:00' },
  { caseId: 'D-412', start: '11:30', end: '13:00' }
];

function findConflicts(events) {
  const sorted = [...events].sort((a, b) =>
    a.start < b.start ? -1 : a.start > b.start ? 1 : 0
  );
  const conflicts = [];
  let last = sorted[0];
  for (let i = 1; i < sorted.length; i++) {
    const curr = sorted[i];
    if (curr.start < last.end) {
      conflicts.push([last.caseId, curr.caseId]);
    }
    if (curr.end > last.end) last = curr;
  }
  return conflicts;
}

console.log(JSON.stringify(findConflicts(depositions)));
  • Sort by start time first — overlap logic only holds once events are in chronological order.
  • Track the event with the furthest end seen so far, not just the immediately previous one: a long early deposition can overlap several later ones, which a bare i-1 comparison would miss.
  • The overlap test is strict — curr.start < last.end. Touching boundaries (one ends exactly when the next starts) are NOT a conflict.

Q1 Why sort the events by start time before scanning for conflicts?

  1. A Sorting removes duplicate depositions
  2. B Overlap detection compares each event to earlier ones — 'earlier' only means something on a chronologically ordered list correct
  3. C JavaScript requires arrays to be sorted before a for loop
  4. D Sorting converts the time strings into Date objects

Why: Conflict detection is about whether an event starts before an earlier one ends. 'Earlier' is only well-defined once the events are sorted by start time.

Q2 Why compare each event against the event with the FURTHEST end seen so far, rather than just the immediately previous event?

  1. A It makes the scan run faster
  2. B A long early deposition can overlap several later ones; comparing only to the immediately previous event would miss those conflicts correct
  3. C JavaScript cannot compare two array elements directly
  4. D Sorting by start guarantees the previous element is always the closest in time

Why: Once sorted by start, the previous element isn't necessarily the one that ends latest. A 9:00–13:00 event overlaps everything starting before 13:00 — you must compare against the furthest-reaching end, not just index i-1.

Q3 Given curr starts after prev, what condition means they overlap?

  1. A curr.start <= prev.start
  2. B curr.start < prev.end correct
  3. C curr.end < prev.end
  4. D curr.start > prev.end

Why: If the later event starts before the earlier one has ended (curr.start < prev.end), the two intervals overlap in time.

Q4 One deposition ends at 11:00 and the next starts at exactly 11:00. Using curr.start < last.end, is that a conflict?

  1. A Yes — they touch, so they collide
  2. B No — the test is strict <, so a shared boundary is not an overlap correct
  3. C Yes — adjacent events in the sorted array always conflict
  4. D Only if the two share the same caseId

Why: '11:00' < '11:00' is false, so back-to-back events that merely touch are not flagged. This matches reality: you can finish one deposition and start the next at the same minute.
