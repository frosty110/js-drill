PII Redaction

Redact a medical note with word-boundary regexes — string scan that replaces any SSN pattern and each sensitive term case-insensitively, counting replacements via a replacer callback.

Problem

Redact a medical note: replace any SSN (###-##-####) and each sensitive term with [REDACTED] (case-insensitive, whole-word). Return the redacted text and the redaction count.

Expected output: Patient [REDACTED] Doe, SSN [REDACTED], treated by Dr. [REDACTED]. [REDACTED] reported pain. Redactions: 4

Canonical solution

function redact(text, terms) {
  let count = 0;
  // SSN pattern first; the replacer callback lets us count every hit.
  let out = text.replace(/\b\d{3}-\d{2}-\d{4}\b/g, () => { count++; return '[REDACTED]'; });
  for (const term of terms) {
    // Escape regex metacharacters so a term like 'Dr.' is treated literally.
    const escaped = term.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
    // \b...\b = whole word; g = all occurrences; i = case-insensitive.
    const re = new RegExp('\\b' + escaped + '\\b', 'gi');
    out = out.replace(re, () => { count++; return '[REDACTED]'; });
  }
  return { text: out, count };
}
const note = 'Patient Jane Doe, SSN 123-45-6789, treated by Dr. Smith. Jane reported pain.';
const result = redact(note, ['Jane', 'Smith']);
console.log(result.text);
console.log('Redactions: ' + result.count);
  • \b word boundaries make each term match whole words only — 'Smith' won't redact inside 'Smithson', and a short term won't hit substrings of unrelated words.
  • Each term is run through .replace(/[.*+?^${}()|[\]\\]/g, '\\$&') to escape regex metacharacters, so a term like 'Dr.' or 'a+b' is matched literally instead of as a pattern.
  • Flags matter: g replaces every occurrence (not just the first) and i makes it case-insensitive. Using a replacer function () => { count++; return '[REDACTED]' } lets you tally hits while substituting.
  • Time O((1 + k)·L), Space O(L) — 1 SSN sweep + k term sweeps, each linear in text length L; each replace returns a fresh string but doesn't re-scan inserted text. Collapse k sweeps into one alternation regex to get O(L) if k is large.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why wrap each term in \b...\b word boundaries before building the regex?

  1. A \b anchors the regex to the start and end of the string, so the term only matches at the very beginning or end of text
  2. B So a term matches only whole words — 'Smith' won't redact the 'Smith' inside 'Smithson', and short terms won't hit unrelated substrings correct
  3. C Without \b, the g flag would only fire once per word and silently skip later occurrences
  4. D \b is the only way to make the regex emit [REDACTED] instead of the raw match into the output

Why: Without \b, redacting 'Jan' would also blank out the middle of 'January'. Word boundaries anchor the match to whole tokens, which is what redaction of names/terms requires.

Q2 Why escape the term with term.replace(/[.*+?^${}()|[\]\\]/g, '\\$&') before passing it to new RegExp?

  1. A To normalize Unicode combining marks so accented names match their canonical form
  2. B To treat regex metacharacters in the term (like the dot in 'Dr.') as literal text instead of pattern syntax correct
  3. C To prevent new RegExp from parsing the term as a regex literal /.../ instead of a string source
  4. D To strip the backslashes that JS auto-inserts when reading the term from JSON

Why: A raw '.' in a regex matches any character; '+' or '(' have special meaning too. Escaping turns a user-supplied term into a literal pattern, so 'Dr.' matches only 'Dr.' and not 'Drx'.

Q3 In new RegExp('\\b' + escaped + '\\b', 'gi'), what do the g and i flags do?

  1. A g = greedy (consume the longest match), i = ignore newlines
  2. B g = replace every occurrence (not just the first), i = case-insensitive match correct
  3. C g = group the captures, i = include surrounding whitespace in the match
  4. D g = use ASCII mode, i = use Unicode (icu) mode

Why: Without g, only the first 'Jane' would be redacted. Without i, 'jane' in lowercase would slip through. Both flags are needed to catch every occurrence regardless of case.

Q4 Given the note 'Jane Doe ... Dr. Smith. Jane reported pain.' redacting ['Jane', 'Smith'] plus one SSN, why is the count 4?

  1. A SSN once + Jane once + Smith once = 3 (the g flag dedupes repeated terms across one scan)
  2. B SSN once + Jane twice + Smith once = 4 correct
  3. C SSN once + each distinct redacted token = 4 ('[REDACTED]' itself, Jane, Smith, the SSN pattern)
  4. D Two terms × two passes + SSN sweep + initial baseline = 4

Why: 'Jane' appears twice (start and in 'Jane reported'), 'Smith' once, and the SSN once. The replacer callback increments count on each substitution: 1 + 2 + 1 = 4.
