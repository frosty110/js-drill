Treatment Gap Detector

Algorithm shape — sort the visit dates, then a single `for` loop comparing each visit to the previous one (i vs i-1) to flag any gap longer than a threshold.

Problem

Given treatment dates (ISO strings) and a max-gap threshold in days, return each gap LONGER than the threshold between consecutive visits, formatted prev → next: N days.

Expected output: Gaps over 30 days: 2024-01-10 → 2024-04-01: 82 days

Canonical solution

function findGaps(dates, maxDays) {
  // Sort first — gaps are measured between CONSECUTIVE visits, and the
  // input may arrive unordered. Copy with [...dates] so we don't mutate the caller's array.
  const sorted = [...dates].sort();
  const gaps = [];
  // Start at i=1 so each iteration can compare i to i-1 (adjacent pair).
  for (let i = 1; i < sorted.length; i++) {
    // Date.parse(ISO) gives UTC milliseconds; /86400000 (ms per day) yields whole days.
    const days = (Date.parse(sorted[i]) - Date.parse(sorted[i - 1])) / 86400000;
    if (days > maxDays) gaps.push(`${sorted[i - 1]} → ${sorted[i]}: ${days} days`);
  }
  return gaps;
}
  • Sort BEFORE comparing — a gap is the distance between consecutive visits, so unsorted input would produce nonsense diffs (even negative ones).
  • Date.parse(isoString) returns UTC milliseconds since epoch; subtracting two and dividing by 86400000 (ms in a day) gives a whole number of days for date-only ISO strings.
  • The loop index starts at i = 1 because the body reads sorted[i] and sorted[i - 1] together; starting at 0 would read sorted[-1] (undefined).
  • Time O(n log n), Space O(n) — sort dominates; sweep is O(n). If input is already sorted (DB ORDER BY date), drops to O(n).

Q1 Why does findGaps sort the dates before the loop?

  1. A Date.parse returns NaN for any date that is earlier than the previous call, so sorting prevents NaN diffs
  2. B Gaps are measured between consecutive visits, so the dates must be in order or the diffs are meaningless correct
  3. C Sorting collapses duplicate visit dates into a single entry, which the gap formula relies on
  4. D Array iteration in JS is undefined order unless the array has been sorted first

Why: A gap is the distance between adjacent visits. If the input isn't sorted, comparing position i to i-1 gives diffs that aren't real time gaps.

Q2 What does (Date.parse(b) - Date.parse(a)) / 86400000 compute for two ISO date strings?

  1. A The number of seconds between them — 86400000 is the seconds-per-day divisor
  2. B The number of whole days between them (86400000 = ms per day) correct
  3. C The number of days since the Unix epoch for date b, with a ignored
  4. D The fractional difference normalized to a 0..1 day-of-year scale

Why: Date.parse returns UTC milliseconds; 86400000 is the milliseconds in one day, so the quotient is whole days for date-only strings.

Q3 Why does the loop start at i = 1 instead of i = 0?

  1. A The first visit is the baseline 'no-gap' anchor and is excluded from every adjacent-pair scan by convention
  2. B Because the body compares sorted[i] to sorted[i - 1]; starting at 0 would index sorted[-1] correct
  3. C for loops in JavaScript treat i = 0 as a guard value that aborts on the first iteration when the array contains dates
  4. D Starting at 1 keeps the gap count equal to the visit count, which the formatted output depends on

Why: Each iteration reads the current and previous element as a pair, so the earliest valid current index is 1.

Q4 Why is the input copied with [...dates] before sorting?

  1. A .sort() requires an iterable, and a plain array argument is rejected without spreading first
  2. B .sort() mutates in place, so copying avoids reordering the caller's original array correct
  3. C Spreading materializes any lazy Date proxies in the array so the comparator sees concrete values
  4. D Without the copy, the loop closure would capture a stale reference to the pre-sort length

Why: Array.prototype.sort sorts in place and returns the same array; spreading into a new array first protects the caller's data.

L3 — Write it from memory

One position, the code's third segment.

Given treatment dates (ISO strings) and a max-gap threshold in days, return each gap LONGER than the threshold between consecutive visits, formatted prev → next: N days.

Hints
  • Sort the dates first (copy with [...dates]), since gaps are between consecutive visits.
  • Loop from i = 1 and compare sorted[i] to sorted[i - 1].
  • Day count = (Date.parse(later) - Date.parse(earlier)) / 86400000; only push when it exceeds maxDays.
function findGaps(dates, maxDays) {
  const sorted = [...dates].sort();
  const gaps = [];
  for (let i = 1; i < sorted.length; i++) {
    const days = (Date.parse(sorted[i]) - Date.parse(sorted[i - 1])) / 86400000;
    if (days > maxDays) gaps.push(`${sorted[i - 1]} → ${sorted[i]}: ${days} days`);
  }
  return gaps;
}
