Document Update Propagation

Graph problem — when a source doc changes, regenerate every downstream doc in dependency (topological) order with a DFS-based topo sort, bailing out via 3-color cycle detection if the dependency graph has a cycle.

Problem

Documents depend on each other ([dependent, dependsOn], e.g. ['chronology','records']). When one node changes, return all transitively-dependent docs to regenerate, in topological order (a doc regenerates only after its inputs). If the graph contains a cycle, return ['CYCLE DETECTED']. Print the regeneration order for a change to 'records' (join with ' -> '), then the result for a 3-node cyclic graph.

Expected output: chronology -> demand-letter -> complaint CYCLE DETECTED

Canonical solution

3-color DFS cycle check, then Kahn topological sort · O(V² log V + E) / O(V+E) (time / space)

// Docs depend on each other: edge [dependent, dependsOn].
// A doc may only regenerate AFTER every input it depends on.
function regenerationOrder(edges, changed) {
  // dependents: who reads me (reverse edges); deps: who I read (forward edges).
  const dependents = new Map();
  const deps = new Map();
  const nodes = new Set();
  for (const [dep, on] of edges) {
    nodes.add(dep);
    nodes.add(on);
    if (!dependents.has(on)) dependents.set(on, []);
    dependents.get(on).push(dep);
    if (!deps.has(dep)) deps.set(dep, new Set());
    deps.get(dep).add(on);
  }
  // 3-color DFS: 0=white (unseen), 1=gray (on stack), 2=black (done).
  // A back-edge to a GRAY node is a cycle — the timeline can never settle.
  const color = new Map([...nodes].map(n => [n, 0]));
  const hasCycle = n => {
    color.set(n, 1);
    for (const d of dependents.get(n) || []) {
      if (color.get(d) === 1) return true;
      if (color.get(d) === 0 && hasCycle(d)) return true;
    }
    color.set(n, 2);
    return false;
  };
  for (const n of nodes) {
    if (color.get(n) === 0 && hasCycle(n)) return ['CYCLE DETECTED'];
  }
  // Collect everything transitively downstream of the changed node.
  const affected = new Set();
  const stack = [...(dependents.get(changed) || [])];
  while (stack.length) {
    const n = stack.pop();
    if (affected.has(n)) continue;
    affected.add(n);
    for (const d of dependents.get(n) || []) stack.push(d);
  }
  // Kahn's algorithm over the affected subgraph: count only in-affected inputs.
  const indeg = new Map();
  for (const n of affected) {
    let cnt = 0;
    for (const dep of deps.get(n) || []) if (affected.has(dep)) cnt++;
    indeg.set(n, cnt);
  }
  const ready = [...affected].filter(n => indeg.get(n) === 0).sort();
  const order = [];
  while (ready.length) {
    const n = ready.shift();
    order.push(n);
    for (const d of dependents.get(n) || []) {
      if (!affected.has(d)) continue;
      indeg.set(d, indeg.get(d) - 1);
      if (indeg.get(d) === 0) { ready.push(d); ready.sort(); }
    }
  }
  return order;
}
  • A doc may only regenerate after every doc it depends on — that's why the output is a topological order, not just a reachability list. Regenerating the demand letter before the chronology it cites would embed stale text.
  • A cycle means A depends on B depends on A: there is no valid order, so the graph can never settle into a finished state. Return a sentinel instead of looping forever or returning a partial order.
  • The 3-color DFS distinguishes a back-edge (to a GRAY node still on the recursion stack = a real cycle) from a cross-edge (to a BLACK node already finished = fine). A plain visited-set would false-positive on the cross-edge.
  • Time O(V² log V + E) as shipped, NOT the textbook O(V + E). The three phases (cycle-DFS, reachability, Kahn's) are each O(V + E), but keeping ready sorted for deterministic output costs a full ready.sort() per node that becomes ready, plus an O(V) shift() per pop. Swap in a binary heap — or drop the tie-break sort — to get O(V + E) back. Space O(V + E) for the two adjacency maps.

Q1 Why must the output be in topological order rather than any order of downstream docs?

  1. A Topological order deduplicates nodes reachable by two paths, which any-order traversal would regenerate twice
  2. B A doc can only regenerate after the docs it depends on, or it would embed stale upstream content correct
  3. C Any other order would violate the BFS visitation guarantee that the affected-set was built with
  4. D Topological order is what allows Kahn's algorithm to skip the cycle-detection pass entirely

Why: If the demand letter regenerates before the chronology it cites, it pulls in the old chronology text. Inputs must be rebuilt first.

Q2 What does a cycle in the dependency graph mean for this problem?

  1. A Two docs share a common input, so the regeneration would repeat that input twice and waste work
  2. B A depends on B which depends on A — there is no valid regeneration order, so it can never settle correct
  3. C The graph has more edges than nodes, exceeding the in-degree budget Kahn's algorithm allows
  4. D A node is reachable from itself by a path of length > 1 through unrelated docs

Why: A circular dependency has no node that can go first, so any rebuild would loop forever. The function returns a sentinel instead.

Q3 In the 3-color DFS, what specifically signals a cycle?

  1. A Reaching any node that was visited before — a plain visited-set check is sufficient and equivalent
  2. B Reaching a BLACK (fully-finished) node — a back-edge always targets a finished node
  3. C Reaching a GRAY node — one still on the current recursion stack (a back-edge) correct
  4. D Finishing the outer DFS loop with at least one node still WHITE

Why: GRAY means 'currently being explored, still on the stack.' An edge back to a GRAY node is a back-edge = a cycle. A BLACK node is finished and safe to re-encounter as a cross-edge.

Q4 Why count only inputs that are themselves in the affected set when computing in-degree (Kahn's algorithm)?

  1. A Including unaffected inputs would double-count edges shared by two affected nodes and inflate the in-degree past the edge count
  2. B Inputs outside the affected set are unchanged and already current, so they impose no ordering constraint correct
  3. C Unaffected inputs may not yet exist when Kahn's runs, so referencing them would throw a ReferenceError on indeg.get
  4. D Kahn's algorithm requires that in-degree reflect the full graph; the affected filter is applied later, on the output

Why: An untouched upstream doc is already up to date; it does not need to be rebuilt first, so it should not block its dependent's readiness.

When one node changes, return all transitively-dependent docs to regenerate, in topological order (a doc regenerates only after its inputs). If the graph contains a cycle, return ['CYCLE DETECTED']. Print the regeneration order for a change to 'records' (join with ' -> '), then the result for a 3-node cyclic graph.

Hints
  • Build two maps: dependents (reverse edges, who reads me) and deps (forward edges, who I read). The topo order walks the reverse edges.
  • Run a 3-color DFS over the whole graph first and bail with the sentinel if any back-edge to a GRAY node exists.
  • Then collect the transitive dependents of the changed node and run Kahn's algorithm over only that subgraph, counting in-degree from inputs that are themselves affected.
function regenerationOrder(edges, changed) {
  const dependents = new Map();
  const deps = new Map();
  const nodes = new Set();
  for (const [dep, on] of edges) {
    nodes.add(dep);
    nodes.add(on);
    if (!dependents.has(on)) dependents.set(on, []);
    dependents.get(on).push(dep);
    if (!deps.has(dep)) deps.set(dep, new Set());
    deps.get(dep).add(on);
  }
  const color = new Map([...nodes].map(n => [n, 0]));
  const hasCycle = n => {
    color.set(n, 1);
    for (const d of dependents.get(n) || []) {
      if (color.get(d) === 1) return true;
      if (color.get(d) === 0 && hasCycle(d)) return true;
    }
    color.set(n, 2);
    return false;
  };
  for (const n of nodes) {
    if (color.get(n) === 0 && hasCycle(n)) return ['CYCLE DETECTED'];
  }
  const affected = new Set();
  const stack = [...(dependents.get(changed) || [])];
  while (stack.length) {
    const n = stack.pop();
    if (affected.has(n)) continue;
    affected.add(n);
    for (const d of dependents.get(n) || []) stack.push(d);
  }
  const indeg = new Map();
  for (const n of affected) {
    let cnt = 0;
    for (const dep of deps.get(n) || []) if (affected.has(dep)) cnt++;
    indeg.set(n, cnt);
  }
  const ready = [...affected].filter(n => indeg.get(n) === 0).sort();
  const order = [];
  while (ready.length) {
    const n = ready.shift();
    order.push(n);
    for (const d of dependents.get(n) || []) {
      if (!affected.has(d)) continue;
      indeg.set(d, indeg.get(d) - 1);
      if (indeg.get(d) === 0) { ready.push(d); ready.sort(); }
    }
  }
  return order;
}
