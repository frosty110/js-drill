Event Emitter

Pub/sub primitive — multiple listeners per event, remove a specific handler with off(), invoke all in registration order on emit().

Problem

Implement EventEmitter with on/off/emit. Subscribe two listeners to 'tick', emit twice, off the first, emit again. Listeners should log identifying strings.

Expected output: one:1 two:1 one:2 two:2 two:3

Canonical solution

Pub/sub registry: event → array of handlers · O(k) emit / O(n) total (time / space)

class EventEmitter {
  constructor() {
    this.handlers = {};                          // event -> array of fns
  }
  on(event, fn) {
    (this.handlers[event] ||= []).push(fn);      // lazy-create the bucket
  }
  off(event, fn) {
    const arr = this.handlers[event];
    if (!arr) return;
    const i = arr.indexOf(fn);                   // identity match — exact same fn reference
    if (i !== -1) arr.splice(i, 1);
  }
  emit(event, ...args) {
    const arr = this.handlers[event];
    if (!arr) return;
    for (const fn of arr.slice()) fn(...args);   // copy so off-during-emit is safe
  }
}
  • off() removes by reference — passing an equivalent-looking anonymous fn won't match. Store the fn if you plan to off it.
  • Iterate a copy in emit() so a listener that calls off() inside doesn't skip the next handler.
  • (this.handlers[event] ||= []) lazily creates the bucket on first on() — common interview shorthand.
  • Time: on O(1), off O(k) where k = listeners on that event, emit O(k). Space O(total listeners).

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What does off(event, fn) use to find the listener?

  1. A Structural equality of the function's .toString() source — equivalent-looking arrows match
  2. B Identity comparison — the exact same function reference correct
  3. C Match by the name property of the function (anonymous functions share name '' so they all match)
  4. D Position in the bucket — off(event, n) removes the nth registered listener

Why: arr.indexOf(fn) compares references, so the fn you pass to off must be the very object you passed to on. ee.on('tick', x => f(x)) followed by ee.off('tick', x => f(x)) silently removes nothing — the two arrows are distinct objects.

Q2 Why does emit() iterate a copy of the handler array?

  1. A .slice() freezes the function references so listeners can't be reassigned mid-dispatch
  2. B To allow listeners that call off() or on() during dispatch without breaking iteration correct
  3. C for...of over a live array throws TypeError if its length changes during iteration
  4. D Iterating a copy lets the engine inline the handler calls, which is faster than indexed access

Why: A handler that unsubscribes itself makes off splice the live array, shifting every later handler down one index — the iterator then skips the next one entirely (handlers [a,b,c] where a removes itself dispatch as a, c). Iterating arr.slice() freezes the dispatch list, so a mid-emit on/off takes effect from the NEXT emit.

Q3 What happens when you emit an event with no registered listeners?

  1. A It throws TypeError — arr.slice() is called on undefined
  2. B Nothing — emit is a no-op for unknown events correct
  3. C It auto-creates an empty bucket for the event and returns false
  4. D It fires every listener subscribed to '*' as a wildcard fallback

Why: this.handlers[event] is undefined for an event nobody subscribed to, and the if (!arr) return guard bails before .slice() is reached. Drop that guard and the throw in the first distractor is exactly what you get.

Q4 If on('x', fn) is called twice with the same fn, how many times will emit('x') invoke fn?

  1. A 0 — the second on() overwrites the first registration
  2. B 1 — Array.prototype.push is a Set-like operation that ignores existing entries
  3. C 2 — duplicates are stored separately correct
  4. D 1 the first time, 2 on subsequent emits as duplicates accrete

Why: on is a bare push with no dedupe, so the bucket holds the same reference twice and emit walks both slots. Note the asymmetry with off: indexOf finds only the first, so one off leaves the duplicate still subscribed.

Hints

  • off() must match by function reference — Array.indexOf works because === compares fn refs.
  • Iterate a slice() copy in emit so concurrent off() calls don't skip handlers.
class EventEmitter {
  constructor() { this.handlers = {}; }
  // ||= lazily creates the bucket on first on() for this event.
  on(event, fn) { (this.handlers[event] ||= []).push(fn); }
  off(event, fn) {
    const arr = this.handlers[event];
    if (!arr) return;
    // Identity match — equivalent-looking anon fns won't match. Store the ref.
    const i = arr.indexOf(fn);
    if (i !== -1) arr.splice(i, 1);
  }
  emit(event, ...args) {
    const arr = this.handlers[event];
    if (!arr) return;
    // Iterate a copy so an off() inside a listener doesn't skip the next handler.
    for (const fn of arr.slice()) fn(...args);
  }
}
