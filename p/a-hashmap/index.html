Implement a HashMap

Hash table with separate chaining. Each bucket is an array of [key, value] entries. Hashing: Knuth's multiplicative hash for ints, djb2-style for strings, both modulo capacity. put updates in place if the key exists; otherwise appends. get/has/remove walk the bucket linearly — O(1) average with a decent hash.

Problem

Build HashMap with put/get/has/remove/size. Insert (1,'a'), (2,'b'), (17,'c'); log get(1), get(2), get(17), get(99), has(2); put(2,'B') then log get(2), size; remove(1), log has(1), size.

Expected output: a b c -1 true B 3 false 2

Canonical solution

class HashMap {
  constructor(capacity = 16) {
    this.capacity = capacity;
    // Separate chaining — each bucket is an array of [k,v] entries.
    this.buckets = Array.from({ length: capacity }, () => []);
    this.size = 0;
  }
  _hash(k) {
    // Knuth multiplier 2654435761 ≈ 2^32/phi — good spread for sequential int keys.
    if (typeof k === "number") return ((k * 2654435761) >>> 0) % this.capacity;
    const s = String(k); let h = 0;
    for (let i = 0; i < s.length; i++) h = ((h << 5) - h + s.charCodeAt(i)) | 0;
    // >>> 0 coerces to unsigned 32-bit before modulo — avoids negative bucket index.
    return (h >>> 0) % this.capacity;
  }
  put(k, v) {
    const b = this.buckets[this._hash(k)];
    // Walk bucket FIRST to update in place; otherwise duplicates leak and size lies.
    for (const e of b) if (e[0] === k) { e[1] = v; return; }
    b.push([k, v]); this.size++;
  }
  get(k) {
    const b = this.buckets[this._hash(k)];
    for (const e of b) if (e[0] === k) return e[1];
    return -1;
  }
  has(k) {
    const b = this.buckets[this._hash(k)];
    for (const e of b) if (e[0] === k) return true;
    return false;
  }
  remove(k) {
    const b = this.buckets[this._hash(k)];
    for (let i = 0; i < b.length; i++) if (b[i][0] === k) { b.splice(i, 1); this.size--; return true; }
    return false;
  }
}
// Avg O(1) per op, worst O(n) on pathological collisions
  • Use >>> 0 to coerce a 32-bit hash to an unsigned int before modulo — otherwise negative numbers give negative bucket indices.
  • put must SEARCH the bucket first to update an existing key in place. Without that, duplicates accumulate and size lies.
  • Knuth's multiplier 2654435761 = floor(2^32 / phi) — good distribution for sequential integer keys.
  • Avg O(1) per op (put/get/has/remove); worst O(n) with pathological collisions. Space O(n + capacity).

Alternate approaches

Open addressing (linear probing) O(1) avg / O(n+cap)

Use when cache efficiency matters more than code simplicity. Open addressing stores entries directly in the slot array — no inner arrays — so accesses are cache-friendly and memory layout is tighter. The trade-off: remove() requires tombstone markers so probe sequences aren't broken, making the code more fiddly than chaining.

class HashMap {
  constructor(capacity = 16) {
    this.capacity = capacity;
    // Flat parallel arrays — each slot holds one key/value entry.
    this.keys = new Array(capacity).fill(undefined);
    this.vals = new Array(capacity).fill(undefined);
    this.size = 0;
    // Tombstone symbol distinguishes 'deleted' from 'empty' so probe sequences survive removes.
    this.DELETED = Symbol('deleted');
  }
  _hash(k) {
    if (typeof k === 'number') return ((k * 2654435761) >>> 0) % this.capacity;
    const s = String(k); let h = 0;
    for (let i = 0; i < s.length; i++) h = ((h << 5) - h + s.charCodeAt(i)) | 0;
    return (h >>> 0) % this.capacity;
  }
  // Walk slots (mod capacity) from hash(k) until we find the key, an empty slot,
  // or have probed every slot. Return the first deleted slot if key not found (for put).
  _find(k) {
    let firstDeleted = -1;
    for (let step = 0; step < this.capacity; step++) {
      const slot = (this._hash(k) + step) % this.capacity;
      if (this.keys[slot] === undefined) return firstDeleted !== -1 ? firstDeleted : slot;
      if (this.keys[slot] === this.DELETED) { if (firstDeleted === -1) firstDeleted = slot; continue; }
      if (this.keys[slot] === k) return slot;
    }
    return firstDeleted !== -1 ? firstDeleted : -1;
  }
  put(k, v) {
    const slot = this._find(k);
    if (this.keys[slot] !== k) this.size++;
    this.keys[slot] = k; this.vals[slot] = v;
  }
  get(k) {
    const slot = this._find(k);
    return this.keys[slot] === k ? this.vals[slot] : -1;
  }
  has(k) { return this.keys[this._find(k)] === k; }
  remove(k) {
    const slot = this._find(k);
    if (this.keys[slot] !== k) return false;
    // Tombstone — do NOT set to undefined, which would break downstream probe sequences.
    this.keys[slot] = this.DELETED; this.vals[slot] = undefined; this.size--;
    return true;
  }
}

  • Tombstone (DELETED symbol) is what makes remove() safe — setting to undefined would truncate the probe sequence and break subsequent lookups for keys that were placed past this slot.
  • Keep load factor below ~0.7; above that, probe chains get long and performance degrades. Chaining degrades more gracefully at high load.
  • _find returns the first DELETED slot for put (reuse the tombstone slot), but must still probe past DELETED slots when searching for an existing key.

Q1 What does separate chaining mean?

  1. A One global linked list of all entries that uses the hash only to pick a starting node for traversal
  2. B Each bucket holds a list of colliding entries correct
  3. C On collision, scan forward to the next empty slot and place the entry there (open addressing)
  4. D Each key is hashed twice with two separate functions; the second hash is the 'chain' offset into a parallel table

Q2 Why must put walk the bucket before appending?

  1. A To compute the running hash of existing entries so the new entry can be placed in sorted order
  2. B To update the value in place when the key already exists — otherwise duplicates leak correct
  3. C Array.prototype.push returns the new length, not the new entry — the walk reads back the appended pair
  4. D To detect a full bucket and trigger a resize before the new entry overflows

Q3 Purpose of >>> 0 in the hash function?

  1. A Right-shifts the value zero places, a no-op used as a hint to the JIT to specialize the call site
  2. B Coerces to an unsigned 32-bit int so modulo yields a non-negative bucket correct
  3. C Casts the float result of the multiply to an integer, since % rejects non-integer operands in strict mode
  4. D Bitwise OR with zero — needed because >> (signed) would corrupt the high bit

Q4 Average-case time complexity of get?

  1. A O(log n) — the bucket walk uses binary search after the hash narrows the range
  2. B O(n) — every get must scan all entries to confirm the key isn't a hash collision elsewhere
  3. C O(1) correct
  4. D O(capacity) — every get must touch every bucket until it finds the key, regardless of load factor
