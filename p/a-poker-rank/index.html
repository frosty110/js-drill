Poker Hand Rank

Classify a 5-card poker hand into its category. Parse `rank+suit` strings, build a rank histogram, check straight + flush flags, then walk the ranking ladder from royal-flush downward.

Problem

Implement rankHand(cards). Log ranks for: royal flush (TS-AS spades), four kings, full house (KKK + 22), wheel straight (A-5 mixed), pair of nines.

Expected output: royal-flush four-of-a-kind full-house straight pair

Canonical solution

Feature extraction + top-down ladder · O(1) / O(1) (time / space)

function rankHand(cards) {
  const order = '23456789TJQKA';
  // Normalize '10' to 'T' so every rank is a single char (indexable + sortable).
  const ranks = cards.map(c => c.slice(0, -1) === '10' ? 'T' : c.slice(0, -1));
  const suits = cards.map(c => c.slice(-1));
  const idx = ranks.map(r => order.indexOf(r)).sort((a, b) => a - b);
  const counts = {};
  for (const r of ranks) counts[r] = (counts[r] || 0) + 1;
  // Sort counts desc: [4,1]=four, [3,2]=full-house, [2,2,1]=two-pair.
  const groups = Object.values(counts).sort((a, b) => b - a);
  const flush = suits.every(s => s === suits[0]);
  let straight = idx.every((v, i) => i === 0 || v === idx[i-1] + 1);
  // Wheel straight (A-2-3-4-5): ace is low — indices aren't consecutive otherwise.
  if (!straight && ranks.includes('A') && ranks.includes('2') && ranks.includes('3') && ranks.includes('4') && ranks.includes('5')) straight = true;
  // Ladder checked top-down — first match wins; stronger categories sit above weaker.
  if (straight && flush && idx[0] === order.indexOf('T')) return 'royal-flush';
  if (straight && flush)                                   return 'straight-flush';
  if (groups[0] === 4)                                     return 'four-of-a-kind';
  if (groups[0] === 3 && groups[1] === 2)                  return 'full-house';
  if (flush)                                               return 'flush';
  if (straight)                                            return 'straight';
  if (groups[0] === 3)                                     return 'three-of-a-kind';
  if (groups[0] === 2 && groups[1] === 2)                  return 'two-pair';
  if (groups[0] === 2)                                     return 'pair';
  return 'high-card';
}
  • Normalize '10' to a single character ('T') so rank ordering uses a simple string index.
  • The rank ladder must be checked TOP-DOWN: a full-house also matches three-of-a-kind, but we return the stronger category first.
  • Wheel straight (A-2-3-4-5) is the special case where the ace is low — handle it explicitly because indices wouldn't be consecutive otherwise.
  • Time O(1), Space O(1) — hand is always 5 cards; all loops and arrays are bounded by a constant.

Alternate approaches

Groups-signature dispatch table O(1) / O(1)

Reach for this when an interviewer says 'can you make the ladder more declarative?' or you want to collapse the group-based categories into a single Map lookup. The same feature extraction (groups + flush + straight) feeds a string key like '4,1' or '3,2' that looks up the category in a table. Reads more like a config than control flow — easier to extend (add a new variant just by adding a row), harder to re-order accidentally. Flush + straight + royal still need explicit if-checks since they don't reduce to a pure group signature.

function rankHand(cards) {
  const order = '23456789TJQKA';
  const ranks = cards.map(c => c.slice(0, -1) === '10' ? 'T' : c.slice(0, -1));
  const suits = cards.map(c => c.slice(-1));
  const idx = ranks.map(r => order.indexOf(r)).sort((a, b) => a - b);
  const counts = {};
  for (const r of ranks) counts[r] = (counts[r] || 0) + 1;
  const groups = Object.values(counts).sort((a, b) => b - a);
  const flush = suits.every(s => s === suits[0]);
  let straight = idx.every((v, i) => i === 0 || v === idx[i-1] + 1);
  if (!straight && ranks.includes('A') && ranks.includes('2') && ranks.includes('3') && ranks.includes('4') && ranks.includes('5')) straight = true;
  // Flush/straight/royal first — they don't reduce to a pure group signature.
  if (straight && flush && idx[0] === order.indexOf('T')) return 'royal-flush';
  if (straight && flush) return 'straight-flush';
  if (flush) return 'flush';
  if (straight) return 'straight';
  // Now dispatch on the sorted-groups signature.
  const table = {
    '4,1':     'four-of-a-kind',
    '3,2':     'full-house',
    '3,1,1':   'three-of-a-kind',
    '2,2,1':   'two-pair',
    '2,1,1,1': 'pair'
  };
  return table[groups.join(',')] || 'high-card';
}
console.log(rankHand(['10S','JS','QS','KS','AS']));
console.log(rankHand(['KH','KD','KS','KC','3D']));
console.log(rankHand(['KH','KD','KS','2H','2D']));
console.log(rankHand(['AH','2D','3S','4C','5H']));
console.log(rankHand(['9H','9D','5S','3C','2H']));
  • The key insight: every group-based category has a unique sorted-counts signature, so groups.join(',') is a perfect-hash dispatch key — no need to compare element-by-element.
  • Flush, straight, straight-flush, and royal-flush can't go in the table because they don't depend on the groups signature alone — they cross over with [1,1,1,1,1]. Handle them explicitly above the dispatch.
  • Default branch (|| 'high-card') handles the [1,1,1,1,1] non-flush, non-straight case — no signature, no flush, no straight means nothing matches.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why check royal-flush and straight-flush BEFORE four-of-a-kind?

  1. A Checking flush-based hands first lets the function skip computing the rank histogram entirely on those branches
  2. B The categories are ordered by strength — the first matching category wins, and royal/straight-flush are stronger than four-of-a-kind correct
  3. C A four-of-a-kind whose four cards share a suit must be reclassified as a straight-flush by Hoyle's rules
  4. D Four-of-a-kind shares the groups[0]===4 shape with a straight-flush, so the more specific predicate must run first

Q2 What is groups if the hand is a full house?

  1. A [2, 2, 1] — the pair + pair + odd-rank-out is the structural fingerprint
  2. B [3, 2] correct
  3. C [5] — all five cards share a single bucket because the full house collapses the histogram
  4. D [3, 1, 1] — the trips dominate; the pair is recorded as two singletons

Q3 Why rewrite '10' to 'T' before indexing into '23456789TJQKA'?

  1. A '10'.indexOf in a single-char rank string returns -1, which would mis-sort the ten below the deuce
  2. B So every rank is a single character — index lookup and sorting stay simple correct
  3. C String.prototype.slice(0, -1) returns the full string when the slice length is 2, so '10H' would parse as '10H' instead of '10'
  4. D The order string '23456789TJQKA' uses 'T' specifically because '10' would collide with the '1' suit-prefix used in some decks

Q4 How is a flush detected from the parsed suits array?

  1. A All 5 suits identical correct
  2. B Three or more matching suits — the standard 'majority-suit' flush rule
  3. C At least one suit appears twice — a single pair of same-suit cards establishes the flush flag
  4. D The set of unique suits has size 1 OR 2 — same-color (red/black) qualifies as a flush
