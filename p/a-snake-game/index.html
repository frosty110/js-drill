Snake Game Logic

Snake on a w x h grid. Maintain the body as a queue of cells plus a Set for O(1) self-collision lookup. Each move: compute the new head, drop the tail UNLESS the new cell eats food, then check walls and self-overlap.

Problem

Build Snake(width, height, food) with move(dir) returning new score or -1 on crash. On a 3x3 grid with one food at [0,1], run R, R, U. Logs: 1, 1, -1.

Expected output: 1 1 -1

Canonical solution

Body queue + cell Set for collisions · O(1) per move / O(n) (time / space)

class Snake {
  constructor(width, height, food) {
    this.w = width; this.h = height;
    // Food is a FIFO queue — only food[0] is eligible to eat.
    this.food = food.slice();
    this.snake = [[0, 0]];              // head is last; tail is first
    // Set keyed 'r,c' — O(1) self-collision lookup; array gives ordering.
    this.set = new Set(["0,0"]);
    this.score = 0;
  }
  move(dir) {
    const [r, c] = this.snake[this.snake.length - 1];
    let nr = r, nc = c;
    if (dir === "U") nr--; else if (dir === "D") nr++;
    else if (dir === "L") nc--; else if (dir === "R") nc++;
    if (nr < 0 || nr >= this.h || nc < 0 || nc >= this.w) return -1;
    const ate = this.food.length && this.food[0][0] === nr && this.food[0][1] === nc;
    // Drop tail BEFORE self-check so moving into the old tail cell isn't a false collision.
    if (!ate) {
      const t = this.snake.shift();
      this.set.delete(t[0] + "," + t[1]);
    }
    const key = nr + "," + nc;
    if (this.set.has(key)) return -1;   // self-collision
    this.snake.push([nr, nc]); this.set.add(key);
    if (ate) { this.food.shift(); this.score++; }
    return this.score;
  }
}
// Time O(1) per move, Space O(snake length)
  • Drop the tail BEFORE checking self-overlap — otherwise legal moves that occupy the old tail cell falsely register as collisions.
  • Track body cells in a Set keyed by 'r,c' for O(1) collision lookup; the array gives ordered queue semantics.
  • Food is a queue (FIFO) — only the FRONT food piece is eligible. Compare head's new cell against food[0] only.

Alternate approaches

Array-only scan — no Set (O(snake length) per move) O(n) move / O(n) space

Reach for this when the interviewer wants the simplest possible implementation and the snake is known to stay short. For competitive-programming toy grids it's fine; for long games it degrades to O(snake²) total work.

class Snake {
  constructor(width, height, food) {
    this.w = width; this.h = height;
    this.food = food.slice();
    this.snake = [[0, 0]];  // head is last; tail is first
    this.score = 0;
  }
  move(dir) {
    const [r, c] = this.snake[this.snake.length - 1];
    let nr = r, nc = c;
    if (dir === "U") nr--; else if (dir === "D") nr++;
    else if (dir === "L") nc--; else if (dir === "R") nc++;
    if (nr < 0 || nr >= this.h || nc < 0 || nc >= this.w) return -1;
    const ate = this.food.length && this.food[0][0] === nr && this.food[0][1] === nc;
    // Drop tail before self-check — same ordering invariant as the Set version.
    if (!ate) this.snake.shift();
    // O(snake_length) linear scan instead of O(1) Set lookup.
    if (this.snake.some(([br, bc]) => br === nr && bc === nc)) return -1;
    this.snake.push([nr, nc]);
    if (ate) { this.food.shift(); this.score++; }
    return this.score;
  }
}

  • Array.some scans every body cell looking for a match — O(snake_length) per move vs O(1) with a Set.
  • The tail-drop-before-collision-check ordering is identical — the Set version doesn't change that invariant.
  • Simpler to write under time pressure; upgrade to Set+array when the snake can grow long.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why store the body in a Set in addition to an array?

  1. A Faster head lookup — the Set's last accessor returns the most recently added cell in O(1)
  2. B O(1) self-collision check; the array preserves order for tail removal correct
  3. C The Set persists across move calls while the array is rebuilt each frame, so it caches the previous tail
  4. D JavaScript arrays can't store [r, c] tuples because nested arrays lose identity across calls

Why: this.set.has(nr + ',' + nc) is the collision test and has to be constant-time on every move, but a Set has no notion of which cell is the tail — that is what this.snake.shift() needs the array for. The two are kept in lockstep: every add and delete touches both.

Q2 When the snake eats food, what changes vs a regular move?

  1. A The head doubles in position — nr += 2 rather than += 1 to account for the energy boost
  2. B The head advances but the snake also rewinds one step the next move to digest, leaving net-zero growth
  3. C The tail is NOT removed, so the snake grows by one correct
  4. D The food queue rotates so the next food spawns adjacent to the new head

Why: The tail shift() is wrapped in if (!ate). A normal move pushes a head and drops a tail for net-zero length; eating just skips the drop, and this.food.shift(); this.score++ runs afterwards once the move is known to be legal.

Q3 Why remove the tail before the self-collision check?

  1. A Set.delete is O(n) when called after a Set.has on the same key, so removing the tail first avoids re-hashing
  2. B Order does not matter — but array.shift() would mutate during iteration if called inside the collision check loop
  3. C Otherwise moving into the old tail cell would falsely flag as a collision correct
  4. D The tail must be removed first to free up its slot in the food queue for the next eat

Why: The tail vacates its cell on the same tick the head arrives, so a head landing there is legal. Run set.has(key) first and it still sees the stale tail key, so move returns -1 on a legal move.

Q4 What does move return on a wall or self crash?

  1. A 0 — the score resets to zero on crash and the game restarts implicitly
  2. B undefined — the function exits without an explicit return after the crash branch fires
  3. C -1 correct
  4. D Throws GameOverError — the caller is expected to wrap move in a try/catch

Why: Both failure paths — the wall test nr < 0 || nr >= this.h || nc < 0 || nc >= this.w and this.set.has(key) — return -1. A legal move returns this.score, which starts at 0, so the crash sentinel has to be a value a score can never take.
