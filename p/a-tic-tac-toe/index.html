Tic-Tac-Toe

Online game-state class. After each `play`, check only the four lines that pass through that cell — row, column, and (if on a diagonal) the two diagonals. O(n) per move instead of scanning the whole board.

Problem

Implement TicTacToe(n) with play(player, row, col). Play 5 moves where X wins the main diagonal; log 'no' for non-wins and the winner string for the final move.

Expected output: no no no no X

Canonical solution

Per-line tallies (+1 X / -1 O) · O(1) per move / O(n) (time / space)

class TicTacToe {
  constructor(n) {
    this.n = n;
    // Per-line tallies (+1 for X, -1 for O). |tally| === n means that line wins.
    this.rows = new Array(n).fill(0);
    this.cols = new Array(n).fill(0);
    this.diag = 0;
    this.anti = 0;
  }
  play(player, row, col) {
    const v = player === 'X' ? 1 : -1;
    this.rows[row] += v;
    this.cols[col] += v;
    // Main diagonal: row === col. Touches at most 4 lines per move — O(1).
    if (row === col)              this.diag += v;
    // Anti-diagonal: row + col === n - 1.
    if (row + col === this.n - 1) this.anti += v;
    // abs() because X reaches +n, O reaches -n — sign tells which player won.
    if (Math.abs(this.rows[row]) === this.n) return player;
    if (Math.abs(this.cols[col]) === this.n) return player;
    if (Math.abs(this.diag)        === this.n) return player;
    if (Math.abs(this.anti)        === this.n) return player;
    return '';
  }
}
  • Tally per line (+1 for X, -1 for O). |tally| === n is a win — sign tells you which player.
  • Diagonals: main has row === col; anti-diagonal has row + col === n - 1.
  • O(1) per move with O(n) space — beats the naive 'scan the whole board' check on every move.

Alternate approaches

Board-scan after each move (O(n) per move) O(n) move / O(n²) space

Reach for this when n is small and fixed (classic 3×3), or when you want the simplest possible code before optimizing. The board representation is more readable; the tally trick is the optimization you add once correctness is proven.

class TicTacToe {
  constructor(n) {
    this.n = n;
    // O(n²) board — simpler to reason about, but O(n) scan per move.
    this.board = Array.from({ length: n }, () => new Array(n).fill(null));
  }
  play(player, row, col) {
    this.board[row][col] = player;
    const n = this.n;
    const b = this.board;
    // Scan the four lines that pass through (row, col) — O(n) each.
    if (b[row].every(cell => cell === player)) return player;
    if (b.every(r => r[col] === player)) return player;
    if (row === col && b.every((r, i) => r[i] === player)) return player;
    if (row + col === n - 1 && b.every((r, i) => r[n - 1 - i] === player)) return player;
    return "";
  }
}
const g = new TicTacToe(3);
const show = r => console.log(r || "no");
show(g.play("X", 0, 0));
show(g.play("O", 0, 1));
show(g.play("X", 1, 1));
show(g.play("O", 0, 2));
show(g.play("X", 2, 2));
  • Board is an n×n array; each play() scans up to 4 lines of n cells — O(n) vs O(1) for tallies.
  • Short-circuit the diagonal scans with the same row === col / row + col === n - 1 guards — otherwise you'd scan the full main diag on every non-diagonal move.
  • Uses O(n²) space instead of O(n); upgrade to tallies once correctness is confirmed.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why use +1 / -1 tallies instead of scanning the board after each move?

  1. A Tallies can be packed into a single 32-bit integer, while a 2D board requires n² allocations
  2. B Each move only touches up to 4 lines — O(1) per move vs O(n²) for a scan correct
  3. C The board scan can't detect diagonal wins because adjacent diagonal cells aren't contiguous in memory
  4. D Tallies generalize to k > 2 players via additional sentinel values, which a board scan cannot

Why: A move at (row, col) can only complete lines that pass through it — rows[row], cols[col], and the two diagonals when it sits on them. Rescanning would re-examine n² cells to learn what four counters already hold.

Q2 What condition signals that (row, col) lies on the anti-diagonal of an n×n board?

  1. A row === col — the anti-diagonal mirrors the main diagonal so the same identity holds
  2. B row + col === n - 1 correct
  3. C row === n - col — the diagonal passes through (1, n-1) and (n-1, 1)
  4. D (row + 1) * (col + 1) === n — derived from the corner product invariant

Why: The anti-diagonal runs from (0, n-1) to (n-1, 0), and every cell on it sums to n - 1. row === col is the MAIN diagonal — the code tests both separately and keeps separate diag and anti tallies.

Q3 Why check Math.abs(tally) === n?

  1. A Math.abs normalizes the tally back to a non-negative range so it can be safely used as an array index in the next move
  2. B X is +n on a win, O is -n — absolute value detects either correct
  3. C Negative tallies would otherwise satisfy the === n check via sign coercion in ===
  4. D Tallies can wrap past Number.MAX_SAFE_INTEGER on long games; abs collapses the overflow

Why: v is +1 for X and -1 for O, so a line owned outright by O tallies to -n, never +n. Math.abs collapses both win conditions into one comparison, and player is returned directly so the sign never has to be read back.

Q4 What does play return when the move does NOT end the game?

  1. A null — the absence of a winner is signaled by the absence of a value
  2. B false — play returns a boolean indicating whether the game continues
  3. C An empty string '' correct
  4. D The current player's token — so the caller knows whose move it was, but without a win flag

Why: The last line is return ''; — falsy, so a caller can just write if (winner). The driver leans on exactly that with r => console.log(r || 'no').
