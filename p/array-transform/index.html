map / filter / reduce

`map`, `filter`, and `reduce` — three callbacks, three different shapes of output.

syntax Arrays 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write sumSqEvens(arr) returning the sum of squares of the EVEN numbers. Log sumSqEvens([1,2,3,4,5]).

Expected output: 20

Canonical solution

// map → new array, SAME length, transformed values
[1, 2, 3].map(n => n * 2);          // [2, 4, 6]

// filter → new array, ≤ length, only truthy callbacks kept
[1, 2, 3, 4].filter(n => n % 2);    // [1, 3]

// reduce → fold into a single value: (acc, item) => newAcc
[1, 2, 3].reduce((a, n) => a + n, 0);  // 6
  • All three are non-mutating — they always return a new array (or value for reduce).
  • Always pass an initial accumulator to reduce. Skipping it makes reduce throw on empty arrays.
  • Chain freely: arr.filter(...).map(...).reduce(...) reads top-to-bottom.

L3 — Write it from memory

One position, the code's third segment.

Write sumSqEvens(arr) returning the sum of squares of the EVEN numbers. Log sumSqEvens([1,2,3,4,5]).

Hints
  • Chain filter → map → reduce.
  • 2² + 4² = 4 + 16 = 20.
function sumSqEvens(arr) {
  return arr
    .filter(n => n % 2 === 0)
    .map(n => n * n)
    .reduce((a, b) => a + b, 0);
}
console.log(sumSqEvens([1, 2, 3, 4, 5]));
