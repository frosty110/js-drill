Add Two Numbers

Two singly-linked lists store digits in reverse order. Walk both with a carry; build the sum list using a dummy head. Continue while either list has nodes left or carry is non-zero.

Problem

Write addTwoNumbers(l1, l2) where each list represents a non-negative integer with digits stored in reverse. Return the sum as a list. Use toList/toArr helpers. Log JSON.stringify(toArr(addTwoNumbers(toList([2, 4, 3]), toList([5, 6, 4])))).

Expected output: [7,0,8]

Canonical solution

Column-by-column carry walk with a dummy head · O(max(m,n)) / O(max(m,n)) (time / space)

function addTwoNumbers(l1, l2) {
  // Dummy sentinel — first sum node attaches without a special case.
  const dummy = { val: 0, next: null };
  let tail = dummy, carry = 0;
  // Carry in the condition: 5+5 still owes a leading 1 after both lists end.
  while (l1 || l2 || carry) {
    // Treat a missing node as 0 so unequal lengths just work.
    const a = l1 ? l1.val : 0;
    const b = l2 ? l2.val : 0;
    const sum = a + b + carry;
    carry = Math.floor(sum / 10);
    tail.next = { val: sum % 10, next: null };
    tail = tail.next;
    if (l1) l1 = l1.next;
    if (l2) l2 = l2.next;
  }
  return dummy.next;
}
// Time O(max(m, n)), Space O(max(m, n))
  • Lists store digits in reverse order — the head is the ones place. That means you add left-to-right without any reversal step.
  • Loop condition is l1 || l2 || carry — a leftover carry creates a new most-significant digit (e.g. 5 + 5 → [0, 1]).
  • Use a dummy head so you don't special-case the first appended node.
  • Read each list's val defensively (0 if null) since the two lists can differ in length.

Q1 Why is the loop condition l1 || l2 || carry?

  1. A Because || short-circuits, so checking carry first would skip the list walks once carry is 0
  2. B A leftover carry can produce one more digit even after both lists run out correct
  3. C To guarantee the output list is the same length as max(m, n) — without carry, it could be off-by-one shorter
  4. D So the loop runs at least once even when both lists are empty, ensuring a zero node is always appended

Why: 5 + 5 exhausts both lists yet still owes a leading 1 — drop carry from the guard and the loop exits one iteration early, returning [0] instead of [0,1].

Q2 Which digit does the HEAD of each list represent?

  1. A The most significant
  2. B The ones place (least significant) correct
  3. C The sign bit, followed by digits most-significant-first
  4. D Whichever end the caller passes first — the lists are bidirectional

Why: Digits are stored reversed — [2,4,3] is 342 — so walking head-to-tail is already the ones-then-tens order schoolbook addition needs, and no reversal step is required.

Q3 What does the dummy head simplify?

  1. A It lets the loop run in O(1) extra space instead of O(max(m,n))
  2. B It avoids a special case when appending the first sum node correct
  3. C It allows reverse iteration of the sum list without a separate tail pointer
  4. D It catches null-input cases by returning dummy.next (which is null) automatically

Why: Every iteration runs the same tail.next = {...}; tail = tail.next; without the sentinel the first digit would need an if to become the head instead. The dummy costs one node, not a different space class.

Q4 Time complexity for lists of length m and n?

  1. A O(m * n)
  2. B O(m + n)
  3. C O(max(m, n)) correct
  4. D O(min(m, n))

Why: The loop runs once per output digit — at most max(m, n) + 1, counting the final carry-out — with fixed work per column. O(m + n) is a valid upper bound too, but max is the tight one.
