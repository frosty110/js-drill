BFS Level Order

BFS with a queue, processing one level per outer iteration by snapshotting the queue size before the inner loop.

patterns Trees 9 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write levelOrder(root) returning BFS level-order traversal as array of arrays. Log JSON.stringify(levelOrder(root)) for the tree [3, 9, 20, null, null, 15, 7].

Expected output: [[3],[9,20],[15,7]]

Canonical solution

BFS queue with a per-level size snapshot · O(n) / O(w) (time / space)

function levelOrder(root) {
  if (!root) return [];
  const res = [];
  const queue = [root];
  while (queue.length) {
    const size = queue.length;          // snapshot — only THIS level
    const level = [];
    for (let i = 0; i < size; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left)  queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    res.push(level);
  }
  return res;
}
// Time O(n), Space O(w) where w is max level width
  • Snapshot queue.length BEFORE the inner loop — children pushed during the loop belong to the NEXT level.
  • Guard the root: if root is null return [] (not [[]]).
  • Array.shift is O(n); for very large trees prefer a head index or a real deque.

Alternate approaches

DFS with depth parameter O(n) / O(h)

Use when you're already doing DFS for a related computation and want to avoid a second pass, or when the interviewer asks for a recursive solution. Same O(n) time; uses O(h) stack space instead of O(w) queue space — better for deep-but-narrow trees.

function levelOrder(root) {
  const res = [];
  function dfs(node, depth) {
    if (!node) return;
    // First time we reach this depth — open a new level bucket.
    if (depth === res.length) res.push([]);
    res[depth].push(node.val);
    dfs(node.left,  depth + 1);
    dfs(node.right, depth + 1);
  }
  dfs(root, 0);
  return res;
}
const root = { val: 3, left: { val: 9, left: null, right: null }, right: { val: 20, left: { val: 15, left: null, right: null }, right: { val: 7, left: null, right: null } } };
console.log(JSON.stringify(levelOrder(root)));
  • When depth === res.length the bucket for this level doesn't exist yet — create it before pushing.
  • Pre-order (self before children) ensures the left child is always appended before the right within each level bucket.
  • Space is O(h) for the recursion stack — strictly better than BFS on tall-narrow trees; strictly worse on wide trees where h ≈ log n but w ≈ n/2.

Q1 Why snapshot queue.length into size before the inner loop?

  1. A So queue.shift() becomes O(1) once the length is cached in a local
  2. B Because children pushed during the loop belong to the next level correct
  3. C So the loop terminates before the queue grows past its initial capacity
  4. D To skip the final level whose children would otherwise be re-enqueued

Why: queue.push(node.left) grows the queue mid-loop, so reading queue.length inside the for would let the next level bleed into the current one. The frozen size pins the level boundary.

Q2 Time complexity?

  1. A O(log n)
  2. B O(n) — each node enqueued and dequeued once correct
  3. C O(n log n)
  4. D O(n^2)

Why: Every node is pushed once and shifted once; the level snapshot only chunks that same work. Caveat worth stating out loud: Array.shift() is O(n) in JS, so the literal code is O(n²) on huge trees unless you swap in a head index.

Q3 For a null root, the function returns:

  1. A [[]]
  2. B [] correct
  3. C null
  4. D [null]

Why: The if (!root) return [] guard fires. An empty tree has zero levels, so [[]] — one level that happens to be empty — is the wrong shape.

Q4 Which data structure is BFS built on?

  1. A Stack (LIFO)
  2. B Queue (FIFO) correct
  3. C Priority queue
  4. D Hash map

Why: FIFO is what keeps siblings adjacent and defers children until the current level drains. Swap in a LIFO stack and the same loop dives down one branch first — that's DFS.

Q5 If you swapped the queue for a stack (LIFO) — pop from the back instead of shift from the front — what traversal would you get?

  1. A Still level-order BFS
  2. B Depth-first (DFS) — a stack dives down one branch before backtracking, not level by level correct
  3. C A sorted traversal
  4. D An infinite loop

Why: FIFO queue → BFS (breadth, level by level); LIFO stack → DFS (depth-first). The data structure IS the difference between the two.

Q6 Core distinction: when do you reach for BFS over DFS on a tree?

  1. A BFS for balanced trees, DFS for skewed trees — the queue width determines which is feasible
  2. B BFS when you need shortest-path/level info or to process nodes nearest-first; DFS when you explore each branch fully (subtree aggregates, path-to-leaf problems) correct
  3. C BFS guarantees O(log n) for any tree question because it processes levels; DFS is O(n)
  4. D DFS for any problem that returns a single value, BFS for any problem that returns an array

Why: BFS expands by distance from the root (great for levels and shortest unweighted paths); DFS goes deep first (great for subtree/path computations).

Q7 Space complexity of this BFS?

  1. A O(1)
  2. B O(h) where h is the height
  3. C O(w) where w is the max level width — the queue can hold a whole level at once correct
  4. D O(n^2)

Why: The queue holds at most one level; the widest level of a balanced tree is ~n/2, so worst case is O(n). DFS, by contrast, is O(h).

Q8 To get 'right-side view' (the last node visible at each level), what is the minimal change to this template?

  1. A Switch the queue to a stack
  2. B Reverse the final result array
  3. C Inside the level loop, only record the node when i === size - 1 (the last one in the level) correct
  4. D Sort each level before pushing

Why: Right-side view is the same level snapshot; you just keep the last node of each level instead of all of them.

Q9 For zig-zag (boustrophedon) level order, how do you adapt the template?

  1. A Use a stack instead of a queue
  2. B Build each level normally, but reverse (or unshift into) every other level before pushing it to the result correct
  3. C Sort alternate levels
  4. D Run DFS instead

Why: The BFS structure is unchanged; you just flip the direction of every other level when emitting it.
