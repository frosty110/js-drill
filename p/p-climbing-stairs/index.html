Climbing Stairs

Ways to reach step n taking 1 or 2 steps at a time. Fibonacci-shaped DP: ways(n) = ways(n-1) + ways(n-2). O(1) space with rolling variables.

Problem

Write climbStairs(n) returning the number of ways to climb n stairs taking 1 or 2 steps at a time. Use O(1) space. Log climbStairs(5).

Expected output: 8

Canonical solution

function climbStairs(n) {
  if (n <= 1) return 1;
  // Base cases seeded: ways(0)=1 (stay), ways(1)=1 (one step).
  let prev2 = 1, prev1 = 1;     // ways(0), ways(1)
  // Fibonacci recurrence: ways(i) = ways(i-1) + ways(i-2).
  for (let i = 2; i <= n; i++) {
    const curr = prev1 + prev2;
    // Roll: assign prev2 BEFORE overwriting prev1 — order matters.
    prev2 = prev1;
    prev1 = curr;
  }
  return prev1;
}
// Time O(n), Space O(1)
  • Recurrence: to land on step i you came from i-1 (1 step) or i-2 (2 steps), so ways(i) = ways(i-1) + ways(i-2).
  • Base cases: ways(0) = 1 (one way: stay) and ways(1) = 1. Both seed prev2 and prev1.
  • Only the last two values matter — use two rolling scalars and drop space to O(1).

Alternate approaches

DP array (O(n) space) O(n) / O(n)

Reach for this as the 'teaching step' before the rolling-pair optimization: it makes the Fibonacci table explicit and is easier to explain in an interview when you're building up to the O(1)-space version. Some interviewers prefer seeing the table first.

function climbStairs(n) {
  if (n <= 1) return 1;
  // Explicit dp table: dp[i] = number of ways to reach step i.
  const dp = new Array(n + 1);
  dp[0] = 1; dp[1] = 1;
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];   // Fibonacci recurrence
  }
  return dp[n];
}
console.log(climbStairs(5));
  • Identical recurrence to the rolling-pair version — just stores every Fibonacci value instead of only the last two.
  • The full dp array is a useful teaching aid: you can point to dp[i] and explain 'this is the number of ways to reach step i' without describing the rolling state.
  • Transition to O(1) space: notice dp[i] reads only dp[i-1] and dp[i-2] — two rolling scalars are sufficient.

Top-down memoization (O(n) / O(n)) O(n) / O(n)

Reach for this when the interviewer asks for the recursive formulation first, or you want to show the memoization pattern before deriving the bottom-up table. Natural to write if you're already thinking of the recursion.

function climbStairs(n) {
  const memo = new Array(n + 1).fill(-1);
  function dp(k) {
    if (k <= 1) return 1;
    if (memo[k] !== -1) return memo[k];
    memo[k] = dp(k - 1) + dp(k - 2);
    return memo[k];
  }
  return dp(n);
}
console.log(climbStairs(5));
  • Each subproblem dp(k) is computed once; subsequent calls return from memo in O(1).
  • Recursion depth is O(n) — hits JS's call stack limit around n≈10000; prefer the iterative version for large n.
  • The three versions (memo → table → rolling-pair) form the canonical DP optimization ladder: O(2^n) → O(n)/O(n) → O(n)/O(1).

Q3 Why is O(1) space enough?

  2. B Only the last two dp values are ever read correct
  3. C Numeric scalars use 8 bytes regardless of n, so the total is constant
  4. D Because the answer fits in a single 64-bit double for all n we care about

Q4 Time complexity of the iterative bottom-up version?

  1. A O(1)
  2. B O(log n)
  3. C O(n) correct
  4. D O(2^n)

Why: A single loop from i=2 to n with constant work per step is O(n).

Q5 WHY is the recurrence ways(n) = ways(n-1) + ways(n-2)?

  1. A Because n is split in half each time
  2. B Because the last move was either a 1-step (from n-1) or a 2-step (from n-2), and those cases are disjoint correct
  3. C Because every step doubles the options
  4. D It is an arbitrary pattern that happens to work

Why: Every path to step n ends with exactly one of two moves; summing the disjoint counts of ways to reach n-1 and n-2 covers all paths exactly once.

Q6 Why is naive recursion ways(n)=ways(n-1)+ways(n-2) O(2^n)?

  1. A Each recursive call doubles the stack frame size, so total memory grows as 2^n
  2. B The same subproblems (e.g. ways(n-3)) are recomputed in many branches — overlapping subproblems correct
  3. C Each call evaluates ways(n-1) and ways(n-2) in parallel, and the join cost compounds exponentially
  4. D Because the answer itself is roughly 2^n, and any algorithm that produces an exponential output must take exponential time

Why: Without memoization the recursion tree re-derives identical subtrees repeatedly; caching them collapses it to O(n).

Q7 Why does the roll assign prev2 = prev1 BEFORE prev1 = curr?

  1. A Because prev1 is declared first, so JS hoisting requires the matching assignment order
  2. B Reversing the order overwrites prev1 first, so prev2 gets curr and both rails collapse to the wrong value correct
  3. C Otherwise the loop body's last assignment short-circuits via const re-binding
  4. D To keep the recurrence symmetric with the n-2 base case

Why: prev2 must capture the OLD prev1; if prev1 is updated first, the old value is lost and the sequence diverges.

Q8 If each move could be 1, 2, or 3 stairs, the recurrence becomes:

  1. A ways(n) = ways(n-1) + ways(n-2) + ways(n-3) correct
  2. B ways(n) = ways(n-1) * 3
  3. C ways(n) = ways(n-3)
  4. D ways(n) = 3^n

Why: The last move is now one of three sizes, so sum the three disjoint predecessors (tribonacci) — same template, deeper look-back.
