Combination Sum

Classic backtracking: explore every combination summing to target with unlimited reuse. A start index keeps combinations sorted and prevents duplicates like [2,3] vs [3,2].

patterns Backtracking 4 concept · 1 fill-in · 1 drill

Results carried by this link

Problem

Write combinationSum(candidates, target) returning all unique combos (numbers may be reused) that sum to target. Log JSON.stringify(combinationSum([2, 3, 6, 7], 7)).

Expected output: [[2,2,3],[7]]

Canonical solution

function combinationSum(candidates, target) {
  const res = [];
  const path = [];
  function backtrack(start, remaining) {
    // Base case: hit target exactly — snapshot path (later mutations corrupt refs).
    if (remaining === 0) { res.push([...path]); return; }
    // Loop from `start`, not 0 — keeps combos sorted, blocks [2,3] vs [3,2].
    for (let i = start; i < candidates.length; i++) {
      if (candidates[i] > remaining) continue;
      path.push(candidates[i]);
      // Recurse with SAME i (not i+1) — that allows reusing this number.
      backtrack(i, remaining - candidates[i]);
      path.pop();
    }
  }
  backtrack(0, target);
  return res;
}
// Time O(N^(T/M)) where M = min candidate, Space O(T/M) recursion depth
  • Recurse with the SAME i (not i+1) — that is what permits reusing the same number.
  • Loop from start, not from 0 — guarantees combinations are sorted and avoids [2,3] vs [3,2] duplicates.
  • Push a COPY ([...path]) on the base case. Saving the reference would store a snapshot that empties out.
  • Skipping candidates[i] > remaining is a small prune; sorting candidates first would let you break instead of continue.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why recurse with i and not i + 1?

  1. A Because i+1 would skip past candidates[i] before the prune check fires, missing some valid combos
  2. B To allow the same number to be reused in the same combination correct
  3. C Because the for-loop already increments to i+1 on the next iteration, so passing i+1 would advance by two
  4. D Because i+1 would shift the start index, producing the sibling problem Combinations rather than Combination Sum with reuse

Q2 Why does the loop start at start instead of 0?

  1. A Looping from 0 would re-enter the recursion with negative remaining and stack-overflow
  2. B It forces combinations to be in non-decreasing index order so [2,3] and [3,2] are not both produced correct
  3. C It skips candidates already added to path, preventing the same index from appearing twice in one combo
  4. D It avoids re-checking the remaining === 0 base case on candidates the parent call already pruned

Q3 Why push [...path] instead of path itself?

  1. A Spreading converts the typed-array view into a plain array so JSON.stringify formats it correctly
  2. B path is mutated by later backtracking — storing the reference would leave a hollow snapshot correct
  3. C res is a Set internally and rejects duplicate array references, so each push must be a distinct object
  4. D Without the spread, the path's prototype chain still points to the recursion's lexical scope and pins it in memory

Q4 When does the recursion record a result?

  1. A When start reaches the end
  2. B When remaining hits 0 exactly correct
  3. C When path length equals target
  4. D When every candidate has been tried at least once at the current depth
