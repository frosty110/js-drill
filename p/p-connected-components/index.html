Connected Components

Build an adjacency list, then DFS from every unvisited node — each fresh DFS launch is one new component. O(V + E).

Problem

Write countComponents(n, edges) using DFS over an adjacency list. Log the count for (n=5, edges=[[0,1],[1,2],[3,4]]) and for (n=5, edges=[[0,1],[1,2],[2,3],[3,4]]).

Expected output: 2 1

Canonical solution

DFS launched from each unvisited node (adjacency list) · O(V+E) / O(V+E) (time / space)

function countComponents(n, edges) {
  const adj = Array.from({ length: n }, () => []);
  // Undirected — push BOTH directions so DFS can traverse either way.
  for (const [u, v] of edges) {
    adj[u].push(v);
    adj[v].push(u);
  }
  const seen = new Array(n).fill(false);
  let count = 0;
  function dfs(u) {
    seen[u] = true;
    for (const v of adj[u]) if (!seen[v]) dfs(v);
  }
  for (let i = 0; i < n; i++) {
    // Each fresh launch from an unvisited node is exactly one new component.
    if (!seen[i]) { count++; dfs(i); }
  }
  return count;
}
// Time O(V + E), Space O(V + E) for adj + O(V) seen
  • Push BOTH directions when building adj — the graph is undirected.
  • Increment count exactly when you START a new DFS from an unvisited node.
  • Union-Find (DSU) is an alternative: O((V + E) * α(V)). DFS is simpler when you already have the adjacency list.

Alternate approaches

Union-Find (DSU) O((V+E)*α(V)) / O(V)

Prefer Union-Find when edges arrive as a stream and you must report the component count after each addition — DFS would need to rebuild the adjacency list and re-scan from scratch. For a fully batched edge list like this problem, DFS and UF are equivalent; UF requires no adjacency list.

function countComponents(n, edges) {
  const parent = Array.from({length: n}, (_, i) => i);
  function find(x) {
    while (parent[x] !== x) { parent[x] = parent[parent[x]]; x = parent[x]; }
    return x;
  }
  // Start with n isolated nodes; each successful union merges two components.
  let count = n;
  for (const [u, v] of edges) {
    const ru = find(u), rv = find(v);
    if (ru !== rv) { parent[ru] = rv; count--; }
  }
  return count;
}
console.log(countComponents(5, [[0, 1], [1, 2], [3, 4]]));
console.log(countComponents(5, [[0, 1], [1, 2], [2, 3], [3, 4]]));
  • No adjacency list needed — each edge is consumed directly as a union(u, v) call.
  • Decrement count only on a successful union (different roots); same-root edges are already in one component.
  • Path compression (halving) keeps amortized find near O(α(n)) — effectively constant for any practical n.

Q1 Why push both adj[u].push(v) AND adj[v].push(u)?

  1. A Pushing both halves the DFS recursion depth by letting it descend either neighbor first
  2. B The graph is undirected — edges connect in both directions correct
  3. C It deduplicates parallel edges by ensuring each endpoint records the connection symmetrically
  4. D DFS needs each edge in both directions to compute correct in-degree and out-degree counts

Why: With only adj[u].push(v), adj[v] never mentions u, so DFS can cross that edge one way only — the same 5-node chain written as [[1,0],[2,1],[3,2],[4,3]] would score 5 components instead of 1.

Q2 When do you increment the component count?

  1. A On every dfs call
  2. B Once per edge
  3. C When you launch a new dfs from an unvisited node correct
  4. D Each time the recursion stack unwinds back to depth 0

Why: count++ lives in the outer if (!seen[i]) guard, so it fires once per component; moving it inside dfs would add one per NODE, turning a 5-node chain into 5 components instead of 1.

Q3 Time complexity?

  1. A O(V)
  2. B O(E)
  3. C O(V + E) correct
  4. D O(V * E)

Why: Building adj is one pass over the edges, seen[u] gates each node to a single DFS body, and each undirected edge is inspected at most twice (once from each endpoint) — the phases add, they do not nest.

Q4 For n=5 and edges [[0,1],[1,2],[3,4]] the answer is:

  1. A 1
  2. B 2 correct
  3. C 3
  4. D 5

Why: Components: {0,1,2} and {3,4}.
