Container w/ Most Water

Two pointers at the ends. Water is bounded by the shorter side, so always move the shorter pointer inward. O(n).

patterns Two Pointers 8 concept · 1 fill-in · 1 drill

Problem

Write maxArea(height) returning the largest rectangular water area between two vertical lines. Log maxArea([1,8,6,2,5,4,8,3,7]).

Expected output: 49

Canonical solution

function maxArea(height) {
  // Start at the widest possible base; we'll trade width for taller walls.
  let l = 0, r = height.length - 1, best = 0;
  while (l < r) {
    // Water bounded by the SHORTER wall.
    const h = Math.min(height[l], height[r]);
    const area = h * (r - l);
    if (area > best) best = area;
    // Move the shorter side — moving the taller one only shrinks width with no upside.
    if (height[l] < height[r]) l++;
    else r--;
  }
  return best;
}
// Time O(n), Space O(1)
  • Water level is bounded by the SHORTER wall — moving the taller side cannot help; it only shrinks width.
  • Area = min(height[l], height[r]) * (r - l).
  • Use < (not <=) — when l === r the width is 0.

Alternate approaches

Brute force O(n²) O(n²) / O(1)

The natural first solution — every pair (i, j) is a candidate container. Name it out loud to anchor the area formula min(h[i], h[j]) * (j − i), then explain why we can prune this to O(n) by always moving the shorter side.

function maxArea(height) {
  let best = 0;
  for (let i = 0; i < height.length - 1; i++) {
    for (let j = i + 1; j < height.length; j++) {
      const area = Math.min(height[i], height[j]) * (j - i);
      if (area > best) best = area;
    }
  }
  return best;
}
console.log(maxArea([1,8,6,2,5,4,8,3,7]));
  • O(1) extra space — the only state is best, i, and j; no additional structures.
  • For n=10⁵ this is ~5×10⁹ iterations — far too slow; the two-pointer solution reduces this to ~10⁵ by pruning dominated pairs.
  • The area formula min(h[i], h[j]) * (j − i) is identical to what the two-pointer version computes — the optimization is purely about which pairs to evaluate.

Q1 Why move the SHORTER side inward instead of the taller?

  1. A The shorter side is more likely to be next to a taller bar, raising the height bound on the next step
  2. B Water is bounded by the shorter wall; moving the taller side only shrinks width correct
  3. C Moving the taller side is safe but redundant — both sides converge to the same answer; we pick the shorter for cache locality
  4. D It keeps the two pointers in sorted order, which the area formula assumes

Q2 Time complexity?

  1. A O(log n)
  2. B O(n) correct
  3. C O(n log n)
  4. D O(n^2)

Q3 Area at each step is computed as:

  1. A max(h[l], h[r]) * (r - l)
  2. B min(h[l], h[r]) * (r - l) correct
  3. C (h[l] + h[r]) * (r - l)
  4. D h[l] * h[r]

Q4 Why while (l < r) and not l <= r?

  1. A l <= r would attempt to read height[r] after r decremented past zero, causing a TypeError
  2. B When l === r width is 0 — no container to measure correct
  3. C l <= r would double-count the diagonal pair (i, i), inflating the best answer
  4. D Strict-less is faster than less-or-equal on V8 because it avoids a branch on the equality check

Q5 What is the precise reason moving the TALLER pointer inward can never improve the answer?

  1. A It always lands on a strictly shorter bar next, so height drops on every taller-side move
  2. B Width strictly shrinks by 1, and the height is still capped by the unchanged shorter side, so the new area can only be smaller or equal correct
  3. C Moving the taller side abandons the current shorter side, and that shorter side may have been the global optimum's partner
  4. D Both pointers must move toward each other in lockstep for the search invariant to hold

Why: The shorter side still bounds the height after the move, but width dropped by 1, so the area cannot increase — moving the taller side is provably useless.

Q6 Why is the brute force O(n^2) while the two-pointer solution is O(n)?

  1. A The two-pointer version uses a SIMD min() instruction that evaluates all pairs in parallel
  2. B Brute force checks every pair (i, j); the two-pointer version advances exactly one pointer per step, so it does ~n total iterations instead of ~n^2 correct
  3. C The two-pointer version sorts the input first, dropping the inner loop to O(log n)
  4. D Brute force evaluates each pair twice (once forward, once backward), and the two-pointer fix halves that

Why: Brute force evaluates all O(n^2) pairs; the two-pointer scan moves one pointer inward each iteration and finishes in n-1 steps because each move prunes a whole class of dominated pairs.

Q7 When height[l] === height[r] (the two sides are equal), what does the canonical if (height[l] < height[r]) l++; else r--; do, and is it safe?

  1. A It moves l because < falls through to the truthy branch on equality — this is a subtle correctness bug
  2. B The condition is false, so it moves r; safe, because either move gives a symmetric result and any container through the side we keep can't beat the current width correct
  3. C It moves r, but is unsafe — discarding either side could lose a future container of equal area but greater width
  4. D It moves neither; the loop stalls until a tiebreak rule outside the if changes the heights

Why: On a tie the < is false so r-- runs; moving either side is equivalent here, and discarding one of two equal walls loses no better container since width only shrinks from now on.

Q8 A candidate writes area = max(height[l], height[r]) * (r - l). Why is this wrong?

  1. A Math.max returns the second argument on ties, so the formula picks the wrong height when the walls are equal
  2. B Water cannot rise above the SHORTER wall — using max would count water that would spill over the shorter side correct
  3. C The width should be (r - l + 1), not (r - l) — the off-by-one swamps the max-vs-min question
  4. D max breaks the loop invariant that areas are monotonically non-increasing, so the early-termination guard would fire too early

Why: The container holds water only up to the shorter of the two walls; min(h[l], h[r]) is the true height, so max overstates the area.
