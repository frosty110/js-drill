Contains Duplicate

Stream once; the first repeated value short-circuits to true. Set membership is O(1).

patterns Arrays & Hashing 8 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write containsDuplicate(nums) returning true iff any value repeats. O(n). Log containsDuplicate([1, 2, 3, 1]).

Expected output: true

Canonical solution

function containsDuplicate(nums) {
  const seen = new Set();
  for (const n of nums) {
    // Check BEFORE add — otherwise every element would match itself.
    if (seen.has(n)) return true;
    seen.add(n);
  }
  return false;
}
// Time O(n), Space O(n)
  • Check has BEFORE add — otherwise every element would falsely match itself.
  • Set.has is O(1) average; sorting + scan would be O(n log n) and unnecessary.
  • Short-circuit on the first duplicate — no need to keep counting.

Alternate approaches

One-liner: Set size comparison O(n) / O(n)

Reach for this in code-golf or when you want the most readable expression of the idea. Building a Set and comparing its size to the array length collapses duplicates implicitly — if any value repeated, the Set shrank.

function containsDuplicate(nums) {
  return new Set(nums).size !== nums.length;
}
console.log(containsDuplicate([1, 2, 3, 1]));
  • No early exit — always constructs the full Set even if a duplicate is in position 1.
  • Identical asymptotic complexity to the streaming approach; loses the short-circuit advantage.
  • More readable in a code review; the streaming check-before-add form is better when the list is huge and duplicates are early.

Sort then scan adjacent pairs O(n log n) / O(1)

Reach for this when the interviewer asks for O(1) extra space (though sorting in place mutates the input). After sorting, any duplicate must be adjacent — one linear scan suffices.

function containsDuplicate(nums) {
  const sorted = [...nums].sort((a, b) => a - b);
  for (let i = 1; i < sorted.length; i++) {
    if (sorted[i] === sorted[i - 1]) return true;
  }
  return false;
}
console.log(containsDuplicate([1, 2, 3, 1]));
  • O(n log n) time vs O(n) for Set — slower, but uses a copy-sort so the original array is not mutated.
  • Sort in JS requires a numeric comparator (a,b)=>a-b; the default lexicographic sort would mis-order [1,10,2].
  • If mutating the input is acceptable, skip the spread and sort nums directly — space drops to O(log n) stack for the sort.

Why: If you add first, every element finds itself in the Set on the very next check.

  2. B Set gives O(n) instead of O(n log n)
  3. C Sort needs a custom numeric comparator (default sort is lexicographic — [1,10,2])
  4. D Both the mutation and the asymptotic reasons correct

Q5 What is the one-liner return new Set(nums).size !== nums.length doing?

  1. A Returning true iff every value in nums is unique (Set.size grows past nums.length when so)
  2. B If dedup shrank the count, some value repeated — so a duplicate exists correct
  3. C Returning the number of distinct values that appeared more than once
  4. D Comparing two different array lengths — only safe when nums is non-empty

Why: Building a Set drops repeats; if its size is smaller than the array length, at least one value collapsed, meaning there was a duplicate.

Q6 What does the canonical return on an empty array []?

  1. A true
  2. B false correct
  3. C undefined — return false is unreachable when the for-of loop never iterates
  4. D An empty Set object, not a boolean

Why: The loop body never runs, so control falls through to the trailing return false — no values means no duplicates, which is vacuously correct.

Q7 Why does the early return true on the first duplicate not change the worst-case time complexity?

  1. A The amortized average becomes O(n/2) but Big-O drops constants, so it's still O(n)
  2. B The worst case is all-unique input, where no early exit fires and the full array is scanned correct
  3. C Set.has is O(n), so the early return doesn't actually shorten the work it skips
  4. D It does — early termination drops the bound to O(log n) in the average case

Why: Short-circuiting only helps when a dup appears early; the worst case (all distinct) still walks every element, so the bound stays O(n).

Q8 The brute-force nested-loop version is O(n²). What does the Set buy in exchange for its O(n) space?

  1. A It drops time to O(n log n) by maintaining the seen values in a sorted internal tree
  2. B It replaces the O(n) inner membership scan with an O(1) Set lookup, dropping time to O(n) correct
  3. C It eliminates the inner loop by batching all comparisons into a single CPU SIMD instruction
  4. D It removes the need for a separate result variable by returning directly from Set.add when a dup is detected

Why: Brute force re-scans seen elements (O(n)) for each item; the Set answers 'have I seen this?' in O(1), trading O(n) memory for O(n) total time.
