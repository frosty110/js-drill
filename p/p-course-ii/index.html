Course Schedule II (Topological Sort)

Kahn's algorithm: BFS on nodes with in-degree 0, peeling them off the DAG. Returns a valid topological order, or [] on cycle. O(V+E).

Problem

Write findOrder(numCourses, prerequisites) returning any valid topological order, or [] if a cycle exists. Use Kahn's BFS. Log results for a valid 4-course DAG and a 2-course cycle.

Expected output: [0,1,2,3] []

Canonical solution

Kahn's algorithm (BFS topological sort) · O(V+E) / O(V+E) (time / space)

function findOrder(numCourses, prerequisites) {
  const adj = Array.from({length: numCourses}, () => []);
  const indeg = new Array(numCourses).fill(0);
  // [a, b] means b is prereq of a → edge b -> a, indeg[a]++.
  for (const [a, b] of prerequisites) {                  // b -> a (take b before a)
    adj[b].push(a);
    indeg[a]++;
  }
  const queue = [];
  // Seed with every node that starts with NO prerequisites — BFS roots.
  for (let i = 0; i < numCourses; i++) if (indeg[i] === 0) queue.push(i);
  const order = [];
  while (queue.length) {
    const u = queue.shift();
    order.push(u);
    for (const v of adj[u]) {
      // Decrement first, then test === 0 — v has all prereqs satisfied now.
      if (--indeg[v] === 0) queue.push(v);                // becomes a new root
    }
  }
  // Short order means a cycle absorbed the rest — spec returns [].
  return order.length === numCourses ? order : [];        // cycle => incomplete
}
// Time O(V+E), Space O(V+E)
  • Edge direction matters: [a, b] means b is a prerequisite of a, so add edge b -> a and increment indeg[a].
  • Seed the queue with every node whose in-degree starts at 0; otherwise the BFS never begins.
  • If the final order.length is less than V, a cycle absorbed the missing nodes — return [] per spec.

Alternate approaches

DFS post-order with 3-color cycle detection O(V+E) / O(V+E)

Reach for this when the interviewer asks for the recursive/DFS variant, or when the graph is sparse and you'd rather avoid building an indegree array. Detects cycles via WHITE/GRAY/BLACK coloring: GRAY means 'on the current DFS path,' so re-entering a GRAY node is a back-edge = cycle. The topological order falls out of reverse post-order — you push each node AFTER all its descendants are finished.

function findOrder(numCourses, prerequisites) {
  const adj = Array.from({length: numCourses}, () => []);
  for (const [a, b] of prerequisites) adj[b].push(a);     // edge b -> a
  // 0 = WHITE (unvisited), 1 = GRAY (on current path), 2 = BLACK (finished).
  const color = new Array(numCourses).fill(0);
  const order = [];
  let hasCycle = false;
  function dfs(u) {
    if (hasCycle) return;
    color[u] = 1;                                          // entering — mark GRAY
    for (const v of adj[u]) {
      if (color[v] === 1) { hasCycle = true; return; }     // back-edge → cycle
      if (color[v] === 0) dfs(v);
    }
    color[u] = 2;                                          // finished — mark BLACK
    order.push(u);                                         // POST-order push
  }
  for (let i = 0; i < numCourses; i++) {
    if (color[i] === 0) dfs(i);
  }
  if (hasCycle) return [];
  return order.reverse();                                  // reverse post-order = topo order
}
console.log(JSON.stringify(findOrder(4, [[1,0],[2,1],[3,2]])));
console.log(JSON.stringify(findOrder(2, [[0,1],[1,0]])));
  • Three colors are the key: WHITE = untouched, GRAY = currently on the DFS stack, BLACK = fully processed. Hitting a GRAY node mid-DFS is the back-edge that proves a cycle exists.
  • Push each node AFTER recursing into all its descendants (post-order), then reverse the final array — a node's dependencies finish (and get pushed) before the node itself, so reversing puts prereqs first.
  • Output ordering will differ from Kahn's — DFS naturally produces a depth-first topo order, while Kahn's gives a breadth-first one. Both are valid; check whether the judge accepts any valid topo sort.

Q1 What does Kahn's algorithm use as its frontier?

  1. A Nodes with the highest in-degree
  2. B Nodes whose in-degree is currently 0 correct
  3. C Leaves with no outgoing edges
  4. D Nodes ordered by descending out-degree to drain the most dependents first

Why: The queue holds only nodes with indeg === 0 — every prerequisite already emitted — and a node joins the frontier the instant --indeg[v] hits 0.

Q2 How is a cycle detected?

  1. A A node's in-degree decrements below 0, signaling that a back-edge was traversed
  2. B The queue becomes empty before all V nodes are emitted correct
  3. C Two distinct enqueued nodes share an out-edge to the same successor
  4. D BFS revisits a node that's already in the emitted order array

Why: Nodes inside a cycle keep each other's indegree above 0 forever, so they never enqueue; order.length === numCourses is the test, and a short order returns []. No indegree ever goes negative — each edge decrements exactly once.

Q3 For prerequisites = [[a, b]], the edge direction is:

  1. A a -> b
  2. B b -> a correct
  3. C Both a -> b and b -> a (the pair encodes a mutual dependency)
  4. D a -> b for indegree bookkeeping, but b -> a in the adjacency list

Why: b is the prerequisite, so the canonical writes adj[b].push(a) and indeg[a]++ — the edge points from the prereq toward the course it unlocks, and both structures use that same direction.

Q4 Time complexity?

  1. A O(V * E)
  2. B O(V + E) correct
  3. C O(V^2)
  4. D O(E log V)

Why: The build pass costs O(V + E); afterwards each node is popped from the queue once and each adj entry is decremented once, so no node or edge is revisited. The log factor would only appear if the queue were swapped for a min-heap to break ties lexicographically.
