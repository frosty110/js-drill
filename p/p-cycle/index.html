Detect Cycle

Floyd tortoise-and-hare: two pointers move at 1x and 2x speed. If they ever meet, there is a cycle. O(n) time, O(1) space.

Problem

Write hasCycle(head) using Floyd two-pointer (O(1) space). Build a 2-node cycle a → b → a and log hasCycle(a).

Expected output: true

Canonical solution

Floyd's tortoise-and-hare (fast/slow pointers) · O(n) / O(1) (time / space)

function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;        // 1 step
    fast = fast.next.next;   // 2 steps
    if (slow === fast) return true;
  }
  return false;
}
// Time O(n), Space O(1)
// Why: if there's a cycle, fast laps slow inside it.
// If no cycle, fast hits null.
  • Loop condition checks BOTH fast and fast.next — fast moves 2, so both hops must be legal.
  • Compare with === (reference equality on the node object), not by .val.
  • Hash-set approach also works in O(n) time but uses O(n) space. Floyd is the canonical O(1)-space.

Alternate approaches

Hash Set (visited nodes) O(n) / O(n)

Reach for this when O(n) space is acceptable and you want the simplest code. It's also the right answer if you need to find the FIRST duplicate node (not just whether one exists), since the Set holds references and you can return the repeated node directly.

function hasCycle(head) {
  const seen = new Set();
  let curr = head;
  while (curr) {
    if (seen.has(curr)) return true;
    seen.add(curr);
    curr = curr.next;
  }
  return false;
}
const a={val:1,next:null};const b={val:2,next:null};
a.next=b;b.next=a;
console.log(hasCycle(a));
  • Store node REFERENCES in the Set (not values) — two distinct nodes can share the same .val.
  • The Set grows up to n entries in the worst case (acyclic list); Floyd uses only two pointers.
  • Useful when you also need to identify WHICH node starts the cycle — return curr instead of true.

Q1 Why must the loop check both fast AND fast.next?

  1. A Checking just fast.next is enough — if fast were null, fast.next would already throw
  2. B fast moves two steps; both .next hops must be non-null correct
  3. C To match the loop condition slow uses, keeping the two pointer walks symmetric
  4. D Without the fast check, slow could overtake fast and cause an infinite loop

Why: fast = fast.next.next dereferences twice, so fast.next has to exist before the second hop — and && short-circuits, so the leading fast check is what stops fast.next itself from throwing on null.

Q2 Space complexity of Floyd cycle detection?

  1. A O(1) correct
  2. B O(log n)
  3. C O(n)
  4. D O(n^2)

Why: Two pointer variables and nothing else — O(n) is the hash-Set alternative, whose Set grows to hold up to n node references.

Q3 How do slow and fast compare when checking for a meeting?

  1. A By .val (value equality)
  2. B By === (reference equality on the node) correct
  3. C By position index
  4. D By .next pointer

Why: slow === fast compares object identity, which is what "landed on the same node" means; comparing .val would fire on two distinct nodes that merely hold equal values.

Q4 If there is no cycle, the loop ends because:

  1. A slow reaches the tail node first and triggers a slow.next === null exit
  2. B fast or fast.next becomes null correct
  3. C fast eventually points back at the head, which the loop treats as a sentinel
  4. D slow and fast converge on the tail and pass the slow === fast check

Why: fast moves 2x, so it runs off the end first: on an odd-length list fast.next goes null, on an even-length one fast itself does. That guard is the only exit — slow is never tested, so the acyclic exit is always fast's.

Q5 Once both pointers are inside the cycle, why are they guaranteed to meet?

  1. A They start at the same node
  2. B The gap between them shrinks by exactly 1 node each iteration, so it eventually hits 0 correct
  3. C fast resets to slow's position periodically
  4. D The cycle length is always even

Why: Fast gains 1 net node on slow per step (2 minus 1), so the gap modulo the cycle length decreases by 1 each iteration until it reaches 0 — a collision.

Q6 If both pointers moved at the SAME speed (slow +1, fast +1), would cycle detection still work?

  1. A Yes, they would still meet
  2. B No — they keep a fixed gap forever and never collide inside the cycle correct
  3. C Yes, but only for even-length cycles
  4. D No — they would both immediately point to null

Why: Equal speed means the gap never changes, so they never close in; the 2-to-1 ratio is what forces the gap to shrink to 0.

Q7 What is Floyd's main advantage over storing visited nodes in a Set?

  1. A It is asymptotically faster in time
  2. B It uses O(1) space instead of O(n) correct
  3. C It handles unsorted lists
  4. D It can find the cycle length

Why: Both are O(n) time, but the Set holds up to n nodes (O(n) space) while Floyd uses only two pointers (O(1) space).

Q8 Why compare nodes with slow === fast rather than slow.val === fast.val?

  1. A === is faster than .val comparison
  2. B Distinct nodes can hold equal values, so value equality would give false positives correct
  3. C .val might be undefined
  4. D Reference equality skips the head node

Why: Two different nodes can share the same value; only reference equality confirms the pointers landed on the same node.

Q9 To find WHERE the cycle starts (LeetCode 142), after slow and fast meet you:

  1. A Return the meeting node directly
  2. B Reset one pointer to head, then advance both by 1 — they meet at the cycle entry correct
  3. C Count nodes until fast wraps again
  4. D Reverse the list from the meeting point

Why: Floyd's math: the head-to-entry distance equals the meeting-point-to-entry distance, so two 1-step walkers from head and meeting point converge at the entry.
