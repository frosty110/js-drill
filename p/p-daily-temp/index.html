Daily Temperatures

Monotonic decreasing stack of indices: pop while the new temp is warmer, recording the wait for each popped index.

patterns Stack 9 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write dailyTemperatures(temps) returning an array where result[i] is days until a warmer temperature (0 if none). Log JSON.stringify(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73])).

Expected output: [1,1,4,2,1,1,0,0]

Canonical solution

Monotonic decreasing stack of indices · O(n) / O(n) (time / space)

function dailyTemperatures(temps) {
  // Default 0 stays for any index that never finds a warmer day.
  const res = new Array(temps.length).fill(0);
  const stack = [];                       // indices, temps[stack] decreasing
  for (let i = 0; i < temps.length; i++) {
    // Strict > keeps the stack monotonically decreasing; equal temps don't resolve.
    while (stack.length && temps[i] > temps[stack[stack.length - 1]]) {
      const j = stack.pop();
      res[j] = i - j;                     // days waited
    }
    // Push the INDEX (not temp) — we need it to compute i - j later.
    stack.push(i);
  }
  return res;
}
// Time O(n) — each index is pushed and popped at most once
// Space O(n)
  • Stack stores INDICES, not temperatures — you need the index to compute i - j.
  • Strict greater-than (>) keeps the stack monotonically decreasing.
  • Indices left on the stack at the end have no warmer day — they keep their initial 0.

Alternate approaches

Brute force (nested scan) O(n²) / O(1)

Reach for this when n is small (≤ a few thousand) or when the interviewer explicitly says O(n²) is acceptable. Simpler to reason about — no monotonic invariant to maintain.

function dailyTemperatures(temps) {
  const res = new Array(temps.length).fill(0);
  for (let i = 0; i < temps.length; i++) {
    for (let j = i + 1; j < temps.length; j++) {
      if (temps[j] > temps[i]) { res[i] = j - i; break; }
    }
  }
  return res;
}
console.log(JSON.stringify(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73])));
  • Inner loop breaks on the first warmer day — no need to scan the whole tail.
  • O(1) extra space (no stack) at the cost of O(n²) time — fine for small n.
  • The monotonic stack is the same idea but lets each warmer day broadcast to all pending colder days at once, dropping the inner loop.

Q1 What does the stack hold?

  1. A Temperatures
  2. B Indices into temps correct
  3. C Wait counts
  4. D Pairs of (index, temp)

Why: stack.push(i) stores the position; the temperature is read back on demand as temps[stack[stack.length - 1]], so the index is the strictly more useful half of the pair.

Q2 Time complexity?

  1. A O(n^2)
  2. B O(n log n)
  3. C O(n) — each index pushed and popped at most once correct
  4. D O(1)

Why: Nothing sorts (ruling out O(n log n)) and nothing rescans: an index enters the stack once and leaves once, so the inner while fires at most n times across the whole outer loop.

Q3 Why initialize the result array with zeros?

  1. A So the stack push doesn't read an undefined slot before the first assignment
  2. B Indices with no warmer day to the right keep 0 by default correct
  3. C Zeros are needed as sentinels for the strict > comparison to fall through
  4. D new Array(n) returns a sparse array — fill(0) densifies it for fast V8 iteration

Why: res[j] = i - j only runs on a pop, so indices still on the stack when the loop ends are never written — fill(0) is what already gives them the right answer, which is why there is no cleanup pass.

Q4 The stack stays monotonically:

  1. A Increasing in temperature
  2. B Decreasing in temperature correct
  3. C Sorted by index only
  4. D Unordered

Why: The while clears out every pending index colder than temps[i] before pushing i, so bottom-to-top the temperatures only ever fall — on [73,74,75,71,69,…] the stack reads 75 > 71 > 69.

Q5 What does it mean when you pop index j because temps[i] > temps[j]?

  1. A Day i is the coldest day so far
  2. B Day i is the FIRST day after j that is warmer than j correct
  3. C Day j had a duplicate temperature
  4. D The stack overflowed

Why: j sat on the stack unresolved because nothing warmer came yet; i is the nearest later day that finally exceeds it, so res[j] = i - j.

Q6 Why store INDICES on the stack instead of the temperatures themselves?

  1. A Indices take less memory than temperatures
  2. B You need the index to compute the day gap i - j; a temperature can't give you that correct
  3. C Temperatures can be negative
  4. D It keeps the stack sorted automatically

Why: The answer is the number of days waited (i - j), which requires the popped element's position, not its value.

Q7 The inner while makes this look O(n^2). Why is it actually O(n)?

  1. A The while rarely executes
  2. B Each index is pushed once and popped at most once, so total pops across the whole run is bounded by n correct
  3. C JavaScript optimizes nested loops
  4. D The stack is capped at a constant size

Why: Amortized analysis: total inner-loop work over the entire outer loop is at most n pops, giving O(n) overall.

Q8 Why use strict > rather than >= in the pop condition?

  1. A It is faster
  2. B Equal temperatures are not 'warmer', so an equal day must not resolve a pending index correct
  3. C >= would crash on duplicates
  4. D It changes the time complexity

Why: The problem asks for a strictly warmer day; >= would wrongly settle equal-temperature days as warmer.

Q9 After the loop, what is true of the indices still left on the stack?

  1. A They had warmer days but were skipped
  2. B No later day was warmer than them, so their result stays the default 0 correct
  3. C They must be popped in a cleanup loop
  4. D They are duplicates of earlier indices

Why: Anything never popped never found a warmer day; the fill(0) initialization already gives them the correct answer of 0.
