Edit Distance (Levenshtein)

Minimum insert/delete/replace edits to turn word1 into word2. 2D DP: dp[i][j] = edits between word1[:i] and word2[:j]. Match → carry diagonal; mismatch → 1 + min(insert, delete, replace).

Problem

Write minDistance(w1, w2) returning the minimum number of insert/delete/replace edits to turn w1 into w2. Log minDistance("horse", "ros") and minDistance("intention", "execution").

Expected output: 3 5

Canonical solution

2D tabulation over prefix pairs (delete / insert / replace) · O(m·n) / O(m·n) (time / space)

function minDistance(w1, w2) {
  const m = w1.length, n = w2.length;
  // dp[i][j] = edits to turn w1[..i] into w2[..j]; (m+1)x(n+1) including empty-prefix row/col.
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  // Base cases: empty target costs i deletes; empty source costs j inserts.
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      // Chars match → no edit needed, inherit diagonal.
      if (w1[i - 1] === w2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1];
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j],     // delete from w1
          dp[i][j - 1],     // insert into w1
          dp[i - 1][j - 1]  // replace
        );
      }
    }
  }
  return dp[m][n];
}
// Time O(m*n), Space O(m*n)
  • Row 0 and column 0 are the base cases: converting to/from the empty string costs exactly the other length.
  • On a character match the cost CARRIES from dp[i-1][j-1] — no +1.
  • The three predecessors map to delete (top), insert (left), replace (diagonal). Take min, then add one.

Alternate approaches

1D rolling array (O(min(m,n)) space) O(m*n) / O(min(m,n))

Reach for this when space is the bottleneck — e.g. very long strings where the full O(m*n) table would exhaust memory. Each row of the 2D table only reads from the previous row, so a single rolling row of length n+1 suffices. Make the shorter string the columns to minimize the array size.

function minDistance(w1, w2) {
  // Always iterate over the shorter string as columns to keep the array small.
  if (w1.length < w2.length) return minDistance(w2, w1);
  const m = w1.length, n = w2.length;
  // prev[j] represents the previous row (dp[i-1][0..n]).
  let prev = Array.from({ length: n + 1 }, (_, j) => j);
  for (let i = 1; i <= m; i++) {
    const curr = new Array(n + 1);
    curr[0] = i;     // base case: i deletes to reach empty w2
    for (let j = 1; j <= n; j++) {
      if (w1[i - 1] === w2[j - 1]) {
        curr[j] = prev[j - 1];        // match: carry diagonal
      } else {
        curr[j] = 1 + Math.min(
          prev[j],       // delete from w1 (above)
          curr[j - 1],   // insert into w1 (left)
          prev[j - 1]    // replace (diagonal)
        );
      }
    }
    prev = curr;
  }
  return prev[n];
}
console.log(minDistance("horse", "ros"));
console.log(minDistance("intention", "execution"));
  • prev holds the previous row; curr builds the current row — only O(n) space instead of O(m*n).
  • The diagonal value (prev[j-1]) must be captured BEFORE it gets overwritten by the next cell — here prev is a separate array so prev[j-1] is safe to read in the j-th iteration.
  • Swap w1/w2 so the shorter string is always the columns: the rolling array is length min(m,n)+1, halving memory use on asymmetric inputs.

L1 — Concept questions 4

Q1 Why is dp[i][0] = i and dp[0][j] = j?

  1. A It's a sentinel row/column used to detect when a recurrence reads out of bounds
  2. B Converting to/from the empty string costs exactly that many edits correct
  3. C It anchors the diagonal so dp[i-1][j-1] never reads undefined when i or j is 1
  4. D i and j are the indices of the last matched character in each prefix

Why: Turning an i-character prefix into the empty string takes exactly i deletes, and building a j-character prefix from empty takes j inserts. Those two edges are the only cells the recurrence cannot compute, so they have to be filled by hand before the nested loops start.

Q2 On a character match (w1[i-1] === w2[j-1]) the recurrence is:

  1. A dp[i][j] = 1 + dp[i-1][j-1]
  2. B dp[i][j] = dp[i-1][j-1] correct
  3. C dp[i][j] = 1 + min(...three neighbors)
  4. D dp[i][j] = 0

Why: Matching characters need no edit, so the cost carries across unchanged from the diagonal. The 1 + … forms are the mismatch branch — charging +1 here would bill a replace that never happened.

Q3 Which DP neighbors correspond to the three edit operations?

  1. A Top = replace, Left = match, Diagonal = delete
  2. B Top = delete, Left = insert, Diagonal = replace correct
  3. C Top = insert, Left = delete, Diagonal = match
  4. D Top = delete, Left = replace, Diagonal = insert

Why: dp[i-1][j] consumed one more char of w1 than of w2, so it is a delete; dp[i][j-1] consumed one more of w2, so it is an insert; the diagonal advances both by one, so it is a replace. Each costs 1 on top of its predecessor, which is the 1 + Math.min(...).

Q4 Time and space complexity of the standard 2D DP?

  1. A O(m + n) / O(1)
  2. B O(m*n) / O(m*n) correct
  3. C O(m*n) / O(min(m,n))
  4. D O((m+n) log (m+n)) / O(m+n)

Why: Space CAN be O(min(m,n)) with rolling rows, but the canonical 2D table is O(m*n).
