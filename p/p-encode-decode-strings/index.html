Encode/Decode Strings

Serialize a list of arbitrary strings into one string and round-trip it back. Length-prefix scheme `len#payload` avoids any delimiter collision.

patterns Arrays & Hashing 8 concept · 1 fill-in · 1 drill

Results carried by this link

Problem

Implement encode(strs) and decode(str) using a length-prefix scheme. Log encode(["hello","world"]) then JSON.stringify(decode(encode(["hello","world"]))).

Expected output: 5#hello5#world ["hello","world"]

Canonical solution

function encode(strs) {
  let out = "";
  // Length-prefix is delimiter-safe — payload may contain '#' itself.
  for (const s of strs) out += s.length + "#" + s;
  return out;
}
function decode(str) {
  const res = [];
  let i = 0;
  while (i < str.length) {
    let j = i;
    while (str[j] !== "#") j++;            // find delimiter
    // Header is the digits in [i, j); the '#' lives at j.
    const len = Number(str.slice(i, j));
    res.push(str.slice(j + 1, j + 1 + len));
    // Jump past '#' (1) + payload (len) to land on next header.
    i = j + 1 + len;
  }
  return res;
}
// Time O(N) total chars, Space O(N).
  • Length-prefix is delimiter-safe: payloads can contain '#' or any character.
  • Find '#' via a scan, not split — the payload may itself contain '#'.
  • Empty string encodes as 0#; empty array encodes as "" and decodes to [].

L1 — Concept questions 8

Positions 1–8 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why prefix with length + '#' instead of just joining on a separator?

  1. A Length-prefixed strings can be parsed in parallel because each header is fixed-width
  2. B Any separator could collide with a payload character — length prefix is collision-proof correct
  3. C Array.prototype.join inserts the separator between every char, not between strings — the wrong shape entirely
  4. D String.prototype.split has a 65535-element output limit that join+split would silently hit

Q2 When decoding, why scan for '#' instead of using split('#')?

  1. A split builds the whole array up front, defeating the streaming, length-bounded read we want
  2. B Payloads themselves can contain '#', so a global split would over-split correct
  3. C split returns a string when called with one argument and an array when called with two — too inconsistent here
  4. D We need to keep the '#' character in the output, which split discards

Q3 How is the empty string "" encoded?

  1. A As an empty string
  2. B As "#" — header is omitted when length is zero
  3. C As "0#" correct
  4. D As "#0" — the delimiter must come before the length

Q4 After reading length L from a header ending at index j, where does the next header begin?

  1. A j + L
  2. B j + 1 + L correct
  3. C j + L + 2
  4. D i + L

Why: Skip the '#' (1 char) and the payload (L chars).

Q5 Why can the digit characters of the length header never be confused with the payload that follows?

  1. A The header is escaped as \d so the decoder can distinguish header digits from payload digits
  2. B The first '#' marks the boundary — everything before it is the header, everything after (for len chars) is payload correct
  3. C The encoder validates that no payload begins with a digit and rejects inputs that do
  4. D Payload positions are tracked in a parallel index array passed alongside the encoded string

Why: The decoder scans to the FIRST '#' to read the length, then consumes exactly len chars — the header digits and payload are separated by that boundary, not by ambiguity.

Q6 Why does the naive strs.join('#') then split('#') round trip break?

  1. A join drops trailing empty strings, so ['a',''] would lose the empty element after the round trip
  2. B If a payload itself contains '#', split produces extra pieces and the count no longer matches correct
  3. C split with a single-char delimiter coerces the result elements to numbers, breaking string payloads
  4. D join collapses consecutive separators in its output, so back-to-back empty strings get merged

Why: A delimiter that can also appear inside a payload is ambiguous — ['a','#b'] joins to 'a##b' and splits to three pieces, losing the original boundaries.

Q7 How does the empty array [] round-trip?

  1. A Encodes to '0#' and decodes to [''] — encode must emit a zero-length header
  2. B Encodes to '' and decodes back to [] because the while loop never enters correct
  3. C Encodes to '' but decode throws because the inner scan can't find a '#' to break on
  4. D Encodes to '0' — the count of elements becomes the entire encoded form

Why: No strings means nothing is concatenated, so encode returns '', and decode's while (i < str.length) is immediately false, yielding [].

Q8 Length-prefix framing is robust precisely when:

  1. A Payload sizes are known up front, so the encoder can pre-allocate the output buffer
  2. B The payload alphabet can overlap any candidate delimiter, so no separator char is reserved-safe correct
  3. C The decoder is allowed to scan the entire string twice — once for headers, once for payloads
  4. D All payloads share a common prefix the encoder can factor out

Why: When payloads may contain arbitrary characters, no single delimiter is safe; encoding an explicit length makes the framing self-describing regardless of payload contents.
