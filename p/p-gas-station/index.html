Gas Station

Given gas[i] and cost[i] around a circular route, return the starting index that lets you finish the loop, or -1. Greedy: if total gas >= total cost a solution exists; reset start whenever the tank goes negative.

Problem

Write canCompleteCircuit(gas, cost) returning a valid starting index for the circular trip, or -1. Log the result for ([1,2,3,4,5], [3,4,5,1,2]) then ([2,3,4], [3,4,3]).

Expected output: 3 -1

Canonical solution

One-pass greedy (running tank + total balance) · O(n) / O(1) (time / space)

function canCompleteCircuit(gas, cost) {
  // total = whole-loop balance (decides feasibility); tank = running balance from current candidate start.
  let total = 0, tank = 0, start = 0;
  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    total += diff;
    tank  += diff;
    // If tank goes negative, every index in [start..i] is disqualified — jump past i.
    if (tank < 0) {
      start = i + 1;
      tank = 0;
    }
  }
  // If total < 0 no start works; otherwise the last surviving start is THE answer.
  return total >= 0 ? start : -1;
}
// Time O(n), Space O(1)
  • If total (sum of gas - cost) is negative, no start can work — return -1.
  • Whenever the running tank goes negative, every index from old start up to i is disqualified; jump start to i+1.
  • One pass, no need to re-simulate from the candidate start.

Alternate approaches

Brute force (try every start) O(n²) / O(1)

Name this before coding the greedy — it proves you understand the simulation before the optimization. O(n²) is acceptable for very small n, but interviewers expect you to discard it in favor of the one-pass approach.

function canCompleteCircuit(gas, cost) {
  const n = gas.length;
  for (let start = 0; start < n; start++) {
    let tank = 0;
    let completed = true;
    for (let k = 0; k < n; k++) {
      const i = (start + k) % n;
      tank += gas[i] - cost[i];
      if (tank < 0) { completed = false; break; }
    }
    if (completed) return start;
  }
  return -1;
}
console.log(canCompleteCircuit([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]));
console.log(canCompleteCircuit([2, 3, 4], [3, 4, 3]));
  • For each candidate start, simulate the full n-step loop using modular indexing.
  • Bail early on a negative tank — this is the one optimization the brute force gets.
  • O(n²) worst-case because every start may almost complete the loop before failing.

Q1 If sum(gas) < sum(cost), the answer is:

  1. A Index 0 — the only universally safe default start
  2. B argmax(gas[i] - cost[i]) — the station with the largest single-step surplus
  3. C -1 — no valid start exists correct
  4. D argmin(cost[i]) — the cheapest station to leave from

Why: total accumulates every gas[i] - cost[i], so a negative total means the whole loop burns more fuel than it holds no matter where you begin — that is exactly the total >= 0 ? start : -1 guard.

Q2 When the running tank goes negative at index i, what does the algorithm do?

  1. A Returns -1 immediately because a negative tank proves the loop is infeasible
  2. B Sets start = i + 1 and resets tank to 0 correct
  3. C Decrements start by 1 to try an earlier candidate that might have had more gas
  4. D Sets start = i (the failing index — perhaps the failure means start at i itself)

Why: Arriving at i with a negative tank disqualifies every start in [start..i], so the next candidate is i + 1 and tank restarts from empty; feasibility is not decided here — that is total's job after the full pass.

Q3 Why is it safe to skip every index from the old start through i?

  1. A Indices in [start..i] are values already counted toward total, so re-using them would double-count
  2. B Starting at any of them would also fail before i — their prefix sums are even worse correct
  3. C Once tank goes negative, the circular wraparound shifts the array by i-start+1, making those indices unreachable anyway
  4. D The problem's uniqueness guarantee means the answer is monotonic — only forward candidates remain

Why: Removing a non-negative prefix only lowers the running tank, so no inner index can survive past i either.

Q4 Time complexity?

  1. A O(n^2) — try every start
  2. B O(n log n)
  3. C O(n) correct
  4. D O(n + k) where k is the number of resets

Why: One pass with O(1) work per index — start = i + 1 never rewinds i, so no candidate start is ever re-simulated.
