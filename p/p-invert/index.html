Invert Binary Tree

Swap each node’s left and right children recursively — the mirror image of the original tree.

patterns Trees 8 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write invertTree(root) that swaps every node’s children in place. Log the inorder traversal of the inverted BST [4, 2, 7, 1, 3, 6, 9]. Expected reversed order.

Expected output: [9,7,6,4,3,2,1]

Canonical solution

Recursive mirror — invert both children, then swap · O(n) / O(h) (time / space)

function invertTree(root) {
  if (!root) return null;          // base case: null subtree stays null
  const left = invertTree(root.left);
  const right = invertTree(root.right);
  root.left = right;               // swap the two recursed subtrees
  root.right = left;
  return root;
}
// Time O(n), Space O(h) for recursion stack
// Famous Max Howell tweet: rejected from Google after failing this whiteboard.
  • Pure recursive swap — recurse first, then assign, so children are independently inverted before the swap.
  • Base case if (!root) return null covers empty trees and terminates at leaf children.
  • O(n) time, O(h) space; h = O(log n) balanced, O(n) skewed.

Alternate approaches

Iterative BFS queue O(n) / O(w)

Reach for this when the tree could be adversarially skewed — deep enough to blow the JS call stack (~10k+ levels). Any traversal order works for invert because each swap is independent, so BFS is the cleanest iterative shape.

function invertTree(root) {
  if (!root) return root;
  const queue = [root];
  while (queue.length) {
    const node = queue.shift();
    // Swap children in place.
    const tmp = node.left;
    node.left = node.right;
    node.right = tmp;
    if (node.left)  queue.push(node.left);
    if (node.right) queue.push(node.right);
  }
  return root;
}
function inorder(node, out = []) {
  if (!node) return out;
  inorder(node.left, out);
  out.push(node.val);
  inorder(node.right, out);
  return out;
}
const root = { val: 4, left: { val: 2, left: { val: 1, left: null, right: null }, right: { val: 3, left: null, right: null } }, right: { val: 7, left: { val: 6, left: null, right: null }, right: { val: 9, left: null, right: null } } };
console.log(JSON.stringify(inorder(invertTree(root))));
  • Push root, pop, swap children, push the (now swapped) children — order of push doesn't matter because each swap is local.
  • Space is O(w) — the queue holds at most one level; on a balanced tree that is ~n/2 at the bottom, heavier than recursion's O(log n) average but bounded by width not call-stack depth.
  • A DFS stack version is identical — just replace queue.shift() with stack.pop(). Both are O(n) time, only the traversal order and space constant differ.

L1 — Concept questions 8

Positions 1–8 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What does invertTree do at every node?

  1. A Replaces the node's value with its sibling's value
  2. B Swaps the left and right children correct
  3. C Sorts the children by value
  4. D Negates the node's value (val → -val) and recurses

Why: root.left = right; root.right = left — only the two child pointers move. val is never touched, so the result is a mirror of the original shape, not a renumbering of it.

Q2 Base case for invertTree(root)?

  1. A root is a leaf — return root immediately without recursing
  2. B root is null — return null correct
  3. C root.left and root.right both null — return a fresh node with the same val
  4. D Recursion depth equals tree height — return root to unwind

Why: Hitting null is what stops the descent at a leaf's missing children. A leaf-only base case has to read root.left to detect the leaf, so it throws on an empty tree.

Q3 Time complexity?

  1. A O(log n)
  2. B O(n) — each node visited once correct
  3. C O(n log n)
  4. D O(n^2)

Why: The recursion tree mirrors the actual tree — exactly one call per node, and the work inside a call is two assignments.

Q4 Space complexity of the recursive version (call stack)?

  1. A O(1)
  2. B O(h) where h is the tree height correct
  3. C Always O(log n)
  4. D O(n^2)

Why: Frames live only along the current descent path, so the peak is the tree height: O(log n) balanced, O(n) for a skewed chain. O(h) is the bound that covers both.

Q5 Can you invert a tree iteratively, and if so with what data structure?

  1. A No — invert requires recursion
  2. B Yes — a BFS queue OR a DFS stack both work; pop a node, swap its children, push the children back correct
  3. C Only a priority queue works
  4. D Only a hash map works

Why: The swap is independent per node, so any traversal order works — a queue (BFS) or a stack (DFS) both correctly visit every node to swap.

Q6 Pre-order and post-order both work for invert, but plain in-order is awkward. Why?

  1. A In-order visits each node twice (once between left and right, once on return), so swaps happen twice and cancel out
  2. B After you swap a node's children, an in-order traversal's 'left then right' no longer refers to the original sides, so you can double-swap or visit wrong subtrees correct
  3. C In-order requires the tree to be a BST; the inverted tree's in-order ordering breaks the BST invariant mid-traversal
  4. D In-order is iterative-only in JS, so it can't perform the swap during recursion

Why: Swapping mid-traversal changes which child in-order visits next; pre/post-order swap before or after both recursions, avoiding the confusion.

Q7 Does the order — swap-then-recurse vs recurse-then-swap — affect correctness?

  1. A Yes, only recurse-then-swap is correct
  2. B Yes, only swap-then-recurse is correct
  3. C No — the two recursive calls are independent of the swap, so either order produces the same mirrored tree correct
  4. D It depends on whether the tree is a BST

Why: Each subtree is inverted independently of the swap at the current node, so the operations commute.

Q8 What is the base case that makes the recursion terminate?

  1. A When root is a leaf — return root without making the two recursive calls
  2. B When root is null — return null (or just return), so leaves' null children stop the descent correct
  3. C When root.left === root.right — both are null, so the swap is a no-op and we return early
  4. D When the recursion stack reaches the tree's height — unwinding terminates the descent

Why: Hitting null is the floor of the recursion; without it you'd dereference null.left and crash.
