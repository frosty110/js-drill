Jump Game

Given nums where nums[i] is the max jump length from i, determine if you can reach the last index. Greedy: walk forward tracking the farthest reachable index.

patterns Greedy 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write canJump(nums) returning true iff you can reach the last index. Log canJump([2,3,1,1,4]) then canJump([3,2,1,0,4]).

Expected output: true false

Canonical solution

Greedy farthest-reach frontier · O(n) / O(1) (time / space)

function canJump(nums) {
  let reach = 0;                            // farthest index reachable so far
  for (let i = 0; i < nums.length; i++) {
    if (i > reach) return false;            // stuck before this index
    reach = Math.max(reach, i + nums[i]);   // extend farthest
  }
  return true;
}
// Time O(n), Space O(1)
  • If i ever exceeds reach, you cannot have walked here — return false.
  • Once reach >= nums.length - 1 you could return true early, but the loop is fine.
  • Greedy beats DP here: you only need the farthest reachable, not per-index reachability.

Alternate approaches

Backward DP ('good index' scan) O(n²) / O(n)

Some interviewers ask for the DP formulation explicitly. Walk backward from the last index; mark each position 'good' if it can jump to a known-good index. Returns true iff index 0 ends up 'good'. O(n²) worst-case.

function canJump(nums) {
  const n = nums.length;
  const good = new Array(n).fill(false);
  good[n - 1] = true;   // last index is always good
  for (let i = n - 2; i >= 0; i--) {
    const farthest = Math.min(i + nums[i], n - 1);
    for (let j = i + 1; j <= farthest; j++) {
      if (good[j]) { good[i] = true; break; }
    }
  }
  return good[0];
}
console.log(canJump([2, 3, 1, 1, 4]));
console.log(canJump([3, 2, 1, 0, 4]));
  • Seed good[n-1] = true; every index that can reach any good index becomes good itself.
  • Scanning forward from i is O(nums[i]) per index — O(n²) worst-case (e.g. all large values).
  • The greedy collapses this to O(1) state by observing that reachability is a contiguous prefix, so one running max captures the whole good-index array.

Q1 What does reach represent?

  1. A Minimum number of jumps still needed from index i
  2. B The farthest index reachable from indices walked so far correct
  3. C Sum of nums[0..i] — total jump budget spent
  4. D Index of the most recent local maximum in nums

Why: reach = Math.max(reach, i + nums[i]) keeps the farthest index anything walked so far can land on — a single frontier value, not per-index state.

Q2 Why does i > reach mean failure?

  1. A It means nums[i] would have to be negative, which violates the problem constraints
  2. B It means no earlier index could jump to i, so the path is broken correct
  3. C It signals that the array's prefix sum exceeded the array length, meaning we've over-counted jumps
  4. D It only matters when nums[i] === 0 — otherwise the next index would still be reachable

Why: reach is the farthest any earlier index could land on, so i > reach is a gap nothing before it can clear; the frontier only grows forward, so no later index can rescue it.

Q3 Time complexity?

  1. A O(n^2)
  2. B O(n log n)
  3. C O(n) correct
  4. D O(n * max(nums))

Why: A single pass with O(1) work per index — reach is a running max, so there is no inner loop over each index's jump length.

Q4 Why is greedy correct here versus DP?

  1. A Because nums values are bounded, eliminating the need for memoization
  2. B You only need the farthest reachable index — not whether each index is reachable individually correct
  3. C Greedy works because the array is processed in monotonic order, so once reach exceeds an index it never needs to be revisited
  4. D DP would need O(n) auxiliary memory but only stores booleans — greedy collapses booleans into a single integer for the same information

Why: If you can reach some j, you can reach every i < j. So one running max captures everything.
