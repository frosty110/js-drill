Largest Rectangle in Histogram

Monotonic increasing stack of indices. When a shorter bar arrives, pop and compute the rectangle whose height is the popped bar; its width spans from the new stack-top to the current index. Append a 0 sentinel so everything drains at the end.

Results carried by this link

Problem

Write largestRectangleArea(heights) returning the area of the largest rectangle. Use a monotonic stack with a 0 sentinel. Log largestRectangleArea([2, 1, 5, 6, 2, 3]).

Expected output: 10

Canonical solution

function largestRectangleArea(heights) {
  const stack = [];                                  // indices, heights[idx] strictly increasing
  let best = 0;
  // Sentinel 0 at the end forces every remaining bar to pop and settle its area.
  const h = heights.concat(0);
  for (let i = 0; i < h.length; i++) {
    // Pop while current bar breaks the increasing run — each popped bar's max rect ends here.
    while (stack.length && h[stack[stack.length - 1]] > h[i]) {
      const top = stack.pop();
      // Width = gap between new stack top and i, minus 1; if stack empty, span is [0..i).
      const width = stack.length ? i - stack[stack.length - 1] - 1 : i;
      best = Math.max(best, h[top] * width);
    }
    stack.push(i);
  }
  return best;
}
// Time O(n), Space O(n)
  • Stack stores INDICES with strictly increasing heights — that lets you derive width on pop.
  • Width on pop: if the stack is empty, the popped bar extends from 0 to i (width = i). Otherwise width = i - newTop - 1.
  • Append a 0 sentinel to the heights array so the final stretch of increasing bars also gets popped and measured.
  • Each index is pushed and popped at most once → O(n) amortized.

Alternate approaches

Brute force (expand each bar left and right) O(n²) / O(1)

Reach for this when n is small or to ground your thinking before optimizing. Treating each bar as the limiting height and expanding outward is the same conceptual model the stack uses — but O(n²) because each bar scans its neighbors directly.

function largestRectangleArea(heights) {
  let best = 0;
  for (let i = 0; i < heights.length; i++) {
    let minH = heights[i];
    for (let j = i; j < heights.length; j++) {
      minH = Math.min(minH, heights[j]);
      best = Math.max(best, minH * (j - i + 1));
    }
  }
  return best;
}
console.log(largestRectangleArea([2, 1, 5, 6, 2, 3]));
  • For each start index i, extend right and track the running minimum height — no need for an inner min scan.
  • O(1) extra space at the cost of O(n²) time — acceptable for small inputs.
  • The monotonic stack replaces the inner loop by precomputing left/right extents for every bar in a single pass.

  2. B i (the popped bar extends all the way from index 0 to i) correct
  3. C 0
  4. D i - top - 1

Why: With no smaller bar to the left, top is the minimum over [0..i), so it spans the full width i.

Q7 Why must the stack heights stay strictly increasing (use > to pop, so equal heights are NOT popped)?

  1. A To save memory
  2. B Equal-height bars belong to the same rectangle; keeping them lets the later flush measure the full span at once correct
  3. C Strict comparison is faster
  4. D It prevents integer overflow

Why: Popping on equal heights would split a flat run prematurely; deferring the pop lets the whole equal run be measured together when a strictly shorter bar arrives.

Q8 Without the appended 0 sentinel, what goes wrong on a strictly increasing input like [1, 2, 3]?

  1. A It throws on an empty stack
  2. B No bar is ever popped, so no rectangle is measured and it returns 0 correct
  3. C It double-counts the last bar
  4. D The width becomes negative

Why: Increasing bars never trigger a pop during the scan; the sentinel 0 is shorter than everything and forces the final drain that measures them.

Q9 Why is this O(n) despite the nested while loop?

  1. A The while loop is capped at a constant
  2. B Each index is pushed once and popped at most once, so total pop work is bounded by n correct
  3. C Histograms are always small
  4. D The sentinel makes it constant time

Why: Amortized: every index enters and leaves the stack exactly once, so the combined inner-loop work across the whole scan is O(n).
