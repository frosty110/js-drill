LCA in a BST

In a BST, walk down from root: if both p, q < root go left, both > root go right, else root IS the split point and therefore the LCA.

Results carried by this link

Problem

Write lowestCommonAncestor(root, p, q) for a BST. Build [6,2,8,0,4,7,9,null,null,3,5] and log the LCA of (2,8), (2,4), and (3,5) — each .val on its own line.

Expected output: 6 2 4

Canonical solution

function lowestCommonAncestor(root, p, q) {
  let node = root;
  while (node) {
    // Both targets in left subtree — LCA lives there.
    if (p.val < node.val && q.val < node.val) node = node.left;
    // Both in right subtree — same idea.
    else if (p.val > node.val && q.val > node.val) node = node.right;
    // Split point (or node equals p/q) — THIS node IS the LCA.
    else return node;
  }
  return null;
}
// Time O(h), Space O(1) — h is tree height
  • BST ordering is the whole trick — you never need to search both subtrees like in a generic binary tree.
  • The first node where p and q diverge (one goes left, other right) OR equals one of them IS the LCA.
  • Iterative form is O(1) space; the recursive version is O(h) for the call stack.

Alternate approaches

Recursive descent O(h) / O(h)

Use when the interviewer asks for a recursive solution, or when you prefer the functional style. Same O(h) time; pays O(h) call-stack space instead of O(1), which rarely matters in practice but is worth naming.

function lowestCommonAncestor(root, p, q) {
  if (p.val < root.val && q.val < root.val)
    return lowestCommonAncestor(root.left, p, q);
  if (p.val > root.val && q.val > root.val)
    return lowestCommonAncestor(root.right, p, q);
  // Split point or one of the targets equals root — root IS the LCA.
  return root;
}
const n3 = { val: 3, left: null, right: null };
const n5 = { val: 5, left: null, right: null };
const n4 = { val: 4, left: n3, right: n5 };
const n0 = { val: 0, left: null, right: null };
const n2 = { val: 2, left: n0, right: n4 };
const n7 = { val: 7, left: null, right: null };
const n9 = { val: 9, left: null, right: null };
const n8 = { val: 8, left: n7, right: n9 };
const root = { val: 6, left: n2, right: n8 };
console.log(lowestCommonAncestor(root, n2, n8).val);
console.log(lowestCommonAncestor(root, n2, n4).val);
console.log(lowestCommonAncestor(root, n3, n5).val);
  • Identical logic to the iterative version — just expressed as tail recursion: one recursive call per iteration, no branching into both subtrees.
  • In JS there is no tail-call optimization, so recursion depth equals h; for a 1M-node skewed BST prefer the iterative form to avoid stack overflow.
  • The base case is the else branch — any state that is neither both-less nor both-greater returns root immediately.

Q5 If p = 2 is an ancestor of q = 4, what is their LCA?

  4. D The root

Why: By definition a node is a descendant of itself, so when the descent reaches 2 (neither both-less nor both-greater holds) it returns 2 as the LCA.

Q6 Why is the descent O(h) and not O(n) like generic-tree LCA?

  1. A It memoizes visited nodes
  2. B BST ordering lets it descend exactly one subtree per step, following a single root-to-split path instead of exploring both subtrees correct
  3. C It uses a hash map of ancestors
  4. D The tree is always balanced

Why: Each step picks one direction by comparing both targets to the node, so it walks at most one root-to-node path of length h — generic LCA must recurse into both subtrees, visiting up to all n nodes.

Q7 Why don't you need to locate p and q in the tree first?

  1. A Because p and q are guaranteed to be siblings of the root, so the LCA is always the root
  2. B The split point depends only on comparing p.val and q.val against each node's value, so the LCA is found during a single descent correct
  3. C Locating them first would build a hash of ancestors, which the iterative descent already provides via the BST property
  4. D The descent finds them first as a side effect, then continues until it reaches their common ancestor

Why: Knowing only p.val and q.val is enough — the BST ordering tells you which side each target lies on at every node, so the first divergence is the LCA without a separate search.

Q8 What is the space complexity of the iterative form, and how does it compare to recursive?

  1. A O(h) iterative, O(1) recursive
  2. B O(1) iterative (one pointer), versus O(h) for the recursive call stack correct
  3. C O(n) for both
  4. D O(log n) iterative, O(n) recursive

Why: The iterative loop holds a single node pointer for O(1) space; the recursive version pays O(h) for the call stack, so iterative is the strict space win.

Q9 The O(h) algorithm assumes both p and q exist in the tree. If a target is absent (and inputs aren't guaranteed), what happens?

  1. A It returns the deepest node whose value is between the present target and the missing one
  2. B The descent can walk off the tree to null and the loop returns null correct
  3. C It returns the closest ancestor of the present target, treating the missing one as inserted at that point
  4. D It returns the node whose value is numerically closest to the missing target

Why: Comparisons still steer the descent, but with a missing target it may reach a null child; the while(node) guard then exits and returns null.
