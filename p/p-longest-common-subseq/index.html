Longest Common Subsequence

2D DP where dp[i][j] = LCS length of the first i chars of `a` and first j chars of `b`. Match → 1 + diagonal; otherwise max of top, left.

Problem

Write lcs(a, b) returning the LENGTH of the longest common subsequence. Log lcs("abcde", "ace") and lcs("abc", "def").

Expected output: 3 0

Canonical solution

2D tabulation over prefix pairs — diagonal +1 on a match · O(m·n) / O(m·n) (time / space)

function longestCommonSubsequence(a, b) {
  const m = a.length, n = b.length;
  // dp[i][j] = LCS length of a[..i] and b[..j]; row/col 0 stay 0 (empty prefix).
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      // Chars match → extend diagonal by 1.
      if (a[i - 1] === b[j - 1]) {
        dp[i][j] = 1 + dp[i - 1][j - 1];
      } else {
        // No match → take the better of dropping a char from either side.
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }
  return dp[m][n];
}
// Time O(m*n), Space O(m*n)
  • Row 0 and column 0 stay at 0 — LCS with the empty prefix is 0, so no explicit init needed beyond fill(0).
  • On a match the diagonal carries +1; on a mismatch take max of the two adjacent cells (drop one char from either side).
  • Subsequence (order preserved, characters not necessarily adjacent) — distinct from substring, which requires contiguity.

Alternate approaches

1D rolling array (O(min(m,n)) space) O(m*n) / O(min(m,n))

Reach for this when memory is the constraint — the full 2D table is O(m*n) but each row only reads the row above it. A single row of length n+1 plus one saved diagonal value suffices. Make the shorter string the columns to minimize the array.

function lcs(a, b) {
  // Keep shorter string as columns to minimize the rolling array.
  if (a.length < b.length) return lcs(b, a);
  const m = a.length, n = b.length;
  // prev[j] = LCS of a[0..i-1] and b[0..j-1] (the row above the current one).
  let prev = new Array(n + 1).fill(0);
  for (let i = 1; i <= m; i++) {
    const curr = new Array(n + 1).fill(0);
    for (let j = 1; j <= n; j++) {
      if (a[i - 1] === b[j - 1]) {
        // Match: extend the diagonal (prev[j-1] is dp[i-1][j-1]).
        curr[j] = 1 + prev[j - 1];
      } else {
        // Mismatch: max of drop-a (prev[j]) or drop-b (curr[j-1]).
        curr[j] = Math.max(prev[j], curr[j - 1]);
      }
    }
    prev = curr;
  }
  return prev[n];
}
console.log(lcs("abcde", "ace"));
console.log(lcs("abc", "def"));
  • prev is the completed previous row; curr builds the current row — only O(n) space instead of O(m*n).
  • prev[j-1] (the diagonal) is safely read before curr[j] overwrites it because j increments left-to-right.
  • Swapping a and b so the shorter string is columns is optional but halves memory when the strings have very different lengths.

L1 — Concept questions 4

Q1 What does dp[i][j] represent?

  1. A Whether a[i] equals b[j]
  2. B LCS length of a[:i] and b[:j] correct
  3. C LCS length of suffixes
  4. D Edit distance of the prefixes

Why: i and j are prefix LENGTHS, not positions — which is why the comparison is a[i-1] === b[j-1] and why row 0 / column 0 (the empty prefix) stay 0 and need no explicit init.

Q2 On a character match the recurrence is:

  1. A dp[i][j] = dp[i-1][j-1]
  2. B dp[i][j] = 1 + dp[i-1][j-1] correct
  3. C dp[i][j] = max(dp[i-1][j], dp[i][j-1])
  4. D dp[i][j] = 1 + max(dp[i-1][j], dp[i][j-1])

Why: A matching pair can always be appended to the best LCS of BOTH prefixes shortened by one, so the diagonal carries +1. Adding 1 to a neighbour instead double-counts — that neighbour may already have consumed the matched character ("aa" vs "a" would score 2, not 1). Plain max-of-neighbours is the MISMATCH branch.

Q3 On a mismatch the recurrence is:

  1. A dp[i][j] = 0
  2. B dp[i][j] = 1 + min(top, left)
  3. C dp[i][j] = max(dp[i-1][j], dp[i][j-1]) correct
  4. D dp[i][j] = dp[i-1][j-1]

Why: The two last characters differ, so at most one of them can be in the LCS — drop a[i-1] or drop b[j-1] and keep the better result. No +1, because nothing was matched. Resetting to 0 is the longest common SUBSTRING recurrence, not this one.

Q4 How does LCS differ from longest common substring?

  1. A Substring matches reset to 0 on a mismatch in a 1D scan; subsequence allows the same DP table but tracks the global max instead of dp[m][n]
  2. B Substring requires contiguity; subsequence only preserves order correct
  3. C Subsequence requires contiguity in BOTH strings; substring only requires it in one
  4. D They're identical when the strings have no repeated characters

Why: A subsequence keeps relative order but allows gaps — "ace" in "abcde" scores 3 here. A substring must be contiguous in both strings, which is why its table resets to 0 on a mismatch and the answer is the running max over all cells rather than dp[m][n].
