Longest Inc. Subseq.

Length of the Longest Increasing Subsequence. dp[i] = 1 + max dp[j] over j < i with nums[j] < nums[i]. O(n²) DP; O(n log n) with patience-sort + binary search.

Problem

Write lengthOfLIS(nums) returning the length of the longest strictly increasing subsequence. O(n²) DP is fine. Log lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18]).

Expected output: 4

Canonical solution

Ending-at-i DP — scan every earlier j for a legal extension · O(n²) / O(n) (time / space)

function lengthOfLIS(nums) {
  const n = nums.length;
  // dp[i] = LIS length that ENDS at i. Every element alone is a length-1 subseq.
  const dp = new Array(n).fill(1);          // each element alone has LIS 1
  for (let i = 1; i < n; i++) {
    // Scan every j < i; extend if nums[j] < nums[i] (strictly increasing).
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }
  // Answer is max over ALL ending positions, not dp[n-1].
  return Math.max(...dp);
}
// Time O(n^2), Space O(n)
  • dp[i] = the LIS length that ENDS at index i — the final answer is Math.max over the whole dp.
  • Initialize every dp[i] to 1 because each element by itself is a valid subsequence of length 1.
  • Faster variant: maintain a tails array and binary-search the first tail >= nums[i] (lower_bound). O(n log n).

Alternate approaches

Patience sort + binary search (O(n log n)) O(n log n) / O(n)

Reach for this when n can be 10^5+ and O(n²) is too slow, or when the interviewer explicitly asks for the most efficient solution. The insight is maintaining a tails array where tails[k] is the smallest possible tail of any length-(k+1) increasing subsequence seen so far. IMPORTANT: tails is NOT the actual LIS — only its length matters.

function lengthOfLIS(nums) {
  if (nums.length === 0) return 0;
  // tails[k] = smallest tail element of all length-(k+1) increasing subsequences seen so far.
  // tails stays sorted, enabling binary search.
  const tails = [];
  for (const x of nums) {
    // Binary search for the first tail >= x (lower bound).
    let lo = 0, hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    // lo is the index to update: either extend tails (new longest LIS) or replace (keep tails optimal).
    tails[lo] = x;
  }
  // The length of tails is the LIS length.
  return tails.length;
}
console.log(lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18]));
  • tails is always sorted, so binary search (lo/hi halving) finds the insertion point in O(log n) per element.
  • Replacing tails[lo] = x never changes the tails length unless lo === tails.length (a new longest extension) — either way tails[lo] becomes the best (smallest) tail for subsequences of that length.
  • tails is NOT the actual LIS: e.g. for [3,1,2] tails becomes [1,2] but the LIS is [1,2] or [3] — the array can be 'fictitious'. Only tails.length is the answer.

Q1 What does dp[i] represent in the O(n²) solution?

  1. A LIS length over the whole array up to i
  2. B LIS length ending exactly at index i correct
  3. C Number of strictly increasing pairs
  4. D Count of elements smaller than nums[i]

Why: The inner loop only extends from a j < i where nums[j] < nums[i], so nums[i] is pinned as the LAST element of the subsequence dp[i] measures. That is exactly why the answer is Math.max(...dp) and not dp[n-1].

Q2 Why initialize every dp[i] to 1?

  1. A So dp[i] = Math.max(dp[i], dp[j] + 1) resolves to at least 2 when an extension fires, encoding 'self + one predecessor'
  2. B Each single element is itself an increasing subsequence of length 1 correct
  3. C Because elements with no smaller predecessor would otherwise stay at 0 and break Math.max(...dp) on all-decreasing inputs
  4. D Because dp[i] is later treated as an INDEX into nums, and 0 would alias the first element

Why: The element on its own is already a valid increasing subsequence, so 1 is the floor before any extension fires. On a fully decreasing input no dp[j] + 1 ever applies, every cell stays 1, and Math.max(...dp) correctly returns 1.

Q3 Time complexity of the standard DP?

  1. A O(n)
  2. B O(n log n)
  3. C O(n^2) correct
  4. D O(n^3)

Why: Two nested loops where the inner one rescans every j < i — about n²/2 comparisons. O(n log n) is reachable, but only by replacing that inner scan (see the tails-array question).

Q4 Which technique reduces LIS to O(n log n)?

  1. A Memoization alone
  2. B Divide and conquer
  3. C Patience sorting with binary search on a tails array correct
  4. D Hash map of seen values

Why: Keep a tails array where tails[k] is the smallest possible tail of an increasing subsequence of length k+1; it stays sorted, so each element is placed by binary search and the O(n) inner scan becomes O(log n). The answer is tails.length — the array itself is not necessarily a real subsequence.

Hints
  • Guard nums.length === 0 first — Math.max(...[]) is -Infinity.
  • dp[i] = LIS that ENDS at index i.
  • For each i, look back at every j < i with nums[j] < nums[i] and take dp[j] + 1.
function lengthOfLIS(nums) {
  if (nums.length === 0) return 0;       // Math.max(...[]) is -Infinity — guard it
  // dp[i] = LIS length that ENDS at i. Every element alone is a length-1 subseq.
  const dp = new Array(nums.length).fill(1);
  for (let i = 1; i < nums.length; i++) {
    // Scan every j < i; extend if nums[j] < nums[i] (strictly increasing).
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
    }
  }
  // Answer is max over ALL ending positions, not dp[n-1].
  return Math.max(...dp);
}
