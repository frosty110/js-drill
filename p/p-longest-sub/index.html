Longest substring

Sliding window with a Set: expand the right edge, shrink the left while a duplicate sits in the window. O(n) time.

patterns Sliding Window 8 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write lengthOfLongestSubstring(s) returning the length of the longest substring without repeating chars. Log lengthOfLongestSubstring("pwwkew").

Expected output: 3

Canonical solution

Variable sliding window + Set of the window's chars · O(n) / O(min(n,|α|)) (time / space)

function lengthOfLongestSubstring(s) {
  const seen = new Set();              // chars currently in the window
  let l = 0, best = 0;
  // Expand right edge; shrink left while the new char duplicates one already in the window.
  for (let r = 0; r < s.length; r++) {
    while (seen.has(s[r])) {
      seen.delete(s[l]);   // shrink from the left
      l++;
    }
    seen.add(s[r]);
    // Window length is r - l + 1 (inclusive on both ends).
    best = Math.max(best, r - l + 1);
  }
  return best;
}
// Time O(n) — each char is added and removed at most once
// Space O(min(n, |alphabet|))
  • Window is the substring s[l..r] inclusive — its length is r - l + 1.
  • Shrink with a while loop so the template generalizes to count-based windows.
  • Delete s[l] BEFORE incrementing l — otherwise you delete the wrong char.

Alternate approaches

Index map (jump l directly) O(n) / O(min(n,|α|))

Reach for this when you want l to jump straight past the duplicate in one step instead of shrinking one character at a time. Slightly harder to reason about (the max guard is easy to forget), but avoids the inner while loop and is often the variant interviewers expect if they say 'can you do it without a nested loop?'

function lengthOfLongestSubstring(s) {
  const lastSeen = new Map();  // char → most recent index
  let l = 0, best = 0;
  for (let r = 0; r < s.length; r++) {
    const c = s[r];
    // If c was seen inside the current window, jump l past it.
    // max(l, ...) prevents l from moving backward when lastSeen is stale (left of l).
    if (lastSeen.has(c) && lastSeen.get(c) >= l) {
      l = lastSeen.get(c) + 1;
    }
    lastSeen.set(c, r);
    best = Math.max(best, r - l + 1);
  }
  return best;
}
console.log(lengthOfLongestSubstring("pwwkew"));
  • Map stores index, not a boolean — that's what enables the O(1) jump.
  • max(l, lastSeen.get(c) + 1) is load-bearing: without it, a stale entry (char last seen before l) would pull l backward and re-admit characters already outside the window.
  • Same O(n) / O(min(n,|alphabet|)) as the Set version; the constant factor differs but the class is identical.

Q1 Window length expression for indices l..r inclusive?

  1. A r - l
  2. B r - l + 1 correct
  3. C r - l - 1
  4. D r + l

Why: Both ends are inside the window, so it spans r - l + 1 characters. r - l counts the gaps between them, which undercounts by one — at l === r it would report 0 for a window holding one char.

Q2 Why a Set rather than a count Map?

  1. A Set.has is O(1) while Map.get is O(log n) due to internal tree storage
  2. B We only need membership (in the window) — uniqueness is implicit correct
  3. C Maps can't be iterated in O(1), and the algorithm iterates the window each step
  4. D Sets handle the shrink step automatically — deleting from a Map would require checking count first

Why: The window is never allowed a second copy of a char, so a count could only ever be 0 or 1 — has and delete carry all the information. Min Window Substring is where counts start mattering, because there t can demand two A's.

Q3 Overall time complexity?

  1. A O(n^2)
  2. B O(n log n)
  3. C O(n) — each char enters and leaves the window once correct
  4. D O(1)

Why: The inner while looks like a nested loop, but l never moves backward — across the whole run the two pointers make at most 2n moves combined, so the shrink work is amortized rather than multiplied.

Q4 When the right pointer sees a duplicate, you should:

  1. A Reset l to r
  2. B Shrink from the left until the duplicate is removed correct
  3. C Skip the right pointer forward
  4. D Return immediately

Why: The earlier copy of s[r] can sit anywhere inside the window, so you delete s[l] and advance until it's gone. Jumping l straight to r throws away still-valid chars in between — on "abac" that loses the b and returns 2 instead of 3.

Q5 In the Set-based version, why shrink with a while loop (deleting s[l] and l++) rather than a single l++?

  1. A A single l++ is faster
  2. B You must keep deleting from the left until the duplicate of s[r] is actually gone from the window, which can take more than one step correct
  3. C The while loop sorts the characters
  4. D A single l++ would use more memory

Why: The duplicate of s[r] can sit several positions inside the window, so you must delete and advance l repeatedly until it's removed before adding s[r].

Q6 The index-map variant stores each char's LAST seen index. On a duplicate it jumps l = max(l, lastSeen[c] + 1). Why the max with the current l?

  1. A To handle empty strings
  2. B A stale last-seen index could be left of l (already outside the window); max prevents l from moving backward correct
  3. C To make the code shorter
  4. D Because Math.max is required for indices

Why: If the duplicate's last-seen index is behind the current l, moving l there would re-expand the window and re-admit chars already removed — max(l, ...) keeps l monotonically forward.

Q7 What is the space complexity of the window?

  1. A O(1) always
  2. B O(n^2)
  3. C O(min(n, |charset|)) — bounded by the alphabet size or the string length correct
  4. D O(n log n)

Why: The Set/map can hold at most one entry per distinct character, so it's capped by the alphabet (e.g. 128 for ASCII) or by n, whichever is smaller.

Q8 Why is the overall time O(n) even though there's an inner while loop?

  1. A The while loop runs at most a constant number of times per outer step
  2. B Each character is added to the window once and removed once, so total left+right pointer moves are bounded by 2n correct
  3. C Because the string is short
  4. D The while loop never actually executes

Why: l only ever advances (never resets backward) and r advances once per step, so across the whole run each pointer moves at most n times — amortized O(n), not O(n^2).
