Maximum Product Subarray

Like Kadane's, but a negative number can flip the smallest (most-negative) product into the new maximum — so you must track BOTH the max and min ending at the current index.

Problem

Write maxProduct(nums) returning the maximum product of any contiguous non-empty subarray. Log results for [2,3,-2,4], [-2,0,-1], and [-2,3,-4].

Expected output: 6 0 24

Canonical solution

Two-track rolling Kadane (max & min scalars) · O(n) / O(1) (time / space)

function maxProduct(nums) {
  // Track BOTH max and min ending here — a min × negative flips into the new max.
  let maxHere = nums[0];
  let minHere = nums[0];
  let best   = nums[0];
  for (let i = 1; i < nums.length; i++) {
    const x = nums[i];
    // Multiplying by a negative swaps max and min — capture both candidates.
    const candMax = Math.max(x, maxHere * x, minHere * x);
    const candMin = Math.min(x, maxHere * x, minHere * x);
    maxHere = candMax;
    minHere = candMin;
    best = Math.max(best, maxHere);
  }
  return best;
}
// Time O(n), Space O(1)
  • A negative element flips min ↔ max, so a Kadane-style single-track DP fails here — you need both rails.
  • Compute new max and min from the SAME (old) maxHere/minHere — don't overwrite maxHere before computing minHere.
  • Including x alone in the max/min handles the reset case (e.g. when the previous product was zero or the wrong sign).

Alternate approaches

Explicit DP arrays (maxArr[] + minArr[]) O(n) / O(n)

Reach for this when the interviewer asks 'walk me through the DP recurrence' or wants to see the full table for didactic clarity. Same O(n) time but O(n) space — the two scalars become two arrays indexed by i, making each step's dependency on i-1 explicit at the cost of memory. Useful as a stepping stone: write this first, then optimize to the rolling-scalar version by noting only i-1 is ever read. Some interviewers prefer it because the same-source-before-assign trap disappears (each cell reads only from the prior cell).

function maxProduct(nums) {
  const n = nums.length;
  // maxArr[i] = best product of any subarray ending exactly at i.
  // minArr[i] = worst product of any subarray ending exactly at i.
  const maxArr = new Array(n);
  const minArr = new Array(n);
  maxArr[0] = minArr[0] = nums[0];
  let best = nums[0];
  for (let i = 1; i < n; i++) {
    const x = nums[i];
    // Each cell reads only from i-1 — no same-source-before-assign trap.
    maxArr[i] = Math.max(x, maxArr[i-1] * x, minArr[i-1] * x);
    minArr[i] = Math.min(x, maxArr[i-1] * x, minArr[i-1] * x);
    best = Math.max(best, maxArr[i]);
  }
  return best;
}
console.log(maxProduct([2, 3, -2, 4]));
console.log(maxProduct([-2, 0, -1]));
console.log(maxProduct([-2, 3, -4]));
  • Each row depends only on row i-1, which is the textbook signal that the array can be collapsed to two rolling scalars — that's the optimization back to the canonical.
  • No same-source-before-assign hazard here: maxArr[i] reads maxArr[i-1] (untouched), so the order of the max/min assignments doesn't matter.
  • Best teaching version of the recurrence: write this on the whiteboard first, then point at 'we only ever read i-1' to motivate the space-optimized scalars.

Q1 Why does Kadane's single-track DP (max only) fail for product subarray?

  1. A Kadane's reset-to-zero condition (drop the running sum when it goes negative) doesn't have a product equivalent
  2. B A negative element can flip the running min into the new max correct
  3. C Zeros in the array break the running max in a way that's irrecoverable without backtracking
  4. D Multiplication is not associative on floats, so the running product order matters and Kadane assumes associativity

Why: The most negative running product is one negative element away from being the largest. In [-2, 3, -4] the min rail holds -6 going into the last element, and -6 × -4 = 24 is the answer — a max-only track would have thrown that -6 away.

Q2 Why include x itself in the max/min of the three candidates?

  1. A It seeds Math.max so the three-arg form doesn't fall back to -Infinity on the first iteration
  2. B Handles the reset case — when the previous product is zero or the wrong sign, start fresh at x correct
  3. C It guarantees the answer is at least one element, satisfying the non-empty subarray constraint
  4. D It anchors the index — without x, the recurrence loses track of which position the running max ends at

Why: The best subarray ending at i may be x on its own. In [2, 3, -2, 4] the -2 step's two products are maxHere*x = -12 and minHere*x = -6 — both worse than -2 itself, so the bare x is what restarts the max rail instead of dragging a negative product forward. After a zero the products are both 0, and only x can revive the rails.

Q3 What is the space complexity of the optimal solution?

  1. A O(n)
  2. B O(log n)
  3. C O(1) correct
  4. D O(n^2)

Why: Three scalars carry the whole state — maxHere, minHere and best. No dp array is ever allocated, so nothing scales with nums.length.

Q4 Why must you compute candMax and candMin from the SAME maxHere/minHere before assigning?

  1. A Otherwise Math.max and Math.min would each get called twice on the same arg, doubling the comparator cost
  2. B If you overwrite maxHere first, candMin sees the new value and computes the wrong product correct
  3. C Because const re-binding inside the loop body would throw in strict mode if the order is swapped
  4. D Because the cand variables are hoisted into the outer scope, so a swap captures stale references

Why: Both new candidates depend on the OLD pair. Overwriting one early corrupts the other.
