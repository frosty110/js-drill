Maximum Subarray (Kadane's)

Find the max sum of any contiguous subarray. Kadane's: at each index, either extend the running sum or restart from the current value.

Results carried by this link

Problem

Write maxSubArray(nums) returning the max sum of any contiguous subarray. Log maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4]).

Expected output: 6

Canonical solution

Kadane's — running sum with restart · O(n) / O(1) (time / space)

function maxSubArray(nums) {
  // Seed both with nums[0] — handles all-negative arrays (return the largest).
  let cur = nums[0], best = nums[0];
  for (let i = 1; i < nums.length; i++) {
    cur = Math.max(nums[i], cur + nums[i]);   // extend or restart
    // Track best separately — cur can fall after a peak.
    best = Math.max(best, cur);
  }
  return best;
}
// Time O(n), Space O(1)
  • Initialize cur AND best to nums[0] — handles all-negative arrays correctly.
  • cur = max(nums[i], cur + nums[i]) is the heart: drop the prefix when it hurts.
  • Best is the max over all cur values seen, not the final cur.

Alternate approaches

Divide and conquer O(n log n) / O(log n)

Reach for this when the interviewer asks for a recursive solution or wants to see an O(n log n) approach. Also a good teaching step in the O(n³) → O(n²) → O(n log n) → O(n) complexity ladder that shows HOW Kadane wins.

function maxSubArray(nums) {
  function helper(lo, hi) {
    if (lo === hi) return nums[lo];
    const mid = (lo + hi) >> 1;
    const leftMax = helper(lo, mid);
    const rightMax = helper(mid + 1, hi);
    // Max crossing subarray: expand from mid outward on each side
    let leftCross = -Infinity, sum = 0;
    for (let i = mid; i >= lo; i--) { sum += nums[i]; leftCross = Math.max(leftCross, sum); }
    let rightCross = -Infinity; sum = 0;
    for (let i = mid + 1; i <= hi; i++) { sum += nums[i]; rightCross = Math.max(rightCross, sum); }
    return Math.max(leftMax, rightMax, leftCross + rightCross);
  }
  return helper(0, nums.length - 1);
}
console.log(maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4]));
  • The max subarray is entirely in the left half, entirely in the right half, or crosses the midpoint — those three cases are exhaustive.
  • Cross-boundary sum: scan outward from mid on each side independently, taking the best prefix on each side.
  • T(n) = 2T(n/2) + O(n) solves to O(n log n) by Master Theorem; O(log n) stack space.

Brute force (prefix sums) O(n²) / O(n)

Name this before Kadane to show the O(n²) stepping stone. Using a prefix-sum array makes every subarray sum an O(1) lookup, bringing naive all-pairs from O(n³) to O(n²). Interviewers rarely want you to code this, but naming it earns the optimization.

function maxSubArray(nums) {
  const n = nums.length;
  const prefix = new Array(n + 1).fill(0);
  for (let i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
  let best = -Infinity;
  for (let i = 0; i < n; i++) {
    for (let j = i; j < n; j++) {
      const sum = prefix[j + 1] - prefix[i];
      best = Math.max(best, sum);
    }
  }
  return best;
}
console.log(maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4]));
  • prefix[j+1] - prefix[i] gives the sum of nums[i..j] in O(1) — removes the inner summation loop.
  • Still O(n²) pairs to check; Kadane avoids them by observing only the BEST end at i-1 matters.
  • Handles all-negative correctly since best starts at -Infinity, not 0.

Q1 Why initialize both cur and best to nums[0] instead of 0?

  1. A Initializing to 0 would make the first iteration's cur + nums[i] lose nums[0] from the window
  2. B So all-negative arrays return the largest (least negative) element correct
  3. C Because the loop starts at i=1, and any zero-init would leave best stale through the first iteration
  4. D Because Math.max(0, nums[0]) would clamp negative values to 0, distorting the running max

Why: A 0 seed lets best report an empty subarray, so [-3,-1,-2] would return 0 instead of -1; starting both at nums[0] forces a non-empty answer.

Q2 The core recurrence cur = max(nums[i], cur + nums[i]) means:

  1. A Always extend the running sum — take cur + nums[i] unconditionally
  2. B Either extend the running sum or start a new subarray at i correct
  3. C Pick the larger of the current element and the previous element
  4. D Take the max of nums[i] and the global best so far

Why: The two branches are 'extend the run ending at i-1' versus 'drop the prefix and start fresh at nums[i]' — whichever is larger wins.

Q3 Time complexity?

  1. A O(n^2)
  2. B O(n log n)
  3. C O(n) correct
  4. D O(n * average-subarray-length)

Why: One pass over two scalars, no nested loop; the O(n^2) option is the brute force that re-sums every start/end pair.

Q4 Why track best separately instead of returning cur?

  1. A Because cur may not be defined after the loop if nums.length === 1
  2. B cur can drop after hitting a peak; best holds the running maximum correct
  3. C Because returning cur would only give the sum of the final subarray, ignoring earlier subarrays of different starts
  4. D Because cur accumulates floating-point error over the loop and best is the integer-clamped checkpoint

Why: After a peak, a string of negatives makes cur fall. best preserves the max seen.

Q5 Precisely, what does cur represent at index i?

  1. A The total sum of the whole array up to i
  2. B The maximum sum of a subarray that ENDS exactly at index i correct
  3. C The largest single element seen so far
  4. D The number of restarts

Why: cur is the best subarray ending at i; the recurrence cur = max(nums[i], cur + nums[i]) is its definition, and best is the max over all such cur.

Q6 Why is restarting (dropping the prefix) the right greedy move when the running sum goes negative?

  1. A Dropping the prefix re-aligns the subarray with the next local maximum, which is always near the next positive value
  2. B A negative prefix can only DECREASE any future subarray that includes it, so discarding it never loses a better answer correct
  3. C Restarting frees the DP table entries for that prefix, reducing space to O(1)
  4. D Because the prefix's sum has already been recorded in best, restarting avoids double-counting it

Why: If cur + nums[i] < nums[i], the carried prefix is a net drag, so nums[i] alone starts a strictly better window — the local choice is provably globally safe.

Q7 On an ALL-NEGATIVE array like [-3,-1,-2], what must Kadane's return, and what makes it work?

  1. A 0, because no positive subarray exists
  2. B The largest (least-negative) element, -1 — achieved by seeding cur AND best with nums[0], not 0 correct
  3. C The sum of all elements, -6
  4. D It throws an error

Why: The non-empty constraint means the answer is the max single element; initializing to nums[0] (not 0) prevents returning a spurious 0.

Q8 If you initialized cur = 0, best = 0 instead of nums[0], which input would give a WRONG answer?

  1. A [1,2,3] — all positive
  2. B [-3,-1,-2] — all negative; it would return 0 instead of -1, implying an empty subarray correct
  3. C [5] — single element
  4. D [0,0,0] — all zeros

Why: With a 0 seed an all-negative array yields 0 (an empty subarray), violating the non-empty rule; nums[0] seeding fixes it.

Q9 Kadane's is a 1D DP collapsed to O(1) space. What is the DP relationship being exploited?

  1. A Each state depends on all previous states
  2. B The state at i depends only on the state at i-1 (cur[i] = max(nums[i], cur[i-1] + nums[i])), so one rolling variable suffices correct
  3. C It needs a 2D table
  4. D There is no DP involved

Why: Because cur[i] needs only cur[i-1], the whole DP table collapses to a single scalar — the same trick as House Robber and Climbing Stairs.

function maxSubArray(nums) {
