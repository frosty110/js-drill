Find Median from Data Stream

Two heaps: a max-heap for the lower half and a min-heap for the upper half, kept balanced. addNum O(log n), findMedian O(1).

Problem

Implement MedianFinder with addNum(n) and findMedian(). Use two inline heaps (max-heap for the lower half, min-heap for the upper half). After adding 1,2,3,4 with a findMedian after each pair, log the running medians.

Expected output: 1.5 2 2.5

Canonical solution

// Two heaps split the stream so the median is always at one of the roots.
// MaxHeap: lower half, root = largest of the smalls
// MinHeap: upper half, root = smallest of the bigs
class MedianFinder {
  constructor() {
    this.lo = new MaxHeap();
    this.hi = new MinHeap();
  }
  addNum(n) {
    // Route to lower half if it fits there; otherwise to upper.
    if (this.lo.size() === 0 || n <= this.lo.peek()) this.lo.push(n);
    else this.hi.push(n);
    // Rebalance: lo may exceed hi by 1 (odd count); never by 2, and hi never exceeds lo.
    if (this.lo.size() > this.hi.size() + 1) this.hi.push(this.lo.pop());
    else if (this.hi.size() > this.lo.size()) this.lo.push(this.hi.pop());
  }
  findMedian() {
    // Odd total → lo holds the middle; even → average the two roots.
    if (this.lo.size() > this.hi.size()) return this.lo.peek();
    return (this.lo.peek() + this.hi.peek()) / 2;
  }
}
// Time addNum O(log n), findMedian O(1); Space O(n)
  • Invariant: every value in lo is <= every value in hi, and lo.size() - hi.size() is 0 or 1.
  • Route incoming n by comparing to lo.peek(); then rebalance by transferring at most one element.
  • If total count is odd, lo holds the extra and lo.peek() is the median. If even, average the two roots.

Alternate approaches

Sorted array (binary-search insert) O(n) add / O(1) median / O(n) space

Use when addNum is called rarely but findMedian is called constantly — the sorted invariant gives O(1) median reads. The O(n) splice cost is only paid on insert, not on every findMedian call. Also a good starting point in an interview before presenting the heap optimization.

class MedianFinder {
  constructor() { this.sorted = []; }
  addNum(n) {
    // Binary search for the insert position, then splice in.
    let lo = 0, hi = this.sorted.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (this.sorted[mid] < n) lo = mid + 1;
      else hi = mid;
    }
    this.sorted.splice(lo, 0, n); // O(n) shift
  }
  findMedian() {
    const n = this.sorted.length;
    const mid = n >> 1;
    if (n % 2 === 1) return this.sorted[mid];
    return (this.sorted[mid - 1] + this.sorted[mid]) / 2;
  }
}

  • Binary search finds the index in O(log n) but splice must shift all subsequent elements — the insert is O(n) even with the fast lookup.
  • findMedian is O(1): just index into the middle of the sorted array (two reads for even count).
  • This is the natural 'step 2' answer — start here to show you understand the problem, then motivate two-heaps as the O(log n) add upgrade.

Q1 Why use a MAX-heap for the lower half and a MIN-heap for the upper half?

  1. A So both heaps share the same comparator, allowing the rebalance step to swap roots without a sign flip
  2. B So the two heap roots are the median candidates correct
  3. C A max-heap on the upper half would route incoming values incorrectly because hi.peek() would be the maximum, not the minimum
  4. D Inverting the types lets lo.size - hi.size stay non-negative without an explicit rebalance

Q2 addNum time complexity?

  1. A O(1)
  2. B O(log n) correct
  3. C O(n)
  4. D O(n log n)

Q3 findMedian time complexity?

  1. A O(1) correct
  2. B O(log n)
  3. C O(n)
  4. D O(n log n)

Q4 When the two heaps have equal size, the median is:

  1. A lo.peek() — by the convention that lo holds the lower-or-equal half
  2. B hi.peek() — the smaller of the two valid medians for an even count
  3. C Average of lo.peek() and hi.peek() correct
  4. D Either peek — they are equal whenever the heaps are balanced

class MinHeap {
  constructor() { this.h = []; }
  size() { return this.h.length; }
  peek() { return this.h[0]; }
  push(v) {
    this.h.push(v);
    let i = this.h.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.h[p] <= this.h[i]) break;
      [this.h[p], this.h[i]] = [this.h[i], this.h[p]];
      i = p;
    }
  }
  pop() {
    const top = this.h[0];
    const last = this.h.pop();
    if (this.h.length) {
      this.h[0] = last;
      let i = 0, n = this.h.length;
      while (true) {
        const l = 2*i+1, r = 2*i+2;
        let s = i;
        if (l < n && this.h[l] < this.h[s]) s = l;
        if (r < n && this.h[r] < this.h[s]) s = r;
        if (s === i) break;
        [this.h[s], this.h[i]] = [this.h[i], this.h[s]];
        i = s;
      }
    }
    return top;
  }
}
