Implement Min-Heap

Array-as-binary-heap with siftUp on push and siftDown on pop — the real priority-queue primitive behind heapsort, Dijkstra, and Top-K.

Problem

Implement a MinHeap class with push, pop, peek, and size. Push 5,3,8,1,9,2 then pop everything into an array and log JSON.stringify of it.

Expected output: [1,2,3,5,8,9]

Canonical solution

Array-as-complete-tree heap with siftUp/siftDown · O(log n) / O(n) (time / space)

class MinHeap {
  constructor() { this.a = []; }
  size() { return this.a.length; }
  peek() { return this.a[0]; }
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    // siftUp: parent = (i-1)>>1; swap while parent is larger.
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    // Save root; move LAST to index 0 to keep the array (and tree) contiguous.
    const a = this.a, top = a[0], last = a.pop();
    if (!a.length) return top;
    a[0] = last;
    let i = 0;
    // siftDown: swap with the SMALLER child while it is smaller than current.
    while (true) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let s = i;
      if (l < a.length && a[l] < a[s]) s = l;
      if (r < a.length && a[r] < a[s]) s = r;
      // No smaller child — heap property restored, done.
      if (s === i) return top;
      [a[s], a[i]] = [a[i], a[s]];
      i = s;
    }
  }
}
// Time O(log n) per push/pop, Space O(n)
  • Index math: parent = (i-1) >> 1, left = 2*i+1, right = 2*i+2.
  • Push: append at the end, then siftUp — swap with parent while parent is larger.
  • Pop: save root, move last element to index 0, then siftDown — swap with the SMALLER child while it is smaller.
  • Always swap with the smaller child on siftDown — swapping with the larger one would violate the heap property.

Alternate approaches

Bottom-up heapify constructor (Floyd's O(n) build) O(n) build / O(n)

Reach for this when the interviewer hands you an existing array and asks you to heapify it in place — pushing n items one-by-one is O(n log n), but Floyd's bottom-up siftDown builds the heap in O(n). The intuition: most nodes are near the bottom (n/2 leaves need no work; the next level needs at most 1 swap each), so the total work telescopes to O(n) by the standard sum Σ(h · n/2^(h+1)) = 2n.

class MinHeap {
  constructor(arr = []) {
    this.a = arr.slice();                              // copy — do not mutate caller's array
    // Floyd's heapify: siftDown from the last internal node up to the root.
    // Last internal node is at index (n>>1)-1; everything past it is a leaf (already a valid 1-node heap).
    for (let i = (this.a.length >> 1) - 1; i >= 0; i--) {
      this._siftDown(i);
    }
  }
  size() { return this.a.length; }
  peek() { return this.a[0]; }
  push(x) {
    const a = this.a;
    a.push(x);
    let i = a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (a[p] <= a[i]) break;
      [a[p], a[i]] = [a[i], a[p]];
      i = p;
    }
  }
  pop() {
    const a = this.a, top = a[0], last = a.pop();
    if (!a.length) return top;
    a[0] = last;
    this._siftDown(0);
    return top;
  }
  _siftDown(i) {
    const a = this.a;
    while (true) {
      const l = 2 * i + 1, r = 2 * i + 2;
      let s = i;
      if (l < a.length && a[l] < a[s]) s = l;
      if (r < a.length && a[r] < a[s]) s = r;
      if (s === i) return;
      [a[s], a[i]] = [a[i], a[s]];
      i = s;
    }
  }
}
// Build the heap in O(n) from the input array — no per-element siftUp.
const h = new MinHeap([5, 3, 8, 1, 9, 2]);
const out = [];
while (h.size()) out.push(h.pop());
console.log(JSON.stringify(out));
  • Start siftDown from index (n>>1) - 1 — the last internal node. Indices past that are leaves: a single-node subtree is already a valid heap, so they need no work.
  • The O(n) bound is non-obvious: it's NOT n/2 · log n. Most nodes are near the bottom (cheap to sift), and the sum Σ(h · n/2^(h+1)) collapses to 2n by the geometric-series identity.
  • Push and pop still cost O(log n) — bottom-up heapify only speeds up the INITIAL build from a known array, not subsequent operations.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Given index i, the parent index is:

  1. A i / 2
  2. B (i - 1) >> 1 correct
  3. C i - 1
  4. D 2 * i

Why: Children sit at 2*i+1 and 2*i+2, so the inverse is (i - 1) halved and floored — >> 1 does the floor for free, and indices 3 and 4 both map back to parent 1 (plain i / 2 would give 1.5).

Q2 On siftDown, which child do you swap with when both children are smaller than the node?

  1. A The left child always
  2. B The right child always
  3. C The smaller of the two children correct
  4. D Either — it does not matter

Why: Swapping with the larger child would leave the smaller child violating the heap property under it.

Q3 Time complexity of push and pop?

  1. A O(1)
  2. B O(log n) correct
  3. C O(n)
  4. D O(n log n)

Why: Both walk exactly one root-to-leaf path — siftUp on push, siftDown on pop — and a complete binary tree of n nodes has height ⌊log₂ n⌋. Only peek and size are O(1).

Q4 Why move the LAST element to index 0 before siftDown on pop?

  1. A The last element is guaranteed to be the second-smallest, so it is the cheapest replacement for the root
  2. B It keeps the underlying array contiguous so the tree shape stays complete correct
  3. C It promotes the deepest leaf, which is closest to becoming the new root after siftDown
  4. D siftDown only restores order downward — without seeding index 0 from the tail, the loop has no starting node

Why: Removing the root leaves a hole, and only the tail can be spliced off without punching a gap in the array — moving last to index 0 keeps the tree complete, and siftDown then repairs the order invariant.
