Min Window Substring

Smallest substring of s containing every char of t (with multiplicities). Sliding window with need-Map + have/required counter. O(|s| + |t|).

Problem

Write minWindow(s, t) returning the smallest substring of s containing every char of t (with multiplicities), or "" if impossible. Log minWindow("ADOBECODEBANC","ABC") then JSON.stringify(minWindow("a","aa")).

Expected output: BANC ""

Canonical solution

Variable sliding window + have/required counter · O(|s| + |t|) / O(|s| + |t|) (time / space)

function minWindow(s, t) {
  if (t.length === 0 || s.length < t.length) return "";
  // need[c] = required count of c in any valid window.
  const need = new Map();
  for (const c of t) need.set(c, (need.get(c) || 0) + 1);
  // have = DISTINCT chars whose window count has hit their need quota. required = distinct chars in t.
  const required = need.size;
  const window = new Map();
  let have = 0, l = 0, bestL = 0, bestLen = Infinity;
  for (let r = 0; r < s.length; r++) {
    const c = s[r];
    window.set(c, (window.get(c) || 0) + 1);
    // === (not >=): going past the quota mustn't bump have again.
    if (need.has(c) && window.get(c) === need.get(c)) have++;
    // Window satisfies t — shrink from left while it still does, recording the best.
    while (have === required) {
      if (r - l + 1 < bestLen) { bestLen = r - l + 1; bestL = l; }
      const lc = s[l];
      window.set(lc, window.get(lc) - 1);
      // Only decrement have when we drop BELOW the quota (excess removals don't break the window).
      if (need.has(lc) && window.get(lc) < need.get(lc)) have--;
      l++;
    }
  }
  return bestLen === Infinity ? "" : s.slice(bestL, bestL + bestLen);
}
// Time O(|s| + |t|), Space O(|s| + |t|)
  • have counts DISTINCT chars whose window count reached the need count — not total chars. required = need.size.
  • Only increment have when window[c] hits need[c] EXACTLY (===). Going above does not change have.
  • Decrement have when window[lc] drops BELOW need[lc] after shrinking — only then has the window stopped satisfying t.

Alternate approaches

Need-map covers check (no have counter) O(|s|·|t|) / O(|s| + |t|)

Reach for this when the interviewer says 'just write something correct, we'll optimize after' or when the alphabet is small enough that the per-step factor doesn't matter. The validity test inlines as 'does the window's count for every needed char meet its quota?' — a small loop over need instead of a single integer compare. Same expand/shrink skeleton, same shrink trigger, just an O(|need|) check per step instead of O(1). Reads more directly ('window covers t means every needed char is covered'), and removes the asymmetric === / < traps that the have/required version has.

function minWindow(s, t) {
  if (t.length === 0 || s.length < t.length) return "";
  const need = new Map();
  for (const c of t) need.set(c, (need.get(c) || 0) + 1);
  const window = new Map();
  // Window is valid iff every needed char has at least its required count.
  const covers = () => {
    for (const [c, n] of need) if ((window.get(c) || 0) < n) return false;
    return true;
  };
  let l = 0, bestL = 0, bestLen = Infinity;
  for (let r = 0; r < s.length; r++) {
    window.set(s[r], (window.get(s[r]) || 0) + 1);
    while (covers()) {
      if (r - l + 1 < bestLen) { bestLen = r - l + 1; bestL = l; }
      window.set(s[l], window.get(s[l]) - 1);
      l++;
    }
  }
  return bestLen === Infinity ? "" : s.slice(bestL, bestL + bestLen);
}
console.log(minWindow("ADOBECODEBANC", "ABC"));
console.log(JSON.stringify(minWindow("a", "aa")));
  • covers() rebuilds the validity decision every step — that's the per-step O(|need|) factor that pushes total time to O(|s|·|t|) in the worst case.
  • No asymmetric === / < traps: window counts can go arbitrarily above or below need, and covers() re-derives the answer each call.
  • Use this as the 'write it correct first' draft on a whiteboard, then sell the have/required optimization as 'we only need to recompute when a char crosses the quota boundary.'

Why: r grows the window until it covers t, then the inner while shrinks l as far as possible while still valid, capturing the minimum length at each valid moment.

  4. D Every time r advances

Why: Each valid window (have === required) is a candidate, so you compare r - l + 1 to bestLen before dropping s[l], capturing the leftmost-shortest window.

  3. C It becomes O(n^2)
  4. D The window never shrinks

Why: Multiplicities matter — t = "aa" needs two a's; a Set only tracks presence, so s = "a" would wrongly count as containing t.
