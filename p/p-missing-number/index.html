Missing Number

XOR every index 0..n with every value — paired numbers cancel and the missing one survives. O(n) time, O(1) space.

Results carried by this link

Problem

Write missingNumber(nums) where nums contains n distinct values from 0..n with exactly one missing. Use XOR over indices and values. Log it for [3,0,1], [0,1], and [9,6,4,2,3,5,7,0,1].

Expected output: 2 2 8

Canonical solution

XOR every index against every value · O(n) / O(1) (time / space)

function missingNumber(nums) {
  // Seed with n — the loop never visits index n, so include it on the index side of the XOR.
  let xor = nums.length;
  for (let i = 0; i < nums.length; i++) {
    // XOR every index and value: matched pairs cancel (a ^ a = 0), the missing value survives.
    xor ^= i ^ nums[i];
  }
  return xor;
}
// Time O(n), Space O(1)
  • Indices range 0..n-1, values are a permutation of 0..n with one missing — XOR both side ranges and pairs cancel.
  • Seed xor with n so the index n (never iterated) is included in the index side of the XOR.
  • Sum formula n*(n+1)/2 - sum(nums) also works but can overflow on huge inputs; XOR is overflow-free.

Alternate approaches

Gauss sum formula O(n) / O(1)

Use this when the XOR trick isn't top of mind — the expected sum of 0..n is n*(n+1)/2; subtract the actual array sum and the difference is the missing value. Same O(n) time, O(1) space, slightly more intuitive arithmetic. Caveat: can lose precision for very large n (above ~94 million) due to JS float representation.

function missingNumber(nums) {
  const n = nums.length;
  const expected = n * (n + 1) / 2;
  const actual = nums.reduce((s, v) => s + v, 0);
  return expected - actual;
}
console.log(missingNumber([3, 0, 1]));
console.log(missingNumber([0, 1]));
console.log(missingNumber([9, 6, 4, 2, 3, 5, 7, 0, 1]));
  • Expected sum n*(n+1)/2 minus actual sum leaves exactly the missing value.
  • Can overflow JS's safe integer range (~9×10^15) for n above ~134 million — XOR has no such risk.
  • Slightly more readable than XOR; both are O(n)/O(1) so pick based on what the interviewer emphasizes.

Q1 Why initialize xor to nums.length?

  1. A To prime the accumulator with a non-zero value so the first XOR doesn't degenerate
  2. B So index n is included — the loop only visits 0..n-1 correct
  3. C Because xor = 0 would make the loop produce the bitwise NOT of the missing value instead
  4. D So the accumulator's bit-width matches the largest possible value in nums

Why: The loop only produces indices 0..n−1, but the range being checked is 0..n. Seeding with nums.length supplies that final index n so every number in the range appears exactly once on the index side of the XOR.

Q2 Why does XOR work here?

  1. A The XOR of any permutation of 0..n is itself — nums is a permutation minus one value, so XOR-ing recovers that value
  2. B Every value present in the array also appears as an index — they cancel, leaving only the missing value correct
  3. C XOR is commutative, so the missing value bubbles to the end of the accumulator naturally
  4. D Indices XOR'd with their own values produce 0 only when no value is missing; the non-zero residue is the answer

Why: Each iteration folds in one index and one value, so across the whole loop every number 0..n shows up once as an index and — unless it is the missing one — once as a value. The matched pairs cancel to 0 and the unpaired number is what is left.

Q3 Edge case: nums = [0]. What is missing?

  1. A 0
  2. B 1 correct
  3. C -1
  4. D undefined (n=1 means the range is just {0}, which is fully covered)

Why: nums.length is 1, so the range is {0, 1} and the absent value is 1. Trace it: xor starts at 1, then 1 ^ 0 ^ 0 is still 1.

Q4 Advantage of XOR over the sum formula?

  1. A Fewer keystrokes and no need to compute n*(n+1)/2 at the start
  2. B No risk of integer overflow on huge n correct
  3. C Constant-factor speed: XOR is one CPU instruction whereas multiply+divide is several
  4. D It works even when the input contains duplicates — the sum formula does not

Why: n * (n + 1) / 2 can outgrow the exact-integer range (past 2^53 in JS, past a 32-bit int far sooner elsewhere) while XOR never produces a value wider than its operands. Both are O(n) time and O(1) space, so overflow is the actual differentiator.
