Number of 1 Bits (Hamming Weight)

Brian Kernighan: `n & (n - 1)` clears the lowest set bit. Loop until n is 0; each iteration counts one bit. O(set bits), not O(32).

Problem

Write hammingWeight(n) returning the number of 1-bits in n using Brian Kernighan's n & (n - 1) trick. Log it for 11, 128, and 2147483645.

Expected output: 3 1 30

Canonical solution

function hammingWeight(n) {
  let count = 0;
  while (n !== 0) {
    // Brian Kernighan: n & (n - 1) clears the lowest set bit — loops once per 1-bit, not per 32 bits.
    n = n & (n - 1);
    count++;
  }
  return count;
}
// Time O(k) where k = popcount(n), Space O(1)
  • n - 1 flips the lowest set bit AND every 0 below it; ANDing with n zeroes that lowest 1-bit and everything beneath.
  • Loops only k times (k = number of set bits), beating the naive for 32 bits scan when n is sparse.
  • Works on JS 32-bit ints. For unsigned semantics on values >= 2^31, coerce with n >>>= 0 first if needed.

Alternate approaches

Naive 32-bit scan (shift and mask) O(32) = O(1) / O(1)

Name this brute force before pitching Brian Kernighan — scanning all 32 positions with n >>> k & 1 is the first thing most candidates think of, and it's always O(32) regardless of how many bits are set. Use it when you need a simple, obviously-correct fallback.

function hammingWeight(n) {
  let count = 0;
  for (let k = 0; k < 32; k++) {
    if ((n >>> k) & 1) count++;
  }
  return count;
}
console.log(hammingWeight(11));
console.log(hammingWeight(128));
console.log(hammingWeight(2147483645));
  • Checks each of the 32 bit positions with (n >>> k) & 1 — always exactly 32 iterations.
  • Uses >>> (unsigned right shift) so the sign bit is treated as a data bit, not a fill bit.
  • Brian Kernighan's variant is faster for sparse bit patterns — it only loops once per set bit, skipping positions that are 0.
