Number of Provinces (Union-Find)

Count connected components in an n x n adjacency matrix using Union-Find with path compression. Each union of two distinct roots merges two components — start with n, subtract one per successful union.

Problem

Write findCircleNum(isConnected) returning the number of provinces using Union-Find with path compression. Log results for [[1,1,0],[1,1,0],[0,0,1]] and [[1,0,0],[0,1,0],[0,0,1]].

Expected output: 2 3

Canonical solution

Union-Find with path compression, counting down from n · O(n^2 α(n)) / O(n) (time / space)

function findCircleNum(isConnected) {
  const n = isConnected.length;
  // Union-Find init: parent[i] = i — every node starts as its own root (n singleton sets).
  const parent = Array.from({ length: n }, (_, i) => i);
  function find(x) {
    while (parent[x] !== x) {
      parent[x] = parent[parent[x]]; // path compression (halving)
      x = parent[x];
    }
    return x;
  }
  // n unconnected nodes = n provinces; each successful union drops it by 1.
  let count = n;
  // Symmetric matrix — upper triangle (j > i) avoids double-unioning each edge.
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {
      if (isConnected[i][j] === 1) {
        const ra = find(i), rb = find(j);
        // Only merge if roots differ — same root means already in one province.
        if (ra !== rb) {
          parent[ra] = rb;
          count--;
        }
      }
    }
  }
  return count;
}
// Time ~O(n^2 * α(n)), Space O(n)
  • The matrix is symmetric — only iterate j > i to avoid double-unions.
  • Decrement count only on a SUCCESSFUL union (different roots). Same root → already in one province.
  • Path compression (halving or full) keeps amortized union/find at near O(α(n)) — effectively constant.

Alternate approaches

DFS over adjacency matrix O(n²) / O(n)

Use DFS when you're more comfortable with the flood-fill pattern and want to reuse the same mental model as Number of Islands or Connected Components. Both approaches are O(n²) here because reading the matrix to discover neighbors costs O(n) per node regardless of algorithm.

function findCircleNum(isConnected) {
  const n = isConnected.length;
  const seen = new Array(n).fill(false);
  // Row i of the matrix is city i's neighbor list (j where isConnected[i][j] === 1).
  function dfs(i) {
    seen[i] = true;
    for (let j = 0; j < n; j++) {
      if (isConnected[i][j] === 1 && !seen[j]) dfs(j);
    }
  }
  let count = 0;
  for (let i = 0; i < n; i++) {
    if (!seen[i]) { count++; dfs(i); }
  }
  return count;
}
console.log(findCircleNum([[1, 1, 0], [1, 1, 0], [0, 0, 1]]));
console.log(findCircleNum([[1, 0, 0], [0, 1, 0], [0, 0, 1]]));
  • Each row of the matrix IS the adjacency list for that city — no separate build step needed.
  • DFS visits every cell in the matrix (O(n) per launched node × n nodes = O(n²)), identical to Union-Find's O(n²) loop.
  • Recursion depth can reach n; prefer Union-Find for very large n where stack overflow is a concern.

Q1 Why iterate j from i + 1 instead of 0?

  1. A To skip the diagonal — j == i would self-union a city with itself, corrupting the parent array
  2. B The matrix is symmetric; (i,j) and (j,i) are the same edge correct
  3. C Otherwise the count would over-decrement because each edge would trigger two distinct unions on different roots
  4. D Starting at i+1 ensures finds traverse only forward indices, keeping path compression monotonic

Why: isConnected[i][j] and isConnected[j][i] encode one undirected edge, so the lower triangle just re-unions an already-merged pair. It is a constant-factor saving, not a correctness fix — the repeat call finds the same root, so ra !== rb is false and count is untouched.

Q2 When do you decrement the province count?

  1. A On every isConnected[i][j] === 1
  2. B Only when find(i) and find(j) return different roots correct
  3. C Once per row, equal to the number of 1s above the diagonal in that row
  4. D Every time parent[i] is updated by path compression, since that means a new ancestor was found

Why: count starts at n and only a merge of two DISTINCT roots actually reduces the province tally. Decrementing on every isConnected[i][j] === 1 would run 6 times on a fully-connected 4x4 and return -2.

Q3 What does path compression do?

  1. A Guarantees rank-balanced merges between two roots
  2. B Flattens the tree so future finds run faster correct
  3. C Re-roots each tree at its deepest leaf so subsequent unions are bounded by tree diameter
  4. D Eliminates duplicate edges by collapsing parallel parent pointers into one

Why: parent[x] = parent[parent[x]] re-points each node to its grandparent as find walks up, halving the chain so later finds take fewer hops. It changes the shape of the tree, never which root is returned.

Q4 For the matrix [[1,1,0],[1,1,0],[0,0,1]] the answer is:

  1. A 1
  2. B 2 correct
  3. C 3
  4. D 0

Why: Rows 0 and 1 are connected; row 2 is alone — two provinces.
