Remove Nth Node From End

Remove the n-th node from the end in a single pass. Two pointers: fast moves n steps ahead, then both advance until fast hits null — slow lands on the node BEFORE the one to remove.

Problem

Write removeNthFromEnd(head, n) removing the n-th node from the end of a singly linked list in one pass. Use toList/toArr helpers and log JSON.stringify(toArr(removeNthFromEnd(toList([1, 2, 3, 4, 5]), 2))).

Expected output: [1,2,3,5]

Canonical solution

function removeNthFromEnd(head, n) {
  const dummy = { val: 0, next: head };           // dummy handles removing the head
  let fast = dummy, slow = dummy;
  for (let i = 0; i < n; i++) fast = fast.next;   // gap of n
  while (fast.next) { fast = fast.next; slow = slow.next; }
  slow.next = slow.next.next;                     // unlink
  return dummy.next;
}
// Time O(L), Space O(1)
  • The dummy lets you remove the original head without a special case.
  • Walk fast n steps first, then advance both until fast.next is null — slow ends up at the predecessor of the target.
  • Stop the second loop on fast.next (not fast) so slow lands one before the removal target.

Alternate approaches

Two-pass (count length, then walk) O(L) / O(1)

Reach for this when clarity matters more than a single-pass constraint, or when the interviewer hasn't asked for one-pass. It's easier to get right on a whiteboard because there's no gap-pointer math — just count, compute L−n, walk, unlink.

function removeNthFromEnd(head, n) {
  const dummy = { val: 0, next: head };
  // Pass 1: count the length.
  let len = 0, curr = head;
  while (curr) { len++; curr = curr.next; }
  // Walk L−n steps from dummy to reach the predecessor of the target.
  let steps = len - n;
  let prev = dummy;
  while (steps > 0) { prev = prev.next; steps--; }
  prev.next = prev.next.next;
  return dummy.next;
}
function toList(arr) { let d = { next: null }, c = d; for (const v of arr) { c.next = { val: v, next: null }; c = c.next; } return d.next; }
function toArr(h) { const o = []; while (h) { o.push(h.val); h = h.next; } return o; }
console.log(JSON.stringify(toArr(removeNthFromEnd(toList([1, 2, 3, 4, 5]), 2))));
  • Two passes, same O(L) time as the one-pass version — just 2× the constant, not asymptotically worse.
  • The dummy node is still needed for the same reason: removing the head (n = L) means steps = 0, so prev stays at dummy and dummy.next gets reassigned.
  • No gap-pointer math: len - n gives the 0-indexed position of the predecessor from the dummy.

Q1 Why introduce a dummy node?

  1. A So fast and slow can start one node apart, establishing the n-gap implicitly
  2. B So removing the head node is not a special case correct
  3. C To turn the singly-linked list into a doubly-linked one for backward traversal
  4. D Because slow.next.next would deref null without an extra leading node

Q2 After advancing fast n steps, why advance both until fast.next is null (not fast itself)?

  1. A Stopping on fast itself would skip the final node and leave slow one short of the predecessor
  2. B So slow lands on the node BEFORE the one to remove correct
  3. C while (fast) is fine — both conditions land slow on the same node
  4. D It prevents slow from walking past the tail and dereferencing null

Q3 Time complexity (L = list length)?

  1. A O(L^2)
  2. B O(L log L)
  3. C O(L) correct
  4. D O(n)

Q4 How is the actual unlink performed?

  1. A slow.next = null
  2. B slow = slow.next.next
  3. C slow.next = slow.next.next correct
  4. D fast.next = null

Why: Skip the target by routing slow.next past it.
