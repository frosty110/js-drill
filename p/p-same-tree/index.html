Same Tree

Two binary trees are identical iff their roots match in value AND their left and right subtrees are recursively identical. Straight structural recursion.

patterns Trees 8 concept · 2 fill-in · 1 drill

Problem

Write isSameTree(p, q) returning true iff two binary trees are structurally and value-equal. Log isSameTree(a, b) then isSameTree(a, c) where c differs in one node.

Expected output: true false

Canonical solution

function isSameTree(p, q) {
  if (!p && !q) return true;                       // both empty → identical
  if (!p || !q) return false;                      // one empty, one not → differ
  if (p.val !== q.val) return false;               // values differ
  return isSameTree(p.left, q.left)
      && isSameTree(p.right, q.right);
}
// Time O(n), Space O(h) for recursion stack
  • Three base cases in order: both null → true, exactly one null → false, values differ → false.
  • Short-circuit && so the right subtree isn't walked once the left disagrees.
  • Space is O(h), the height of the tree — O(n) worst case for a skewed tree, O(log n) for balanced.

Alternate approaches

Iterative paired queue (BFS) O(n) / O(w)

Reach for this when the trees could be adversarially deep (skewed to ~10k+ nodes in JS) and you want to avoid call-stack overflow. Applies identical base-case logic per pair; trades O(h) recursion for O(w) queue space.

function isSameTree(p, q) {
  const queue = [[p, q]];
  while (queue.length) {
    const [a, b] = queue.shift();
    if (!a && !b) continue;         // both null — this pair OK
    if (!a || !b) return false;     // one null, one not
    if (a.val !== b.val) return false;
    queue.push([a.left,  b.left]);
    queue.push([a.right, b.right]);
  }
  return true;
}
const a = { val: 1, left: { val: 2, left: null, right: null }, right: { val: 3, left: null, right: null } };
const b = { val: 1, left: { val: 2, left: null, right: null }, right: { val: 3, left: null, right: null } };
const c = { val: 1, left: { val: 2, left: null, right: null }, right: { val: 4, left: null, right: null } };
console.log(isSameTree(a, b));
console.log(isSameTree(a, c));
  • Queue holds PAIRS of corresponding nodes — the same three base-case checks apply per pair, just inside a loop instead of recursive calls.
  • Null pairs are a legitimate entry in the queue (both null → continue, one null → false) so you never need to guard before pushing children.
  • Space is O(w) where w is the max level width across both trees; for balanced trees that is ~n/2, potentially heavier than recursion's O(log n) average.

Q1 What is the correct base case when BOTH p and q are null?

  1. A Return false — there is nothing to compare
  2. B Return true — two empty subtrees are identical correct
  3. C Return true only if both parent nodes had the same value; otherwise false
  4. D Skip this pair and continue with the next recursive call without returning

Why: Two missing subtrees are trivially the same shape.

Q2 What if exactly one of p or q is null?

  1. A Treat the missing node as a fresh node with the same val as its sibling and continue
  2. B Return true
  3. C Return false — the structures differ correct
  4. D Recurse on the non-null one

Q3 If you check p.val !== q.val BEFORE the null checks, what bug occurs?

  1. A Same output, just slightly slower
  2. B Throws TypeError — p.val crashes when p is null correct
  3. C Returns wrong answer on identical trees
  4. D Always returns false

Why: p.val throws TypeError if p is null — must guard with both-null and one-null checks first. Order matters.

Q4 Why use && between the two recursive calls?

  1. A & would coerce the boolean returns to integers and break the recursion's truthiness
  2. B Both subtrees must match; && also short-circuits when the left disagrees correct
  3. C && evaluates the right recursion first, which matches the post-order semantics
  4. D Replacing it with , (comma operator) would evaluate only the right side and miss left mismatches

Q5 Trees p=[1,2] (left child only) and q=[1,null,2] (right child only) have the same in-order traversal [1,2]. Are they the same tree?

  1. A Yes — identical in-order means identical tree
  2. B No — same values but different structure; the exactly-one-null check catches the mismatch correct
  3. C Yes — values are all that matter
  4. D Cannot be determined

Why: Same-tree requires matching STRUCTURE plus values; comparing flattened in-order arrays misses shape differences, which is why parallel recursion is the correct approach.

Q6 Can you solve Same Tree iteratively, and how?

  1. A No — it must be recursive
  2. B Yes — a queue (or stack) of PAIRED (p-node, q-node) tuples; pop a pair, run the same base-case checks, push the children pairs correct
  3. C Yes, but only with a priority queue
  4. D Yes, by hashing both trees to strings — the only way

Why: The iterative form walks both trees in lockstep via a worklist of paired nodes, applying the identical base-case logic per pair.

Q7 Tightest time complexity, given early-exit on the first mismatch?

  1. A O(n^2)
  2. B O(min(n, m)) — you can't compare more pairs than the smaller tree has nodes (worst case still O(n) for identical trees) correct
  3. C O(log n)
  4. D O(1)

Why: Comparison stops at the first disagreement, bounded by the smaller tree; for two identical trees you must visit every node, so worst case is O(n).

Q8 Why must the both-null and one-null base cases come BEFORE recursing into children?

  1. A For readability only
  2. B Recursing into children of a null node would dereference null.left/null.right and throw correct
  3. C It changes the time complexity
  4. D Children must be sorted first

Why: The null guards stop the descent; without checking null first, the recursive call would access properties of a null node and crash.
