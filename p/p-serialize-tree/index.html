Serialize & Deserialize Binary Tree

Pre-order DFS with null markers makes serialization round-trippable: serialize emits a comma-separated stream, deserialize consumes it via a shared queue/index.

Problem

Implement serialize(root) and deserialize(s) using pre-order DFS with # null markers. Build a sample tree [1, 2, 3, null, null, 4, 5], round-trip it via serialize(deserialize(serialize(root))), and log the result.

Expected output: 1,2,#,#,3,4,#,#,5,#,#

Canonical solution

Pre-order DFS with # null markers + shared read index · O(n) / O(n) (time / space)

// Pre-order DFS, write "#" for null. Round-trips because null markers preserve shape.
function serialize(root) {
  const out = [];
  const dfs = (n) => {
    if (!n) { out.push("#"); return; }
    out.push(String(n.val));
    dfs(n.left);
    dfs(n.right);
  };
  dfs(root);
  return out.join(",");
}
function deserialize(s) {
  const toks = s.split(",");
  let i = 0;
  const dfs = () => {
    const t = toks[i++];
    if (t === "#") return null;
    return { val: Number(t), left: dfs(), right: dfs() };
  };
  return dfs();
}
// Time O(n) for both directions, Space O(n) for the token stream
  • Pre-order alone is ambiguous — you need explicit null markers (or BOTH pre + in-order) to recover the shape.
  • Deserialize must consume tokens IN ORDER via a shared index or shifted queue; recursing without state corrupts the stream.
  • Use String(val) on write and Number(tok) on read — splitting on comma turns numbers into strings.

Alternate approaches

Iterative serialize + queue-based deserialize O(n) / O(n)

Use when the tree could be adversarially deep (skewed ~10k+ nodes in JS) and you need to avoid call-stack overflow in both directions. Produces the same pre-order-with-null-markers format — just uses an explicit stack/queue instead of the call stack.

function serialize(root) {
  const out = [];
  // Iterative pre-order: push right before left so left is processed first.
  const stack = [root];
  while (stack.length) {
    const n = stack.pop();
    if (!n) { out.push("#"); continue; }
    out.push(String(n.val));
    stack.push(n.right); // right first so left is popped first
    stack.push(n.left);
  }
  return out.join(",");
}
function deserialize(s) {
  const toks = s.split(",");
  const queue = [...toks]; // shift from the front = consume in order
  function build() {
    const t = queue.shift();
    if (t === "#") return null;
    const node = { val: Number(t), left: null, right: null };
    node.left  = build();
    node.right = build();
    return node;
  }
  return build();
}
const root = {
  val: 1,
  left: { val: 2, left: null, right: null },
  right: {
    val: 3,
    left: { val: 4, left: null, right: null },
    right: { val: 5, left: null, right: null }
  }
};
console.log(serialize(deserialize(serialize(root))));
  • Serialize: push right before left onto the stack so left is popped and emitted first — this replicates pre-order (self, left, right) iteratively.
  • Deserialize: spread tokens into an array and shift() from the front; the consumption order is identical to the recursive shared-index approach.
  • Space for the serialize stack is O(h) — the call stack is replaced with an explicit one of the same depth. Deserialize copies all tokens into the queue (O(n)), same as the recursive version's token array.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why does pre-order with null markers uniquely identify a binary tree?

  1. A Because in-order alone is enough
  2. B Null markers record the absence of children, so the shape is reconstructable correct
  3. C Because pre-order on a binary tree is a permutation that the inverse traversal recovers in one pass
  4. D Because pre-order writes each node twice (once on entry, once on exit), which encodes the shape

Why: Every node declares BOTH child slots, # included, so the stream says where each subtree ends. Without markers the left-only tree [1,2] and the right-only tree [1,null,2] both emit 1,2 — same string, different trees.

Q2 What state must deserialize share across recursive calls?

  1. A The original tree
  2. B A position/index (or queue) into the token stream correct
  3. C Nothing — each call parses independently
  4. D The output array

Why: let i = 0 sits outside dfs, so every call consumes the NEXT token. Give each call its own index and they all re-read token 0 — the recursion never advances.

Q3 Time complexity of serialize on n nodes?

  1. A O(log n)
  2. B O(n) correct
  3. C O(n log n)
  4. D O(n^2)

Why: A binary tree of n nodes has exactly n+1 empty child slots, so the stream is 2n+1 tokens — one push each, then a single join.

Q4 Why convert tokens with Number() during deserialize?

  1. A JSON.parse on each token would work but is slower than Number()
  2. B split(",") yields strings; the val field should be numeric correct
  3. C Number() guards against the # marker by coercing it to NaN, which the caller checks
  4. D Without it, string vals would be compared by reference rather than value in later traversals

Why: Splitting on a comma gives string tokens. Without Number(), node.val would be the string "3", not 3.
