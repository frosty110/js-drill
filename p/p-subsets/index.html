Subsets

Backtracking: build every subset by deciding include-or-skip at each index. 2^n results.

patterns Backtracking 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write subsets(nums) returning every subset (including the empty set) via backtracking. Log JSON.stringify(subsets([1, 2, 3])).

Expected output: [[],[1],[1,2],[1,2,3],[1,3],[2],[2,3],[3]]

Canonical solution

Backtracking — record at every node, start-index floor · O(n·2^n) / O(n) (time / space)

function subsets(nums) {
  const res = [];
  function backtrack(start, path) {
    // Record at EVERY node — every prefix is a valid subset (no leaf base case).
    res.push([...path]);              // every node is a valid subset
    // Loop from `start`, not 0 — prevents revisiting earlier indices (no duplicates).
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);              // choose
      backtrack(i + 1, path);          // explore (i+1 prevents reuse)
      path.pop();                      // un-choose
    }
  }
  backtrack(0, []);
  return res;
}
// Time O(n * 2^n), Space O(n) recursion + output
  • Push a COPY ([...path]) — the same path array is mutated across recursive calls.
  • Use start (not 0) so each element is only considered once per branch.
  • Every recursion node is a valid subset — record before the loop, not at a base case.

Alternate approaches

Iterative cascading (BFS-style) O(n * 2^n) / O(n * 2^n)

Reach for this when the interviewer asks for an iterative solution or when you want to avoid recursion. Each pass doubles the result list by appending new subsets that include the current element. Very readable if you've seen it before, but harder to extend to Subsets II or Combination Sum.

function subsets(nums) {
  let res = [[]];
  for (const num of nums) {
    // For each existing subset, create a new one with `num` appended.
    const newSubs = res.map(sub => [...sub, num]);
    res = res.concat(newSubs);
  }
  return res;
}
const result = subsets([1, 2, 3]);
result.sort((a, b) => { for (let i = 0; i < Math.min(a.length, b.length); i++) { if (a[i] !== b[i]) return a[i] - b[i]; } return a.length - b.length; });
console.log(JSON.stringify(result));
  • Start with res=[[]] (just the empty set); each iteration doubles its length.
  • No recursion stack — max memory is O(n * 2^n) for the result itself.
  • Order differs from the recursive version — sort is needed to match canonical output.

Bitmask enumeration O(n * 2^n) / O(n * 2^n)

Reach for this when the interviewer wants you to frame subsets as binary strings, or when n is small (n ≤ 20) and you want the most direct mathematical mapping. Each integer 0..2^n-1 uniquely encodes one subset via its bit pattern.

function subsets(nums) {
  const n = nums.length;
  const res = [];
  for (let mask = 0; mask < (1 << n); mask++) {
    const sub = [];
    for (let i = 0; i < n; i++) {
      if (mask & (1 << i)) sub.push(nums[i]);  // bit i set → include nums[i]
    }
    res.push(sub);
  }
  return res;
}
const result = subsets([1, 2, 3]);
result.sort((a, b) => { for (let i = 0; i < Math.min(a.length, b.length); i++) { if (a[i] !== b[i]) return a[i] - b[i]; } return a.length - b.length; });
console.log(JSON.stringify(result));
  • Bit i of mask controls inclusion of nums[i] — 2^n masks cover all 2^n subsets.
  • Fails when n > 30 (integer overflow on 1 << n in JS); stick to backtracking for large n.
  • Elegant for interview whiteboard explanation but doesn't generalize to Subsets II or Combination Sum.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why does the inner loop start at start rather than 0?

  1. A Starting at 0 would re-enter the same recursion frame and stack-overflow on n≥2
  2. B To prevent revisiting earlier elements and producing duplicates correct
  3. C Starting at 0 would skip the empty subset because the snapshot fires after the loop
  4. D It synchronizes the loop counter with path.length so i === path.length is the snapshot trigger

Why: Looping from start and recursing with i + 1 together force every subset to ascend by index, so [1,2] is reachable and [2,1] is not — the same membership is never emitted in two orders.

Q2 Why push [...path] instead of path into res?

  1. A Spreading deduplicates the subset against entries already in res
  2. B Because path is mutated by later push/pop calls correct
  3. C Because path lives in the recursion's closure and goes out of scope when backtrack returns
  4. D Because nested arrays in res are auto-flattened unless wrapped in a spread

Why: path is one array mutated in place by every push/pop, so storing the reference would leave res holding aliases that are all empty once the recursion unwinds. The spread freezes a snapshot of the contents at that moment.

Q3 How many subsets does an array of length n produce?

  1. A n + 1 (including the empty subset)
  2. B n!
  3. C 2^n correct
  4. D C(n, n/2) — the middle binomial row

Why: Each element is an independent in-or-out decision, so the decision tree has 2^n nodes and the canonical records once per node. n! counts orderings — that is Permutations, not membership.

Q4 When is a partial path recorded as a result?

  1. A Only when path.length === nums.length
  2. B At every recursive call correct
  3. C Only when the loop body finishes (after all i ≥ start have been tried)
  4. D Only when start === nums.length (loop body never runs)

Why: res.push([...path]) sits at the top of backtrack, before the loop, so every node is recorded — every prefix is itself a valid subset. Permutations is the sibling that records only when path.length === nums.length; Subsets has no leaf base case at all.
