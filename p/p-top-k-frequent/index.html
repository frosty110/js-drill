Top K Frequent

Count frequencies in a Map, then keep the K most frequent. Sort + slice is the readable baseline; a size-K min-heap is the O(n log k) upgrade.

patterns Heap 9 concept · 1 fill-in · 1 drill

Results carried by this link

Problem

Write topKFrequent(nums, k) returning the K most-frequent values. Log JSON.stringify(topKFrequent([1, 1, 1, 2, 2, 3], 2)).

Expected output: [1,2]

Canonical solution

function topKFrequent(nums, k) {
  // Map preserves numeric keys without string coercion + iterates in insertion order.
  const count = new Map();
  // Single O(n) pass: bump existing count or seed with 1 via the `|| 0` fallback.
  for (const n of nums) count.set(n, (count.get(n) || 0) + 1);
  return [...count.entries()]
    // Descending by count — b[1] - a[1]; reverse operands for ascending.
    .sort((a, b) => b[1] - a[1])
    .slice(0, k)
    .map(([num]) => num);
}
// Time O(n log n) via sort, Space O(n)
// Optimal: O(n log k) with a size-K MIN-heap keyed by frequency.
  • Step 1 is always the same: build a frequency Map in one O(n) pass.
  • Sort DESCENDING by count: (a, b) => b[1] - a[1]. Reversing the operands gives ascending.
  • For O(n log k), push each entry into a min-heap of size K and pop when it overflows — keeps only the top K alive.
  • Bucket sort by frequency is the third option: O(n) overall, but uses O(n) extra buckets.

Alternate approaches

Size-k min-heap by frequency O(n log k) / O(n+k)

Reach for this when k << d (number of distinct values) and you want O(n log k) instead of O(n log n). Also the right answer for streaming input where n isn't known in advance — you can't pre-size a bucket array but you can always maintain a bounded heap.

function topKFrequent(nums, k) {
  const count = new Map();
  for (const n of nums) count.set(n, (count.get(n) || 0) + 1);
  // Min-heap keyed by frequency — root = entry with LOWEST count among keepers.
  const heap = [];  // [ [freq, num], ... ]
  const heapPush = (entry) => {
    heap.push(entry);
    let i = heap.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (heap[p][0] <= heap[i][0]) break;
      [heap[p], heap[i]] = [heap[i], heap[p]];
      i = p;
    }
  };
  const heapPop = () => {
    const top = heap[0];
    const last = heap.pop();
    if (heap.length) {
      heap[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1, r = 2 * i + 2;
        let s = i;
        if (l < heap.length && heap[l][0] < heap[s][0]) s = l;
        if (r < heap.length && heap[r][0] < heap[s][0]) s = r;
        if (s === i) break;
        [heap[s], heap[i]] = [heap[i], heap[s]];
        i = s;
      }
    }
    return top;
  };
  for (const entry of count.entries()) {
    heapPush(entry);
    if (heap.length > k) heapPop(); // evict the least-frequent keeper
  }
  // Pop all k entries (ascending freq), reverse for descending, project to nums.
  const result = [];
  while (heap.length) result.push(heapPop()[1]);
  return result.reverse();
}
console.log(JSON.stringify(topKFrequent([1, 1, 1, 2, 2, 3], 2)));
  • Heap is keyed by frequency (entry[0]); the root is always the entry with the LOWEST count among the k kept — anything with a lower count gets evicted.
  • After processing all entries, the heap holds exactly k entries and their order is arbitrary — the result array may differ from the sort-based approach for tied frequencies.
  • Memory stays O(k) for the heap itself (plus O(d) for the count Map); much better than bucket sort's O(n) when k is tiny.

Bucket sort by frequency O(n) / O(n)

Reach for this when the interviewer pushes past O(n log n) and asks for the asymptotic best — frequencies are bounded by n, so we can index buckets by count and skip comparison sorting entirely. Not viable for streaming input (no bound on n) but optimal when the full array is in hand.

function topKFrequent(nums, k) {
  // Step 1 is identical to every other approach — O(n) frequency Map.
  const count = new Map();
  for (const n of nums) count.set(n, (count.get(n) || 0) + 1);
  // buckets[f] = values that appeared exactly f times. Max frequency is nums.length.
  const buckets = Array.from({ length: nums.length + 1 }, () => []);
  for (const [num, freq] of count.entries()) buckets[freq].push(num);
  // Walk highest frequency down, collecting until we have k.
  const result = [];
  for (let f = buckets.length - 1; f >= 1 && result.length < k; f--) {
    for (const v of buckets[f]) {
      if (result.length === k) break;
      result.push(v);
    }
  }
  return result;
}
console.log(JSON.stringify(topKFrequent([1, 1, 1, 2, 2, 3], 2)));
  • Why linear: each value pays O(1) into the count Map and O(1) into one bucket; the descending walk visits each bucket once and stops at k.
  • Bucket length is nums.length + 1 because the maximum possible frequency is n (every element identical) and we need index n to exist.
  • Ties at the cutoff resolve by Map insertion order — values that hashed earlier appear earlier in their shared bucket; specify a tiebreaker if the contract demands one.

Why: Bucket sort is linear only when keys fall in a small known range; here a count cannot exceed n, so buckets[0..n] cover every possible frequency — no O(log) comparison sort required.

Q6 In the bucket-sort approach, what does buckets[f] hold?

  2. B The list of values that each appear exactly f times correct
  3. C The fth most frequent value
  4. D A count of how many buckets are used

Why: Index = frequency: buckets[f] collects every distinct value whose count equals f, so walking from high f down gathers the most frequent first.

Q7 To collect the answer from the buckets, you walk:

  1. A From buckets[0] upward until you have k values
  2. B From buckets[n] down toward buckets[1], collecting values until you have k correct
  3. C Only buckets[k]
  4. D In random order

Why: The most frequent values sit in the highest-index buckets, so you descend from buckets[n] and stop once k values are gathered.

Q8 When does the size-k min-heap beat bucket sort in practice?

  1. A Never — bucket sort always wins
  2. B In a stream of unbounded length where you cannot pre-size an n+1 bucket array, the heap maintains the top k online correct
  3. C When k equals the number of distinct values
  4. D When all counts are equal

Why: Bucket sort needs a bounded, known n to size the array; for an unbounded stream the size-k heap keeps the top k alive in O(log k) per element without that bound.

Q9 The first step is identical across all three approaches (sort, heap, bucket). What is it?

  1. A Sort nums ascending
  2. B Build a frequency map in one O(n) pass correct
  3. C Allocate a heap
  4. D Remove duplicates

Why: All three need value-to-count first; the count map is the shared O(n) preprocessing step, and only the ranking step after it differs.
