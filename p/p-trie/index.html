Prefix tree of nested objects: each character is a key, an `end` flag marks a complete word.

Problem

Implement a Trie with insert, search, startsWith. Run: insert("apple"), log search("apple"), log search("app"), log startsWith("app"), insert("app"), log search("app").

Expected output: true false true true

Canonical solution

class Trie {
  constructor() {
    // Object.create(null) — no prototype, so input "__proto__" cannot collide
    this.root = Object.create(null);
  }
  insert(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node[ch]) node[ch] = Object.create(null);
      node = node[ch];
    }
    node.end = true;
  }
  search(word) {
    const node = this._walk(word);
    return !!node && node.end === true;
  }
  startsWith(prefix) {
    return !!this._walk(prefix);
  }
  _walk(s) {
    let node = this.root;
    for (const ch of s) {
      if (!node[ch]) return null;
      node = node[ch];
    }
    return node;
  }
}
// Time O(L) per op where L is the string length
  • search vs startsWith differ ONLY in whether you require the terminal node.end flag.
  • Use Object.create(null) (not {}) so input characters like "__proto__" cannot collide with the prototype chain — a classic interview follow-up.
  • Pick a terminal sentinel that cannot collide with a character — end works for ASCII words; Symbol/$ is safer for arbitrary input.
  • Time O(L) per op, Space O(total characters inserted) worst case.

Alternate approaches

Array[26] fixed-slot children (lowercase ASCII) O(L) / O(26L)

Reach for this when the problem guarantees lowercase ASCII letters only (the standard LeetCode constraint). Fixed-size 26-slot arrays replace the hash-keyed object: index = charCode - 97. Slightly faster in practice (no hashing) and immune to prototype-collision bugs without needing Object.create(null).

class Trie {
  constructor() { this.children = new Array(26).fill(null); this.end = false; }
  insert(word) {
    let node = this;
    for (const ch of word) {
      const i = ch.charCodeAt(0) - 97;
      if (!node.children[i]) node.children[i] = new Trie();
      node = node.children[i];
    }
    node.end = true;
  }
  search(word) {
    const node = this._walk(word);
    return !!node && node.end === true;
  }
  startsWith(prefix) {
    return !!this._walk(prefix);
  }
  _walk(s) {
    let node = this;
    for (const ch of s) {
      const i = ch.charCodeAt(0) - 97;
      if (!node.children[i]) return null;
      node = node.children[i];
    }
    return node;
  }
}
const t = new Trie();
t.insert("apple");
console.log(t.search("apple"));
console.log(t.search("app"));
console.log(t.startsWith("app"));
t.insert("app");
console.log(t.search("app"));
  • Each node IS a Trie instance — the class doubles as its own child-slot container. Fewer object-wrapper allocations than a separate 'children' object per node.
  • O(26) constant space per node regardless of how many children are occupied — trades wasted nulls for O(1) index access.
  • Breaks for non-lowercase input (index goes negative or > 25); fall back to the Object.create(null) version for arbitrary character sets.

  1. A startsWith creates missing nodes during the walk, while search must not mutate the trie
  2. B search additionally requires the terminal node end flag correct
  3. C search must check that no child characters exist beyond the last position
  4. D startsWith returns true only when the prefix matches at least two inserted words

Q2 Time complexity of insert(word) where word has length L?

  1. A O(1)
  2. B O(L) correct
  3. C O(L log L)
  4. D O(L^2)

Q3 After inserting "apple" only, what does search("app") return?

  1. A true
  2. B false correct
  3. C true, because the node at 'app' exists and has children
  4. D true only if you call startsWith first to mark the prefix as visited

Why: The node at "app" exists but its end flag was never set.

Q4 Common interview follow-up: which input character would BREAK a Trie using plain {}?

  1. A "hasOwnProperty"
  2. B "$"
  3. C "__proto__" correct
  4. D "end"

Why: "__proto__" walks the prototype chain on a plain object — use Object.create(null) to avoid the collision.
