Unique Paths

Count paths from top-left to bottom-right in an m×n grid moving only right or down. Classic 2D DP: dp[i][j] = dp[i-1][j] + dp[i][j-1], with the entire first row and first column equal to 1.

Problem

Write uniquePaths(m, n) returning the number of paths from top-left to bottom-right moving only right or down. Log uniquePaths(3, 7).

Expected output: 28

Canonical solution

2D grid DP — paths in from above plus paths in from the left · O(m·n) / O(m·n) (time / space)

function uniquePaths(m, n) {
  // Init all-1s pre-fills the first row and first column (single path along an edge).
  const dp = Array.from({ length: m }, () => new Array(n).fill(1));
  // Skip row 0 and col 0 — they're already correct from the init.
  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      // Recurrence: paths to (i,j) = paths from above + paths from the left.
      dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
  }
  return dp[m - 1][n - 1];
}
// Time O(m*n), Space O(m*n). Can compress to O(n) by reusing a single row.
  • First row and first column are all 1 — there is exactly one way to reach any cell on the top edge (all rights) or the left edge (all downs).
  • Recurrence dp[i][j] = dp[i-1][j] + dp[i][j-1] says: paths to (i,j) = paths through the cell above + paths through the cell to the left.
  • Space can drop to O(n) by reusing a single row left-to-right (newRow[j] += newRow[j-1]).

Alternate approaches

Rolling row (O(n) space) O(m*n) / O(n)

Reach for this when an interviewer asks 'can you reduce space?' after seeing the 2D table. Each cell only reads the cell directly above (previous row, same column) and the cell to its left (same row). One row of length n is enough — update it in-place left-to-right.

function uniquePaths(m, n) {
  // Single row initialized to 1 (the top-row base case).
  const row = new Array(n).fill(1);
  // For each subsequent grid row, update the row in-place.
  for (let i = 1; i < m; i++) {
    // row[j] currently holds dp[i-1][j] (above); after update it becomes dp[i][j].
    // row[j-1] already holds the updated dp[i][j-1] (left), because we go left-to-right.
    for (let j = 1; j < n; j++) {
      row[j] += row[j - 1];   // dp[i][j] = dp[i-1][j] + dp[i][j-1]
    }
  }
  return row[n - 1];
}
console.log(uniquePaths(3, 7));
  • row[j] before the update is dp[i-1][j] (the cell above); row[j-1] after update is dp[i][j-1] (the cell to the left) — one array covers both.
  • The left column implicitly stays 1 because j starts at 1 and row[0] is never modified (it's always the base-case 1).
  • For a further O(min(m,n)) variant, swap m and n so the shorter dimension is the column — the row array is then length min(m,n).

Combinatorics: C(m+n-2, m-1) (O(min(m,n)) time) O(min(m,n)) / O(1)

Reach for this when you recognize the combinatorial structure: every path from (0,0) to (m-1,n-1) is a sequence of exactly (m-1) DOWNs and (n-1) RIGHTs in some order. The answer is just choose which (m-1) of the (m+n-2) moves are DOWNs. This is O(min(m,n)) time and O(1) space — much faster than any DP approach. Skip it if obstacles are possible (Unique Paths II), since the closed form doesn't extend to blocked cells.

function uniquePaths(m, n) {
  // C(m+n-2, m-1): choose which (m-1) of the (m+n-2) moves are DOWNs.
  // Compute iteratively to avoid factorial overflow: multiply and divide step-by-step.
  let result = 1;
  const k = Math.min(m - 1, n - 1);   // choose the smaller to minimize iterations
  const total = m + n - 2;
  for (let i = 0; i < k; i++) {
    // Multiply by (total - i) and divide by (i + 1) at each step — stays integer.
    result = result * (total - i) / (i + 1);
  }
  return result;
}
console.log(uniquePaths(3, 7));
  • C(m+n-2, m-1) counts the number of ways to arrange (m-1) DOWNs and (n-1) RIGHTs — every distinct arrangement is a unique path.
  • Compute iteratively as result *= (total-i)/(i+1) to stay integer at each step (JS floats handle this exactly for small m,n; switch to BigInt near m+n≈60).
  • Cannot extend to Unique Paths II (obstacles) or Minimum Path Sum — those require the DP table.

Q1 What is the recurrence for Unique Paths?

  1. A dp[i][j] = dp[i-1][j-1] + 1
  2. B dp[i][j] = dp[i-1][j] + dp[i][j-1] correct
  3. C dp[i][j] = max(dp[i-1][j], dp[i][j-1])
  4. D dp[i][j] = dp[i-1][j] * dp[i][j-1]

Why: You can only arrive at (i,j) from above or from the left, and those two sets of paths are disjoint, so the counts add. Taking a max would OPTIMISE over paths (the Min/Max Path Sum shape) instead of counting them.

Q2 Why is the entire first row filled with 1?

  1. A To match the convention from Pascal's triangle, where the outer rows are bordered with 1 to anchor the recurrence
  2. B There is exactly one path along the top edge — all moves are rights correct
  3. C Because dp[0][j] would otherwise be undefined and break the dp[i-1][j] read on row 1
  4. D Because the first row represents the cumulative path count after the first move from (0,0) — always exactly one move

Why: On row 0 there is no cell above, so the only legal move is right — one path to every top-edge cell. The same argument fills column 0 with all-downs, which is why fill(1) covers both bases and the loops can start at i=1, j=1.

Q3 Time complexity of the 2D DP solution?

  1. A O(m + n)
  2. B O(m * n) correct
  3. C O(m^2 * n^2)
  4. D O(2^(m+n))

Why: Each of the m×n cells is settled once — the two edges by fill(1), every interior cell by a single add. The exponential figure is the un-memoised recursion that re-walks each path; the table is what collapses it.

Q4 How can you reduce space from O(m*n) to O(n)?

  1. A Use the closed-form binomial C(m+n-2, m-1) — but that gives O(1) space, not O(n)
  2. B Reuse a single row of length n, updating left-to-right correct
  3. C Store only the diagonals of the dp table — there are O(m+n) of them, each O(1) wide on average
  4. D Use only dp[i][j-1] and skip the row-above lookup — the answer doubles each step so the row-above term is implied

Why: Each cell depends only on the cell above (previous row, same column) and the cell to the left (current row). One row suffices.
