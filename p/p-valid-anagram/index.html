Valid Anagram

Two strings are anagrams iff their character counts match. One Map, increment for s, decrement for t — all zero at the end means anagram. O(n).

Problem

Write isAnagram(s, t) using one Map of character counts (O(n) time). Log isAnagram("anagram", "nagaram") then isAnagram("rat", "car").

Expected output: true false

Canonical solution

Frequency counter (+1 over s, −1 over t) · O(n) / O(1) (time / space)

function isAnagram(s, t) {
  // Different lengths cannot be anagrams — and lets us skip a final zero-check.
  if (s.length !== t.length) return false;
  const count = new Map();
  // +1 per char in s — Map key is char, value is remaining quota.
  for (const c of s) count.set(c, (count.get(c) || 0) + 1);
  for (const c of t) {
    if (!count.has(c)) return false;
    count.set(c, count.get(c) - 1);
    // Negative means t has an extra of c that s didn't.
    if (count.get(c) < 0) return false;
  }
  return true;
}
// Time O(n), Space O(1) for a bounded alphabet
  • Length check first — different lengths cannot be anagrams, and it lets us skip a final zero-check.
  • Single Map: +1 walking s, -1 walking t. If any count goes negative, t has a char s did not have.
  • Space is O(1) because the alphabet is fixed; sorting both strings is O(n log n) — fine in interviews but slower.

Alternate approaches

Sort both strings and compare O(n log n) / O(n)

Reach for this when you want the shortest possible code and O(n log n) is acceptable. Two sorted strings are anagrams iff they are identical — no Map needed. Idiomatic Python/Swift one-liner; in JS it requires spreading to avoid in-place mutation.

function isAnagram(s, t) {
  if (s.length !== t.length) return false;
  // Spread to char arrays, sort, rejoin — compare the canonical forms.
  return [...s].sort().join("") === [...t].sort().join("");
}
console.log(isAnagram("anagram", "nagaram"));
console.log(isAnagram("rat", "car"));
  • Simpler code than the counter, but O(n log n) time vs O(n) for the counter approach.
  • Use [...s] (spread) not s.split('') to handle emoji / surrogate pairs correctly.
  • Allocates two new sorted strings — O(n) extra space even for a bounded alphabet.

L1 — Concept questions 8

Positions 1–8 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why is the length check at the top important?

  1. A Without it, iterating over the longer string would index past the end of the shorter one and throw
  2. B Different lengths cannot be anagrams, and skipping it would force a final scan for non-zero counts correct
  3. C It prevents s and t from being implicitly coerced to numbers during the loop
  4. D The Map throws when its internal load factor exceeds the size hint passed at construction

Why: Equal multisets imply equal lengths, so a mismatch is an instant false. Without the guard a shorter t would leave positive leftovers the decrement loop never inspects, forcing a trailing scan of the Map for non-zero entries — nothing throws, for...of over t just stops early.

Q2 What does it mean if a counter goes BELOW zero during the t scan?

  1. A t is a prefix of s, so the remaining s chars are unmatched
  2. B t contains a character that s did not — not an anagram correct
  3. C We've already matched every occurrence of that char and should switch to comparing the next one
  4. D It indicates a hash collision in the Map and the count for that key should be reset

Why: The stored count is s's remaining quota for that character, so dropping below zero means t spent more of it than s ever had. The mirror case (a count left ABOVE zero) can't happen once the lengths match.

Q3 Why is the space complexity considered O(1) here?

  1. A Counts are decremented to zero, so the Map ends empty regardless of input size
  2. B The alphabet is bounded, so the Map has a fixed maximum size independent of n correct
  3. C The Map is allocated once at module-load time and reused across all calls
  4. D Map entries with value 0 are garbage-collected during iteration, bounding live size to O(1)

Why: The Map holds one entry per DISTINCT character, capped by the alphabet (26 lowercase, 128 ASCII) rather than by n. Entries hit zero but are never deleted, so it's the fixed alphabet — not shrinkage — that bounds the size.

Q4 Time complexity?

  1. A O(log n)
  2. B O(n) correct
  3. C O(n log n)
  4. D O(n^2)

Why: Two sequential passes — one over s to build the counts, one over t to decrement — each doing O(1) Map work per character. 2n is O(n); the sort-and-compare alternative is the O(n log n) one.

Q5 The counter approach beats the 'sort both strings and compare' approach because:

  1. A Sorting allocates a new string per comparison; the counter mutates in place, avoiding GC pressure
  2. B Counting is O(n) while sorting both is O(n log n) correct
  3. C Sorting both strings then comparing requires O(n²) char-by-char equality checks
  4. D Sort is non-deterministic in V8 for equal-length strings, so it can return the wrong answer

Why: Sorting each string costs O(n log n); the frequency-counter does it in a single linear pass, so it is asymptotically faster (sorting is still correct, just slower).

Q6 If you increment for every char in s and decrement for every char in t, two strings are anagrams exactly when:

  1. A At least one count is positive, indicating s contributed something
  2. B Every count ends at zero correct
  3. C The sum of all counts equals the length of s
  4. D Every count in the map matches the count of the most-frequent character

Why: Equal counts mean each character appeared the same number of times in both; every entry nets to zero only when the multisets match.

Q7 Why does counting handle repeated characters correctly where a plain Set would fail?

  1. A A Set's .has returns false on the second occurrence of a value, so duplicates would be silently dropped during the s scan
  2. B A Set only records presence, losing multiplicity — aab vs abb look identical to a Set correct
  3. C Set iteration ordering is undefined, so comparing the s-set to the t-set requires sorting first
  4. D Set membership is checked by == not ===, so 'a' and a boxed String('a') would be conflated

Why: Anagram validity depends on HOW MANY of each char; a Set collapses duplicates, so it cannot distinguish two a's from one, but a count map tracks the exact quantity.

Q8 What does isAnagram("", "") return with this canonical?

  1. A false — empty strings have no characters to be anagrams of
  2. B true correct
  3. C undefined — neither loop runs, so the function never reaches a return statement
  4. D 0 — the empty Map's size is returned implicitly

Why: Lengths match (0 === 0), both loops are no-ops, and control reaches return true — two empty strings share the empty multiset, so they are anagrams.
