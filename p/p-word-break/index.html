Word Break (DP)

Bottom-up DP: dp[i] is true iff s[0..i] can be segmented into dictionary words. Transition: dp[i] = ∃ j < i with dp[j] true AND s[j..i] in the dict.

Problem

Write wordBreak(s, wordDict) using bottom-up DP. Log wordBreak("applepenapple", ["apple","pen"]) then wordBreak("catsandog", ["cats","dog","sand","and","cat"]).

Expected output: true false

Canonical solution

Bottom-up DP (tabulation) · O(n²·k) / O(n) (time / space)

function wordBreak(s, wordDict) {
  // Set for O(1) word membership checks (vs O(d) array.includes).
  const set = new Set(wordDict);
  // dp[i] = can s[0..i) be segmented? Length n+1 to index past the end.
  const dp = new Array(s.length + 1).fill(false);
  dp[0] = true;                                  // empty prefix is segmentable
  for (let i = 1; i <= s.length; i++) {
    // j is the split point: prior segment ends at j, candidate word is s[j..i).
    for (let j = 0; j < i; j++) {
      if (dp[j] && set.has(s.slice(j, i))) {
        dp[i] = true;
        break;                                   // one valid split is enough
      }
    }
  }
  return dp[s.length];
}
  • dp[0] = true is the base case — the empty prefix is trivially segmentable.
  • Inner loop j scans 0..i-1: j marks the END of the previous word and the START of the candidate s[j..i].
  • Break as soon as you set dp[i] = true — one valid split suffices.

Alternate approaches

Top-down memoization (recursive) O(n²·k) / O(n)

Reach for this if the interviewer says 'can you do it recursively?' or you find recursion easier to reason about than tabulation. Same asymptotic complexity as the bottom-up DP — the recursion mirrors the 'where does the next word start?' decision tree, which some find more natural than threading the same idea through a dp[] array. Lazy: a lucky early split can skip whole regions of the table the iterative version still fills.

function wordBreak(s, wordDict) {
  const set = new Set(wordDict);
  // memo[start] = can the suffix s[start..] be segmented?
  const memo = new Map();
  function canBreak(start) {
    if (start === s.length) return true;        // consumed the whole string ✓
    if (memo.has(start)) return memo.get(start);
    for (let end = start + 1; end <= s.length; end++) {
      // Try every word that could start at `start`, then recurse on the rest.
      if (set.has(s.slice(start, end)) && canBreak(end)) {
        memo.set(start, true);
        return true;
      }
    }
    memo.set(start, false);
    return false;
  }
  return canBreak(0);
}
console.log(wordBreak("applepenapple", ["apple", "pen"]));
console.log(wordBreak("catsandog", ["cats", "dog", "sand", "and", "cat"]));
  • Memo keys on start (the suffix's first index), not the dp[] table index — semantically equivalent but lets the recursion read forward ("can the rest be broken?") instead of backward.
  • Without the memo, the recursion fans out to O(d^n) — every overlapping split path re-derives the same suffixes. The memo collapses it back to O(n²·k).
  • The base case start === s.length is the recursive analog of bottom-up's dp[0] = true seed — it's the terminal that lets any earlier call ever return true.

Q1 What does dp[i] represent?

  2. B Whether s[0..i] can be segmented into dictionary words correct

  4. D Longest dict word at index i

Q2 Why initialize dp[0] = true?

  1. A To bias the recurrence toward earlier splits, since shorter prefixes are more likely to be in the dictionary
  2. B Empty prefix is segmentable, letting dp[i] turn on when s[0..i] is itself a word correct
  3. C It marks the dp[0] slot as the 'sentinel start' so the inner loop's bounds check j < i doesn't read undefined
  4. D It encodes the convention that single-character strings are always segmentable into themselves

Q3 Time complexity, ignoring substring cost?

  1. A O(n)
  2. B O(n log n)
  3. C O(n^2) correct
  4. D O(2^n)

Q4 Why use a Set for wordDict instead of an array?

  1. A Sets are iterable in insertion order, which makes the inner-loop split-point scan deterministic
  2. B O(1) average membership check vs O(d) for array.includes correct
  3. C Sets hash by reference, so duplicate dictionary entries from the caller are silently collapsed
  4. D Set.has uses Boyer-Moore for substring matching, which is faster than == on long words
