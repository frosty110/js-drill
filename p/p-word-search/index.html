Word Search

DFS backtracking on a char grid: mark visited by mutating the cell, recurse into 4 neighbors, then restore. O(m*n*4^L).

Problem

Write exist(board, word) returning true if word can be assembled from adjacent (up/down/left/right) cells without reusing a cell. Mutate then restore. Log three test results.

Expected output: true true false

Canonical solution

function exist(board, word) {
  const rows = board.length, cols = board[0].length;
  function dfs(r, c, i) {
    // Success base FIRST — check before bounds so a tail match ends cleanly.
    if (i === word.length) return true;                  // matched all chars
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[i]) return false;
    const tmp = board[r][c];
    board[r][c] = "#";                                   // mark visited
    // Short-circuit `||` — first successful neighbor stops the recursion.
    const found = dfs(r+1,c,i+1) || dfs(r-1,c,i+1)
               || dfs(r,c+1,i+1) || dfs(r,c-1,i+1);
    board[r][c] = tmp;                                   // restore (backtrack)
    return found;
  }
  // Try every cell as a possible starting point.
  for (let r = 0; r < rows; r++)
    for (let c = 0; c < cols; c++)
      if (dfs(r, c, 0)) return true;
  return false;
}
// Time O(m*n*4^L) where L = word.length, Space O(L) recursion
  • Mutate-then-restore is the backtracking signature — save the char, overwrite to mark visited, recurse, then put it back.
  • Short-circuit with || so the first successful neighbor stops the recursion.
  • Check i === word.length BEFORE bounds — a successful tail match ends recursion cleanly.

Alternate approaches

Explicit visited Set (no board mutation) O(m*n*4^L) / O(L)

Use this when the interviewer says 'don't mutate the input' or when the board might contain the sentinel character '#'. Passes a Set of encoded cell keys through the recursion instead of overwriting board cells. Space goes from O(L) to O(L) for the Set (only L cells are ever in it at once), but allocating a Set object per DFS start cell is slower in practice.

function exist(board, word) {
  const rows = board.length, cols = board[0].length;
  function dfs(r, c, i, visited) {
    if (i === word.length) return true;
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    const key = r * cols + c;
    if (visited.has(key) || board[r][c] !== word[i]) return false;
    visited.add(key);                    // mark visited (no board mutation)
    const found = dfs(r+1,c,i+1,visited) || dfs(r-1,c,i+1,visited)
               || dfs(r,c+1,i+1,visited) || dfs(r,c-1,i+1,visited);
    visited.delete(key);                 // un-mark (backtrack)
    return found;
  }
  for (let r = 0; r < rows; r++)
    for (let c = 0; c < cols; c++)
      if (dfs(r, c, 0, new Set())) return true;
  return false;
}
const board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]];
console.log(exist(board, "ABCCED"));
console.log(exist(board, "SEE"));
console.log(exist(board, "ABCB"));
  • Encode (r,c) as r * cols + c — a unique integer key that avoids string allocation.
  • Set.add / Set.delete mirrors board overwrite / restore: same backtracking discipline, different container.
  • The Set holds at most L keys at any moment, so space is still O(L) — same asymptotic as the in-place version.

Direction-array DFS (one neighbor loop) O(R·C·4^L) / O(L)

The same backtracking DFS, with the ||-chained neighbor calls rewritten as a for…of with an early break. Worth it when you want a single reusable neighbor-walk; the explicit || form is terser for plain 4-directional.

const DIRS = [[1, 0], [-1, 0], [0, 1], [0, -1]];
function exist(board, word) {
  const rows = board.length, cols = board[0].length;
  function dfs(r, c, i) {
    if (i === word.length) return true;
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[i]) return false;
    const tmp = board[r][c];
    board[r][c] = "#";
    let found = false;
    for (const [dr, dc] of DIRS) {
      if (dfs(r + dr, c + dc, i + 1)) { found = true; break; }  // break = the `||` short-circuit
    }
    board[r][c] = tmp;
    return found;
  }
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (dfs(r, c, 0)) return true;
    }
  }
  return false;
}
const board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]];
console.log(exist(board, "ABCCED"));
console.log(exist(board, "SEE"));
console.log(exist(board, "ABCB"));
  • break on the first truthy dfs reproduces the canonical's || short-circuit exactly — don't drop it or you explore dead branches.
  • The mark/restore (board[r][c] = '#' … = tmp) still brackets the loop — backtracking is unchanged.
  • DIRS hoisted to module scope; row delta first, column delta second.

Q1 Why restore board[r][c] after the recursive calls?

  1. A To undo the visited marker so other paths can reuse the cell correct
  2. B To trigger garbage collection of the sentinel '#' string allocation
  3. C Because mutating the input is undefined behavior in strict mode
  4. D So that a later DFS at the same cell can detect the cell was tried and bail early

Q2 Time complexity?

  1. A O(m*n*L)
  2. B O((m*n)^L)
  3. C O(m*n*4^L) where L = word.length correct
  4. D O(m*n*L!)

Q3 What does || chaining the four DFS calls accomplish?

  1. A Runs all four directions in parallel via the JS engine's microtask queue
  2. B Short-circuits — stops at the first true correct
  3. C Aggregates the per-direction booleans into the OR of all four (always evaluating each)
  4. D Coerces each falsy 0/false return into a boolean so the outer return type stays bool

Q4 Why check i === word.length at the top of dfs?

  1. A It is the base case — every char matched, return true correct
  2. B To avoid reading word[i] out of bounds, which would throw RangeError
  3. C To skip the bounds check on the wrap-around when L exceeds m*n
  4. D So the visited-marker overwrite doesn't happen on a cell we won't recurse from
