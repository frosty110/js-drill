push / pop / splice

The mutating array methods — push, pop, shift, unshift, splice — and what each returns vs. mutates.

syntax Arrays 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write rotateLeft(arr) that moves the first element to the end (mutating) and returns the array. Log JSON.stringify(rotateLeft([1, 2, 3, 4])).

Expected output: [2,3,4,1]

Canonical solution

// END of array (fast)
arr.push(x);        // appends, returns NEW length
arr.pop();          // removes last, returns the removed item (or undefined)

// FRONT of array (slow, O(n) — re-indexes everything)
arr.unshift(x);     // prepends, returns NEW length
arr.shift();        // removes first, returns the removed item

// splice — surgical insert/remove ANYWHERE (mutates, returns removed)
arr.splice(start, deleteCount, ...itemsToInsert);
[1,2,3,4].splice(1, 2);          // returns [2,3], arr becomes [1,4]
[1,2,3].splice(1, 0, "a", "b");  // returns [],   arr becomes [1,"a","b",2,3]
  • push/unshift return the NEW LENGTH; pop/shift/splice return the REMOVED items.
  • shift and unshift are O(n) — they re-index every remaining element. Prefer push/pop when order does not matter.
  • splice MUTATES. The non-mutating cousin is toSpliced (ES2023) or [...arr.slice(0,i), ...arr.slice(j)].

Q1 What does arr.push(x) return?

  1. A The pushed item
  2. B The new array length correct
  3. C undefined
  4. D The original array

Q2 What does arr.pop() return?

  1. A The new length
  2. B The removed item correct
  3. C undefined always
  4. D A boolean

Q3 Why is unshift slower than push on large arrays?

  1. A unshift internally calls Array.from to rebuild the array with the new head
  2. B unshift re-indexes every element correct
  3. C unshift triggers a structural-sharing copy because index 0 is the prototype-lookup slot
  4. D unshift returns a new array, so the cost is in the copy rather than the assignment

Why: Front operations shift every remaining index by one — O(n).

Q4 splice(1, 2) on [1,2,3,4] — what does it RETURN?

  1. A [1, 4]
  2. B [2, 3] correct
  3. C 2
  4. D undefined

Why: splice returns the removed slice; the original mutates to [1, 4].

L3 — Write it from memory

One position, the code's third segment.

Write rotateLeft(arr) that moves the first element to the end (mutating) and returns the array. Log JSON.stringify(rotateLeft([1, 2, 3, 4])).

Hints
  • shift removes and returns the first item.
  • push that item to the end.
function rotateLeft(arr) {
  const first = arr.shift();
  arr.push(first);
  return arr;
}
console.log(JSON.stringify(rotateLeft([1, 2, 3, 4])));
