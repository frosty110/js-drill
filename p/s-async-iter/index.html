Async iterators (for await…of)

Async iterables expose `[Symbol.asyncIterator]` and let `for await...of` consume values that arrive over time.

syntax Iterators & Generators 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Build an async iterable that yields Promise.resolve(n) for n = 1, 2, 3. Consume with for await...of and log each value.

Expected output: 1 2 3

Canonical solution

// Sync iterator vs async iterator:
//   sync:  next() -> { value, done }
//   async: next() -> Promise<{ value, done }>

const asyncIterable = {
  [Symbol.asyncIterator]() {
    let i = 1;
    return {
      next() {
        if (i <= 3) {
          return Promise.resolve({ value: i++, done: false });
        }
        return Promise.resolve({ value: undefined, done: true });
      }
    };
  }
};

(async () => {
  for await (const n of asyncIterable) {
    // n is the resolved value (1, then 2, then 3)
  }
})();
  • for await...of is ONLY valid inside an async function (or top-level module).
  • [Symbol.asyncIterator] is a DIFFERENT well-known symbol from [Symbol.iterator] — don't mix them up.
  • next() returns a Promise that resolves to { value, done } — the wrapper, not the value, is async.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What does an async iterator's next() return?

  1. A { value, done }
  2. B Promise<{ value, done }> correct
  3. C Promise<value>
  4. D AsyncGenerator<value>

Why: The Promise wraps the whole result record, not just the item — for await...of awaits it, then reads .value and .done off the settled object.

Q2 Where is for await...of legal?

  1. A Anywhere
  2. B Only inside an async function or top-level module correct
  3. C Only inside a generator
  4. D Only inside try/catch

Why: It needs an await-capable scope — inside a plain function it's a SyntaxError, which is why the reference wraps the loop in an (async () => { ... })() IIFE.

Q3 Which well-known symbol does for await...of look up FIRST when iterating an object?

  1. A Symbol.iterator — async iteration just awaits each sync value
  2. B Symbol.asyncIterator correct
  3. C Symbol.for('asyncIterator') — the cross-realm registered version
  4. D Symbol.asyncIterator on the returned iterator, not the iterable itself

Why: for await...of asks the iterable for [Symbol.asyncIterator] first, and only falls back to [Symbol.iterator] (awaiting each yielded value) when it's absent. Symbol.for('asyncIterator') is an unrelated registry symbol — not equal to Symbol.asyncIterator.

Q4 What happens if you use for...of (no await) on an object with only [Symbol.asyncIterator]?

  1. A It works, JS auto-awaits each value
  2. B It logs Promises instead of values
  3. C TypeError: not iterable correct
  4. D It throws after the first iteration

Why: Sync for...of looks up [Symbol.iterator], which isn't defined here.
