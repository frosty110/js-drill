async / await

Async functions return Promises; await pauses until one resolves. Wrap awaits in try/catch and parallelize with Promise.all.

syntax Async 4 concept · 2 fill-in · 1 drill

Problem

Write an async fetchVal(x) that returns Promise.resolve(x * 2). Call it 3 times in parallel with Promise.all on inputs 1,2,3 and log the sum.

Expected output: 12

Canonical solution

// 1) Declare with async — it always returns a Promise.
async function getNum() {
  return await Promise.resolve(7);   // await unwraps the Promise
}

// 2) Errors propagate as rejections — handle with try/catch.
async function safe() {
  try {
    return await Promise.reject(new Error("boom"));
  } catch (e) {
    return e.message;
  }
}

// 3) Run independent awaits in PARALLEL with Promise.all.
async function parallel() {
  const [a, b] = await Promise.all([
    Promise.resolve(1),
    Promise.resolve(2)
  ]);
  return a + b;
}
  • await is only valid inside an async function (or a top-level module).
  • Sequential awaits run one-at-a-time — use Promise.all for independent work.
  • A throw inside an async function becomes a rejected Promise; catch it with try/catch around the await.

Q1 What does an async function always return?

  1. A The raw value, unwrapping any returned Promise automatically
  2. B A Promise correct
  3. C A thenable proxy — Promise-like but not a real Promise
  4. D Whatever the last await resolved to, returned synchronously

Why: Whatever you return is wrapped in a Promise; whatever you throw becomes a rejection.

Q2 Where is await legal?

  1. A Anywhere — it just blocks the current function
  2. B Only inside an async function (or top-level module) correct
  3. C Inside any function, but only if the function returns a Promise
  4. D Inside an async function OR any callback passed to .then

Why: await is syntax, not a call — it only parses inside an async body or a module's top level. A callback handed to .then is its own non-async function, so await in there is a SyntaxError.

Q3 Two independent awaits that take the same time — fastest pattern?

  1. A await one then the other — the runtime parallelizes consecutive awaits automatically
  2. B Promise.all on both correct
  3. C Pass them to Promise.race, since both resolving at the same time short-circuits
  4. D Use .then chains so each handler returns the next promise

Why: Sequential awaits add latencies; Promise.all runs them concurrently.

Q4 How do you catch a rejected awaited Promise?

  1. A Pass an onRejected callback as the second argument to await
  2. B try/catch around the await correct
  3. C Attach .catch() to the awaited expression — await unwraps the resolved branch only
  4. D Listen for a unhandledrejection event inside the async function

Why: await rethrows the rejection at the await point, inside the current frame, so an ordinary try/catch catches it — unlike .then, await takes no onRejected argument.
