extends / super

extends sets the prototype chain; super() calls the parent constructor; super.method() calls a parent method from an override.

syntax Classes 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Build Animal with describe() returning the name, and Dog extends Animal whose describe() returns parent describe + " the " + breed. Log new Dog("Rex", "lab").describe().

Expected output: Rex the lab

Canonical solution

class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return this.name + " makes a sound";
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);            // MUST call super() before using this
    this.breed = breed;
  }
  speak() {
    return super.speak() + " (bark)";  // delegate up, then extend
  }
}

const d = new Dog("Rex", "lab");
d.speak();                  // "Rex makes a sound (bark)"
d instanceof Dog;           // true
d instanceof Animal;        // true (prototype chain)
  • In a subclass constructor you MUST call super(...) before touching this — otherwise ReferenceError.
  • super.method() inside a method calls the parent version; super alone in a constructor calls the parent constructor.
  • instanceof walks the prototype chain — a Dog is also an Animal.

Q1 Which keyword sets up class inheritance?

  1. A inherits
  2. B extends correct
  3. C super
  4. D prototype

Why: extends is what links Dog.prototype to Animal.prototype; super is what you call once that chain exists, not what creates it.

Q2 What happens if you use this before calling super() in a subclass constructor?

  1. A It silently uses undefined
  2. B ReferenceError is thrown correct
  3. C It copies parent fields automatically
  4. D Nothing — super is optional

Why: In a derived constructor this stays uninitialized until super() returns — reading it early throws ReferenceError: Must call super constructor.... That is why super(name) precedes this.breed = breed.

Q3 Inside an overridden method, how do you call the parent version?

  1. A parent.method()
  2. B this.super.method()
  3. C super.method() correct
  4. D Animal.prototype.method.call(this)

Why: super.speak() resolves on the parent prototype while keeping this as the instance. Animal.prototype.speak.call(this) does the same by hand — it works, but it hard-codes the parent name and breaks the moment the chain changes.

Q4 For class Dog extends Animal {} and const d = new Dog(), what is d instanceof Animal?

  1. A true correct
  2. B false
  3. C undefined
  4. D TypeError

Why: instanceof walks the whole prototype chain, and extends put Animal.prototype on it — so d is an instance of both Dog and Animal.

Hints

  • In Dog.describe(), compose super.describe() with " the " + this.breed.
class Animal {
  constructor(name) { this.name = name; }
  describe() { return this.name; }
}
class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
  describe() {

  }
}
