Scope & closures

A closure is a function plus the variables it captured from its surrounding scope — the foundation of factories, currying, and the classic var-vs-let loop bug.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write makeAdder(x) that returns a function adding x to its argument. Log makeAdder(5)(3).

Expected output: 8

Canonical solution

// A closure: returned function "remembers" count
function makeCounter() {
  let count = 0;
  return function() {
    count += 1;
    return count;
  };
}
const c = makeCounter();
c(); c(); c();           // 3 — same captured count

// The classic loop bug — var captures the SAME binding
const withVar = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);
withVar.map(f => f());   // [3, 3, 3]  ← all share one i

// Fixed with let — a fresh binding per iteration
const withLet = [];
for (let j = 0; j < 3; j++) withLet.push(() => j);
withLet.map(f => f());   // [0, 1, 2]
  • A closure keeps the variable alive — even after the outer function returns.
  • var creates one binding shared by every loop iteration; let creates a fresh binding each iteration.
  • Closures are how factories (makeAdder, makeCounter), private state, and currying work.

Q1 What is a closure?

  1. A A function that has finished executing
  2. B A function plus the variables it captured from its enclosing scope correct
  3. C A deep copy of an outer function's local variables, taken at return time
  4. D Any function created inside another function, even if it references nothing outside

Why: The function returned by makeCounter holds a live reference to count, not a snapshot taken at return — that is why three calls give 1, 2, 3 rather than 1, 1, 1, and why count outlives the call that created it.

Q2 In for (var i = 0; i < 3; i++) fns.push(() => i), what do the calls return?

  1. A 0, 1, 2
  2. B 3, 3, 3 correct
  3. C 0, 0, 0
  4. D undefined

Why: var shares one binding — by the time the callbacks run, i is 3.

Q3 Switching that loop to let i gives:

  1. A Still 3, 3, 3
  2. B 0, 1, 2 — fresh binding per iteration correct
  3. C A SyntaxError
  4. D 0, 1, 2 only in strict mode

Why: let gives the loop head a fresh binding each iteration, so every arrow closes over its own i. The fix is the keyword alone — strict mode changes nothing here.

Q4 Which is block-scoped?

  1. A var
  2. B let and const correct
  3. C var inside a strict-mode block
  4. D Both var and let

Why: let and const are scoped to the nearest braces. var is function-scoped wherever it is written, and strict mode does not narrow it — that is the whole cause of the 3, 3, 3 loop bug above.
