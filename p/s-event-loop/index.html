Event loop & microtasks

Sync runs first. Microtasks (Promise.then) drain COMPLETELY before the next macrotask (setTimeout). That is why a Promise.then logs before a setTimeout(_, 0).

Problem

Log "start", schedule chain .then(log "micro1").then(log "micro2"), then log "end". Expect: start, end, micro1, micro2.

Expected output: start end micro1 micro2

Canonical solution

// 1) Sync code runs to completion BEFORE any queued task fires.
console.log("A");                              // sync
Promise.resolve().then(() => console.log("B"));// microtask — queued
console.log("C");                              // sync
// Output: A, C, B

// 2) Microtasks drain fully between sync code and the next macrotask.
Promise.resolve()
  .then(() => console.log(1))                  // micro level 1
  .then(() => console.log(2));                 // micro level 2 (queued by level 1)
Promise.resolve().then(() => console.log(3));  // micro level 1 (queued earlier)
console.log(4);                                // sync
// Output: 4, 1, 3, 2
//   sync 4 first; then FIFO level-1 (1, 3), then level-2 (2).
  • Sync code always runs first. Microtasks (Promise.then, queueMicrotask) drain before the next macrotask.
  • A .then enqueued inside another .then waits for the rest of the current microtask level to drain.
  • setTimeout(fn, 0) is NOT zero delay — it schedules a macrotask, so any pending Promise.then runs first.
