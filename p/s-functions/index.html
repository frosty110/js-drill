Functions & arrows

Three ways to declare callable code: function declarations, expressions, and arrows — plus how each handles this, default params, and implicit returns.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write a function multiply(a, b) where b defaults to 1. Log multiply(4, 3) and multiply(7) on the same line separated by a space.

Expected output: 12 7

Canonical solution

// Function declaration — hoisted, has its own this
function add(a, b) {
  return a + b;
}

// Function expression — NOT hoisted; assigned to a variable
const sub = function(a, b) {
  return a - b;
};

// Arrow function — concise; LEXICAL this (inherits from enclosing scope)
const mul = (a, b) => a * b;          // implicit return (no braces)
const sq  = n => n * n;               // single param: parens optional
const log = () => console.log("hi"); // zero params: parens required

// Default parameters
function greet(name = "world") {
  return `hi ${name}`;
}
  • Arrows do NOT bind their own this — they capture this from the enclosing scope.
  • Implicit return only works with a single expression body (no braces).
  • Function declarations are hoisted; expressions and arrows assigned to const are NOT — calling them before assignment throws ReferenceError.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Which form is hoisted (callable before its line of code)?

  1. A function declaration correct
  2. B function expression assigned to const
  3. C arrow function assigned to const
  4. D None of them

Why: A declaration is hoisted whole, so add is callable above its own line. const-assigned expressions and arrows hoist the BINDING only and it sits in the temporal dead zone — calling early throws ReferenceError, not "is not a function".

Q2 What does an arrow function do with this?

  1. A Binds it to undefined
  2. B Binds it to the global object
  3. C Inherits it lexically from the enclosing scope correct
  4. D Binds it to the first argument

Why: An arrow has no this of its own, so this resolves through the enclosing scope at definition time — which is why arrows are safe as callbacks inside a method and wrong as the method itself. call/bind cannot override it either.

Q3 Which has implicit return?

  1. A function declaration
  2. B arrow with braces { return x }
  3. C arrow with no braces n => n * 2 correct
  4. D function expression

Why: Dropping the braces makes the body a single expression whose value is returned. Put the braces back and it is a statement body again — n => { n * 2 } returns undefined, the classic silent bug.

Q4 function greet(name = "world") — what happens when called as greet()?

  1. A Throws TypeError
  2. B name becomes undefined
  3. C name becomes "world" correct
  4. D name becomes null

Why: A default fires when the argument is undefined — whether omitted or passed explicitly as undefined. null does NOT trigger it: greet(null) gives "hi null".
