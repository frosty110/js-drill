Heap index math + sift

The whiteboard boilerplate for a 0-indexed array heap: parent/child index math plus sift-up and sift-down loops.

Problem

Given the min-heap array [1, 5, 3, 10, 8, 7], use the parent index formula to find the parent of position 4, then log the value stored at that parent index.

Expected output: 5

Canonical solution

0-indexed array heap with sift-up / sift-down · O(log n) / O(1) (time / space)

// 0-indexed array heap — index math
const parent = i => (i - 1) >> 1;   // floor((i-1) / 2)
const left   = i => 2 * i + 1;
const right  = i => 2 * i + 2;

// Sift UP — used after appending a new element at the tail (push)
//   bubble the new item upward while it is smaller than its parent
let i = heap.length - 1;
while (i > 0 && heap[parent(i)] > heap[i]) {
  [heap[i], heap[parent(i)]] = [heap[parent(i)], heap[i]];
  i = parent(i);
}

// Sift DOWN — used after moving the last element to index 0 (pop-root)
//   bubble it downward, always swapping with the SMALLER child
let j = 0;
while (true) {
  const l = left(j), r = right(j);
  let s = j;
  if (l < heap.length && heap[l] < heap[s]) s = l;
  if (r < heap.length && heap[r] < heap[s]) s = r;
  if (s === j) break;
  [heap[j], heap[s]] = [heap[s], heap[j]];
  j = s;
}
  • A heap is just an array — no node objects. The tree shape is encoded by the index math.
  • Parent = (i-1) >> 1, left = 2*i+1, right = 2*i+2 — memorize these three formulas.
  • Sift UP after a push (new item is at the tail). Sift DOWN after a pop-root (move last to index 0, then bubble down).
  • On sift-down ALWAYS swap with the smaller child — swapping with the larger would leave the smaller child violating the heap property.
  • MAX-heap variant: same code, flip every comparison (> ↔ <) in the sift loops. The index math is identical.

Alternate approaches

Bottom-up heapify (Floyd, O(n)) O(n) / O(1)

Reach for this when you're handed an UNORDERED array up front and need to heap-ify it once before draining. Naive 'push every element' is O(n log n); Floyd's bottom-up heapify is O(n) — half the nodes are leaves with zero work, a quarter sift at most one level, and the weighted sum converges to linear. Standard interview answer when the problem starts 'given an unsorted array, find the k smallest…'.

function heapify(heap) {
  // 0-indexed heap helpers.
  const left  = i => 2 * i + 1;
  const right = i => 2 * i + 2;
  // Sift-down at index j over the prefix heap[0..n).
  function siftDown(j) {
    while (true) {
      const l = left(j), r = right(j);
      let s = j;
      if (l < heap.length && heap[l] < heap[s]) s = l;
      if (r < heap.length && heap[r] < heap[s]) s = r;
      if (s === j) break;
      [heap[j], heap[s]] = [heap[s], heap[j]];
      j = s;
    }
  }
  // Start at the last NON-LEAF (parent of the tail) and walk to the root.
  // Leaves (indices ≥ n/2) are trivially heaps of size 1 — skip them.
  for (let i = (heap.length >> 1) - 1; i >= 0; i--) {
    siftDown(i);
  }
  return heap;
}
const heap = [1, 5, 3, 10, 8, 7];
heapify(heap);
const p = (i) => (i - 1) >> 1;
console.log(heap[p(4)]);
  • Iterate from (n>>1) - 1 down to 0 — that's the last node with at least one child. Anything past it is a leaf and already a valid heap of size 1.
  • The O(n) bound comes from the weighted sum: ~n/2 leaves do 0 work, ~n/4 nodes sift ≤1 level, ~n/8 sift ≤2, etc. The series Σ k·n/2^(k+1) converges to n, not n log n.
  • On already-min-heap input (like [1,5,3,10,8,7]) every siftDown is a no-op — heapify is idempotent, the output equals the input.

Q1 For a 0-indexed array heap, the parent of index 7 is:

  1. A 2
  2. B 3 correct
  3. C 4
  4. D 6

Why: (7 - 1) >> 1 = 6 >> 1 = 3.

Q2 The left child of index 3 sits at which index?

  1. A 4
  2. B 6
  3. C 7 correct
  4. D 8

Why: 2 * 3 + 1 = 7.

Q3 Why is a heap implemented over an array instead of with node objects?

  1. A Arrays give O(1) random access to any tree level, which a linked tree can't
  2. B Index math (parent/left/right) encodes the tree shape compactly with no pointers correct
  3. C A complete binary tree's traversal order is the same as array iteration, so iteration is free
  4. D Arrays guarantee cache locality of sibling nodes, which is what makes sift-down O(log n)

Why: The complete binary tree shape maps perfectly onto contiguous array indices — no parent/child pointers needed.

Q4 When do you sift UP vs sift DOWN?

  1. A Sift up on insert (bubble from the tail); sift down on pop-root (bubble from index 0) correct
  2. B Sift down on insert; sift up on pop-root
  3. C Sift up for both
  4. D Sift down for both

Why: Insert appends at the tail then sifts up. Pop-root swaps root with the tail, shrinks, then sifts down from index 0.

Q5 On a MIN-heap sift-DOWN, you swap the node with the LARGER of its two children. What breaks?

  1. A Nothing — the heap re-balances on the next pop because sift-down is idempotent
  2. B The smaller child stays below a larger value, violating the heap property at that subtree correct
  3. C Only the root invariant breaks; the rest of the tree stays valid because each subtree is independent
  4. D The traversal cost flips from O(log n) to O(n) but the values stay heap-ordered

Why: Promoting the larger child leaves the smaller child sitting under a bigger parent — the min-heap invariant (parent ≤ both children) is violated. Always swap with the SMALLER child.

Q6 Building a heap by heapify (sift-down from the bottom up) over n elements is:

  1. A O(n log n) — n inserts each O(log n)
  2. B O(n) — most nodes are near the leaves and sift down only a few levels correct
  3. C O(n²)
  4. D O(log n)

Why: Bottom-up heapify is O(n): half the nodes are leaves (0 work), a quarter sift at most 1 level, etc. — the weighted sum converges to O(n), unlike n separate O(log n) inserts.

Q7 To turn the min-heap code into a MAX-heap, what's the minimal change?

  1. A Swap the parent/child index formulas — the tree shape inverts for max-heaps
  2. B Flip the comparisons (use > where it used <) so larger values bubble toward the root correct
  3. C Negate every value on push and re-negate on pop — keeps the min-heap logic intact
  4. D Sift-up on extract-max instead of sift-down — only the operation, not the comparators, changes

Why: The index math is identical; only the ordering comparisons flip — a max-heap keeps the largest at the root by reversing every </> in the sift logic.

Q8 You need repeated 'give me the current min, then add more items' on a changing dataset. Why a heap over a sorted array?

  1. A A heap keeps the full ordering of all n elements, while a sorted array only orders adjacent pairs
  2. B Insert is O(log n) on a heap vs O(n) to keep a sorted array sorted; you only pay for the min you actually extract correct
  3. C Binary search on a sorted array is O(log n), but it can't locate the insertion point in less than O(n) due to shifting — and a heap avoids the shift entirely with O(1) access
  4. D A heap's extract-min is O(1) since the min is at heap[0], whereas a sorted array's first-element removal is O(n)

Why: A heap gives O(log n) insert and O(log n) extract-min without maintaining a total order; inserting into a sorted array to stay sorted is O(n) per insert.
