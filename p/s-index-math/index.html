Index arithmetic (r-l+1, midpoint, slice, wrap)

The +1 / -1 / midpoint / modulo idioms behind sliding windows, binary search, fixed-length slices, and circular indexing — the arithmetic you reach for before the algorithm.

Problem

Write maxWindowSum(arr, k) that returns the maximum sum over any sliding window of size k, using r - l + 1 = k as the window-length invariant. Log maxWindowSum([2, 1, 5, 1, 3, 2], 3).

Expected output: 9

Canonical solution

Fixed-size sliding window — seed k, then slide with arr[r] - arr[r-k] · O(n) / O(1) (time / space)

// ────────────────────────────────────────────────────────────
// 1. INCLUSIVE INTERVAL LENGTH:  r - l + 1
// ────────────────────────────────────────────────────────────
//
//   arr  =  [ a , b , c , d , e ]
//   idx     0   1   2   3   4
//               ↑       ↑
//               l       r        l=1, r=3
//               └───┬───┘
//                  3 items       r - l + 1 = 3
//
//   Drop the +1 to get the GAP (steps from l to r):
//                                 r - l     = 2
const inclusiveLen = (l, r) => r - l + 1;
const gap          = (l, r) => r - l;


// ────────────────────────────────────────────────────────────
// 2. MIDPOINT:  (lo + hi) >> 1     ← integer floor-divide
// ────────────────────────────────────────────────────────────
//
//   lo                            hi
//    ▼                            ▼
//   [ _ , _ , _ , _ , _ , _ , _ , _ ]
//     3   4   5   6   7   8   9   10
//                  ▲
//                 mid = (3 + 10) >> 1 = 6
//
//   `>> 1` is a faster `Math.floor((a+b)/2)` and the idiomatic
//   write-up interviewers expect.
const mid = (lo, hi) => (lo + hi) >> 1;


// ────────────────────────────────────────────────────────────
// 3. FIXED-LENGTH SLICE:  arr.slice(start, start + n)
//    slice's 2nd arg is EXCLUSIVE → start + n yields n items.
// ────────────────────────────────────────────────────────────
//
//   [10, 20, 30, 40, 50].slice(1, 1 + 3)
//          ┌──────────────┐
//          │   take 3     │
//          ▼              ▼
//   [10,  20, 30, 40,  50 ]   →   [20, 30, 40]
//
//   Shorthand for last n:
//   [10, 20, 30, 40, 50].slice(-2)   →   [40, 50]


// ────────────────────────────────────────────────────────────
// 4. SLIDING WINDOW OF SIZE k:   k = r - l + 1
// ────────────────────────────────────────────────────────────
//
//   arr = [2, 1, 5, 1, 3, 2]   k=3
//          0  1  2  3  4  5
//
//         [────────]                sum=8    (l=0, r=2)
//            [────────]             sum=7    -arr[0] +arr[3]
//               [────────]   ★      sum=9    -arr[1] +arr[4]
//                  [────────]       sum=6    -arr[2] +arr[5]
//
//   When r advances and length > k, shrink:   l = r - k + 1
//   Element LEAVING the window:               arr[r - k]


// ────────────────────────────────────────────────────────────
// 5. CIRCULAR INDEXING:  ((i % n) + n) % n
//    JS arr[-1] is undefined — NOT the last element.
// ────────────────────────────────────────────────────────────
//
//   arr = [a, b, c, d]   n=4
//          0  1  2  3
//
//   i = -1  →  ((-1 % 4) + 4) % 4 = 3  →  'd'   ← wraps left
//   i =  5  →  (( 5 % 4) + 4) % 4 = 1  →  'b'   ← wraps right
//
//   The double modulo handles negative i (JS `%` keeps the sign
//   of the dividend, so -1 % 4 === -1, not 3).
const circ = (arr, i) => arr[((i % arr.length) + arr.length) % arr.length];


// ────────────────────────────────────────────────────────────
// 6. NTH FROM END:  arr[arr.length - n]   (or arr.at(-n))
// ────────────────────────────────────────────────────────────
//
//   arr = [a, b, c, d, e]    length=5
//                       ▲
//                       n=1  →  arr[5-1] = 'e'   (last)
//                    ▲
//                    n=2  →  arr[5-2] = 'd'
//
//   Off-by-one trap: n must be ≥ 1.
//   arr[arr.length - 0] = arr[5] = undefined.
  • Inclusive length needs +1 because subtraction undercounts the left endpoint.
  • (lo + hi) >> 1 is the idiomatic floor-divide for midpoint — interviewers expect it over Math.floor((lo+hi)/2).
  • slice(start, start + n) gives exactly n items because slice's end is EXCLUSIVE — a frequent off-by-one source.
  • JS % keeps the sign of the dividend, so wrapping a negative index needs ((i % n) + n) % n, not just i % n.

Q1 How many elements are between indices l=2 and r=6, INCLUSIVE of both endpoints?

  1. A 4 — that's r - l
  2. B 5 — that's r - l + 1 correct
  3. C 6 — that's r - l + 2
  4. D 7 — that's r + 1

Why: Inclusive length is r - l + 1. The +1 counts the left endpoint that the subtraction would otherwise drop.

Q2 Binary search: what is the midpoint of lo=3 and hi=10 using (lo + hi) >> 1?

  1. A 6 correct
  2. B 6.5
  3. C 7
  4. D 13

Why: (3 + 10) >> 1 = 13 >> 1 = 6. Right-shift by 1 is integer divide by 2 (floor).

Q3 You want a sub-array of exactly 4 elements starting at index 2. Which call?

  1. A arr.slice(2, 4)
  2. B arr.slice(2, 5)
  3. C arr.slice(2, 2 + 4) correct
  4. D arr.slice(2, 2 + 4 - 1)

Why: slice's 2nd arg is EXCLUSIVE, so end = start + n gives exactly n items. arr.slice(2, 4) returns only 2 elements.

Q4 What does arr[-1] return in JavaScript when arr = [10, 20, 30]?

  1. A 30 — the last element, like Python
  2. B 10 — wraps to the first element
  3. C undefined — JS arrays don't support negative bracket indices correct
  4. D ReferenceError

Why: JS array bracket access with a negative index is just a missing property lookup → undefined. Use arr.at(-1) for the Python-style behavior.

L3 — Write it from memory

One position, the code's third segment.

Write maxWindowSum(arr, k) that returns the maximum sum over any sliding window of size k, using r - l + 1 = k as the window-length invariant. Log maxWindowSum([2, 1, 5, 1, 3, 2], 3).

Hints
  • Seed sum with the first k elements, then slide.
  • When the right pointer advances to r, the element leaving the window is arr[r - k] (because window length k = r - l + 1 means l = r - k + 1).
function maxWindowSum(arr, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += arr[i];
  let best = sum;
  // r is the new right edge; window covers [r - k + 1, r] inclusive,
  // so the element dropping off the left is arr[r - k].
  for (let r = k; r < arr.length; r++) {
    sum += arr[r] - arr[r - k];
    if (sum > best) best = sum;
  }
  return best;
}
console.log(maxWindowSum([2, 1, 5, 1, 3, 2], 3));
