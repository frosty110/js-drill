Custom iterables

Add `[Symbol.iterator]` to a class or object and it instantly works with `for...of`, spread, and array destructuring.

syntax Iterators & Generators 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Build a Range(start, end) class (end-exclusive) made iterable via [Symbol.iterator]. Log JSON.stringify([...new Range(1, 4)]).

Expected output: [1,2,3]

Canonical solution

// A class becomes iterable by defining [Symbol.iterator]()
class Range {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }
  [Symbol.iterator]() {
    let i = this.start;
    const end = this.end;
    return {
      next() {
        return i < end
          ? { value: i++, done: false }
          : { value: undefined, done: true };
      }
    };
  }
}

const r = new Range(1, 4);
[...r];                    // [1, 2, 3]
Array.from(r);             // [1, 2, 3]
for (const n of r) { /* 1, 2, 3 */ }
  • [Symbol.iterator] uses computed-key syntax — the brackets are part of the method name, not array access.
  • Returning a FRESH iterator each call lets the same iterable be looped multiple times.
  • Spread, destructuring, for...of, Array.from, and Promise.all ALL use the iterable protocol.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What method name makes a class iterable?

  1. A iterator()
  2. B [Symbol.iterator]() correct
  3. C next()
  4. D [Symbol.iterable]()

Why: [Symbol.iterator]() is the iterable side; next() is what the object it RETURNS must have. Symbol.iterable is undefined — there is no such well-known symbol.

Q2 Which built-in feature does NOT use the iterable protocol?

  1. A spread [...x]
  2. B for...of
  3. C Array.from
  4. D Object.keys correct

Why: Object.keys reads own enumerable string keys — it doesn't call [Symbol.iterator].

Q3 Why return a fresh iterator object from [Symbol.iterator]()?

  1. A To reset the spec-required internal slot [[IteratorIndex]] between loops
  2. B So the iterable can be looped multiple times independently correct
  3. C To force the engine to recompute the iterator's hidden class for optimization
  4. D It's not required — returning this is identical

Why: The cursor lives on the iterator (let i = this.start), so reusing one object would leave a second for...of already exhausted at i === end.

Q4 What does [...new Range(0, 3)] evaluate to (using the Range from the reference)?

  1. A [0, 1, 2] correct
  2. B [0, 1, 2, 3]
  3. C [1, 2, 3]
  4. D Error: not iterable

Why: end is exclusive — Range(0, 3) yields 0, 1, 2.
