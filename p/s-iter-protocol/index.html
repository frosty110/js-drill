Iterator protocol

An iterator is any object with a `.next()` method that returns `{ value, done }` — the contract `for...of` and spread rely on.

Problem

Write makeIter(arr) returning a manual iterator. Walk [10, 20, 30] by calling .next() until done is true, logging each value.

Expected output: 10 20 30

Canonical solution

// An iterator: object with .next() returning { value, done }
function makeIter(arr) {
  let i = 0;
  return {
    next() {
      return i < arr.length
        ? { value: arr[i++], done: false }
        : { value: undefined, done: true };
    }
  };
}

const it = makeIter([1, 2]);
it.next(); // { value: 1, done: false }
it.next(); // { value: 2, done: false }
it.next(); // { value: undefined, done: true }

// An ITERABLE has [Symbol.iterator]() that returns an iterator.
// Arrays, strings, Maps, Sets are all built-in iterables:
const arrIter = [10, 20][Symbol.iterator]();
arrIter.next(); // { value: 10, done: false }
  • .next() MUST return an object shaped { value, done } — booleans for done, anything for value.
  • Once done: true is returned, calling .next() again should keep returning done — iterators are one-shot.
  • Symbol.iterator (not a string) is the well-known key for iterable lookup — obj[Symbol.iterator].

Q1 What shape must an iterator's .next() return?

  1. A { value, done } correct
  2. B { value, done, index } — index is required so spread can preserve sparse holes
  3. C Just the value, with iteration terminated by returning undefined
  4. D [value, done] — a tuple, matching destructuring conventions

Why: It's an object (not a tuple) with exactly value and done — no index. done has to be a separate flag because undefined is a legal value, so a bare value could never signal the end.

Q2 How do you grab the built-in iterator from an array a?

  1. A a.iterator()
  2. B a['iterator']
  3. C a[Symbol.iterator]() correct
  4. D Symbol.iterator(a)

Why: The lookup key is the well-known symbol itself, used as a computed key — a['iterator'] is undefined because the property is not the string "iterator".

Q3 After an iterator has returned { done: true }, what should .next() keep returning?

  1. A throw an error
  2. B the first value again
  3. C an object with done: true correct
  4. D undefined

Why: Iterators are one-shot — once done, stay done.

Q4 Which is true about iterators vs iterables?

  1. A They are the same thing
  2. B An iterable has [Symbol.iterator]() that returns an iterator correct
  3. C An iterator wraps an iterable via [Symbol.iterable]
  4. D Only arrays are iterables

Why: An iterable only promises a [Symbol.iterator]() factory; the object it hands back — the one with .next() — is the iterator. Strings, Maps and Sets are iterable too.

L3 — Write it from memory

One position, the code's third segment.

Write makeIter(arr) returning a manual iterator. Walk [10, 20, 30] by calling .next() until done is true, logging each value.

Hints
  • Track the index in a closure variable.
  • Loop until .next() returns { done: true }.
  • Each .next() call advances one element.
function makeIter(arr) {
  let i = 0;
  return {
    next() {
      return i < arr.length
        ? { value: arr[i++], done: false }
        : { value: undefined, done: true };
    }
  };
}
const it = makeIter([10, 20, 30]);
let step = it.next();
while (!step.done) {
  console.log(step.value);
  step = it.next();
}
