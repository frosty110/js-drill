Fast/slow pointers

Two pointers from head — slow advances by 1, fast by 2. The boilerplate behind cycle detection, midpoint, and Nth-from-end.

patterns Algorithms 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write middleValue(head) that returns the value at the midpoint using fast/slow pointers. For the even-length list 1→2→3→4, slow lands on the SECOND middle (value 3). Log the result.

Expected output: 3

Canonical solution

Two-pointer (tortoise & hare) walk · O(n) / O(1) (time / space)

// CANONICAL SKELETON
let slow = head, fast = head;
while (fast && fast.next) {
  slow = slow.next;        // +1
  fast = fast.next.next;   // +2
  // optional: if (slow === fast) ...   ← cycle meeting point
}

// THREE CLASSIC USES
// 1) CYCLE DETECTION
//    inside the loop: if (slow === fast) return true;
//    fall-through:    return false;
//
// 2) MIDDLE NODE
//    when fast reaches end, slow is at the midpoint.
//    For even length n, slow lands on the SECOND of the two middles
//    (index n/2). For odd length, slow is at the true center (index (n-1)/2).
//
// 3) NTH FROM END
//    advance fast by N first, THEN move both together until fast is null.
//    slow now points at the node N from the end.
  • The loop condition fast && fast.next is non-negotiable: fast.next must be non-null before you can dereference fast.next.next, or you'll throw.
  • If slow === fast inside the loop, a cycle exists (fast lapped slow). If the loop exits cleanly, no cycle.
  • For even-length lists, slow lands on the SECOND of the two middle nodes — predict this in interviews instead of guessing.
  • Compare nodes with === (reference equality), never by .val — two distinct nodes can share a value.

Alternate approaches

Cycle detection (Floyd) variant O(n) / O(1)

Same scaffold, different termination condition. Reach for this when the problem asks whether the list is circular (LeetCode 141 Linked List Cycle), or when 'O(1) extra space + linked list' appears in the constraints. The trick is the meeting argument: once both pointers are inside the cycle, the gap closes by exactly 1 per iteration, so they collide within C iterations where C is the cycle length. Beats the hash-set version (O(n) space → O(1) space) for the same O(n) time.

function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true;        // meeting point inside the cycle
  }
  return false;                            // fast hit null first — acyclic
}
// Same template body, different exit conditions — re-use it for the midpoint.
function middleValue(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow.val;
}
function toList(arr) { let d = { next: null }, c = d; for (const v of arr) { c.next = { val: v, next: null }; c = c.next; } return d.next; }
// Smoke: a known-acyclic list — hasCycle returns false, midpoint of [1,2,3,4] is 3.
console.log(hasCycle(toList([1, 2, 3, 4])) === false ? middleValue(toList([1, 2, 3, 4])) : 'cycle!');
  • Only ONE line changes vs the midpoint variant: if (slow === fast) return true; inside the loop, plus return false on fall-through. The skeleton is otherwise identical — that's what makes this a TEMPLATE, not three separate algorithms.
  • The meeting-argument proof: once both pointers are inside the cycle, every iteration shrinks the gap by exactly 1 (fast gains 2, slow gains 1, net +1). So they collide within at most C iterations, where C = cycle length ≤ n.
  • Use === (reference equality), NOT slow.val === fast.val. Two distinct nodes can hold the same value — a value-only check would give false positives on lists like 1→2→1→3 (no cycle, but two 1-valued nodes).

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Why must the loop condition be while (fast && fast.next)?

  1. A Equivalent to while (fast) — JS short-circuits both fast.next and fast.next.next to undefined on a missing chain
  2. B fast moves two .next hops; both must be legal or fast.next.next throws correct
  3. C To ensure slow and fast meet on the same node when the cycle length is even (without it, they pass through each other)
  4. D Without it, even-length lists return the first middle instead of the second

Why: Without the fast.next guard, dereferencing fast.next.next when fast.next is null throws a TypeError.

Q2 If slow === fast becomes true inside the loop, what does that prove?

  1. A The two pointers are on nodes that hold the same value (which may or may not indicate a cycle)
  2. B A cycle exists — fast lapped slow correct
  3. C Slow has reached the cycle's entry node (the start of the loop, not the meeting point)
  4. D The remaining nodes form a palindrome around the current position

Why: In a cyclic list the fast pointer eventually catches the slow pointer from behind. In an acyclic list fast hits null first.

Q3 For an even-length list (e.g., 1→2→3→4), where does slow end up when the loop exits cleanly (no cycle)?

  1. A On the first of the two middle nodes (node 2)
  2. B On the second of the two middle nodes (node 3) correct
  3. C Halfway between nodes 2 and 3 — there's no integer midpoint, so slow.next is null and slow.val is undefined
  4. D On the last node (node 4) — fast hits null one iteration after slow finishes the list

Why: After two iterations: slow goes head→2→3, fast goes head→3→null. slow ends at the second middle (node 3).

Q4 To find the Nth node from the end with fast/slow pointers, you:

  1. A Advance both together until fast hits null
  2. B Advance fast by N first, then advance both together until fast is null correct
  3. C Advance slow by N first, then move fast alone
  4. D Walk the list twice — once to count, once to index

Why: The N-step head start on fast is exactly the gap you want to preserve as both walk together.
