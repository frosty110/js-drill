Linked-list walk idioms

The three boilerplate walks every LL problem uses: single walk, parallel walk, and dummy-head builder.

patterns Algorithms 4 concept · 3 fill-in · 1 drill

Results carried by this link

Problem

Write doubleList(head) that returns a NEW list with each value doubled, using the dummy-head builder. Log JSON.stringify(toArr(doubleList(toList([1, 2, 3])))).

Expected output: [2,4,6]

Canonical solution

Single walk + dummy-head builder (sentinel kills the first-node branch) · O(n) / O(n) (time / space)

// 1) SINGLE WALK — visit every node in one list
let curr = head;
while (curr) {
  // visit curr
  curr = curr.next;
}

// 2) PARALLEL WALK — step two lists in lockstep (compare / merge)
let a = h1, b = h2;
while (a && b) {
  // compare a.val vs b.val
  a = a.next;
  b = b.next;
}
// one (or both) of a, b is null here — handle the remainder

// 3) DUMMY-HEAD BUILDER — assemble a new list with no first-node special case
const dummy = { val: 0, next: null };
let tail = dummy;
while (/* more to append */ false) {
  tail.next = { val: 0, next: null }; // attach new node
  tail = tail.next;                   // advance the tail
}
return dummy.next;                    // skip the sentinel
  • Single walk: while(curr) terminates safely on null — no need to test curr.next.
  • Parallel walk uses && so the loop stops the moment either list runs out; attach the remainder afterwards.
  • Dummy head is a sentinel — it eliminates the 'is this the first node?' branch and lets you always do tail.next = ....
  • Always advance tail = tail.next after attaching, or you'll overwrite the same slot next iteration.

Q1 Which loop condition safely walks a single linked list to the end?

  1. A while (curr.next)
  2. B while (curr) correct
  3. C while (curr && curr.next)
  4. D while (curr !== undefined)

Why: while(curr) terminates cleanly when curr becomes null; while(curr.next) would skip the last node and throw if head is null.

Q2 What does a dummy-head sentinel buy you when building a new list?

  1. A Lets you return the head pointer without walking back through the list
  2. B Removes the special case for inserting the first node correct
  3. C Reduces traversal cost from O(n) to O(n/2) by skipping the sentinel slot
  4. D Lets you delete from the front of the list in O(1) without losing the head reference

Why: With a sentinel you can always do tail.next = newNode without branching on 'is this the very first append?'.

Q3 When do you reach for the parallel walk while (a && b)?

  1. A Reversing a single list in place
  2. B Comparing or merging two lists in lockstep correct
  3. C Detecting a cycle in one list
  4. D Counting nodes in one list

Why: Parallel walk is for two-list problems — merge, compare, intersection — where you advance both pointers each iteration.

Q4 After building a list with a dummy head, what do you return?

  1. A dummy
  2. B tail
  3. C dummy.next correct
  4. D tail.next

Why: dummy is the sentinel; the real list starts at dummy.next.

L3 — Write it from memory

One position, the code's third segment.

Write doubleList(head) that returns a NEW list with each value doubled, using the dummy-head builder. Log JSON.stringify(toArr(doubleList(toList([1, 2, 3])))).

Hints
  • Combine single walk (curr = curr.next) with the dummy-head builder.
  • Attach a brand-new node each step; return dummy.next, not dummy.
function doubleList(head) {
  const dummy = { val: 0, next: null };
  let tail = dummy;
  let curr = head;
  while (curr) {
    tail.next = { val: curr.val * 2, next: null };
    tail = tail.next;
    curr = curr.next;
  }
  return dummy.next;
}
function toList(arr) { let d = { next: null }, c = d; for (const v of arr) { c.next = { val: v, next: null }; c = c.next; } return d.next; }
function toArr(h) { const o = []; while (h) { o.push(h.val); h = h.next; } return o; }
console.log(JSON.stringify(toArr(doubleList(toList([1, 2, 3])))));
