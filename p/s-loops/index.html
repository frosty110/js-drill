while / do-while

while tests before the body; do-while tests after (always runs once). break exits, continue skips to next iteration.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write countDown(n) using do-while that returns [n, n-1, ..., 1]. Log JSON.stringify(countDown(3)).

Expected output: [3,2,1]

Canonical solution

// while — check FIRST, may run zero times
let n = 0;
while (n < 3) {
  n += 1;
}
// n === 3

// do-while — body runs FIRST, then test (always at least one iteration)
let m = 10;
do {
  m -= 1;
} while (m > 20);
// m === 9  — body ran once even though the test was false

// break exits the nearest loop
let i = 0;
while (true) {        // intentional infinite loop
  if (i === 5) break; // ALWAYS have an exit
  i += 1;
}

// continue skips to the next iteration
let j = 0, evens = [];
while (j < 6) {
  j += 1;
  if (j % 2 === 1) continue;  // skip odd
  evens.push(j);              // 2, 4, 6
}
  • while may run zero times; do-while always runs at least once.
  • Every while (true) needs a guaranteed break or return path; otherwise the tab freezes.
  • With continue, advance the counter BEFORE the continue — otherwise you skip the increment and loop forever.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Which loop ALWAYS runs its body at least once?

  1. A while
  2. B for
  3. C do-while correct
  4. D for-of

Why: do-while tests AFTER the body, so the reference's m goes 10 → 9 even though m > 20 was false from the start. while, for and for-of all test before entering and can run zero times.

Q2 What happens with let i = 0; while (i < 5) { if (i === 2) continue; i += 1; } ?

  1. A Loops 5 times, skipping the i=2 iteration
  2. B Infinite loop — at i=2 continue triggers BEFORE i += 1, so i stays 2 forever correct
  3. C Throws ReferenceError
  4. D Loops 4 times and returns at continue

Why: Classic gotcha — advance the counter BEFORE the continue keyword, not after, or the increment is unreachable.

Q3 What does continue do?

  1. A Exits the loop
  2. B Skips the rest of this iteration and re-tests the condition correct
  3. C Skips the rest of this iteration AND skips re-testing — jumps straight to the next iteration's body
  4. D Same as break

Why: continue jumps to the condition check, not past it — that is exactly why the counter must be advanced before the continue, or the same test keeps passing. break is the one that leaves the loop.

Q4 Why is while (true) { /* no break */ } dangerous?

  1. A while (true) is a SyntaxError — the condition must be a comparison
  2. B It throws after ~10,000 iterations as a runaway-loop safeguard
  3. C It never exits — freezes the program correct
  4. D It runs once, then exits because true is treated as a one-shot guard

Why: Nothing can re-evaluate true to false, so the only exits are break or return — and with neither, the loop monopolises the single JS thread and the tab stops responding. The language ships no runaway-iteration safeguard.

L3 — Write it from memory

One position, the code's third segment.

Write countDown(n) using do-while that returns [n, n-1, ..., 1]. Log JSON.stringify(countDown(3)).

Hints
  • do { ... } while (n > 0) — body first, test after.
  • Push the current n, then decrement.
function countDown(n) {
  const out = [];
  do {
    out.push(n);
    n -= 1;
  } while (n > 0);
  return out;
}
console.log(JSON.stringify(countDown(3)));
