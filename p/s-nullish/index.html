Nullish coalescing ??

Nullish coalescing ?? returns the right side ONLY when the left is null or undefined — NOT on 0, "", or false.

syntax Modern Syntax 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write withDefault(v) returning v unless v is null or undefined (then "missing"). Log withDefault(0), withDefault(null), withDefault(undefined), withDefault("hi").

Expected output: 0 missing missing hi

Canonical solution

// ?? — fallback only on null/undefined
null ?? "fallback";        // "fallback"
undefined ?? "fallback";   // "fallback"
0 ?? "fallback";           // 0      ← preserved (|| would replace it)
"" ?? "fallback";          // ""     ← preserved
false ?? "fallback";       // false  ← preserved

// || — fallback on ANY falsy value (the classic bug)
0 || "default";            // "default"   ← oops, 0 was a valid count
"" || "default";           // "default"   ← oops, "" was a valid input

// Picking a default for a config field
function setVolume(v) {
  return v ?? 50;          // 0 stays 0; missing → 50
  // return v || 50;       // BUG: 0 becomes 50
}
setVolume(0);              // 0
setVolume(undefined);      // 50

// ?? does NOT mix with && or || without parens — syntax error
// a ?? b || c   ← SyntaxError; write (a ?? b) || c
  • ?? fires ONLY for null and undefined. || fires for ANY falsy value (0, "", false, NaN) — a frequent source of bugs.
  • Use ?? for defaults when 0, "", or false are valid values; use || when any falsy input should be replaced.
  • ?? cannot be combined with || or && without parentheses — JavaScript forces you to be explicit.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 What does 0 ?? 50 return?

  1. A 0 correct
  2. B 50
  3. C false — ?? coerces the left operand to boolean first
  4. D true — short-circuit returns the first truthy operand

Why: ?? only falls back on null/undefined, so a real 0 passes through — this is exactly why setVolume(0) returns 0 instead of the default 50.

Q2 What does 0 || 50 return?

  1. A 0 — || only falls back on null/undefined
  2. B 50 correct
  3. C true — || returns a boolean, not the operand
  4. D NaN — || numerically combines its operands

Why: || tests truthiness, and 0 is falsy, so the fallback fires and a valid count of 0 gets clobbered. || returns the operand, not a boolean — here that operand is 50.

Q3 Which values cause ?? to use the right-hand side?

  1. A Any falsy value
  2. B null and undefined only correct
  3. C Only undefined
  4. D 0 and ""

Why: Nullish means exactly null and undefined. NaN, 0, "" and false are falsy but NOT nullish, so ?? keeps the left side.

Q4 What does "" ?? "default" return?

  1. A "default" — empty string is nullish
  2. B "" correct
  3. C "" only if the literal is a tagged string, else "default"
  4. D Whichever is longer — ?? picks the more-defined operand

Why: An empty string is falsy but not nullish, so ?? hands it straight back. Swap in || and you get "default" — the bug this operator exists to prevent.
