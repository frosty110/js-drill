Number parsing & coercion

Every input is a string until you parse it — pick the right tool (parseInt, parseFloat, Number, unary `+`) and know why `Number.isNaN` is safer than the global `isNaN`.

Problem

Write toIntStrict(s) that returns the integer if s is a clean base-10 integer string (optional leading -), else null. Log results for '42', '-7', '3.14', ' 5 ', '5px'.

Expected output: 42 -7 null null null

Canonical solution

// parseInt — leading digits, stops at first non-digit
parseInt('42px', 10);     // 42
parseInt('  -7 ', 10);    // -7
parseInt('0.9', 10);      // 0   (stops at '.')
parseInt('abc', 10);      // NaN

// ALWAYS pass the radix — '0x10' would parse as hex without it
parseInt('0x10', 10);     // 0
parseInt('0x10');         // 16  (legacy hex detection)

// parseFloat — accepts decimals + exponent
parseFloat('3.14abc');    // 3.14
parseFloat('1e3');        // 1000

// Number — STRICT, whole string must be numeric (trims whitespace)
Number('42');             // 42
Number('42px');           // NaN  (unlike parseInt)
Number('');               // 0    (gotcha)
Number('  3.14  ');       // 3.14

// Unary + — same as Number(x), shorter
+'5';                     // 5
+'';                      // 0
+'5px';                   // NaN

// Validation helpers (DO NOT coerce — false for non-numbers)
Number.isInteger(3);       // true
Number.isInteger(3.0);     // true   (3.0 === 3)
Number.isInteger('3');     // false  (no coercion)
Number.isFinite(Infinity); // false
Number.isFinite('1');      // false  (no coercion)
Number.isNaN(NaN);         // true
Number.isNaN('foo');       // false  (no coercion)
isNaN('foo');              // true   (global — coerces first, surprise)
  • Always pass the radix to parseInt(s, 10) — otherwise '08' and '0x10' get parsed oddly across engines.
  • Number('') and Number(' ') are 0, not NaN. Reject empty input explicitly.
  • Prefer Number.isNaN(x) over global isNaN(x) — the global coerces first so isNaN('foo') is misleadingly true.

Q2 What is Number('42px')?

  1. A 42
  2. B NaN correct
  3. C '42px'
  4. D 0

Why: Number is strict — the whole string must be numeric (whitespace-trimmed).

Q3 What is Number('')?

  1. A NaN
  2. B 0 correct
  3. C undefined
  4. D throws

Why: Empty/whitespace-only strings coerce to 0. Validate first.

Q4 Why prefer Number.isNaN(x) over global isNaN(x)?

  1. A Global isNaN was deprecated in ES2020
  2. B Number.isNaN does not coerce; global isNaN does correct
  3. C Global isNaN returns false for actual NaN values (the historical bug)
  4. D They are identical

Why: isNaN('foo') is true because it coerces; Number.isNaN('foo') is false.

L3 — Write it from memory

One position, the code's third segment.

Write toIntStrict(s) that returns the integer if s is a clean base-10 integer string (optional leading -), else null. Log results for '42', '-7', '3.14', ' 5 ', '5px'.

Hints
  • Validate with a regex (/^-?\d+$/) before coercing.
  • Number(s) is fine once you have confirmed the shape.
function toIntStrict(s) {
  if (typeof s !== 'string' || !/^-?\d+$/.test(s)) return null;
  return Number(s);
}
for (const v of ['42', '-7', '3.14', ' 5 ', '5px']) {
  console.log(toIntStrict(v));
}
