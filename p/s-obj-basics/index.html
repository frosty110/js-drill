Object literals

Object literals — shorthand properties, computed keys, method shorthand, and dot vs bracket access.

syntax Hash Structures 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write makeUser(name, age) returning an object with shorthand properties and a method greet() returning "hi " + this.name. Log makeUser("Ada", 36).greet().

Expected output: hi Ada

Canonical solution

const name = "Ada";
const age = 36;

// 1) Shorthand properties — { name } is { name: name }
const user = { name, age };

// 2) Computed keys — evaluate an expression as the key
const k = "score";
const o = { [k]: 100, ["is_" + k]: true };
// → { score: 100, is_score: true }

// 3) Method shorthand — no function keyword, no colon
const calc = {
  add(a, b) { return a + b; },
  greet() { return "hi " + this.name; }
};

// 4) Access: dot vs bracket
user.name;          // dot — key must be a valid identifier literal
user["name"];       // bracket — key is any string EXPRESSION
user[k];            // bracket lets you use a variable as the key
  • Dot access requires a literal identifier; bracket access takes any expression.
  • Computed keys [expr] run at object-creation time; the result is coerced to a string (or Symbol).
  • Method shorthand defines a normal function — this refers to the object when called as obj.method().

Q1 What does { name } expand to when name is a variable holding "Ada"?

  1. A { name: undefined }
  2. B { name: "Ada" } correct
  3. C { "name": "name" }
  4. D A syntax error

Why: Shorthand expands to { name: name } — the key is the identifier's text, the value is whatever that variable currently holds.

Q2 Given const k = "x", which literal sets key "x" to 1?

  1. A { k: 1 }
  2. B { [k]: 1 } correct
  3. C { "k": 1 }
  4. D { k() { return 1; } }

Why: Only the brackets evaluate k. { k: 1 } and { "k": 1 } both take the identifier literally and produce the key "k", not "x".

Q3 When MUST you use bracket access instead of dot?

  1. A Never — they are interchangeable; dot is just less typing
  2. B When the key is in a variable or not a valid identifier correct
  3. C When the value is a function — bracket access binds this correctly
  4. D When the object was created with Object.create(null) — dot fails on prototype-less objects

Why: Dot needs a literal identifier after it, so user.k looks up the key "k" and never the value of k; bracket takes any expression and coerces the result to a string. Dot works fine on Object.create(null) objects.

Q4 Method shorthand greet() { ... } is equivalent to:

  1. A greet: () => { ... }
  2. B greet: function() { ... } correct
  3. C A getter — accessing obj.greet would invoke the body
  4. D greet: function greet() { ... } — the shorthand adds a name binding inside the function

Why: Shorthand defines an ordinary non-arrow function, so this is the receiver at call time — that's why makeUser("Ada", 36).greet() can read this.name and an arrow could not. It sets .name but, unlike a named function expression, adds no self-reference binding inside the body.

Hints
  • Shorthand: { name, age } takes values from same-named variables.
  • Method shorthand: greet() { ... } — no function keyword.
function makeUser(name, age) {
  return {
    name,
    age,
    greet() { return "hi " + this.name; }
  };
}
console.log(makeUser("Ada", 36).greet());
