Optional chaining ?.

Optional chaining ?. short-circuits to undefined the moment any link is null or undefined — for properties, methods, and indexing.

syntax Modern Syntax 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write cityOf(user) returning user.address.city or undefined if any link is missing. Log cityOf({ address: { city: "Paris" } }), cityOf(null), and cityOf({}).

Expected output: Paris undefined undefined

Canonical solution

// Property access — bail out on null/undefined instead of throwing
const user = { name: "Ada" };
user?.name;              // "Ada"
user?.address?.city;     // undefined  (no error — address is missing)

// Without ?. you would crash:
// user.address.city;    // TypeError: Cannot read properties of undefined

// Method invocation — only call if the function exists
const obj = { fn: () => 7 };
obj?.fn?.();             // 7
obj?.missing?.();        // undefined

// Array indexing — bracket form with ?.[]
const arr = [10, 20, 30];
arr?.[1];                // 20
const maybe = null;
maybe?.[0];              // undefined

// Short-circuit: the WHOLE chain stops at the first nullish link
null?.a.b.c.d();         // undefined
  • Only null and undefined trigger short-circuit — 0, "", false, NaN do NOT (they are valid values).
  • Use ?.() for methods and ?.[i] for indexed access — the dot belongs before the bracket or paren.
  • Do not over-chain: if user.address is REQUIRED, let it throw — silently masking bugs makes them harder to find.
