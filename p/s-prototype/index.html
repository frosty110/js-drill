Prototype chain

Every object has a hidden link to a prototype. Property lookup walks this chain until found or null. class extends sets it up; hasOwnProperty filters own keys, `in` walks the chain.

Problem

Define class Animal { constructor(name); describe() } and class Dog extends Animal { bark() }. Build new Dog("Rex") and log describe() then bark().

Expected output: Rex is an animal Rex says woof

Canonical solution

// Every object has a prototype — Object.getPrototypeOf reads it.
const arr = [1, 2, 3];
Object.getPrototypeOf(arr) === Array.prototype;          // true
Object.getPrototypeOf(Array.prototype) === Object.prototype;  // true

// class extends wires the chain for you.
class Animal {
  speak() { return "noise"; }
}
class Dog extends Animal {
  speak() { return "woof"; }                              // overrides Animal.speak
}
const d = new Dog();
d.speak();                                                // "woof" — found on Dog.prototype
Object.getPrototypeOf(Dog.prototype) === Animal.prototype;// true

// hasOwnProperty vs in: own keys vs the whole chain.
const proto = { inherited: 1 };
const obj = Object.create(proto);
obj.own = 2;
obj.hasOwnProperty("own");        // true
obj.hasOwnProperty("inherited");  // false — lives on proto
"inherited" in obj;               // true — in walks the chain
  • Lookup walks: instance → ClassName.prototype → ParentClass.prototype → Object.prototype → null.
  • Methods declared in a class body live on the prototype (shared), not on each instance.
  • hasOwnProperty checks only own keys; in returns true for inherited keys too.

Q1 Where does d.speak() find speak for const d = new Dog()?

  1. A On the instance d itself
  2. B On Dog.prototype correct
  3. C On Animal.prototype
  4. D On Object.prototype

Why: Lookup starts at the instance — which owns no methods — and stops at the FIRST hit, Dog.prototype.speak, so Animal.prototype.speak is never reached. That is all an override is.

Q2 What does class Dog extends Animal {} do to the prototype chain?

  1. A Replaces Dog.prototype with Animal.prototype, so Dog inherits everything
  2. B Sets Object.getPrototypeOf(Dog.prototype) to Animal.prototype correct
  3. C Sets Dog.prototype to Animal
  4. D Copies Animal methods to every Dog instance

Why: Dog.prototype stays its own distinct object — extends only LINKS it to Animal.prototype. Replacing it outright would leave Dog nowhere to hang its own speak.

Q3 Difference between obj.hasOwnProperty(k) and k in obj?

  1. A in only checks own keys; hasOwnProperty also walks getters
  2. B hasOwnProperty checks own keys only; in walks the prototype chain correct
  3. C in ignores non-enumerable keys, hasOwnProperty includes them
  4. D hasOwnProperty walks the chain

Why: In the reference, obj.hasOwnProperty("inherited") is false while "inherited" in obj is true — in is the one that walks up to proto.

Q4 A method declared inside a class body lives on:

  1. A Each instance directly
  2. B The prototype (shared across instances) correct
  3. C The class constructor itself (like a static)
  4. D A fresh closure created for every new call

Why: One function object on Dog.prototype, shared by every instance — Object.getOwnPropertyNames(new Dog()) comes back empty. Only fields assigned in the constructor are per-instance.

L3 — Write it from memory

One position, the code's third segment.

Define class Animal { constructor(name); describe() } and class Dog extends Animal { bark() }. Build new Dog("Rex") and log describe() then bark().

Hints
  • Dog inherits describe() automatically through the prototype chain.
  • Without an explicit Dog constructor, it forwards (name) to Animal.
class Animal {
  constructor(name) { this.name = name; }
  describe() { return this.name + " is an animal"; }
}
class Dog extends Animal {
  bark() { return this.name + " says woof"; }
}
const d = new Dog("Rex");
console.log(d.describe());
console.log(d.bark());
