Recursion basics

A function that calls itself — every recursion needs a base case to stop and a recursive case that shrinks the input toward it.

syntax Basics 4 concept · 2 fill-in · 1 drill

Problem

Write fib(n) returning the nth Fibonacci number (fib(0)=0, fib(1)=1). Log fib(10).

Expected output: 55

Canonical solution

// Canonical: factorial
function factorial(n) {
  if (n <= 1) return 1;             // BASE case — stops the recursion
  return n * factorial(n - 1);      // RECURSIVE case — smaller subproblem
}
factorial(5);  // 120

// Without a base case → "Maximum call stack size exceeded"

// Fibonacci — exponential without memoization
function fib(n) {
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}

// "Tail call" form — recursive call is the LAST action.
// The ES2015 spec allows tail-call elimination, but V8 / Node / most
// browsers DO NOT implement it, so deep recursion can still overflow.
function factTail(n, acc = 1) {
  if (n <= 1) return acc;
  return factTail(n - 1, n * acc);
}
  • Always write the base case FIRST — it is the easiest way to spot missing exits.
  • Each recursive call must move CLOSER to the base case, or you get infinite recursion → stack overflow.
  • Tail-call optimization is in the spec but NOT in V8/Node — deep recursion can still blow the stack. Prefer iteration for huge inputs.

Q1 What happens if a recursive function has no base case?

  1. A It returns undefined
  2. B It loops forever
  3. C It throws "Maximum call stack size exceeded" correct
  4. D The engine optimizes it away

Why: Every call parks a frame on the stack waiting for the one below it to return, so the stack exhausts and a RangeError is thrown. It does not spin quietly forever the way a while loop with no exit does.

Q2 factorial(5) equals:

  1. A 25
  2. B 60
  3. C 120 correct
  4. D 720

Why: 5 * 4 * 3 * 2 * 1 = 120.

Q3 A "tail call" means:

  1. A A call placed at the end of a .then(...) chain
  2. B The recursive call is the last thing the function does correct
  3. C Any call whose result is used inside a return expression (e.g., return n * f(n-1))
  4. D The function takes an accumulator

Why: In factTail the recursive call IS the returned value — nothing is pending after it. return n * factorial(n - 1) is NOT a tail call: the multiply still has to run once the call comes back, which is why an accumulator is the usual way to get there, not the definition of it.

Q4 Does V8 / Node currently implement tail-call optimization?

  1. A Yes, fully
  2. B Only in strict mode
  3. C No correct
  4. D Only for arrow functions

Why: The ES2015 spec allows it, but mainstream engines never shipped it.
