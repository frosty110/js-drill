Array-as-stack

A plain array becomes a stack with push + pop on the same end — LIFO, both O(1).

Problem

Write reverseString(s) using a stack: push every char, then pop them back into a result string. Log reverseString("hello").

Expected output: olleh

Canonical solution

Array-as-stack — push/pop the same end, drain with while (stack.length) · O(n) / O(n) (time / space)

// Stack = LIFO (Last In, First Out)
const stack = [];

stack.push(1);     // [1]
stack.push(2);     // [1, 2]
stack.push(3);     // [1, 2, 3]

stack.pop();       // 3 → stack is [1, 2]
stack.pop();       // 2 → stack is [1]

// Peek without removing
stack[stack.length - 1];  // 1
stack.at(-1);             // 1 (cleaner)

// Empty check
while (stack.length) { /* drain */ }

// Classic uses:
//   - Bracket matching:  push opens, pop on close, compare pair
//   - Backtracking / DFS: push frame, pop when done
//   - Undo history:       push state, pop to revert
  • Both push and pop are O(1) amortized — the fastest array pattern.
  • Use stack.length as the truthy "non-empty" check; stack.at(-1) to peek.
  • When the problem says "most recent", "matching pairs", or "undo", reach for a stack.

Q1 Which pair of methods turns an array into a stack?

  1. A push / shift
  2. B push / pop correct
  3. C unshift / pop
  4. D shift / unshift

Why: push and pop both act on the END of the array, so the last value in is the first out. Pairing push with shift takes from the front instead — that's a queue, and shift costs O(n) per call.

Q2 A stack is which ordering?

  1. A FIFO — first in, first out
  2. B LIFO — last in, first out correct
  3. C Priority order — the lowest-priority item pops first, like Dijkstra's frontier
  4. D Insertion order with deduplication — repeated pushes of the same value are merged

Why: Last in, first out — which is why reverseString gets the reversal for free: push every char in order, then while (stack.length) out += stack.pop() drains them back in the opposite order.

Q3 Time complexity of stack.push and stack.pop?

  1. A O(n) each
  2. B O(log n) each
  3. C O(1) amortized each correct
  4. D push is O(1), pop is O(n)

Why: Both touch only the last slot, so no element is ever re-indexed. "Amortized" covers the occasional geometric re-allocation when the backing array grows — spread over many pushes, the average stays constant.

Q4 Which problem is the most natural fit for a stack?

  1. A Level-order tree traversal
  2. B Matching balanced brackets correct
  3. C Finding the kth smallest element in a stream
  4. D Detecting whether a linked list has a cycle

Why: Nesting is inherently last-opened-first-closed, so you push each opener and pop-and-compare on each closer. Level-order traversal is the queue case; cycle detection is fast/slow pointers.

L3 — Write it from memory

One position, the code's third segment.

Write reverseString(s) using a stack: push every char, then pop them back into a result string. Log reverseString("hello").

Hints
  • Push every char onto an array.
  • Drain with pop while stack.length is truthy.
function reverseString(s) {
  const stack = [];
  for (const ch of s) stack.push(ch);
  let out = "";
  while (stack.length) out += stack.pop();
  return out;
}
console.log(reverseString("hello"));
