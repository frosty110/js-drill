String basics

Strings are immutable primitives — make them with literals or String(); read with .length and [i]; iterate with for...of.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write firstChar(s) returning the first character of s. Log firstChar("hello"), firstChar("Z"), and typeof "x" === "string".

Expected output: h Z true

Canonical solution

// Two ways to make a string
const a = "hello";           // literal — preferred
const b = String(123);       // "123"  — coerces anything to string
typeof a;                    // "string"  (primitive)

// length and index access
"hello".length;              // 5
"hello"[0];                  // "h"
"hello"[10];                 // undefined  (no out-of-bounds error)

// Iteration with for...of yields each character
let out = "";
for (const ch of "abc") out += ch + "-";
// out === "a-b-c-"

// Immutability — methods return NEW strings; the original is unchanged
const s = "hi";
s.toUpperCase();             // "HI"   — s is still "hi"
// s[0] = "X";               // silently fails (TypeError in strict mode)

// Primitive vs wrapper — avoid new String()
const w = new String("hi");  // object wrapper, typeof "object"
  • Prefer string literals over new String() — the wrapper object breaks === comparisons and has typeof "object".
  • Strings are immutable: s[0] = "X" does nothing; every transform returns a fresh string.
  • Out-of-bounds indexing returns undefined, not an error — guard with .length when iterating manually.

Q1 What does new String("hi") === "hi" return?

  1. A true — both are the string 'hi'
  2. B false — the wrapper object is not the primitive correct
  3. C true — === unwraps the String object before comparing
  4. D false — but new String("hi") == "hi" is also false

Why: new String() creates an object wrapper; typeof is 'object'. Reference-equality against the primitive 'hi' is always false. Avoid new String().

Q2 What does "hello"[10] return?

  1. A ""
  2. B undefined correct
  3. C It throws RangeError
  4. D null

Q3 After const s = "hi"; s.toUpperCase(); what is s?

  1. A "HI"
  2. B "hi" correct
  3. C undefined — the return value was discarded
  4. D "HI" — .toUpperCase() mutates in place when the receiver is a let/const

Q4 Which loop iterates the CHARACTERS of a string?

  1. A for (const ch in s) — yields each character
  2. B for (const ch of s) — yields each character correct
  3. C s.forEach(ch => ...) — works on strings too
  4. D for (let i = 0; i <= s.length; i++) — bracket-access in body

Why: for-in returns string KEYS ('0','1',...), not values. forEach is array-only. The for-loop has an off-by-one (<= instead of <). for...of is the canonical char iterator.
