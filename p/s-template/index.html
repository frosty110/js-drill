Template literals

Backtick strings with ${expr} interpolation, real multi-line support, and tagged-template hooks for custom processing.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write greet(user) returning "Hi <name>, you have <msgs> messages." using a template literal. Log greet({ name: "Ada", msgs: 3 }).

Expected output: Hi Ada, you have 3 messages.

Canonical solution

// Backticks enable interpolation and multi-line strings
const name = "Sam";
const age = 30;
const greeting = `Hello, ${name}! You are ${age}.`;
// "Hello, Sam! You are 30."

// Any expression works inside ${ ... }
`2 + 3 = ${2 + 3}`;                 // "2 + 3 = 5"
`upper: ${name.toUpperCase()}`;     // "upper: SAM"

// Multi-line — newlines are preserved literally
const block = `line 1
line 2
line 3`;

// Tagged template — the tag function receives the parts and values
function tag(strings, ...values) {
  return strings.raw[0] + values.join("|");
}
tag`a${1}b${2}c`;                   // "a1|2"  (raw[0]="a")
  • Use backticks (`), not single or double quotes — only backticks enable ${} and multi-line.
  • Escape a literal backtick with \` and a literal $ with \$ when needed.
  • Tagged templates are rarely used in app code; you will see them in libraries (styled-components, GraphQL gql).

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 Which quote enables ${} interpolation?

  1. A Single quote
  2. B Double quote
  3. C Backtick correct
  4. D Either single or double

Why: Only backticks parse ${...}. Inside single or double quotes it stays literal text — and you lose real multi-line too, since backticks buy both.

Q2 What can go inside ${ ... }?

  1. A Only variable names
  2. B Only string literals
  3. C Any JS expression correct
  4. D Only function calls

Why: Any expression — the reference interpolates 2 + 3 and name.toUpperCase(), not just bare identifiers. Statements are the limit: if or for inside ${} is a SyntaxError, so ternaries are how you branch there.

Q3 Do backtick strings preserve newlines?

  1. A No — you must use \n
  2. B Yes — newlines are literal correct
  3. C Only in strict mode
  4. D Only with a tag function

Why: A newline typed between backticks IS a newline in the value — the reference's block literal spans three lines with no escapes. No mode or tag is required; that is plain template-literal behaviour.

Q4 What is the type of an untagged template literal expression?

  1. A object
  2. B An array of [strings, ...values] until coerced
  3. C string correct
  4. D Whatever the literal's first interpolated expression evaluates to

Why: Interpolation runs immediately and every value is stringified, so the result is a plain string whatever you embed. Only a TAG function ever sees the strings array and the values separately — and a tag can return any type it likes.

L3 — Write it from memory

One position, the code's third segment.

Write greet(user) returning "Hi <name>, you have <msgs> messages." using a template literal. Log greet({ name: "Ada", msgs: 3 }).

Hints
  • Backticks around the whole string.
  • Two ${} slots — one for name, one for msgs.
function greet(user) {
  return `Hi ${user.name}, you have ${user.msgs} messages.`;
}
console.log(greet({ name: "Ada", msgs: 3 }));
