this / bind / call / apply

this is decided by how a function is CALLED. Four call patterns (method, standalone, new, explicit) + the arrow gotcha (lexical capture).

Problem

Inside obj.greet(), declare an arrow function that reads this.name, then return its call. Log obj.greet() for { name: "Ada" }.

Expected output: Ada

Canonical solution

const user = {
  name: "Ada",
  greet() { return "Hi " + this.name; }      // method call → this = user
};

user.greet();                                // "Hi Ada"

const detached = user.greet;
detached();                                  // standalone → this is undefined (strict)

// Fix 1: bind returns a NEW function with this locked
const bound = user.greet.bind(user);
bound();                                     // "Hi Ada"

// Fix 2: call / apply invoke once with an explicit this
function intro(greet, punct) {
  return greet + " " + this.name + punct;
}
intro.call(user, "Hello", "!");              // "Hello Ada!"
intro.apply(user, ["Hey", "."]);             // "Hey Ada." — array form

// Arrow functions IGNORE call/bind — they capture this lexically
const obj = {
  name: "Lee",
  greet() { return (() => this.name)(); }    // arrow → this = obj
};
  • this is bound at CALL time for normal functions; arrow functions capture this at DEFINITION time.
  • bind returns a new function; call/apply invoke immediately. apply takes args as an array.
  • Passing a method as a callback (setTimeout, map) detaches it — wrap in arrow or bind to preserve this.

Q1 When is this resolved for a regular (non-arrow) function?

  1. A Lexically — captured from the enclosing scope at definition
  2. B When the function is called — based on how it is called correct
  3. C Always the global object in strict mode
  4. D Whichever object owns the variable that holds the function

Why: The call site decides: user.greet() binds this to user, but the very same function stored in detached and called bare no longer sees user at all.

Q2 Difference between call and apply?

  1. A call binds permanently, apply does not
  2. B apply takes args as an array; call takes them comma-separated correct
  3. C apply spreads array args; call also accepts an array but spreads it the same way
  4. D apply ignores the first argument (thisArg); call uses it

Why: intro.call(user, "Hello", "!") vs intro.apply(user, ["Hey", "."]) — identical this, identical immediate invocation; only the argument packaging differs (A for apply/array, C for call/comma).

Q3 What does bind return?

  1. A The result of calling the function with the given this
  2. B A Proxy that intercepts calls and substitutes this
  3. C A new function with this (and optional args) locked in correct
  4. D The original function mutated in place

Why: bind does not invoke — it hands back a fresh function object and leaves the original untouched, which is why the reference has to call bound() on its own line.

Q4 Inside obj.greet() { return (() => this.name)(); }, the arrow’s this is:

  1. A undefined — the IIFE is a standalone call, so this is unbound
  2. B The global object — the arrow is invoked without a receiver
  3. C obj — arrows inherit this from the enclosing scope correct
  4. D The arrow function object itself, since arrows self-bind

Why: Arrows have no this of their own, so the lookup goes out to the enclosing greet() frame — where the method call already set this to obj. Invoking the arrow as an IIFE cannot change that.

Inside obj.greet(), declare an arrow function that reads this.name, then return its call. Log obj.greet() for { name: "Ada" }.

Hints
  • Arrow functions do not have their own this — they inherit it from the enclosing method.
  • Inside greet(), this is obj because of the method call.
const obj = {
  name: "Ada",
  greet() {
    const arrow = () => this.name;
    return arrow();
  }
};
console.log(obj.greet());
