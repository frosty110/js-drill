try / catch

try/catch handles thrown errors; the catch parameter exposes .message; finally always runs. Works with async/await too.

syntax Async 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write async function loadJSON(text) that returns the parsed .value, or "bad: " + e.name on failure. Always log "checked" in finally. Run once with {"value":42}, once with "oops".

Expected output: checked 42 checked bad: SyntaxError

Canonical solution

// Synchronous error handling
try {
  JSON.parse("not json");
} catch (err) {
  // err.message — human-readable
  // err.name, err.stack also available
} finally {
  // runs whether try succeeded, threw, or returned
}

// Throw your own errors
function divide(a, b) {
  if (b === 0) throw new Error("div by zero");
  return a / b;
}

// finally runs even when try returns
function f() {
  try {
    return "from try";
  } finally {
    // this line runs BEFORE the function returns
  }
}

// Async usage — await throws into the surrounding try
async function loadUser(id) {
  try {
    const res = await fetch("/api/user/" + id);
    return await res.json();
  } catch (e) {
    return { error: e.message };
  } finally {
    // always runs
  }
}
  • The catch binding is optional in modern JS — write catch {} if you do not need the error.
  • finally runs even when try contains return or throw — perfect for cleanup.
  • await unwraps a rejected promise into a thrown error — wrap awaits in try/catch to handle failures.

L1 — Concept questions 4

Positions 1–4 of the code's first segment. The correct option is marked; in the app the options are shuffled, but the lettering here is the authored order the code refers to.

Q1 When does the finally block run?

  1. A Only if try succeeds
  2. B Only if catch runs
  3. C Always — even after throw or return correct
  4. D Only on uncaught errors

Why: finally runs on the way out however the block exits — including after try has already evaluated its return value, which is why the L3 canonical logs checked before 42.

Q2 How do you read the error message inside catch (e)?

  1. A e.description
  2. B e.message correct
  3. C e.reason
  4. D e.toString() — the only reliable way; Error has no message property

Why: new Error(msg) sets message right on the error object. toString() also works but prefixes the name — "SyntaxError: Unexpected token..." — so it is not the raw text.

Q3 How do you signal an error inside a function?

  1. A return new Error(...) — callers branch on instanceof Error
  2. B throw new Error(...) correct
  3. C Promise.reject(new Error(...)) — the only catchable form from a sync function
  4. D Throw the message string directly: throw "div by zero"

Why: throw unwinds to the nearest catch without the caller opting in. Returning an Error makes every call site remember to check, and throwing a bare string leaves the handler with no .message, .name or stack.

Q4 Inside async function f() { try { await p } catch (e) { ... } }, when does catch run?

  1. A Never — rejections from an awaited promise bypass try/catch and need .catch()
  2. B When p rejects correct
  3. C Only if the await line itself throws a synchronous TypeError before p settles
  4. D When p resolves to an Error instance — resolved errors are auto-thrown

Why: await rethrows a rejection at the await point, which is inside the try, so catch (e) receives the rejection reason. Resolving WITH an Error is just a normal fulfilled value — nothing is thrown.

L3 — Write it from memory

One position, the code's third segment.

Write async function loadJSON(text) that returns the parsed .value, or "bad: " + e.name on failure. Always log "checked" in finally. Run once with {"value":42}, once with "oops".

Hints
  • finally logs BEFORE the function returns its value.
  • Use an async IIFE to await at the top level.
  • e.name is "SyntaxError" — stable across engines (e.message wording is not).
async function loadJSON(text) {
  try {
    return JSON.parse(text).value;
  } catch (e) {
    return "bad: " + e.name;
  } finally {
    console.log("checked");
  }
}
(async () => {
  console.log(await loadJSON("{\"value\":42}"));
  console.log(await loadJSON("oops"));
})();
