Variables & types

let, const, and var differ in scope and reassignment — const locks the binding, not the contents.

syntax Basics 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write describe(v) that returns typeof v. Log describe(1), describe("a"), describe(true), describe(null) on one line.

Expected output: number string boolean object

Canonical solution

// let — block-scoped, reassignable
let x = 1;
x = 2;             // OK

// const — block-scoped, binding is locked
const y = 3;
// y = 4;          // TypeError: Assignment to constant variable

// const on an object locks the BINDING, not the contents
const obj = { n: 1 };
obj.n = 2;         // OK — mutating the object is fine
// obj = {};       // TypeError — cannot rebind

// var — function-scoped, hoisted, avoid in modern code
function f() { if (true) { var v = 1; } return v; }  // 1

// typeof — the seven primitive-ish tags
typeof 1;          // "number"
typeof "a";        // "string"
typeof true;       // "boolean"
typeof undefined;  // "undefined"
typeof null;       // "object"   ← historical bug
typeof {};         // "object"
typeof function(){};// "function"
  • const locks the binding, not the value — you can still mutate the object or array it points to.
  • typeof null returns "object" — a famous historical quirk. Test for null with x === null.
  • var is function-scoped and hoisted; let and const are block-scoped and live in a temporal dead zone until declared.

Q1 Which of these is legal after const obj = { n: 1 };?

  1. A obj = { n: 2 }
  2. B obj.n = 2 correct
  3. C const obj = { n: 2 }
  4. D obj = Object.assign(obj, { n: 2 })

Why: const locks the BINDING, not the contents — mutating properties is fine.

Q2 What does typeof null return?

  1. A "null"
  2. B "undefined"
  3. C "object" correct
  4. D "boolean"

Why: A historical bug preserved for compatibility.

Q3 Which keyword is FUNCTION-scoped (not block-scoped)?

  1. A let
  2. B const
  3. C var correct
  4. D All three are block-scoped

Why: var ignores block boundaries — the reference's f() returns 1 even though v was declared inside the if. let or const there would throw ReferenceError.

Q4 What does typeof undefined return?

  1. A "undefined" correct
  2. B "null"
  3. C "object"
  4. D undefined

Why: typeof always evaluates to a STRING, so the answer is the quoted "undefined", not the value undefined. null is the only tag that lies — it reports "object".
