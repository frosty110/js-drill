delete arr[i] leaves holes

`delete arr[i]` does not shift later elements or shrink `length` — it leaves a sparse hole where the slot reads as `undefined`, and most array methods silently skip it. Use `splice` (mutate) or `filter` (new array) to actually remove an element.

Problem

Write removeAt(arr, i) that removes the element at index i from arr IN PLACE (no holes, length shrinks) and returns the mutated array. Then call it on [10, 20, 30, 40] removing index 1 and log JSON.stringify(result) and result.length on separate lines.

Expected output: [10,30,40] 3

Canonical solution

// `delete` was designed for object properties. On an array it removes
// the slot BUT leaves the length alone — you get a sparse "hole".
const a = [1, 2, 3];
delete a[1];
console.log(JSON.stringify(a));  // [1,null,3] — JSON.stringify writes holes as null
console.log(a.length);           // 3  (NOT 2 — length unchanged)
console.log(a[1]);               // undefined  (the hole reads as undefined)

// How iteration methods treat the hole — silently inconsistent:
const b = [1, 2, 3];
delete b[1];
let feCount = 0;
b.forEach(() => feCount++);
console.log(feCount);                       // 2  (forEach SKIPS holes)
console.log(JSON.stringify(b.map(x => x))); // [1,null,3]  (map PRESERVES holes)
console.log(JSON.stringify(b.filter(() => true))); // [1,3]  (filter SKIPS holes)
let forCount = 0;
for (let i = 0; i < b.length; i++) forCount++;
console.log(forCount);                      // 3  (index-for VISITS the hole as undefined)

// The fix — splice mutates in place AND shifts + shrinks length.
const c = [1, 2, 3];
c.splice(1, 1);
console.log(JSON.stringify(c), c.length);   // [1,3] 2

// Or filter, for a non-mutating new array.
const d = [1, 2, 3];
const e = d.filter((_, i) => i !== 1);
console.log(JSON.stringify(e));             // [1,3]
  • delete arr[i] was inherited from object-property semantics — on arrays it almost never does what you want.
  • Length is unchanged after delete, so loops over arr.length still visit the hole (as undefined).
  • JSON.stringify serializes holes as null — that's why [1, , 3] prints as [1,null,3] in the runner.
  • Iteration methods are split: forEach, map (preserves but doesn't invoke the callback), filter, reduce, some, every SKIP holes; index-based for and for...of VISIT them.
  • Array.from(arr) and the spread [...arr] MATERIALIZE holes into real undefined slots — useful when you need consistent iteration.
  • To actually remove by index, use arr.splice(i, 1) (mutates, returns the removed slice) or arr.filter((_, j) => j !== i) (new array).

  1. A 2

Q3 Which expression removes the element at index 1 AND shifts later elements down?

  1. A delete a[1]
  2. B a.splice(1, 1) correct
  3. C a[1] = null
  4. D a.length--

Why: splice(1, 1) removes one element at index 1 and shifts the rest left, decrementing length. The other three leave the array in a broken state.

Q4 After const a = [1, 2, 3]; delete a[1];, how many times does a.forEach(fn) call fn?

  1. A 3 — once per index
  2. B 2 — forEach skips holes correct
  3. C 1 — only the first defined element
  4. D 0 — forEach throws on sparse arrays

Why: forEach, map (callback), filter, and reduce all silently skip holes. That's why delete produces hard-to-spot bugs — the count is just off by one.

L3 — Write it from memory

One position, the code's third segment.

Write removeAt(arr, i) that removes the element at index i from arr IN PLACE (no holes, length shrinks) and returns the mutated array. Then call it on [10, 20, 30, 40] removing index 1 and log JSON.stringify(result) and result.length on separate lines.

Hints
  • delete arr[i] is the trap this lesson is about — don't reach for it.
  • splice(i, 1) mutates the array, removing 1 element at index i and shifting later elements left.
  • splice returns the REMOVED slice, not the mutated array — return arr directly.
function removeAt(arr, i) {
  arr.splice(i, 1);
  return arr;
}

const result = removeAt([10, 20, 30, 40], 1);
console.log(JSON.stringify(result));
console.log(result.length);
