Temporal Dead Zone (TDZ)

let and const bindings exist from block-entry but throw ReferenceError until their declaration line is reached — unlike var, which hoists with the value undefined.

syntax JS Traps 4 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write inTdz(fn) that calls fn and returns the error name if it throws, otherwise the string "ok". Use it to prove all three TDZ cases throw ReferenceError: reading a let, typeof on a let, and reading a const — each before its declaration. Log the three results, one per line.

Expected output: ReferenceError ReferenceError ReferenceError

Canonical solution

// var hoists with the value `undefined` — no error
console.log(a); // undefined
var a = 1;
console.log(a); // 1

// let / const exist in a Temporal Dead Zone from block-entry until
// their declaration line. Reading them in the TDZ throws.
try {
  console.log(b); // throws ReferenceError
  let b = 1;
} catch (e) {
  console.log(e.name); // "ReferenceError"
}

// Even `typeof` throws in the TDZ — unlike typeof on a TRULY
// undeclared identifier, which safely returns "undefined".
console.log(typeof neverDeclared); // "undefined"
try {
  console.log(typeof c); // throws — c IS declared, just in TDZ
  let c;
} catch (e) {
  console.log(e.name); // "ReferenceError"
}

// const has the exact same TDZ behavior as let.
try {
  console.log(d);
  const d = 1;
} catch (e) {
  console.log(e.name); // "ReferenceError"
}
  • TDZ is per-binding-per-scope: the dead zone runs from block-entry to the declaration line, then the binding becomes live.
  • typeof throws inside the TDZ — the one place where typeof on a name is unsafe. On a truly undeclared name, typeof still returns "undefined".
  • const has the same TDZ behavior as let (plus immutability). Only var skips the TDZ — it hoists with the value undefined.
  • TDZ errors are always ReferenceError, never SyntaxError (the binding is valid; the access is just too early).
  • Restructure to fix: declare the let/const FIRST in the block, or move the read AFTER the declaration line.

Q1 What does console.log(a); var a = 1; print?

  1. A 1
  2. B undefined correct
  3. C ReferenceError

Why: var hoists with the value undefined — no TDZ, just a hoisted-but-not-yet-assigned binding.

Q2 What happens when console.log(b); let b = 1; runs?

  1. A Prints undefined
  2. B Prints 1
  3. C Throws ReferenceError (TDZ) correct
  4. D Throws SyntaxError

Why: let bindings exist from block-entry but are in the Temporal Dead Zone until the declaration line — reading them throws ReferenceError.

Q3 Which of these throws? (A) console.log(typeof notDeclaredAnywhere) (B) { console.log(typeof x); let x; }

  1. A Only A
  2. B Only B correct
  3. C Both A and B
  4. D Neither — typeof never throws

Why: typeof on a truly undeclared name returns "undefined" safely. But typeof on a let/const inside its TDZ DOES throw — the binding exists, it's just not initialized yet.

Q4 Does const have the same TDZ behavior as let?

  1. A No — const is initialized eagerly at block-entry
  2. B Yes — const has the same TDZ as let correct
  3. C Only in strict mode
  4. D Only when declared at module scope

Why: let and const share TDZ semantics — only var skips the dead zone.

L3 — Write it from memory

One position, the code's third segment.

Write inTdz(fn) that calls fn and returns the error name if it throws, otherwise the string "ok". Use it to prove all three TDZ cases throw ReferenceError: reading a let, typeof on a let, and reading a const — each before its declaration. Log the three results, one per line.

Hints
  • The arrow body is its own block scope — let a = 1 inside it creates a TDZ for a from the block-entry to that line.
  • All three reads happen BEFORE the declaration line, so the inner console.log never fires — the read itself throws.
  • typeof is normally the safe way to probe an identifier, but inside a TDZ it throws like any other read.
function inTdz(fn) {
  try {
    fn();
    return "ok";
  } catch (e) {
    return e.name;
  }
}

console.log(inTdz(() => { console.log(a); let a = 1; }));
console.log(inTdz(() => { console.log(typeof b); let b; }));
console.log(inTdz(() => { console.log(c); const c = 1; }));
