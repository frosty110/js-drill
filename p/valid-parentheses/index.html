Valid Parentheses

Push openers; on a closer, the top of the stack must match. Empty stack at the end = valid.

patterns Stack 7 concept · 2 fill-in · 1 drill

Results carried by this link

Problem

Write isValid(s) returning true iff brackets ()[]{} are balanced and properly nested. Log isValid("()[]{}").

Expected output: true

Canonical solution

Stack of pending openers · O(n) / O(n) (time / space)

function isValid(s) {
  const stack = [];
  // Map CLOSER → opener so the lookup at a closer is O(1).
  const pairs = { ')': '(', ']': '[', '}': '{' };
  for (const c of s) {
    if (c in pairs) {
      // pop() on empty returns undefined, mismatching any opener — works as guard.
      if (stack.pop() !== pairs[c]) return false;
    } else {
      stack.push(c);
    }
  }
  // Non-empty means unclosed openers remain — invalid.
  return stack.length === 0;
}
// Time O(n), Space O(n)
  • stack.pop() on an empty array returns undefined — which mismatches every opener, so the early return still works.
  • The final stack.length === 0 check catches unclosed openers at the end of input.
  • Map closer → opener so the lookup at the closer is O(1).

Q1 Why must the final stack be empty for validity?

  1. A The pop on the last closer leaves one residual opener that must be discarded
  2. B Anything left on the stack is an unclosed opener correct
  3. C An empty stack is the only way to confirm the input was balanced ACROSS bracket types — by-type counts can disagree even when the stack is non-empty
  4. D Non-empty stacks signal that the input contained non-bracket characters

Why: An opener is only ever removed by a matching closer, so a leftover entry is an opener that never got one — return stack.length === 0 is the line that rejects '('.

Q2 If stack.pop() runs on an empty stack:

  1. A Throws
  2. B Returns undefined → mismatches every opener → false correct
  3. C Returns null
  4. D Hangs

Why: pop() on an empty array returns undefined rather than throwing, and undefined !== pairs[c] for every closer — which is exactly why the loop body needs no separate empty-stack guard.

Q3 What data structure does this use?

  1. A Queue (FIFO) — openers come out in the order they came in to match closers
  2. B Stack (LIFO) correct
  3. C Min-heap keyed by bracket-type priority
  4. D Doubly-linked list, traversed from both ends inward

Why: Proper nesting means the most recently opened bracket must close first, which is LIFO. A FIFO queue would hand ')' the oldest opener '(' and ']' the next one '[', so it accepts '([)]'.

Q4 Why map closer → opener and not opener → closer?

  1. A Object keys can only be the closing characters because openers are reserved tokens in JSON
  2. B When we see a closer, we want to know what opener it should match correct
  3. C Opener → closer would still work, but the loop body would need two lookups per character instead of one
  4. D Reversed mapping breaks the c in pairs check because JS objects only allow string keys

Why: pairs does two jobs at a closer: c in pairs detects that c IS a closer, and pairs[c] names the opener that must come off the stack. Keying by opener flips the first test — '(' in pairs becomes true and every opener would take the pop branch.

Q5 Why does a stack work but counting each bracket type (e.g. count of '(' must equal count of ')') fail?

  1. A Counters use more memory
  2. B Counters ignore ORDER, so they wrongly accept interleaved input like '([)]' correct
  3. C Counters can't handle three bracket types
  4. D Counters are slower than O(n)

Why: '([)]' has balanced counts for every type, but the nesting is wrong — only a stack enforces the LIFO order that catches it.

Q6 On the closer ')', what must be true for the input to still be valid at that step?

  1. A The stack must be empty
  2. B The popped top must be the matching opener '(' correct
  3. C The next character must also be a closer
  4. D The stack must contain at least two openers

Why: Each closer must pair with the most recently pushed opener; popping and comparing to the closer→opener map enforces that.

Q7 What happens for input ')(' (a closer before any opener)?

  1. A Returns true — counts balance
  2. B Returns false — the first pop on the empty stack yields undefined, mismatching '(' correct
  3. C Throws a runtime error on the empty pop
  4. D Returns true because the '(' is later pushed

Why: pop() on an empty stack returns undefined, which !== '(', so the closer-first case is rejected immediately.
