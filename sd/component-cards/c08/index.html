Indexes & Search

Finding the needle without scanning the haystack. 6 building blocks drilled by recall: the signal that says reach for one, what it costs, how it breaks, which sibling rules it out, and what it is doing across the canonical problems.

Key ideas

  • Inverted Index / Search — A term-to-document mapping built ahead of time, so full-text and faceted queries are lookups rather than scans.
  • Vector Search — Approximate nearest-neighbour lookup over embeddings, retrieving by semantic similarity instead of by keyword.
  • Ranking — Ordering a candidate set by a score — recency, affinity, engagement, relevance — usually as a cheap retrieval stage followed by an expensive scoring stage.
  • Geospatial Index — Mapping 2-D coordinates onto a 1-D key that preserves locality — geohash, quadtree or S2 — so 'what is near me' becomes a range scan.
  • Bloom Filter — A compact probabilistic set that answers 'definitely not present' or 'probably present', trading exactness for tiny memory.
  • Trie / Autocomplete — A prefix tree with top-K completions precomputed at each node, so a keystroke returns suggestions in a single traversal.
