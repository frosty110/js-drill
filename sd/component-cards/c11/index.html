Governance & Accountability

Proving what the system did, for whom, and at what cost. 5 building blocks drilled by recall: the signal that says reach for one, what it costs, how it breaks, which sibling rules it out, and what it is doing across the canonical problems.

Key ideas

  • Audit Log & Provenance — An append-only record of what was decided and what it was shown, pinned to the versions in effect, so the decision can be reconstructed later.
  • Agent Decision Record — The row an autonomous decision writes about itself: what it chose, why, how sure it was, and what it was looking at when it chose.
  • Cost Metering — Attributing the marginal cost of a request to the tenant and unit of work that caused it, then bounding it before it is spent.
  • Progressive Rollout — Earning a change's blast radius in stages, so each widening is justified by evidence the previous stage produced.
  • Tenant Isolation — Keeping one customer's data and load away from another's, enforced below application code so a forgotten predicate cannot leak.

Q2 explain & apply

You put Audit Log & Provenance in a design. Name the signals that should have stopped you — and what it costs even when it is the right call.

Points a strong answer hits:

  • The decision is trivially re-derivable from durable inputs you already retain — then the log stores no information you did not have

  • Evidence has to be captured at decision time, which means storing the third-party response rather than the query that produced it
  • Write amplification on every step of every decision, which is the price of the record being complete rather than sampled
Model answer: Don't reach for it when: The decision is trivially re-derivable from durable inputs you already retain — then the log stores no information you did not have; You only want debugging visibility, where tracing and structured logs are cheaper and are built for the job. Q5 explain & apply

Audit Log & Provenance appears in 6 of the canonical design problems. Name as many as you can, and say what it is doing in each.

Points a strong answer hits:

  • Design a Human Review Queue — A reviewer's decision is written as an immutable event with its reason and the lease that authorised it, and a correction references the original rather than overwriting it.
  • Design a Business Verification Pipeline — Sources disagree routinely, so the record keeps what each one said and which precedence rule decided between them, rather than silently keeping the winner.

Q8 explain & apply

Agent Decision Record is in your design and load goes up ten times. How does it break?

Points a strong answer hits:

  • Free-form reason strings instead of a closed enum, which yields thousands of near-duplicates and no dimension to group by
  • Storing only the applied outcome, so whether a human agreed with the agent cannot be reconstructed and the autonomy metric does not exist
  • Treating a self-reported rationale as proof of reasoning rather than evidence of it, when the model narrates after the fact and can narrate wrongly
  • Collapsing confidence in the answer and completeness of the evidence into one score, which hides the dangerous quadrant where the agent is sure and underinformed
  • Encoding abstention as low confidence plus an escalation, so missing evidence and conflicting sources land in the same bucket and neither gets fixed
  • Referencing a threshold that lives only in config, so the row cannot say what bar it actually cleared
Model answer: Free-form reason strings instead of a closed enum, which yields thousands of near-duplicates and no dimension to group by Storing only the applied outcome, so whether a human agreed with the agent cannot be reconstructed and the autonomy metric does not exist Treating a self-reported rationale as proof of reasoning rather than evidence of it, when the model narrates after the fact and can narrate wrongly Collapsing confidence in the answer and completeness of the evidence into one score, which hides the dangerous quadrant where the agent is sure and underinformed Encoding abstention as low confidence plus an escalation, so missing evidence and conflicting sources land in the same bucket and neither gets fixed Referencing a threshold that lives only in config, so the row cannot say what bar it actually cleared

Q14 explain & apply

Cost Metering vs Rate Limiting vs Resource Scheduling vs Load Shedding — what decides between them?

Points a strong answer hits:

  • Rate Limiting — Bounds request volume; a budget bounds spend, and one expensive request can blow the budget while staying inside the rate limit.
  • Resource Scheduling — Allocates scarce compute between competing work; metering decides what that work was allowed to cost in the first place.
  • Load Shedding — Drops work to protect latency; a budget stops work to protect the bill, and they can disagree about which request to drop.
  • Cost Metering — Attributing the marginal cost of a request to the tenant and unit of work that caused it, then bounding it before it is spent.
Model answer: Rate Limiting: Bounds request volume; a budget bounds spend, and one expensive request can blow the budget while staying inside the rate limit. Resource Scheduling: Allocates scarce compute between competing work; metering decides what that work was allowed to cost in the first place. Load Shedding: Drops work to protect latency; a budget stops work to protect the bill, and they can disagree about which request to drop.

Q19 explain & apply

  • Progressive Rollout — Earning a change's blast radius in stages, so each widening is justified by evidence the previous stage produced.

Reading the s= code

If the URL you opened has an s= parameter, it is a result set: one character per question, in the order the questions appear on this page. Uppercase means credit, lowercase means no credit. The letter is the option index shown here — A is the first option listed.

CharacterMeaning
A B C Dmultiple choice — picked this option, correct
a b c dmultiple choice — picked this option, wrong
Yopen / typed / fill-in — got it
popen — partial credit
nopen / typed / fill-in — missed
-not attempted

One segment: every question on this page, in order.

The order of questions and options on this page is fixed and never changes, which is what makes position alone enough to identify a question. Nothing about the code is stored anywhere — it lives only in the URL its owner chose to share.
