Agent Decision Record

The row an autonomous decision writes about itself: what it chose, why, how sure it was, and what it was looking at when it chose.

Reach for it when

  • A model disposes of work on its own, and someone will later ask why that one went the way it did
  • You want to raise the automated share safely, which means measuring where agent and reviewer disagree
  • Models, prompts, policy and thresholds all move, and a shift has to be attributable to whichever one did

Don't reach for it when

  • The decision is a pure function of stored inputs and a versioned rule, so re-running the rule beats narrating it
  • Only the aggregate is ever questioned, where offline evaluation on a labelled set answers it more cheaply

What it costs you

  • The reason enum must stay closed and versioned to remain queryable, so someone owns a vocabulary that keeps moving
  • Confidence is worthless until calibrated on sampled outcomes, so this only pays off alongside a sampling program
  • A row per decision on the hot path, carrying a rationale and a pointer to the trajectory
  • The threshold in force is copied onto the row on purpose, which looks redundant until it is the only answer

How it breaks

  • Free-form reason strings instead of a closed enum: thousands of near-duplicates and no dimension to group by
  • Storing only the applied outcome, so whether a reviewer agreed with the agent cannot be reconstructed
  • Treating a self-reported rationale as proof of reasoning rather than as evidence of it
  • One score for confidence and completeness, which hides the agent that is sure and underinformed
  • Abstention encoded as low confidence plus an escalation, so missing evidence and source conflict look alike

Instead, consider

  • Audit Log & Provenance — The general provenance record for any decision; this is the shape it takes when the decider is a model, adding calibrated confidence, an abstention state and the agree/disagree column.
  • Progressive Rollout — The mechanism that raises the automated share; this record is the evidence it runs on, because you cannot widen the band without knowing where the agent and the reviewer diverged.

Used in 3 design problems

  • Design a Financial Crime Alert Investigation System — Every auto-closed alert carries the reason code it closed under, the agent's confidence, the threshold in force that day, and whether a reviewer later disagreed.
  • Design a Human Review Queue — The reviewer's verdict is stored beside the agent's recommendation rather than replacing it, so the disagreement rate is a number instead of an impression.
  • Design a Business Verification Pipeline — A verification records which source it believed and how sure it was, so an approval on thin evidence is visible rather than indistinguishable from a confident one.
