Agent Decision Record

The row an autonomous decision writes about itself: what it chose, why, how sure it was, and what it was looking at when it chose.

Reach for it when

  • A model or agent disposes of work on its own and somebody will later ask why that specific one went the way it did
  • You need to move the automated share upward safely, which requires measuring where the agent and a human disagree
  • The decision changes as models, prompts, policy or thresholds change, and you need to attribute a shift to whichever one moved

Don't reach for it when

  • The decision is a pure function of stored inputs and a rule you version anyway, where re-running the rule is cheaper and more honest than a narration of it
  • Nobody ever asks about an individual outcome, only about the aggregate, where offline evaluation over a labelled set answers it more cheaply

What it costs you

  • A reason enum has to be closed and versioned to stay queryable, which means someone owns a vocabulary that will keep changing
  • Confidence is worthless until it is calibrated against sampled outcomes per model and prompt version, so the record only pays off alongside a sampling program
  • A row per decision on the hot path, carrying a rationale and a trajectory reference, so the write is far from free
  • Recording the threshold in force at the time means the row duplicates config on purpose, which reads as denormalization until the day it is the only answer

How it breaks

  • Free-form reason strings instead of a closed enum, which yields thousands of near-duplicates and no dimension to group by
  • Storing only the applied outcome, so whether a human agreed with the agent cannot be reconstructed and the autonomy metric does not exist
  • Treating a self-reported rationale as proof of reasoning rather than evidence of it, when the model narrates after the fact and can narrate wrongly
  • Collapsing confidence in the answer and completeness of the evidence into one score, which hides the dangerous quadrant where the agent is sure and underinformed
  • Encoding abstention as low confidence plus an escalation, so missing evidence and conflicting sources land in the same bucket and neither gets fixed
  • Referencing a threshold that lives only in config, so the row cannot say what bar it actually cleared

Instead, consider

  • Audit Log & Provenance — The general provenance record for any decision; this is the shape it takes when the decider is a model, adding calibrated confidence, an abstention state and the agree/disagree column.
  • Progressive Rollout — The mechanism that raises the automated share; this record is the evidence it runs on, because you cannot widen the band without knowing where the agent and the reviewer diverged.

Used in 3 design problems

  • Design a Financial Crime Alert Investigation System — Every auto-closed alert carries the reason code it closed under, the agent's confidence, the threshold in force that day, and whether a reviewer later disagreed.
  • Design a Human Review Queue — The reviewer's verdict is stored beside the agent's recommendation rather than replacing it, so the disagreement rate is a number instead of an impression.
  • Design a Business Verification Pipeline — A verification records which source it believed and how sure it was, so an approval on thin evidence is visible rather than indistinguishable from a confident one.
