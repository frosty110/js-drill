Cost Metering

Attributing the marginal cost of a request to the tenant and unit of work that caused it, then bounding it before it is spent.

Governance & Accountability signature mechanism 3 problems

Reach for it when

  • The per-request cost is large enough that it, rather than CPU or storage, is the first ceiling you will hit
  • The system decides how much work to do, so it spends autonomously and needs a bound, not a dashboard
  • You bill by consumption, or you need unit economics per tenant to know whether the product works

Don't reach for it when

  • Marginal cost is a rounding error next to fixed infrastructure, so this is overhead on the hot path
  • A flat rate already caps exposure, in which case a budget adds a failure mode without removing one

What it costs you

  • Attribution has to be threaded through every call path, and one unattributed path is the one that will surprise you
  • A budget is a new way to fail: you must decide whether exceeding it degrades, queues, or rejects, and say so
  • Vendor prices change underneath you, so the cost model needs its own update path or it silently stops being true

How it breaks

  • Metering after the fact, which reports the overspend rather than preventing it
  • Budgeting per request while the expensive unit is a whole session or a whole case, so the cap never binds
  • A shared pool with no per-tenant cap, where one tenant's batch consumes the month
  • Counting only the model or vendor bill and missing the retries, which is where a bad day actually gets expensive

Instead, consider

  • Rate Limiting — Bounds request volume; a budget bounds spend, and one expensive request can blow the budget while staying inside the rate limit.
  • Resource Scheduling — Allocates scarce compute between competing work; metering decides what that work was allowed to cost in the first place.
  • Load Shedding — Drops work to protect latency; a budget stops work to protect the bill, and they can disagree about which request to drop.

Used in 3 design problems

  • Design an LLM Inference Platform — GPU seconds are the scarce resource and the KV cache sets how many sequences fit, so admission is a spend decision per request rather than a queueing one.
  • Design a Financial Crime Alert Investigation System — An agent choosing its own tools is spending money autonomously, so each case carries a hard budget and cost becomes an input to tool selection rather than a report afterwards.
  • Design a Business Verification Pipeline — A full ownership walk can fire dozens of paid lookups, so checks are ordered by cost and information gain and results are cached per entity across applications.
