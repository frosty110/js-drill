Deduplication

Storing identical content once by addressing it with a hash of its bytes, so repeats cost a reference instead of a copy.

Storage & Data Stores signature mechanism 2 problems

Reach for it when

  • The prompt implies heavy duplication — shared files, re-uploads, mirrored pages
  • Storage or bandwidth cost is an explicit constraint
  • You need to detect 'have I already processed this?' cheaply

Don't reach for it when

  • Content is unique by nature; you pay hashing cost for nothing
  • Per-copy metadata or permissions must differ, and a shared object cannot carry them

What it costs you

  • Hashing on the write path, and a content-address index that must itself scale
  • Reference counting, which means deletion is now a distributed garbage-collection problem
  • Cross-tenant dedup raises real security and isolation questions

How it breaks

  • Reference count leaks so nothing is ever reclaimed
  • Deleting an object still referenced by another user
  • Hash collision handling ignored entirely because it 'cannot happen'

Instead, consider

  • Bloom Filter — If you only need 'have I seen this before' and can tolerate false positives, a bloom filter is far cheaper.
  • Chunking — Chunk-level dedup catches partial overlap that whole-file dedup misses.

Used in 2 design problems

  • Design a Web Crawler — URL and content deduplication, so the crawler neither re-fetches a page nor stores identical content under two different addresses.
  • Design a File Sync / Object Storage Service — Content-addressed chunks mean an identical block uploaded by any user is stored once — where the storage savings in this design come from.
