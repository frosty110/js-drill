Fan-out

Turning one write into many per-recipient writes — precomputing on write (push) instead of assembling on read (pull).

Async & Messaging signature mechanism 5 problems

Reach for it when

  • Reads vastly outnumber writes and the read must be fast
  • The prompt describes feeds, timelines or notifications with a follower graph
  • The per-recipient view is expensive to assemble at query time

Don't reach for it when

  • One writer has millions of recipients — write amplification explodes
  • Recipients rarely read what you precomputed; you did the work for nothing
  • The content changes after delivery and every copy would need updating

What it costs you

  • Storage for N copies of what was logically one item
  • Write amplification proportional to the fan-out degree
  • Deletes and edits must chase every copy you created

How it breaks

  • Celebrity write becoming a thundering-herd event that stalls the fan-out pipeline
  • Partial fan-out on failure leaving some recipients with the item and others without
  • Unbounded per-recipient lists growing forever because nothing caps them

Instead, consider

  • Ranking — Fan-out decides WHAT is in the feed; ranking decides the order. The hybrid answer needs both.
  • Cache — Fan-out-on-read plus an aggressive cache is the pull-side answer, and it is right for low-follower accounts.

Used in 5 design problems

  • Design a News Feed — The central tradeoff: push each post into every follower's timeline on write, or assemble on read — with the hybrid as the production answer.
  • Design a Photo-Sharing Service — New photos are pushed into follower feeds, carrying the same celebrity write-amplification problem and the same hybrid escape hatch.
  • Design a Chat System — One message delivered to every member of a group conversation — a fan-out over live connections rather than over stored timelines.
  • Design a Notification System — One triggering event expanded into per-user, per-channel deliveries, with email, push and SMS each a separate send from a single source event.
  • Design a Live Streaming Service — One encoded stream distributed to the entire audience at once, where the fan-out degree is the viewer count and the CDN is what makes it affordable.
