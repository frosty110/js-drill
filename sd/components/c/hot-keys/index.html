Hot-Key Mitigation

Techniques for the one key whose traffic exceeds what a single shard or cache node can serve — replicate it, split it, or absorb it locally.

Reach for it when

  • The prompt contains a celebrity, a viral item, or a flash sale on one SKU
  • Load is skewed enough that adding shards does not help because the skew rides along
  • One partition is saturated while the rest of the fleet is idle

Don't reach for it when

  • Load is genuinely uniform; you are solving a problem the workload does not have
  • The hot entity needs strong consistency — replicating it multiplies the write-coordination cost

What it costs you

  • Key splitting (key#1..key#N) pushes fan-in complexity to every reader
  • Local in-process caches multiply staleness windows by the number of app servers
  • Detection needs per-key telemetry you probably are not collecting yet

How it breaks

  • Mitigation applied statically, so yesterday's celebrity is replicated and today's is melting a shard
  • Split counters read before all sub-keys are summed, producing numbers that go backwards
  • The hot key is a WRITE key, so replication makes contention worse rather than better

Instead, consider

  • Consistent Hashing — Solves uneven placement, not uneven demand. Virtual nodes will not save you from one viral key.
  • Cache — A local cache tier in front absorbs read skew without touching the sharding scheme.

Used in 4 design problems

  • Design a News Feed — The celebrity account: one write with tens of millions of followers, which is precisely the case that breaks naive fan-out-on-write.
  • Design a Leaderboard — One popular leaderboard absorbs most of the reads and writes, so its sorted set has to be split or replicated away from the others.
  • Design an Ad Click Aggregator — A viral campaign concentrates click events on a single aggregation key, saturating whichever partition happens to own it.
  • Design a Proximity Service — Dense urban cells hold vastly more entities and receive vastly more queries than the rest of the grid, by orders of magnitude.
