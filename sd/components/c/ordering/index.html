Message Ordering

Guaranteeing that messages sharing a key are processed in the order they were produced — usually by binding a key to one partition.

Reach for it when

  • State transitions must apply in sequence — edits, balances, status changes
  • The prompt says messages in a conversation or a stream must not appear out of order
  • A later event invalidates an earlier one and applying them backwards corrupts state

Don't reach for it when

  • Operations are commutative; ordering costs parallelism you did not need to spend
  • Global ordering across all keys is the requirement — that serialises everything

What it costs you

  • Per-key ordering means per-key serialisation, capping parallelism at the partition count
  • A partition's throughput becomes the ceiling for its hottest key
  • Rebalancing consumers has to preserve the guarantee, which complicates scaling

How it breaks

  • Retrying a failed message out of band and applying it after its successor
  • Repartitioning silently breaking the key-to-partition binding that provided the order
  • Clock-based ordering across producers giving an order that never actually happened

Instead, consider

  • Conflict Resolution — If you cannot order, make the operations mergeable instead — CRDTs and version vectors.
  • Idempotency — Sequence numbers plus idempotent apply lets a consumer detect and discard out-of-order replays.

Used in 4 design problems

  • Design a Chat System — Messages within one conversation must appear in the same order for every participant, which pins a conversation to a single partition.
  • Design a Collaborative Document Editor — Operations on a document must apply in an agreed sequence — the thing the OT or CRDT machinery exists to establish.
  • Design a Distributed Message Queue — Per-partition ordering is the guarantee the broker sells; global ordering is deliberately not offered because it would serialise everything.
  • Design a Human Review Queue — Arrival order carries no information about importance, so the queue orders by risk and deadline with an aging term that bounds how long the tail can wait.
