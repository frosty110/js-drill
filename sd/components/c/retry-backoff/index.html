Retry with Backoff & Jitter

Re-attempting a failed call on an exponentially increasing, randomised delay, so transient failures heal without synchronising the fleet.

Reach for it when

  • Failures are transient — a timeout, a brief unavailability, a throttled response
  • The operation is idempotent or has been made so
  • The prompt asks how you handle partial failure in a distributed call graph

Don't reach for it when

  • The failure is deterministic; retrying a malformed request just multiplies it
  • The operation is not idempotent and duplicates would be harmful
  • You are retrying at several layers at once, multiplying attempts geometrically

What it costs you

  • Retries consume capacity at exactly the moment capacity is scarce
  • Latency budget must accommodate the retries or the caller times out anyway
  • Attempt caps and total deadlines are required, and are extra parameters to get right

How it breaks

  • No jitter, so every client retries in lockstep and produces a synchronised thundering herd
  • Retry amplification across layers turning one user request into dozens of backend calls
  • Retrying a request that actually succeeded but whose response was lost, without an idempotency key

Instead, consider

  • Circuit Breaker — Once failures are sustained rather than transient, stop retrying and trip.
  • Work Queue — Move the work off the request path and let the queue own durable retry.

Used in 4 design problems

  • Design a Web Crawler — Re-fetches a page that timed out on a growing, jittered delay, so a struggling host is not hit again immediately.
  • Design a Notification System — Governs redelivery after a transient provider error, with jitter so every pending notification does not retry in lockstep.
  • Design a Distributed Job Scheduler — Decides how a failed attempt is re-scheduled, and the ceiling at which it stops being retried and is dead-lettered.
  • Design a Webhook Delivery System — The delivery schedule itself — exponential, jittered and capped, because a receiver's outage must not become a retry storm.
