Inverted Index / Search

A term-to-document mapping built ahead of time, so full-text and faceted queries are lookups rather than scans.

Reach for it when

  • Users query by content rather than by key — free text, filters, facets
  • The prompt needs relevance ordering, not just matching
  • A LIKE '%…%' over the primary store would be a full scan

Don't reach for it when

  • Lookups are always by primary key
  • The index would need to be transactionally consistent with the database
  • The corpus is small enough to filter in memory

What it costs you

  • A second copy of the data with its own ingestion pipeline and lag
  • Analysis choices — tokenising, stemming, language — are baked in at index time
  • Reindexing after a mapping change is a full rebuild, not a migration

How it breaks

  • Index drifting from the source of truth with no reconciliation job to catch it
  • Deep pagination degrading badly because every shard must return the full prefix
  • Hot shard from an uneven document distribution
  • Ingestion lag making just-written content unfindable exactly when users look for it

Instead, consider

  • Trie / Autocomplete — For prefix matching specifically, a trie is far cheaper than a general search engine.
  • Vector Search — When the match should be semantic rather than lexical.

Used in 4 design problems

  • Design a Typeahead / Autocomplete Service — The prefix-to-completions structure that turns each keystroke into a lookup rather than a scan over the query log.
  • Design a RAG / Semantic Search System — Keyword retrieval running alongside vector search, because hybrid retrieval consistently beats either one alone on real queries.
  • Design a Search Engine — The inverted index is the system: term → posting list is what makes query time independent of corpus size.
  • Design a Sanctions Screening System — Alias, transliteration and spelling expansion turn 40K sanctioned entities into millions of searchable strings, so candidate generation runs over an n-gram index rather than the entity list.
