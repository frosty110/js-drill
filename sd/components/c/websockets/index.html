WebSockets / Persistent Connections

A long-lived bidirectional connection, so the server can push without the client asking and latency is one hop rather than one poll interval.

APIs & Realtime signature mechanism 4 problems

Reach for it when

  • The server must initiate — chat messages, live location, presence, collaborative edits
  • Updates are frequent enough that polling would be wasteful or too slow
  • The prompt says real time and means sub-second

Don't reach for it when

  • Updates are one-way server-to-client and infrequent — SSE is simpler and survives proxies better
  • Clients are mobile and frequently backgrounded, where connections die constantly
  • Update frequency is low enough that polling is honestly fine

What it costs you

  • Connection state pins users to servers, which breaks stateless load balancing
  • Memory and file descriptors per connection cap how many fit on a box
  • You must build reconnect, resume and missed-message backfill yourself

How it breaks

  • Reconnect storm after a deploy or network blip, all clients at once
  • Messages sent while disconnected being lost with no replay path
  • Idle proxies and load balancers silently killing connections without a heartbeat
  • Uneven connection distribution because balancing happened at connect time and never again

Instead, consider

  • Server-Sent Events — Server-to-client only, over plain HTTP, with automatic browser reconnect. Usually enough for feeds and notifications.
  • Webhooks — When the recipient is a server rather than a browser, push to their endpoint instead of holding a socket.

Used in 4 design problems

  • Design a Chat System — Holds the client connection so inbound messages are pushed instantly, with presence and delivery receipts riding the same channel.
  • Design a Ride-Sharing Service — Carries continuous driver location updates and ride-match offers — both server-initiated and both latency-critical.
  • Design a Collaborative Document Editor — Streams each operation to every other collaborator, which is the only way the shared-cursor experience can feel live.
  • Design a Live Streaming Service — Powers chat and reactions alongside the video, providing the interactive layer a segment-based CDN path structurally cannot.
