Work Queue

A durable buffer of tasks between a producer and a pool of workers, so slow work happens outside the request path.

Async & Messaging signature mechanism 9 problems

Reach for it when

  • The prompt has work that must happen but not before the user gets a response
  • Producer and consumer rates differ, especially in bursts
  • Retries need to be automatic and durable across a worker crash

Don't reach for it when

  • The caller needs the result to continue — you have added latency and a callback problem
  • Strict end-to-end ordering across all work is required
  • The work is trivial; a queue adds an operational component to save nothing

What it costs you

  • Eventual consistency becomes visible to users ('it will appear in a moment')
  • Another durable system to run, monitor and reason about
  • Every consumer must be idempotent, because delivery is at-least-once

How it breaks

  • Unbounded backlog growth when consumers cannot keep up, turning latency into an outage
  • Poison message retried forever, blocking the queue behind it
  • Duplicate processing from redelivery after a consumer crash mid-work

Instead, consider

  • Pub/Sub — A queue gives each message to ONE consumer; pub/sub gives it to all of them. Different question.
  • Backpressure — A queue absorbs bursts; it does not fix a consumer that is permanently too slow.

Used in 9 design problems

  • Design a Web Crawler — The URL frontier — the crawler's queue of what to fetch next, with politeness and priority encoded in how items are dequeued.
  • Design a Notification System — Decouples the triggering event from delivery, so a slow SMS provider cannot block push notifications or the request that caused them.
  • Design a Distributed Job Scheduler — The dispatch path: due jobs are enqueued and worker pools pull from it, which is what separates deciding-what-is-due from running-it.
  • Design an LLM Inference Platform — Inference requests wait for scarce GPU capacity rather than being rejected outright, with queue depth feeding the admission decision.
  • Design a Content Moderation Pipeline — Content awaiting automated scoring and human review moves through queues, decoupling upload throughput from review capacity.
  • Design a Financial Crime Alert Investigation System — Alerts arrive as an overnight batch and each investigation runs for minutes, so the queue is what decouples a 4K-alert dump from a fixed pool of concurrent investigations.
  • Design a Sanctions Screening System — Bulk re-screening after a list change is queued rather than run inline, because the two workloads share a matcher but not a latency budget.
  • Design a Human Review Queue — The workers are people, so the queue hands out leases rather than assignments and reclaims anything a reviewer abandons without needing the client to cooperate.
  • Design a Business Verification Pipeline — Verification hops have wildly different latencies, from a 2-second API call to a manual check taking days, so the work is queued per hop rather than held open per application.
