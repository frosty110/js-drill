  1. How a content delivery network — How a content delivery network caches assets close to users to cut latency and offload the origin: pull vs push distribution, edge PoPs, TTL and Cache-Control headers, purge/cache-busting, origin shielding, and running.
  2. Cache-Control, TTL, versioned URLs, purge — Cache-Control, TTL, versioned URLs, purge APIs, and stale serving define the consistency contract.
  3. Freshness is governed by TTL — Freshness is governed by TTL via Cache-Control: max-age (browser/shared) and s-maxage (shared caches like CDNs).
  4. CDNs shine at caching static — CDNs shine at caching static, cacheable assets close to users, but modern edge configuration (cache keys, vary rules, edge compute) lets them cache dynamic or personalized content too.
  5. Reusing the same URL means — Reusing the same URL means caches keep serving the still-fresh old bytes until the TTL lapses or you purge; this is exactly why fingerprinted URLs are preferred.
