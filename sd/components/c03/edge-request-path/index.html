Edge Request Path

System map study sheet

What this sheet shows

A pull CDN populates lazily: the first request for an object misses, the edge pulls it from the origin and caches it per its TTL, and later requests are served from the edge.

Trace the flow

  1. User — TLS + cache lookup; then continue to Nearest edge PoP.
  2. Nearest edge PoP — regional miss; then continue to Origin shield.
  3. Origin shield — final miss; then continue to Application origin.
  4. Application origin — Observe the result, enforce the contract, and feed failures back into the design.

What this belongs to

How a content delivery network caches assets close to users to cut latency and offload the origin: pull vs push distribution, edge PoPs, TTL and Cache-Control headers, purge/cache-busting, origin shielding, and running compute at the edge.
