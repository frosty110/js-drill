Publish Consume Overview

System map study sheet

What this sheet shows

RabbitMQ is a smart broker: producers publish to exchanges (direct/topic/fanout) that route via bindings into queues; it pushes to consumers, waits for acks, then deletes the message.

Trace the flow

  1. Producer — publish; then continue to Durable broker.
  2. Durable broker — claim + acknowledge; then continue to Consumer group.
  3. Consumer group — idempotent apply; then continue to Side effect / store.
  4. Side effect / store — Observe the result, enforce the contract, and feed failures back into the design.

What this belongs to

Asynchronous messaging decouples producers from consumers so systems can buffer bursts, absorb load spikes, and let components fail and recover independently. This section contrasts the two core delivery shapes (point-to-point queues vs pub/sub fan-out) and the dominant brokers (Kafka's partitioned log vs RabbitMQ's exchange/queue model vs managed SQS), plus the delivery-semantics tradeoffs that force idempotent consumers.
