Distributed counters, reservations, and failure policy

Scale and failure study sheet

What this sheet shows

Twenty independent gateways each enforcing the full quota can admit roughly twenty times the intended traffic. Shared atomic state fixes accuracy but adds a network hop. Local token reservations amortize that hop while accepting bounded overshoot.

Show why local counters overshoot a global quota and where accuracy can be traded for latency and availability.

Trace the flow

  1. Shard by limit key — Consistent hashing spreads users while keeping each user's state on one counter shard.
  2. Execute atomically — A Redis script or transactional primitive owns refill and spend for that key.
  3. Reserve locally when needed — Gateways lease small token batches to remove a shared-store round trip from every request.
  4. Bound the error — Reservation size × active gateways defines the worst-case overshoot.
  5. Choose failure semantics — Fail closed for billing or security; fail open or use an emergency local limit for low-risk availability paths.

What this belongs to

Rate limiting protects a service from overload and abuse by capping how many requests a client may make in a window.
