Traffic & Routing

How a request finds a healthy server.

  • Load Balancer 5 problems — A single address in front of many interchangeable servers, spreading requests and routing around dead ones.
  • Service Discovery 4 problems — A registry that answers 'where is service X right now', so callers reach live instances without hardcoded addresses.
  • API Gateway 3 problems — The single front door for external callers: authenticates, applies quota, routes to the right service, and normalises the response.
  • Reverse Proxy 2 problems — A server-side intermediary that terminates the client connection and speaks to backends on its behalf, so cross-cutting work happens once at the edge.
  • DNS & Anycast Routing 2 problems — Steering users to a region or PoP before a connection is ever made, using DNS answers or a single IP announced from many locations.

Caching & Delivery

How to stop doing the same expensive work twice.

  • Cache signature 13 problems — A fast store holding the answer to work you already did, so the expensive path runs once for many reads.
  • CDN signature 4 problems — A globally distributed cache of your static bytes, serving users from a nearby PoP instead of your origin.
  • Hot-Key Mitigation signature 4 problems — Techniques for the one key whose traffic exceeds what a single shard or cache node can serve — replicate it, split it, or absorb it locally.
  • Edge Compute 2 problems — Running small amounts of your logic in the CDN's PoPs, so personalisation, auth or rewriting happens near the user instead of at origin.

Storage & Data Stores

Where bytes live, and which store to name.

  • Key-Value Store 7 problems — A hash table with an operations team: get and put by key, partitioned across nodes, no query language.
  • Object / Blob Storage signature 5 problems — Cheap, effectively unbounded storage for immutable files addressed by key, with HTTP access and lifecycle tiering.
  • Relational Database 4 problems — Row storage with a fixed schema, joins, secondary indexes and multi-row ACID transactions.
  • Document Store 3 problems — Key-value where the value is a structured document the engine can index and query inside.
  • Wide-Column Store 3 problems — Partition-key-first storage (Cassandra, HBase, DynamoDB) built for enormous write volume and range scans within a partition.
  • Time-Series Store 2 problems — A store specialised for append-only timestamped measurements, with automatic downsampling, retention and time-range queries.
  • Chunking signature 2 problems — Splitting a large payload into independently addressable pieces, so transfer, retry, dedup and parallelism operate per piece.
  • Deduplication signature 2 problems — Storing identical content once by addressing it with a hash of its bytes, so repeats cost a reference instead of a copy.

Data Distribution

Spreading one dataset across many machines.

  • Sharding signature 7 problems — Splitting one logical dataset across many machines by a partition key, so capacity and throughput scale horizontally.
  • Replication signature 6 problems — Keeping copies of the same data on multiple nodes, for read capacity, fault tolerance, or geographic proximity.
  • Consistent Hashing signature 3 problems — Placing keys and nodes on a ring so adding or removing a node moves only ~1/N of keys instead of remapping everything.
  • Quorum (N/W/R) 3 problems — Requiring W acknowledgements to write and R responses to read out of N replicas, tuning consistency against availability.
  • Distributed ID Generation signature 1 problem — Producing unique identifiers across many machines without a central allocator — Snowflake-style, UUID, or ranged counters.

Async & Messaging

Decoupling the producer from the consumer.

  • Work Queue signature 9 problems — A durable buffer of tasks between a producer and a pool of workers, so slow work happens outside the request path.
  • Stream Processing signature 7 problems — Continuous computation over an unbounded event stream — windowed aggregation, enrichment and joins applied as data arrives.
  • Fan-out signature 5 problems — Turning one write into many per-recipient writes — precomputing on write (push) instead of assembling on read (pull).
  • Pub/Sub 4 problems — One published event delivered to every interested subscriber, so producers never learn who consumes them.
  • Message Ordering signature 4 problems — Guaranteeing that messages sharing a key are processed in the order they were produced — usually by binding a key to one partition.
  • At-Least-Once Delivery signature 4 problems — The default durable-messaging guarantee: a message is redelivered until acknowledged, so it may arrive more than once but never zero times.
  • Transactional Outbox / CDC 4 problems — Writing the event into the same database transaction as the state change, then shipping it from the table or the write-ahead log — so the event and the data cannot disagree.
  • Pre-Aggregation & Rollups signature 4 problems — Maintaining counters and summaries as data arrives, so a read is a lookup instead of a scan.
  • Dead-Letter Queue 3 problems — A side channel for messages that have failed processing too many times, so one bad item cannot block the pipeline forever.
  • Exactly-Once (Effectively-Once) signature 2 problems — Making duplicate delivery invisible in the result, by pairing at-least-once transport with idempotent or transactional application.

Correctness & Coordination

Getting the right answer when parts fail independently.

  • Idempotency signature 9 problems — Making a repeated operation produce the same result as one execution, usually via a client-supplied key recorded with the effect.
  • Reservation / Hold signature 4 problems — Temporarily claiming a scarce resource with an expiry, so a user can complete a multi-step flow without it being sold underneath them.
  • Conflict Resolution signature 4 problems — Deciding what the truth is when two writers modified the same thing concurrently — last-write-wins, version vectors, OT or CRDTs.
  • Distributed Lock 3 problems — A lease held in a shared store that grants one holder the right to act on a resource for a bounded time.
  • Saga signature 2 problems — A multi-step workflow across services where each step has a compensating action, because no distributed transaction is available.
  • Leader Election signature 2 problems — Picking exactly one node to perform a role, with an agreed way to notice failure and pick again.

Control & Protection

Keeping load inside what the system can survive.

  • Rate Limiting signature 7 problems — Capping how many requests a caller may make in a window, to protect capacity and enforce fairness.
  • Backpressure signature 6 problems — Letting a saturated consumer slow its producer, so queues stay bounded instead of absorbing an overload until something breaks.
  • Retry with Backoff & Jitter 4 problems — Re-attempting a failed call on an exponentially increasing, randomised delay, so transient failures heal without synchronising the fleet.
  • Load Shedding 4 problems — Deliberately dropping or degrading lower-priority work under overload so the system serves its most important traffic instead of failing at everything.
  • Circuit Breaker 3 problems — Tripping a dependency call to fail fast after repeated failures, then probing periodically to see whether it has recovered.
  • Bulkhead Isolation 3 problems — Partitioning resources — thread pools, connections, even fleets — so one dependency or tenant cannot consume everything.

Indexes & Search

Finding the needle without scanning the haystack.

  • Ranking signature 6 problems — Ordering a candidate set by a score — recency, affinity, engagement, relevance — usually as a cheap retrieval stage followed by an expensive scoring stage.
  • Bloom Filter 5 problems — A compact probabilistic set that answers 'definitely not present' or 'probably present', trading exactness for tiny memory.
  • Inverted Index / Search signature 4 problems — A term-to-document mapping built ahead of time, so full-text and faceted queries are lookups rather than scans.
  • Geospatial Index signature 2 problems — Mapping 2-D coordinates onto a 1-D key that preserves locality — geohash, quadtree or S2 — so 'what is near me' becomes a range scan.
  • Trie / Autocomplete 2 problems — A prefix tree with top-K completions precomputed at each node, so a keystroke returns suggestions in a single traversal.
  • Vector Search signature 1 problem — Approximate nearest-neighbour lookup over embeddings, retrieving by semantic similarity instead of by keyword.

APIs & Realtime

How callers talk to you, and how you talk back.

  • WebSockets / Persistent Connections signature 4 problems — A long-lived bidirectional connection, so the server can push without the client asking and latency is one hop rather than one poll interval.
  • Cursor Pagination 4 problems — Returning a page plus an opaque cursor pointing at the last item, so the next page seeks rather than counting from the start.
  • REST 3 problems — Resource-oriented HTTP with standard verbs, status codes and cacheable GETs — the default public API shape.
  • gRPC 3 problems — Binary RPC over HTTP/2 with an IDL-defined contract, code generation, streaming and multiplexing.
  • Webhooks 3 problems — Pushing events to a URL the customer registered, so their server learns about changes without polling yours.
  • Server-Sent Events 2 problems — A one-way stream of events over a normal HTTP response, with browser-native reconnect and event ids for resumption.
  • GraphQL 2 problems — A single endpoint where the client declares exactly which fields of a graph it wants, in one round trip.

Media & ML Serving

Specialised workloads with their own economics.

  • Transcoding Pipeline signature 3 problems — Converting uploaded media into the ladder of formats, resolutions and bitrates that clients actually stream.
  • Feature Store / Serving signature 2 problems — Serving the same computed signals to training and to inference, with an offline store for history and an online store for low-latency reads.
  • Resource Scheduling signature 1 problem — Allocating scarce, expensive compute — GPUs, batch slots — across competing requests by priority, batching and queueing.

Governance & Accountability

Proving what the system did, for whom, and at what cost.

  • Audit Log & Provenance signature 6 problems — An append-only record of what was decided and what it was shown, pinned to the versions in effect, so the decision can be reconstructed later.
  • Tenant Isolation signature 6 problems — Keeping one customer's data and load away from another's, enforced below application code so a forgotten predicate cannot leak.
  • Progressive Rollout signature 5 problems — Earning a change's blast radius in stages, so each widening is justified by evidence the previous stage produced.
  • Agent Decision Record signature 3 problems — The row an autonomous decision writes about itself: what it chose, why, how sure it was, and what it was looking at when it chose.
  • Cost Metering signature 3 problems — Attributing the marginal cost of a request to the tenant and unit of work that caused it, then bounding it before it is spent.
