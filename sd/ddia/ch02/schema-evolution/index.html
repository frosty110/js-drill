Schema Evolution

Focused mechanism study sheet

What this sheet shows

Tradeoff: schema-on-read gives cheap, incremental evolution over heterogeneous data; schema-on-write gives strong guarantees but a heavier, all-at-once migration.

Trace the flow

  1. Tradeoff — Tradeoff: schema-on-read gives cheap, incremental evolution over heterogeneous data; schema-on-write gives strong guarantees but a heavier, all-at-once migration.
  2. Document databases use schema-on-read versus — Document databases use schema-on-read (implicit, interpreted at read time) versus the relational schema-on-write (explicit, enforced on write), analogous to dynamic vs static type checking.
  3. Schema-on-read is like dynamic type — Schema-on-read is like dynamic type checking — errors surface at runtime when data is accessed — while schema-on-write is like static type checking, catching structural problems up front when data is written.
  4. Schemaless really means schema-on-read — Schemaless really means schema-on-read: the schema still exists but lives in application code and is only interpreted when a record is read, like dynamic typing.
  5. That's cheap and incremental but — That's cheap and incremental but pushes the risk into runtime and my test coverage; a relational schema-on-write would instead force an explicit migration up front where the database enforces the new shape, catching.
