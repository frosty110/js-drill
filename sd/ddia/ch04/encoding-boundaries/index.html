Encoding Boundaries

System map study sheet

What this sheet shows

Avro's encoding is just concatenated values with no tags, so decoding requires the exact writer's schema; the Avro library then resolves it against the reader's schema, matching fields by name and filling in defaults or dropping fields as needed.

Trace the flow

  1. Old + new writers — encode; then continue to Versioned encoding.
  2. Versioned encoding — preserve unknown fields; then continue to Stored / transmitted bytes.
  3. Stored / transmitted bytes — decode compatibly; then continue to Old + new readers.
  4. Old + new readers — Observe the result, enforce the contract, and feed failures back into the design.

What this belongs to

How data is encoded (serialized) for storage or transmission and how those encodings let applications evolve. Because old and new code and data coexist during rolling upgrades, formats must preserve backward and forward compatibility across databases, services, and message brokers.
