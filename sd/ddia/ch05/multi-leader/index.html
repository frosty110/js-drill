Multi-leader replication and conflict resolution

Conflict flow study sheet

What this sheet shows

Each region accepts writes locally and exchanges them asynchronously. When two leaders update the same object without observing each other, the system must preserve causal metadata, detect concurrency, and apply a deterministic policy such as an application merge or CRDT.

Show how local writes become concurrent and why detection, deterministic merge, and convergence are part of the write model.

Trace the flow

  1. Write locally — Region A and Region B acknowledge nearby clients without a cross-ocean round trip.
  2. Replicate asynchronously — Each leader sends operations and causal metadata to the other leaders.
  3. Detect concurrency — Version vectors distinguish overwrites from genuinely concurrent updates.
  4. Resolve deliberately — Prefer application merge or CRDT semantics; last-write-wins silently discards data.
  5. Converge — Replicate the resolved version until every leader and follower agrees.
