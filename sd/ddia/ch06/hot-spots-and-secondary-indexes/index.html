Hot Spots And Secondary Indexes

Scale and trade-offs study sheet

What this sheet shows

Skew means load isn't spread evenly; hot spots bottleneck on a few nodes while others idle.

Trace the flow

  1. Skew means load isn't spread — Skew means load isn't spread evenly; hot spots bottleneck on a few nodes while others idle.
  2. Key-range partitioning keeps keys sorted — Key-range partitioning keeps keys sorted (enabling range scans) but risks hot spots; hash partitioning spreads load evenly but loses efficient range queries.
  3. Secondary indexes are either document-partitioned — Secondary indexes are either document-partitioned (local, scatter/gather reads) or term-partitioned (global, writes fan out but reads hit one partition).
  4. This gives one-partition range queries — This gives one-partition range queries without global hot spots.
  5. Local (document-partitioned) index — Local (document-partitioned) index: each partition indexes only its own docs, so a secondary-index query must scatter to ALL partitions and gather — reads expensive, writes cheap (stay on one partition).
