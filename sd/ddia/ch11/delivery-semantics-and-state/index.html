  1. To avoid a slow remote — To avoid a slow remote lookup per event, the stream processor maintains a local, continuously-updated copy of the table fed by the database's change stream, and enriches events from that local state.
  2. Stream processing treats unbounded events — Stream processing treats unbounded events as data, maintaining derived views while handling time, replay, and delivery.
  3. Event sourcing stores immutable events — Event sourcing stores immutable events as the source of truth and derives current state by replaying them, enabling auditability, multiple read views (CQRS), and reprocessing to fix bugs.
  4. Log compaction keeps just the — Log compaction keeps just the latest message per key and throws away older values for that key, so the compacted log holds current state without growing unbounded.
  5. Event sourcing persists the log — Event sourcing persists the log of state-changing events as the authoritative record and reconstructs current state by folding over them, rather than mutating state in place.
