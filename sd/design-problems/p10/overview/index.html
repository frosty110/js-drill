What this sheet shows

millions of docs, but concurrency-per-doc is small (typically <50 active editors on one doc), which shapes the per-doc room design.

Trace the flow

  1. High-level architecture — A per-document coordinator orders durable edit operations while WebSocket gateways distribute them to collaborators.
  2. Optimistic edit and server-ordered operation flow — Clients apply edits immediately, then the coordinator transforms or merges them, assigns order, persists, and broadcasts.
  3. OT vs CRDT convergence — OT transforms operations against server history; CRDTs use mergeable identifiers and metadata so replicas can converge independently.
  4. Snapshots, logs, and coordinator failover — Durable operation logs rebuild coordinators; periodic snapshots bound replay time and enable version history.

What this belongs to

A Google Docs-style editor where many users edit the same document concurrently and see each other's changes in real time. The signature challenge is concurrent-edit conflict resolution — making every client converge to the same document despite edits arriving out of order — plus low-latency sync, presence, versioning, and offline merge.
