Metadata Versioning And Repair

Failure and recovery study sheet

What this sheet shows

Serve downloads through a CDN and blob store (S3); keep the metadata DB small and strongly consistent while blobs live in cheap object storage.

Trace the flow

  1. Device A Version — Device A Version; then continue to Base Version Check.
  2. Base Version Check — Base Version Check; then continue to Device B Version.
  3. Device B Version — Device B Version; then continue to Current Version.
  4. Current Version — Current Version; then continue to Conflict Copy.
  5. Conflict Copy — Conflict Copy; then continue to CDN.
  6. Stage 6 — CDN; verify the result and expose the outcome.

What this belongs to

A Dropbox/S3-style service that stores files durably and keeps them in sync across a user's devices. The signature challenge is transferring only the bytes that changed: split files into content-addressed chunks, dedup them globally, and separate a metadata service (file → chunk list, versions) from the raw blob store.
