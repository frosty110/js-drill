Offline Index Build

Focused mechanism study sheet

What this sheet shows

Behind it is an offline pipeline: query logs are aggregated (map-reduce or a streaming job) over a rolling window into per-query frequency scores, then a build job constructs the trie and precomputes each node's top-K completions from those scores.

Trace the flow

  1. Prefix new — Prefix new; then continue to Node n.
  2. Node n — Node n; then continue to Node e.
  3. Node e — Node e; then continue to Node w.
  4. Node w — Node w; then continue to Top K Suggestions.
  5. Top K Suggestions — Top K Suggestions; then continue to Response.
  6. Response — Response; verify the result and expose the outcome.

What this belongs to

Search-box suggestions that appear as the user types, in under ~100ms. The signature structure is a trie of prefixes where each node caches its precomputed top-K completions, so a lookup is O(prefix length) rather than a ranking query at request time.
