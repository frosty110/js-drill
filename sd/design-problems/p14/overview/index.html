Typeahead / Autocomplete Service system map

System map study sheet

What this sheet shows

LIKE 'prefix%' (no leading wildcard) can use a B-tree index to find the matching range, but for a hot prefix like 'a' that range is enormous and the DB must still gather and sort by frequency on every keystroke — impossible at hundreds of thousands of QPS within 100ms.

Trace the flow

  1. High-level architecture — An offline aggregation pipeline builds compact top-K tries that a memory-resident serving tier queries in a few hops.
  2. Precompute top suggestions at each trie node — Prefix traversal ends at one node whose cached top-K list makes ranking independent of the number of matching phrases.
  3. Batch build and atomic trie publish — Logs are aggregated and filtered offline, then versioned trie snapshots are warmed and swapped into serving without partial updates.
  4. Route by leading prefix and replicate hot shards — A small router selects the prefix shard; popular prefixes get extra replicas so latency stays bounded under skew.

What this belongs to

Search-box suggestions that appear as the user types, in under ~100ms. The signature structure is a trie of prefixes where each node caches its precomputed top-K completions, so a lookup is O(prefix length) rather than a ranking query at request time.
