Prescription Drug Marketplace system map

System map study sheet

What this sheet shows

Reserve inventory at the chosen pharmacy with a TTL hold, the same reservation pattern as seat booking — but contention here is mild, so the mechanism can be simple.

Trace the flow

  1. High-level architecture — Every order passes through a synchronous clinical gate before pharmacy routing, payment, or dispensing can proceed.
  2. Versioned clinical safety pipeline — A versioned rules pipeline returns severity-tiered findings so hard blocks, pharmacist reviews, and advisories remain explainable.
  3. Every refill earns a new approval — A subscription stores refill intent only; each cycle rechecks prescription state and current medications before creating an order.
  4. Fail-closed order saga — Dependency failure holds the order for review, while reversible reservations and charges complete before the irreversible dispense step.

What this belongs to

An online pharmacy marketplace with recurring refills, where the signature challenge is not scale but SAFETY correctness: no patient may ever be dispensed a medication that is contraindicated for them. A fail-closed clinical validation gate sits synchronously in the order-placement write path, reading a strongly-consistent view of the patient's active medication list, and re-runs on every subscription cycle because a refill that was safe at signup can become unsafe months later.
