Ad click aggregator system map

System map study sheet

What this sheet shows

One durable log feeds two consumers: a stream job for freshness and a raw archive for the nightly batch that produces the number you invoice on.

Establish the component map and the two-consumer split before any mechanism sheet goes deep.

Trace the flow

  1. Collect and batch — Ad servers emit clicks to a collector that validates, enriches and batches into the log.
  2. Partition by ad_id — Every event for one ad lands on one partition so aggregation uses local state, never a shuffle.
  3. Aggregate in event time — The stream job keeps per-ad windowed counters in checkpointed state and emits completed minutes.
  4. Archive and reconcile — A parallel sink writes raw events to object storage; a nightly batch recomputes and overwrites finalized periods.
  5. Serve precomputed rollups — The query service reads only (ad_id, minute) rollups — never raw events.

What this belongs to

Ingest a firehose of ad-click events and serve near-real-time aggregated counts that are accurate enough to bill on. The signature challenge is counting correctly under at-least-once delivery, out-of-order events, and advertiser hot keys.
