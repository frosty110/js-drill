Why a crash does not double-count

Failure study sheet

What this sheet shows

Offsets and sink writes commit in one transaction, and windows are written as absolute upserts — so a replay overwrites rather than increments.

Show the precise crash window and the two properties that close it.

Trace the flow

  1. Checkpoint state and offsets — The processor snapshots keyed state together with its source position.
  2. Process a batch — Counters advance in local state; nothing is durable yet.
  3. Crash before commit — On restart the job restores the checkpoint and replays from that exact offset.
  4. Commit atomically — Source offsets and sink writes land in a single transaction, so there is no gap or overlap.
  5. Upsert absolute values — Writing the window total rather than a delta makes any replay idempotent.

What this belongs to

Ingest a firehose of ad-click events and serve near-real-time aggregated counts that are accurate enough to bill on. The signature challenge is counting correctly under at-least-once delivery, out-of-order events, and advertiser hot keys.
