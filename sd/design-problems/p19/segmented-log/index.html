Partition storage: segments and the sparse index

Mechanism study sheet

What this sheet shows

Appends are sequential into fixed-size segment files; a sparse offset index turns a seek into a binary search plus a short scan, and expiry is a file unlink.

Show why a disk-backed log outruns an in-memory queue.

Trace the flow

  1. Append to the open segment — Only the newest segment accepts writes; older ones are immutable.
  2. Index sparsely — An offset-to-byte index per segment avoids scanning the file to find a position.
  3. Serve reads from page cache — Trailing reads hit the OS page cache rather than the disk.
  4. Send without copying — sendfile pushes pages straight to the socket, never entering application memory.
  5. Expire whole segments — Retention deletes files instead of compacting rows.

What this belongs to

Build the log itself — a Kafka-style partitioned, replicated commit log with durable ordered storage, consumer groups, and offset tracking. The signature challenge is getting durability and throughput from the same design instead of trading one for the other.
