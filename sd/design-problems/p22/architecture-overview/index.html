LLM inference platform system map

System map study sheet

What this sheet shows

Requests queue by priority and are admitted only when free KV blocks exist — because the real capacity unit is cache memory, not connections.

Establish that admission is gated on GPU memory, not on worker count.

Trace the flow

  1. Authenticate and route — The gateway applies auth, rate limits and model routing.
  2. Queue by priority — Interactive chat and offline batch occupy separate classes.
  3. Admit on free blocks — The scheduler admits a sequence only when KV cache capacity exists for it.
  4. Prefill then decode — The prompt is processed in parallel, then tokens are generated one step at a time.
  5. Stream and release — Tokens stream to the client; finishing or disconnecting frees blocks immediately.

What this belongs to

Serve a large language model to many concurrent users on a scarce, expensive GPU fleet. The signature challenge is that generation is autoregressive and variable-length, so classic request-per-worker serving wastes most of the hardware you are paying for.
