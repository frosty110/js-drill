Two-stage hybrid retrieval

Request flow study sheet

What this sheet shows

Bi-encoders can be precomputed but never see the pair; cross-encoders read the pair but cannot be precomputed. So recall about 100 cheaply, then rerank to about five.

Explain why retrieval splits into a cheap recall stage and an expensive precision stage.

Trace the flow

  1. Embed the query — One small forward pass, roughly 10 milliseconds.
  2. Search both ways — ANN for meaning, BM25 for rare literal tokens such as error codes.
  3. Fuse the rankings — Reciprocal rank fusion merges two ordered lists into one.
  4. Rerank the survivors — A cross-encoder scores each query-passage pair jointly.
  5. Apply a relevance floor — If nothing clears it, answer "I do not know" rather than grounding on noise.

What this belongs to

Ground an LLM's answers in a private corpus: chunk and embed documents, retrieve the relevant passages at query time, and cite them. The signature challenge is that retrieval quality — not the model — decides the answer, and the embedding model is a schema you cannot migrate cheaply.
