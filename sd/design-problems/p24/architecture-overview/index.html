Proximity service system map

System map study sheet

What this sheet shows

Static places change rarely, so the whole read path can be precomputed and cached — a design that only works because the data is near-read-only.

Show that the index is small enough to hold in memory and the cell is a natural cache key.

Trace the flow

  1. Receive the query — Latitude, longitude, radius and attribute filters.
  2. Pick the precision — Choose the geohash length whose cell size is nearest the radius.
  3. Look up nine cells — The user cell plus its eight neighbours, from cache or index.
  4. Filter cheaply first — Category and open-now shrink the set before distance maths.
  5. Distance, sort, hydrate — Haversine filter, sort ascending, fetch full records for the page only.

What this belongs to

Answer "what's near me?" over hundreds of millions of places at interactive latency. The signature challenge is that latitude and longitude are two dimensions and every index we have is one-dimensional, so the whole design is about flattening 2D space into a sortable key without losing locality.
