Search engine system map

System map study sheet

What this sheet shows

Every query fans out to every shard and merges — so more documents means more shards, and more queries means more replicas.

Establish that each shard is a complete index and that documents and queries scale differently.

Trace the flow

  1. Analyze at index time — Tokenize, lowercase, remove stopwords, stem.
  2. Write immutable segments — Each shard holds a complete miniature index over its documents.
  3. Analyze the query identically — Any mismatch means a query token can never match its indexed form.
  4. Fan out and score locally — Each shard intersects postings and returns only its local top-K.
  5. Merge and rerank — The coordinator merges, reranks the top few hundred, and fetches the page.

What this belongs to

Serve full-text queries over billions of documents in under a second. The signature challenge is that the inverted index inverts the obvious data layout — you store term to documents rather than document to terms — and everything else follows from making that index shardable, rankable and refreshable.
