Observability platform system map

System map study sheet

What this sheet shows

Metrics, logs and traces have conflicting access patterns — range reads, filtered scans and graph assembly — so they share ingest and diverge at storage.

Show why three signals need three stores behind one ingest path.

Trace the flow

  1. Collect at the host — Agents batch locally and never block the application thread.
  2. Validate and quota — The gateway enforces per-tenant limits before anything reaches storage.
  3. Buffer durably — A queue absorbs storage restarts so ingest never back-pressures production.
  4. Split by signal — Time series, log objects and spans land in stores shaped for their reads.
  5. Query and alert — Dashboards and alert rules read metrics; investigation crosses all three.

What this belongs to

Ingest metrics, logs and traces from thousands of services and make them queryable fast enough to debug an incident. The signature challenge is cardinality — the number of distinct label combinations, not the request rate, is what actually kills a metrics system.
