Per-feature freshness and missing values

Lifecycle study sheet

What this sheet shows

A 30-day average tolerates hours of staleness; a session click count tolerates seconds. A missing value must be a flagged default, never a silent zero.

Show that freshness is declared per feature and that a missing value must be explicit.

Trace the flow

  1. Declare a TTL — Freshness is a property of the feature, not of the system.
  2. Serve if fresh — Value within TTL is returned normally.
  3. Expire if stale — Past TTL, serve the default and raise a staleness alert.
  4. Default if absent — Cold-start entities get a documented default plus a was-defaulted flag.
  5. Log what was served — The served vector is both the debugging record and the skew baseline.

What this belongs to

Serve the same features to model training and to online inference without them disagreeing. The signature challenge is training/serving skew — the silent failure where a model scores well offline and badly in production because the numbers it sees at request time were computed differently.
