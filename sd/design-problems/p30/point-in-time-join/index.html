Point-in-time correctness

Mechanism study sheet

What this sheet shows

A training row may only use values knowable at its label timestamp. Using a later value teaches the model to rely on information it will never have at prediction time.

Show exactly which feature value a training row is allowed to contain.

Trace the flow

  1. Start from label rows — Entity id, label timestamp and label, potentially hundreds of millions of rows.
  2. Keep feature history — Every value stored with the event timestamp it became valid.
  3. Join as-of, backward — Take the latest value at or before the label timestamp.
  4. Bound with a TTL — Without one, a row happily matches a value from a year earlier.
  5. Sort-merge at scale — Both sides stream past each other once instead of per-row lookups.

What this belongs to

Serve the same features to model training and to online inference without them disagreeing. The signature challenge is training/serving skew — the silent failure where a model scores well offline and badly in production because the numbers it sees at request time were computed differently.
