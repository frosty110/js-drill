The reviewer feedback loop and its failure modes

Lifecycle study sheet

What this sheet shows

Reviewer decisions are labels from exactly where the model is weakest, which is active learning by construction — and also a biased sample that automates reviewer bias at scale.

Show what the loop buys and the three ways it degrades.

Trace the flow

  1. Humans decide the band — Every review produces a label plus a policy reason code.
  2. Labels feed retraining — The uncertain band narrows, cutting review cost over time.
  3. Correct sampling bias — Label a random sample too, or the training set only reflects the band.
  4. Audit for bias — Golden sets and per-group error rates catch reviewer bias before it is automated.
  5. Red-team the blind spots — The model never learns about content it never surfaced.

What this belongs to

Screen user-generated content at platform scale using classifiers plus a human review queue. The signature challenge is that both error directions cause real harm, so the design is about routing uncertainty to humans rather than pushing a classifier toward perfect accuracy it will never reach.
