Rotating the signing key without logging everyone out

Lifecycle study sheet

What this sheet shows

Both keys must verify for at least the lifetime of the longest outstanding token, or rotation becomes a fleet-wide forced logout.

Show why the overlap window is the whole mechanism.

Trace the flow

  1. Publish both keys — The key set contains the old and new keys together.
  2. Let verifiers refresh — Services fetch and cache the set before anything changes.
  3. Sign with the new key — Tokens carry a key id so verifiers select correctly.
  4. Wait out the overlap — Old-key tokens remain valid until they expire naturally.
  5. Retire the old key — Only once no outstanding token depends on it.

What this belongs to

Authenticate users once and let every service verify them without a round trip, while still being able to revoke access immediately. The signature challenge is that stateless tokens and instant revocation are in direct tension — the property that makes JWTs scale is exactly the property that makes them impossible to cancel.
