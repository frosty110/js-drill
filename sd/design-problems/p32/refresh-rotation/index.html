Refresh rotation and reuse detection

Mechanism study sheet

What this sheet shows

Each refresh issues a new token and invalidates the old one, so a stolen refresh token is usable at most once and its reuse is a signal.

Show how theft becomes detectable rather than silent.

Trace the flow

  1. Present the refresh token — The only call that reaches the auth service in steady state.
  2. Issue a new pair — A fresh access token and a fresh refresh token.
  3. Invalidate the old one — The previous refresh token is now single-use and spent.
  4. Detect reuse — A spent token reappearing means someone is replaying it.
  5. Kill the family — Revoke every token in the chain and force re-login.

What this belongs to

Authenticate users once and let every service verify them without a round trip, while still being able to revoke access immediately. The signature challenge is that stateless tokens and instant revocation are in direct tension — the property that makes JWTs scale is exactly the property that makes them impossible to cancel.
